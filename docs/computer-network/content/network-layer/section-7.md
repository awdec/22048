<h1><center>第七节 网络层设备</center></h1>

网络层的典型设备是路由器。路由器连接不同 IP 网络，根据目的网络层地址选择下一跳，并在每一段链路上使用相应的数据链路层协议重新封装分组。

## 1. 冲突域和广播域

::: info 408 大纲定位
现行大纲中“网络层设备”的核心要求是路由器的组成和功能、路由表与路由转发。冲突域和广播域主要用于联系集线器、交换机、VLAN 与路由器，本小节作为跨层前置知识回顾。
:::

### 1.1 冲突域

**冲突域**是指使用共享介质时，多个站点同时发送可能相互冲突的网络范围。冲突主要出现在传统半双工共享式以太网中：

- 中继器和集线器只复制物理信号，连接的所有站点仍共享同一个冲突域。
- 网桥和二层交换机在不同端口之间转发帧，每个端口连接的网段构成独立冲突域。
- 交换机端口与单个设备采用全双工点对点链路时，实际上不会发生以太网冲突；但在传统考题的域划分中，仍把每个交换机端口所连接的链路视为独立冲突域。
- 若交换机某端口连接一个集线器，则该端口和集线器下的所有站点共同构成一个冲突域。

交换机分割冲突域，使不同端口可以并行传输，从而提高网络总吞吐量。

### 1.2 广播域

**广播域**是指一个数据链路层广播帧能够到达的网络范围。普通二层交换机收到广播帧后，会在所属 VLAN 内向除入端口外的其他相关端口泛洪，因此交换机默认不能隔离同一 VLAN 内的广播。

路由器不会把普通数据链路层广播帧从一个接口转发到另一个接口。每个路由器接口连接的网络通常属于不同广播域。需要让 DHCP 等特定广播业务跨越路由器时，应由中继代理接收广播请求，再以单播等方式转交服务器，而不是简单透传原广播帧。

VLAN 可以在交换机上逻辑划分广播域：

- 同一 VLAN 即使跨越多台交换机，仍然属于同一逻辑广播域。
- 同一台交换机上的不同 VLAN 属于不同广播域，必须通过路由器或三层交换机才能通信。
- 交换机端口已经划分冲突域，VLAN 主要改变广播域边界，而不是依靠 VLAN 才划分冲突域。

### 1.3 不同设备对域的影响

| 设备或机制 | 是否分割冲突域 | 是否分割广播域 | 说明 |
| --- | --- | --- | --- |
| 中继器、集线器 | 否 | 否 | 所有端口共享物理信号和带宽 |
| 网桥、普通二层交换机 | 是 | 默认否 | 每个端口独立冲突域，广播仍在同一 VLAN 内传播 |
| VLAN | 端口通常已经独立 | 是 | 每个 VLAN 构成独立广播域 |
| 路由器、三层交换机的路由接口 | 是 | 是 | 在不同 IP 网络之间进行网络层转发 |

判断网络中的域数量时，可以先沿物理连接确定集线器形成的共享段和交换机端口边界，统计冲突域；再根据 VLAN 和路由器接口确定广播能够传播的范围，统计广播域。

::: warning 易错点
交换机隔离冲突域，但默认不隔离同一 VLAN 内的广播域；路由器同时构成冲突域和广播域的边界。现代全双工交换链路没有实际冲突，不能因此误认为交换机两侧又属于同一冲突域。
:::

## 2. 路由器的组成和功能

路由器在逻辑上由**控制平面**和**数据平面**组成：

- 控制平面运行路由协议、处理管理配置并计算路由，主要由路由处理器完成。
- 数据平面根据转发表高速处理到达的分组，主要由输入端口、交换结构和输出端口完成。

### 2.1 路由器的主要功能

1. **异构网络互连**：连接使用不同物理介质、帧格式和数据链路层协议的网络。
2. **路由选择**：运行 RIP、OSPF、BGP 等路由协议或使用静态配置，获得到各目的网络的可达路径。
3. **分组转发**：根据目的 IP 地址查找转发表，选择下一跳和输出接口。
4. **逐跳处理**：检查网络层首部，更新 TTL 或跳数限制，并根据协议生成必要的 ICMP 差错报告。
5. **重新封装**：去除输入链路的帧首部和尾部，再按照输出链路协议封装成新帧。
6. **流量管理**：对分组进行排队、调度、丢弃以及必要的服务质量处理。
7. **隔离广播域**：不在不同接口之间直接转发普通数据链路层广播帧。

路由器通常被称为网络层设备，但每个接口仍必须完成相应的物理层和数据链路层功能。它不是只读取 IP 首部而完全不处理帧。

### 2.2 路由器的基本组成

| 组成部分 | 主要功能 | 所属平面 |
| --- | --- | --- |
| 输入端口 | 接收物理信号，处理输入帧，取出网络层分组并进行转发表查找 | 数据平面 |
| 交换结构 | 把分组从输入端口内部传送到选定的输出端口 | 数据平面 |
| 输出端口 | 缓存和调度分组，重新进行链路层封装并发送 | 数据平面 |
| 路由处理器 | 运行路由协议、维护路由表、生成转发表并执行管理控制 | 控制平面 |

输入端口和输出端口不一定对应完全独立的物理部件。一个物理网络接口通常同时具有输入和输出能力，结构图只是按数据处理方向划分其逻辑功能。

### 2.3 输入端口

输入端口通常完成：

- 物理层的信号接收和线路终接。
- 数据链路层的帧同步、地址识别和差错检测。
- 去除链路层首部和尾部，取出网络层分组。
- 进行转发表查找，确定输出端口。
- 在交换结构暂时无法接收时缓存分组。

如果多个分组在同一输入队列中排队，队首分组因目标输出端口忙而不能通过交换结构，即使后面的分组所需输出端口空闲，也可能被阻塞，这称为**队首阻塞 HOL Blocking**。

### 2.4 交换结构

交换结构是路由器内部的分组传送通道，常见实现方式包括：

- **通过内存交换**：输入端口把分组写入共享内存，再由输出端口读出。性能受内存访问带宽限制。
- **通过总线交换**：输入端口把分组放到共享总线上，目标输出端口接收。总线同一时刻通常只能传送有限数量的分组，性能受总线带宽限制。
- **通过互联网络交换**：使用交叉开关等互联结构，可以在输入、输出端口不冲突时并行传送多个分组，扩展能力较强。

### 2.5 输出端口与排队

当多个输入端口的分组同时需要同一个输出端口，或分组到达速度暂时高于输出链路速率时，分组在输出端口排队。输出端口根据调度策略选择下一个发送的分组，并完成链路层封装和物理发送。

缓冲区只能吸收暂时的流量突发。若队列持续增长并耗尽缓冲区，路由器必须丢弃分组；缓冲区过大还可能造成较大的排队时延。

::: warning 易错点
路由处理器主要运行控制平面协议，不应由它逐个处理高速数据流中的所有普通分组；普通分组主要由输入端口、交换结构和输出端口组成的数据平面转发。
:::

## 3. 路由表与分组转发

### 3.1 路由表与转发表

路由表和转发表都与“如何到达目的网络”有关，但用途和组织方式不同：

| 对比项 | 路由表 RIB | 转发表 FIB |
| --- | --- | --- |
| 所属平面 | 控制平面 | 数据平面 |
| 信息来源 | 直连网络、静态配置和动态路由协议 | 根据路由表中选出的有效路由生成 |
| 主要内容 | 目的前缀、下一跳、度量、路由来源等详细信息 | 高速查找所需的目的前缀、下一跳、输出接口和邻接信息 |
| 主要用途 | 比较候选路由，形成全局路由决策 | 对每个到达分组执行快速转发 |
| 实现位置 | 主要由路由处理器维护 | 常下发到线路卡或专用转发硬件 |

路由表可能保存同一目的前缀的多个候选路由，转发表通常保存已经选出的有效转发结果。二者在小型软件路由器中可能使用相近的数据结构，但概念上不能完全等同。

常见路由表项包括：

- **直连路由**：目的网络直接连接在本路由器某接口上。
- **静态路由**：由管理员配置下一跳或输出接口。
- **动态路由**：通过 RIP、OSPF、BGP 等协议学习。
- **主机路由**：只匹配某个具体主机的 `/32` 或 `/128` 前缀。
- **默认路由**：IPv4 中为 `0.0.0.0/0`，在没有更具体匹配时使用。

### 3.2 最长前缀匹配

路由器通常根据分组的**目的 IP 地址**查询转发表。若目的地址同时匹配多条路由，应先选择前缀最长、范围最具体的表项，而不是先选择度量值最小的较短前缀。

例如，某路由器具有：

```text
0.0.0.0/0       → 下一跳 192.168.1.254，接口 G0
10.0.0.0/8      → 下一跳 192.168.1.2，  接口 G0
10.1.0.0/16     → 下一跳 172.16.0.2，   接口 G1
```

目的地址 `10.1.2.3` 同时匹配 `/0`、`/8` 和 `/16`，最终选择 `/16` 路由，从接口 G1 发送给下一跳 `172.16.0.2`。

当多条候选路由的前缀长度相同时，路由器才进一步根据路由来源优先级、度量值或策略选择；若设备支持等价多路径，也可以在代价相同的多条路径间分担流量。

### 3.3 分组转发过程

路由器收到分组后通常按以下顺序处理：

1. **接收链路层帧**：输入接口检查目的链路层地址和帧校验序列，确认帧有效并应由本接口接收。
2. **解封装**：去除输入链路的帧首部和尾部，取出 IP 数据报。
3. **检查网络层首部**：检查版本、长度和其他必要字段；IPv4 还要验证首部校验和。
4. **更新生存字段**：IPv4 TTL 或 IPv6 Hop Limit 减 1。若结果为 0，则丢弃分组并通常发送 ICMP 时间超过报文。
5. **查询转发表**：使用目的 IP 地址执行最长前缀匹配，确定下一跳和输出接口。若没有匹配路由且不存在默认路由，则丢弃分组并通常发送 ICMP 目的不可达报文。
6. **处理 MTU**：若 IPv4 数据报超过输出链路 MTU，根据 DF 位决定分片或丢弃；IPv6 路由器不进行分片，而是丢弃过大数据报并返回 ICMPv6 分组过大报文。
7. **解析下一跳链路地址**：IPv4 通常使用 ARP，IPv6 使用邻居发现协议，获得下一跳接口的链路层地址。
8. **通过交换结构**：把分组从输入端口传送到选定输出端口，必要时进入输出队列。
9. **重新封装并发送**：填写输出链路的新链路层源、目的地址和校验字段，封装成新帧后发送。

若目的网络是路由器的直连网络，下一跳就是最终目的主机；若使用非直连路由，下一跳是另一个路由器接口。ARP 或邻居发现解析的是已经由转发表确定的下一跳，不一定是最终目的主机。

### 3.4 逐跳转发中的字段变化

| 内容 | 经过普通路由器时的变化 |
| --- | --- |
| 源、目的 IP 地址 | 通常保持不变；NAT、隧道等特殊处理除外 |
| IPv4 TTL / IPv6 Hop Limit | 每经过一个路由器减 1 |
| IPv4 首部校验和 | 因 TTL 等字段变化而更新 |
| 源、目的 MAC 地址 | 每一段数据链路上重新填写 |
| 链路层帧校验序列 | 每次重新封装时重新计算 |

::: warning 易错点
路由器先根据目的 IP 地址和转发表确定输出接口及下一跳，再解析下一跳的链路层地址。跨网络转发时，IP 目的地址通常仍是最终主机，帧的目的 MAC 地址则是当前链路的下一跳。
:::

::: tip 本节主线
交换机端口划分冲突域，VLAN 和路由器接口划分广播域；路由处理器在控制平面生成路由和转发表，输入端口、交换结构和输出端口在数据平面完成高速转发。转发时先做最长前缀匹配，再解析下一跳地址并按输出链路重新封装。
:::
