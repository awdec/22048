<h1><center>第四节 路由算法与路由协议</center></h1>

路由算法用于根据网络拓扑、链路代价和管理策略计算到达目的网络的路径；路由协议则规定路由器如何交换路由信息，并利用相应算法生成和更新路由表。路由属于控制平面，路由算法的结果最终用于建立数据平面的转发表。

## 1. 路由算法

理想的路由算法应当正确、简单、健壮、收敛较快，并能在网络拓扑或链路状态变化后形成一致、无环的路由。实际算法还要在路径质量、计算开销、通信开销和管理策略之间折中。

### 1.1 静态路由与动态路由

- **静态路由**：由管理员人工配置，路由器不会仅因拓扑变化而自动学习新路径。它配置简单、可预测、协议开销小，适合规模较小、拓扑稳定的网络以及默认路由、汇总路由等场景。
- **动态路由**：路由器运行路由协议，交换可达性和网络状态信息，能够在拓扑发生变化时重新计算路由。它适合规模较大或经常变化的网络，但需要消耗带宽、存储和计算资源，并存在收敛时间。

静态路由和动态路由可以同时存在。路由器还需要根据路由来源的优先级、度量值和路由策略等因素，从多个来源提供的候选路由中选择最终路由。

### 1.2 距离向量路由算法

距离向量算法是一种分布式、迭代式算法。每个路由器只需要知道：

- 到各目的网络的当前估计距离。
- 到达各目的网络应选择的下一跳。
- 自己与直接相邻路由器之间的链路代价。

路由器把自己的距离向量发送给直接邻居，并利用邻居提供的信息更新本地距离。设路由器 $x$ 到目的 $y$ 的最小代价为 $D_x(y)$，$x$ 的邻居集合为 $N(x)$，到邻居 $v$ 的链路代价为 $c(x,v)$，则 Bellman-Ford 更新公式为：

$$
D_x(y)=\min_{v\in N(x)}\left\{c(x,v)+D_v(y)\right\}.
$$

公式表示：路由器 $x$ 分别假设经每个邻居 $v$ 到达目的 $y$，把“到邻居的代价”和“邻居到目的的距离”相加，再选择总代价最小的邻居作为下一跳。

距离向量算法不要求每个路由器掌握完整拓扑，但可能出现路由环路、慢收敛和**计数到无穷**问题。链路故障后，错误的可达信息可能在邻居之间相互强化，形成“好消息传播快、坏消息传播慢”的现象。

常见缓解措施包括设置较小的无穷大、水平分割、毒性逆转、触发更新和抑制定时器等。这些机制可以减少某些环路和加快收敛，但毒性逆转等方法不能消除所有多路由器环路。

### 1.3 链路状态路由算法

链路状态算法要求每个路由器获得所在路由域或区域的拓扑信息，并独立计算最短路径。基本过程是：

1. 发现直接相邻的路由器，并建立必要的邻接关系。
2. 测量或配置到各邻居的链路代价。
3. 生成描述本路由器链路状态的通告。
4. 采用洪泛方式把链路状态信息可靠地传播到整个路由域或区域。
5. 根据收到的信息建立链路状态数据库 LSDB。
6. 以自己为根运行 Dijkstra 算法，生成最短路径树和路由表。

Dijkstra 算法可以概括为：维护已经确定最短路径的节点集合 $N'$ 和到其他节点的暂定距离 $D(v)$；每次选择暂定距离最小的节点 $w$ 加入 $N'$，再用 $w$ 更新其相邻节点：

$$
D(v)\leftarrow\min\{D(v),D(w)+c(w,v)\}.
$$

当所有节点都加入 $N'$ 后，从根节点到各节点的最短路径即被确定。链路代价必须是非负值。

### 1.4 两类动态路由算法的比较

| 对比项 | 距离向量算法 | 链路状态算法 |
| --- | --- | --- |
| 掌握的信息 | 到目的的距离和下一跳 | 区域或路由域的完整拓扑 |
| 信息交换对象 | 直接邻居 | 通过洪泛传播给区域内路由器 |
| 交换内容 | 距离向量或路由表项 | 本路由器的链路状态 |
| 核心算法 | Bellman-Ford | Dijkstra |
| 典型问题 | 慢收敛、路由环路、计数到无穷 | 洪泛、数据库和计算开销较大 |
| 典型协议 | RIP | OSPF |

::: warning 易错点
距离向量路由器通常不知道完整拓扑，只知道经哪个邻居到达目的以及距离；链路状态路由器通过洪泛获得区域拓扑，但每台路由器仍然独立运行最短路径算法。
:::

## 2. 分层次的路由选择协议

全球互联网规模巨大，不可能让所有路由器运行一个完全统一的平面路由协议。为提高可扩展性并允许不同组织独立管理网络，互联网采用分层次的路由选择体系。

### 2.1 自治系统

**自治系统 AS** 是由同一管理机构控制、对外表现出统一路由策略的一组网络、路由器和链路。每个自治系统使用自治系统号 ASN 标识。

自治系统内部可以根据规模使用一种或多种内部路由机制，但对其他自治系统发布哪些前缀、选择哪些外部路径，由该自治系统的统一管理策略决定。

### 2.2 内部网关协议与外部网关协议

- **内部网关协议 IGP**：在一个自治系统内部交换路由信息，也称域内路由协议。RIP 和 OSPF 都属于 IGP。
- **外部网关协议 EGP**：在不同自治系统之间交换网络可达性和路径信息，也称域间路由协议。当前互联网使用的主要外部网关协议是 BGP。

这里的“网关”沿用了历史名称，实际运行这些协议的设备通常是路由器。边界路由器连接本自治系统与其他自治系统，需要同时处理域内可达性和域间路由信息。

| 层次 | 作用范围 | 主要目标 | 典型协议 |
| --- | --- | --- | --- |
| 域内路由 | 一个 AS 内部 | 根据跳数、代价等选择内部路径，快速适应内部变化 | RIP、OSPF |
| 域间路由 | 不同 AS 之间 | 发布前缀可达性，执行商业、管理和安全策略 | BGP |

### 2.3 分层路由的作用

- 限制路由信息传播范围，减小路由表和更新流量。
- 允许不同自治系统独立选择内部路由协议和度量方式。
- 通过地址聚合减少向外发布的路由前缀数量。
- 隔离内部拓扑变化，避免所有细节传播到整个互联网。
- 允许自治系统根据管理和商业关系实施域间路由策略。

分层会隐藏部分拓扑细节，因此选出的端到端路径不一定是全局代价最小的路径；这是可扩展性和完全最优之间的折中。

OSPF 还可以在一个自治系统内部进一步划分区域。区域属于 OSPF 的域内分层机制，不等同于自治系统；一个自治系统可以包含多个 OSPF 区域。

::: warning 易错点
AS 是管理和路由策略的边界，OSPF 区域是一个 AS 内部的分层单位。RIP、OSPF 解决域内路由，BGP 解决域间路由，不能把 OSPF 区域看成独立 AS。
:::

## 3. 路由信息协议

路由信息协议 RIP 是基于距离向量算法的内部网关协议，适合规模较小、链路结构相对简单的自治系统。

### 3.1 RIP 的基本特点

- RIP 使用**跳数**作为路由度量。每经过一个路由器，跳数增加 1。
- 直接相连网络的 RIP 距离通常记为 1。
- 最大有效距离为 15 跳，度量值 16 表示网络不可达，因此 RIP 网络的规模受到限制。
- 路由器主要与直接邻居交换距离向量，不需要掌握整个自治系统的拓扑图。
- RIP 使用 UDP 传输路由报文，端口号为 520。
- RIP 通常每隔约 30 s 向邻居发送一次完整路由表，并可以在路由变化时发送触发更新。

RIP 使用 UDP 并不表示路由更新本身完全没有控制机制；RIP 通过周期更新、超时和触发更新等方式维护路由。某条路由若在一段时间内没有被刷新，通常会被标记为不可达并最终删除。

### 3.2 RIP 的更新规则

路由器收到邻居发来的 RIP 路由表后，先把其中各目的网络的距离加 1，并把该邻居作为候选下一跳，然后与本地路由比较：

1. 本地没有该目的网络的路由时，加入新表项。
2. 新路由的距离更短时，采用新路由。
3. 现有路由本来就经该邻居时，应使用邻居的新信息更新距离，即使距离变大。
4. 新路由经其他邻居且距离不优时，通常保留原路由。

若邻居通告的距离为 15，再加 1 后得到 16，应把该目的视为不可达。

### 3.3 RIP 的环路与收敛

链路或网络失效后，相邻路由器可能误以为对方仍有可达路径，导致距离逐步增加，形成计数到无穷。RIP 把 16 定义为无穷大，可以限制计数过程，但也使可达网络的直径最多为 15 跳。

RIP 常结合以下机制缓解问题：

- **水平分割**：从某接口学到的路由不再从同一接口通告回去。
- **毒性逆转**：把从某邻居学到的路由向该邻居通告为不可达。
- **触发更新**：重要路由变化后立即发送更新，不等待下一周期。
- **路由超时**：长时间未获得更新的路由被判为失效。

### 3.4 RIPv1 与 RIPv2

- **RIPv1** 使用分类路由，不在更新中携带子网掩码，难以支持 VLSM 和 CIDR。
- **RIPv2** 在路由项中携带子网掩码，支持无分类路由和认证，并通常使用组播地址 `224.0.0.9` 发送更新。

::: warning 易错点
RIP 交换的是“目的网络、距离和下一跳”等距离向量信息，不是完整的 AS 路径；16 表示不可达，而不是允许经过 16 个路由器。
:::

## 4. 开放最短路径优先协议

开放最短路径优先协议 OSPF 是基于链路状态算法的内部网关协议。它使用链路**代价 Cost**作为度量，路径代价是沿途链路代价之和，路由器利用 Dijkstra 算法计算最短路径树。

### 4.1 OSPF 的工作过程

1. 路由器使用 Hello 报文发现邻居、维持邻居关系，并在需要时建立邻接关系。
2. 路由器收集接口、邻居、链路代价和网络前缀等本地状态，生成链路状态通告 LSA。
3. LSA 在所属 OSPF 区域内可靠洪泛，区域内路由器据此建立链路状态数据库 LSDB。
4. 在网络稳定时，同一区域内的路由器应具有逻辑上一致的 LSDB。
5. 每台路由器以自己为根运行 Dijkstra 算法，生成最短路径树，再计算路由表和转发表。

OSPF 的链路代价通常根据接口带宽配置或计算，代价越小越优。它不把跳数限制为 15，也不简单地把“经过路由器数量最少”视为最优路径。

OSPF 主要在拓扑变化时触发新的 LSA 并进行洪泛，同时也会周期性刷新 LSA。它不是像 RIP 那样固定周期向邻居发送整个路由表。

### 4.2 OSPF 报文

OSPF 定义五种基本报文类型：

| 报文 | 作用 |
| --- | --- |
| Hello | 发现和维护邻居，参与指定路由器选举 |
| 数据库描述 Database Description | 摘要描述本地 LSDB，比较数据库状态 |
| 链路状态请求 Link State Request | 请求缺少或较新的 LSA |
| 链路状态更新 Link State Update | 携带一个或多个 LSA |
| 链路状态确认 Link State Acknowledgment | 确认收到 LSA，支持可靠洪泛 |

OSPF 报文直接封装在 IP 数据报中，IPv4 协议号为 89，不使用 TCP 或 UDP。OSPF 自身通过序列号、确认和重传等机制实现链路状态信息的可靠洪泛。

### 4.3 OSPF 区域

大型 OSPF 自治系统可以划分为多个区域，以限制 LSA 洪泛范围和最短路径计算规模：

- **主干区域**：区域号为 0，负责连接其他 OSPF 区域。
- **区域内路由器**：接口全部位于同一区域。
- **区域边界路由器 ABR**：连接主干区域与其他区域，维护多个区域的 LSDB，并在区域间发布路由摘要。
- **自治系统边界路由器 ASBR**：把其他路由协议或外部网络的路由引入 OSPF 自治系统。

非主干区域通常需要连接到主干区域，区域之间的路由经 ABR 传播。区域划分可以减少每台路由器需要保存和处理的拓扑信息，但区域内部仍采用链路状态算法。

### 4.4 多路访问网络中的 DR 和 BDR

在广播型多路访问网络中，如果所有路由器都彼此建立完整邻接并重复洪泛，控制开销会很大。OSPF 选举指定路由器 DR 和备份指定路由器 BDR，以减少邻接关系和 LSA 交换开销。

DR、BDR 是接口所在网络上的角色，不表示该路由器在整个自治系统中始终具有相同角色。发生选举时，通常优先比较接口优先级，再比较路由器 ID。

::: warning 易错点
OSPF 洪泛的是链路状态通告，路由器根据 LSDB 独立运行 Dijkstra 算法；它不是把整个路由表每 30 s 发送给所有路由器。OSPF 直接使用 IP 协议号 89，不使用 UDP 端口。
:::

## 5. 边界网关协议

边界网关协议 BGP 是互联网使用的域间路由协议，负责在自治系统之间交换 IP 前缀可达性和路径属性。BGP 属于**路径向量协议**，选择路由时强调可扩展性和管理策略，并不只追求跳数最少或链路代价最小。

### 5.1 BGP 对等关系

运行 BGP 并与其他路由器交换 BGP 信息的路由器称为 BGP 发言者。两个 BGP 发言者之间建立对等会话：

- **eBGP**：在不同自治系统的 BGP 发言者之间交换路由。
- **iBGP**：在同一自治系统内部传播 BGP 路由，使内部路由器获得外部前缀信息。

iBGP 虽然运行在一个自治系统内部，但它仍然属于 BGP 机制，不能把它等同于 RIP、OSPF 等 IGP。IGP 负责计算自治系统内部如何到达某个 BGP 下一跳，BGP 负责选择和传播外部前缀路径。

BGP 使用 TCP 建立可靠连接，端口号为 179。TCP 提供可靠、有序的字节流，因此 BGP 不需要像 OSPF 那样自行实现链路状态洪泛确认机制。

### 5.2 路径向量与路径属性

BGP 通告的核心是“网络前缀及其路径属性”，而不是只通告一个距离。常见属性包括：

- **AS_PATH**：记录路由通告已经经过的自治系统序列。若 BGP 路由器发现自己的 AS 号已经出现在 AS_PATH 中，就拒绝该路由，从而防止域间路由环路。
- **NEXT_HOP**：指出到达所通告前缀应使用的下一跳地址。
- **LOCAL_PREF**：表示自治系统内部对不同出口路径的偏好，数值通常越大越优先。
- **MED**：向相邻自治系统建议进入本自治系统时优先选择的入口，数值通常越小越优先。
- **ORIGIN**：说明该前缀最初以何种方式进入 BGP。

AS_PATH 较短可能是选路时考虑的因素，但 BGP 策略可以优先于简单的 AS 路径长度。运营商或组织可以根据客户、提供商、对等互联、安全和流量工程等策略决定接受、优选和通告哪些路由。

### 5.3 BGP 报文与更新

BGP 建立 TCP 连接后使用四种基本报文：

| 报文 | 作用 |
| --- | --- |
| OPEN | 协商 BGP 版本、AS 号、保持时间等参数并建立 BGP 会话 |
| UPDATE | 通告新的可达前缀和路径属性，或撤销失效路由 |
| KEEPALIVE | 维持会话并确认 OPEN，不携带路由更新 |
| NOTIFICATION | 报告严重错误并终止 BGP 会话 |

BGP 会话建立后可以交换初始路由信息；此后主要发送增量 UPDATE，只通告新增、变化或撤销的路由，而不是固定周期发送完整的互联网路由表。KEEPALIVE 用于表明会话仍然有效。

### 5.4 RIP、OSPF 与 BGP 对比

| 对比项 | RIP | OSPF | BGP |
| --- | --- | --- | --- |
| 作用范围 | AS 内部 | AS 内部 | AS 之间，并通过 iBGP 在 AS 内传播外部路由 |
| 协议类型 | 距离向量 | 链路状态 | 路径向量 |
| 主要选路依据 | 跳数 | 链路代价 | 路径属性和策略 |
| 信息传播 | 周期性向邻居发送路由表，辅以触发更新 | LSA 在区域内可靠洪泛 | 对等体之间通告或撤销前缀和属性 |
| 拓扑知识 | 距离和下一跳 | 区域完整拓扑 | AS 路径及其他属性 |
| 承载方式 | UDP 520 | 直接封装在 IP 中，协议号 89 | TCP 179 |
| 典型特点 | 简单但规模受 15 跳限制 | 收敛较快，支持区域分层 | 可扩展、策略驱动，适合域间路由 |

::: warning 易错点
BGP 不是用 Dijkstra 求全互联网最短路径，也不是按固定周期向所有自治系统发送完整路由表。它通过 TCP 对等会话交换前缀和路径属性，AS_PATH 用于描述自治系统路径并帮助检测环路。
:::

::: tip 本节主线
距离向量算法让邻居交换“到目的的距离”，链路状态算法让区域内路由器获得拓扑并各自计算最短路径；互联网再通过自治系统实现分层。RIP 是小规模域内距离向量协议，OSPF 是支持区域的域内链路状态协议，BGP 是策略驱动的域间路径向量协议。
:::
