<h1><center>第一节 网络层的功能</center></h1>

网络层位于传输层和数据链路层之间，负责把分组从源主机跨越一个或多个网络交付到目的主机。它以网络层分组为处理单位；在 TCP/IP 体系中，IP 分组通常称为 IP 数据报。

网络层的核心问题是：如何把不同类型的网络互连起来，如何为分组选择路径并逐跳转发，以及如何在网络负载过大时避免或缓解拥塞。

## 1. 异构网络互连

不同网络可能采用不同的传输介质、数据链路层协议、帧格式、传输速率、最大传送单元 MTU 和介质访问方式。**异构网络互连**是指利用网络层协议和路由器，把这些底层技术不同的网络连接成一个逻辑上的互联网络。

网络层通过统一的网络层地址和分组格式屏蔽底层网络之间的差异。以 TCP/IP 体系为例，只要各网络都能够承载 IP 数据报，它们就可以通过路由器互连，而不要求使用相同的物理层和数据链路层技术。

路由器转发分组时通常经历以下过程：

1. 从输入链路收到数据链路层帧，检查后去除帧首部和尾部，取出网络层分组。
2. 检查网络层首部，根据目的网络层地址确定下一跳和输出接口。
3. 按照输出链路的数据链路层协议，把网络层分组重新封装成新的帧并发送。

因此，同一个 IP 数据报经过不同链路时，外层帧格式可以不同，链路层源地址和目的地址也会逐跳改变；若不考虑 NAT 等特殊处理，数据报中的源 IP 地址和目的 IP 地址通常保持不变。路由器还会修改生存时间等必须逐跳更新的首部字段。

网络互连并不会消除底层网络的全部差异。例如，不同链路的 MTU 仍可能影响数据报能否直接通过，具体处理方式与 IP 版本及路径 MTU 有关。

::: warning 易错点
路由器连接的是不同网络，并在网络层转发分组；交换机主要在同一局域网或 VLAN 内依据 MAC 地址转发帧。一个分组从源到目的通常保持网络层的源、目的地址，但每经过一段链路都需要使用适合该链路的新帧重新封装。
:::

## 2. 路由与转发

网络层把分组从源主机送到目的主机，需要完成两个相互联系但含义不同的过程：**路由**和**转发**。

- **路由**：根据网络拓扑、链路代价和路由策略，计算到各目的网络的可达路径，并形成或更新路由信息。它回答“到达目的网络应选择哪条路径”，主要属于控制平面。
- **转发**：路由器收到分组后，根据转发表查找匹配表项，把分组送往相应的输出接口或下一跳。它回答“当前这个分组应从哪个接口发出”，主要属于数据平面。

二者的关系可以概括为：路由过程生成和维护转发所需的信息，转发过程使用这些信息逐个处理分组。源主机到目的主机的完整路径，由沿途各路由器的一系列逐跳转发共同形成。

| 对比项 | 路由 | 转发 |
| --- | --- | --- |
| 所属平面 | 控制平面 | 数据平面 |
| 作用范围 | 关注网络拓扑和端到端路径 | 关注本路由器的一个输入分组 |
| 执行频率 | 可以周期性运行，也会在拓扑、状态或策略变化时更新 | 每个到达的分组都要执行 |
| 主要依据 | 路由算法、路由协议和网络状态 | 转发表中的匹配规则 |
| 主要结果 | 路由信息或转发表项 | 输出接口、下一跳或丢弃动作 |

概念上，**路由表**保存通过路由协议、静态配置等方式获得的路由信息，**转发表**保存实际转发分组所需的优化表项。路由表是生成转发表的重要依据，但在具体设备中二者的组织方式可能不同，不能简单认为它们永远是同一张表。

在传统网络中，路由器通常通过分布式路由协议交换信息并各自计算路由；在 SDN 中，路由或策略计算也可以由逻辑集中的控制器完成。具体的路由算法和路由协议见[第四节“路由算法与路由协议”](./section-4)，路由器结构和分组转发过程见[第七节“网络层设备”](./section-7)。

::: tip 判断方法
题目询问“如何计算路径、维护路由信息”时，考查的是路由；询问“收到一个分组后查表并选择输出端口”时，考查的是转发。
:::

## 3. 网络层提供的两种服务

::: info 408 大纲定位
“数据报与虚电路”属于 408 考查知识，但现行大纲将其列在物理层的“通信基础”中。本节仅从网络层服务方式的角度进行跨章回顾，复习时不必与前述内容重复记忆。
:::

从网络层向上提供服务的方式看，分组交换网络可以采用**数据报服务**或**虚电路服务**。

### 3.1 数据报服务

数据报服务是一种无连接的网络层服务。发送分组前不需要建立网络层连接，每个分组都作为独立的数据报进行处理，并携带完整的目的地址。

- 同一报文的不同数据报可以独立选择路由，因此可能经过不同路径。
- 分组可能出现丢失、重复或失序，具体服务质量取决于网络协议是否提供相应保证。
- 某条链路或路由器发生故障后，后续数据报可以通过更新后的路由改走其他路径。
- 网络中的路由器不需要为每一条端到端通信维护虚电路状态。

因特网的 IP 层提供无连接、尽最大努力交付的数据报服务，不保证可靠交付、按序到达、固定带宽或确定时延。需要可靠传输时，通常由传输层或应用层提供相应机制。

### 3.2 虚电路服务

虚电路服务是一种面向连接的网络层服务，通常包括虚电路建立、数据传输和虚电路释放三个阶段。

1. **建立阶段**：选择一条路径，沿途交换节点建立相应的虚电路表项。
2. **传输阶段**：分组携带较短的虚电路标识，沿已经建立的路径转发。
3. **释放阶段**：通信结束后撤销沿途节点保存的虚电路状态。

虚电路标识通常只在一段链路上具有局部意义。交换节点可以根据“输入接口和输入虚电路号”，查表得到“输出接口和输出虚电路号”，因此同一条虚电路在不同链路上使用的标识可以不同。

虚电路是一条逻辑连接，并不等于独占物理链路的电路交换连接。多条虚电路仍然可以共享链路带宽；某些虚电路网络可以在建立连接时进行资源预留，但“采用虚电路”本身并不必然保证可靠性或服务质量。

### 3.3 两种服务的比较

| 对比项 | 数据报服务 | 虚电路服务 |
| --- | --- | --- |
| 网络层连接 | 无连接 | 面向连接 |
| 建立过程 | 不需要 | 传输前需要建立虚电路 |
| 路由选择 | 每个分组独立处理 | 建立时选择路径，分组通常沿该路径传输 |
| 分组首部 | 携带完整目的地址 | 携带较短的虚电路标识 |
| 节点状态 | 不为每条通信保存虚电路状态 | 沿途节点保存虚电路表项 |
| 到达顺序 | 可能失序 | 通常按序到达 |
| 故障影响 | 后续分组可以重新选择路径 | 受影响的虚电路通常需要重新建立 |
| 典型代表 | 因特网 IP | 采用虚电路机制的分组交换网络 |

::: warning 易错点
“面向连接”不等于“可靠”。虚电路服务强调发送前建立逻辑连接和保存转发状态；是否提供确认、重传、差错恢复或资源保证，还取决于具体协议。
:::

## 4. SDN 的基本概念

传统路由器通常同时包含控制平面和数据平面：控制平面运行路由协议、计算路由并维护转发表，数据平面根据转发表高速处理分组。**软件定义网络 SDN** 的核心思想是把控制平面与数据平面分离，使网络控制具有逻辑集中和可编程的特点。

SDN 的基本结构包括：

1. **应用平面**：运行路由、访问控制、负载均衡等网络应用，通过北向接口向控制器表达网络需求和策略。
2. **控制平面**：由 SDN 控制器维护网络的逻辑全局视图，计算路径或转发策略，并把规则下发给转发设备。
3. **数据平面**：由交换机、路由器等转发设备组成，根据控制器下发的流表或转发规则处理分组。

控制器与数据平面设备之间的接口称为**南向接口**，OpenFlow 是典型的南向协议之一；控制器向上为网络应用提供的接口称为**北向接口**。SDN 不等同于 OpenFlow，OpenFlow 只是实现 SDN 南向控制的一种方式。

SDN 数据平面常采用“匹配—动作”方式处理分组：

- **匹配**：检查入端口以及分组首部中的一个或多个字段。
- **动作**：执行转发、丢弃、修改首部、送交控制器等操作。
- **统计**：记录匹配分组数、字节数等信息，供控制和管理使用。

传统的目的地址转发可以看作广义“匹配—动作”转发的一种情况。SDN 中的“逻辑集中”表示控制决策在逻辑上具有统一视图，并不意味着整个网络只能部署一台物理控制器；控制器可以采用分布式或冗余部署。

::: warning 易错点
SDN 分离的是控制平面与数据平面的功能和控制关系，不是取消数据平面，也不是让控制器亲自转发所有分组。普通分组仍主要由数据平面设备按已安装的规则高速转发。
:::

## 5. 拥塞控制

当网络中的通信量超过链路带宽、路由器处理能力或缓冲容量时，分组会在路由器中大量排队，形成**拥塞**。拥塞可能造成排队时延迅速增加、缓冲区溢出、分组丢失；若发送方因丢包而大量重传，还可能进一步增加网络负载，严重时出现吞吐量下降甚至拥塞崩溃。

拥塞产生的常见原因包括：

- 多个输入链路的流量集中到带宽较小的输出链路。
- 突发流量超过路由器缓冲区的暂时承受能力。
- 路由器处理分组的速度不足。
- 不合理的重传、路由或资源分配策略放大网络负载。

### 5.1 拥塞控制与流量控制

| 对比项 | 拥塞控制 | 流量控制 |
| --- | --- | --- |
| 主要问题 | 网络内部负载超过承载能力 | 发送方速度超过接收方处理能力 |
| 作用对象 | 整个网络或网络中的一部分 | 通信双方或相邻节点 |
| 关注资源 | 链路带宽、路由器处理能力和缓冲区 | 接收方处理速度和接收缓冲区 |
| 常见依据 | 丢包、排队时延、显式拥塞通知 | 接收窗口、确认或接收方反馈 |

流量控制良好并不表示网络一定不会拥塞；即使每个发送方都没有超过接收方的处理能力，许多通信流在网络内部汇聚时仍可能造成拥塞。

### 5.2 拥塞控制的基本方法

根据是否利用网络运行状态的反馈，拥塞控制可以分为开环控制和闭环控制。

- **开环控制**：在拥塞发生前通过合理设计预防拥塞，不依赖当前拥塞状态的反馈。常见措施包括接纳控制、流量整形、资源预留、合理的调度和丢弃策略等。
- **闭环控制**：检测已经发生或即将发生的拥塞，把拥塞信息反馈给有关节点，再降低进入网络的负载。反馈方式包括背压、抑制分组、显式拥塞标记，以及由发送方根据丢包或时延上升推断拥塞等。

拥塞控制的基本闭环可以概括为：监测网络状态、判断拥塞位置和程度、反馈拥塞信息、调整发送速率或资源分配。因特网中的拥塞控制主要由端系统的传输层协议实施，网络层也可以通过丢包、队列管理和显式拥塞通知等机制提供支持。

::: warning 易错点
单纯增大路由器缓冲区不能从根本上消除拥塞。缓冲区只能暂时吸收突发流量，过大的队列还可能显著增加排队时延。解决拥塞的关键是使进入网络的负载与网络可用资源相适应。
:::

::: tip 本节主线
网络层使用统一的分组和地址体系互连异构网络，通过路由形成转发信息、通过转发完成逐跳交付；它可以提供数据报或虚电路服务，控制平面既可以分布在传统路由器中，也可以在 SDN 中逻辑集中，并需要通过拥塞控制维持网络负载与资源之间的平衡。
:::
