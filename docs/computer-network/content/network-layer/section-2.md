<h1><center>第二节 IPv4</center></h1>

IPv4 是 TCP/IP 体系中使用最广泛的网络层协议之一。它使用 32 bit 地址，为上层提供无连接、尽最大努力交付的数据报服务。IPv4 本身不保证数据报可靠、按序、无重复或在规定时间内到达。

## 1. IPv4 分组

IPv4 的网络层分组通常称为 **IPv4 数据报**。一个 IPv4 数据报由首部和数据两部分组成：

$$
\text{IPv4 数据报}=\text{首部}+\text{数据}.
$$

### 1.1 IPv4 数据报首部

IPv4 首部的长度为 20～60 B。没有可选字段时，首部固定部分为 20 B；有可选字段时，需要通过填充使首部长度成为 4 B 的整数倍。

| 字段 | 长度 | 作用 |
| --- | ---: | --- |
| 版本 Version | 4 bit | 固定为 4，表示 IPv4 |
| 首部长度 IHL | 4 bit | 以 4 B 为单位表示首部长度，取值通常为 5～15 |
| 区分服务 | 8 bit | 用于区分流量类别，并可携带显式拥塞通知信息 |
| 总长度 Total Length | 16 bit | IPv4 首部与数据的总长度，单位为字节 |
| 标识 Identification | 16 bit | 标识原始数据报，同一原始数据报的各分片取值相同 |
| 标志 Flags | 3 bit | 包含禁止分片 DF、还有分片 MF 等控制位 |
| 片偏移 Fragment Offset | 13 bit | 指明分片数据在原始数据部分中的相对位置，以 8 B 为单位 |
| 生存时间 TTL | 8 bit | 限制数据报能够经过的路由器数量，防止无限循环 |
| 协议 Protocol | 8 bit | 指明数据部分交付给哪个协议，如 ICMP、TCP 或 UDP |
| 首部校验和 | 16 bit | 只校验 IPv4 首部，不校验数据部分 |
| 源地址 | 32 bit | 源接口的 IPv4 地址 |
| 目的地址 | 32 bit | 最终目的接口的 IPv4 地址 |
| 可选字段和填充 | 0～40 B | 支持可选控制功能，并把首部补齐为 4 B 的整数倍 |

首部长度字段 IHL 的单位是 4 B。因此，IHL 为 5 时首部长度为 $5\times4=20\ \text{B}$；IHL 最大为 15，首部最大长度为 $15\times4=60\ \text{B}$。

总长度字段的单位是 1 B，并且包含首部。总长度字段为 16 bit，所以普通 IPv4 数据报的最大总长度为：

$$
2^{16}-1=65535\ \text{B}.
$$

协议字段用于实现网络层对上层协议的复用。例如，ICMP、TCP、UDP 的常见协议号分别为 1、6、17。

### 1.2 TTL 与首部校验和

数据报每经过一个路由器，TTL 至少减 1；在 408 的逐跳转发题中，通常按每经过一个路由器减 1 处理。若 TTL 减为 0，路由器丢弃数据报，并通常向源主机发送 ICMP 时间超过报文。

IPv4 首部校验和只覆盖首部。发送方计算校验和时，先把校验和字段置 0，再把首部划分为若干个 16 bit 字，使用反码算术逐项相加，最后对结果取反。接收方把包括校验和在内的所有 16 bit 字相加，结果应为全 1。

路由器每次转发都会修改 TTL，因此即使其他字段不变，也必须相应更新 IPv4 首部校验和。TCP、UDP 等协议有各自的校验机制，不能用 IPv4 首部校验和代替。

### 1.3 IPv4 分片

每种数据链路层协议都规定了帧能够承载的最大网络层数据长度，称为最大传送单元 MTU。当 IPv4 数据报长度超过输出链路 MTU 时：

- 若 DF=0，路由器可以把数据报分成若干个较小的分片。
- 若 DF=1，路由器不得分片，只能丢弃数据报，并通常返回 ICMP 目的不可达中的“需要分片但 DF 已设置”报文。

IPv4 分片具有以下规则：

1. 每个分片都是一个独立的 IPv4 数据报，都具有自己的 IPv4 首部。
2. 同一原始数据报的所有分片具有相同的标识字段。
3. 除原始数据报的最后一个分片外，MF 均为 1；原始数据报的最后一个分片 MF=0。
4. 片偏移以 8 B 为单位，表示本分片的数据在原始数据部分中的起始位置。
5. 除最后一个分片外，各分片的数据长度必须是 8 B 的整数倍。
6. 分片可以再次分片，但只在最终目的主机进行重组，中间路由器不负责重组。

若输出链路 MTU 为 $M$，分片使用的 IPv4 首部长度为 $H$，则非最后一个分片能够携带的最大数据长度为：

$$
L=\left\lfloor\frac{M-H}{8}\right\rfloor\times8.
$$

某分片的片偏移为：

$$
\text{片偏移}=\frac{\text{该分片数据在原始数据部分中的起始字节位置}}{8}.
$$

例如，一个总长度为 4000 B、首部为 20 B 的 IPv4 数据报，需要经过 MTU=1500 B 的链路。原始数据长度为 3980 B，每个非最后分片最多携带 1480 B 数据：

| 分片 | 数据长度 | 总长度 | 片偏移 | MF |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 1480 B | 1500 B | 0 | 1 |
| 2 | 1480 B | 1500 B | 185 | 1 |
| 3 | 1020 B | 1040 B | 370 | 0 |

三个分片的标识字段相同。片偏移只计算原始数据的位置，不把原始 IPv4 首部的 20 B 计入偏移。

::: warning 易错点
总长度和 MTU 的单位是字节，片偏移的单位是 8 B；只有分片的数据部分要求按 8 B 对齐。分片的总长度还必须加上各自的 IPv4 首部。
:::

## 2. IPv4 地址

IPv4 地址长度为 32 bit，通常采用点分十进制表示，把地址分为 4 个 8 bit 字节，每个字节写成 0～255 的十进制数。例如：

```text
192.168.10.135
```

IPv4 地址实际标识的是网络接口。一台路由器具有多个接口时，通常需要为不同接口配置不同的 IPv4 地址；一台主机也可以具有多个网络接口和多个地址。

### 2.1 分类编址

早期 IPv4 使用分类编址，把地址分为 A、B、C、D、E 五类：

| 类别 | 最高位模式 | 第一个字节范围 | 默认网络前缀 | 用途 |
| --- | --- | ---: | ---: | --- |
| A 类 | `0` | 1～126 | `/8` | 大型单播网络 |
| B 类 | `10` | 128～191 | `/16` | 中型单播网络 |
| C 类 | `110` | 192～223 | `/24` | 小型单播网络 |
| D 类 | `1110` | 224～239 | 无 | IPv4 组播 |
| E 类 | `1111` | 240～255 | 无 | 保留或实验用途 |

第一个字节为 0 的地址具有特殊用途，`127.0.0.0/8` 用作环回地址，因此普通 A 类单播网络的第一个字节为 1～126。D 类和 E 类地址不按网络号与主机号划分。

分类编址的地址块大小固定，容易造成地址浪费，现已被无分类域间路由选择 CIDR 取代。但 A、B、C 类的默认网络号长度和地址范围仍是常见基础考点。

### 2.2 子网掩码与网络地址

现代 IPv4 地址通常写成“地址/前缀长度”的形式。前缀长度为 $n$ 表示前 $n$ bit 为网络前缀，后 $32-n$ bit 为主机号。对应的子网掩码由连续的 $n$ 个 1 和 $32-n$ 个 0 组成。

网络地址由 IPv4 地址和子网掩码逐位与得到：

$$
\text{网络地址}=\text{IPv4 地址}\ \mathrm{AND}\ \text{子网掩码}.
$$

例如，地址为 `192.168.10.135/26`：

- 子网掩码为 `255.255.255.192`。
- 网络地址为 `192.168.10.128`。
- 定向广播地址为 `192.168.10.191`。
- 传统可分配主机地址为 `192.168.10.129`～`192.168.10.190`。

前缀长度为 $n$ 的地址块包含：

$$
2^{32-n}
$$

个地址。对于具有 $h=32-n$ 个主机位的传统广播子网，主机号全 0 表示网络地址，主机号全 1 表示该子网的定向广播地址，因此通常可分配主机数为：

$$
2^h-2.
$$

考试题若没有特别说明，通常使用上述公式。实际网络中的 `/31` 点对点链路和 `/32` 单主机路由属于特殊情况，不能机械套用减 2 公式。

### 2.3 子网划分

子网划分从原主机号中借用若干位作为子网号。若借用 $s$ 位，可以划分出 $2^s$ 个等长子网；若还剩 $h$ 个主机位，则每个传统子网通常可以分配 $2^h-2$ 个主机地址。

子网划分题可以按照以下顺序计算：

1. 根据所需子网数或主机数确定借位数和新前缀长度。
2. 把新前缀长度转换成子网掩码。
3. 根据变化字节的块大小列出各子网网络地址。
4. 对每个子网确定广播地址和可分配主机范围。

若掩码变化字节的十进制值为 $m$，该字节中的地址块步长为：

$$
256-m.
$$

### 2.4 CIDR 与路由聚合

CIDR 不再使用固定的 A、B、C 类网络边界，而是通过任意长度的网络前缀分配地址块。CIDR 地址块必须满足：地址连续、地址数量为 2 的幂，并且起始地址与地址块大小对齐。

路由聚合把若干条具有相同下一跳、前缀连续且边界对齐的具体路由合并成一条更短的公共前缀，以减少路由表项。例如：

```text
192.168.0.0/24
192.168.1.0/24
192.168.2.0/24
192.168.3.0/24
```

可以聚合为：

```text
192.168.0.0/22
```

当一个目的地址同时匹配多条路由时，路由器选择前缀最长、地址范围最具体的表项，这称为**最长前缀匹配**。

### 2.5 特殊 IPv4 地址

| 地址或地址块 | 含义 |
| --- | --- |
| 主机号全 0 | 表示当前网络或子网本身，不能作为普通主机地址 |
| 主机号全 1 | 当前子网的定向广播地址 |
| `255.255.255.255` | 受限广播地址，只在当前本地网络使用，路由器不转发 |
| `0.0.0.0` | 未指定地址，主机尚未获得地址时可作为源地址 |
| `0.0.0.0/0` | 默认路由，能够匹配任意 IPv4 目的地址 |
| `127.0.0.0/8` | 环回地址，分组不会离开本机 |
| `169.254.0.0/16` | 链路本地地址，只在本地链路范围内使用 |
| `10.0.0.0/8` | 私有 IPv4 地址块 |
| `172.16.0.0/12` | 私有 IPv4 地址块 |
| `192.168.0.0/16` | 私有 IPv4 地址块 |
| `224.0.0.0/4` | IPv4 组播地址范围 |

私有 IPv4 地址可以在不同组织内部重复使用，但通常不能直接在全球互联网中路由。私有网络访问互联网时，常使用 NAT 转换为公网地址。

::: warning 易错点
`0.0.0.0` 是未指定地址，而 `0.0.0.0/0` 是默认路由前缀；网络地址、广播地址和普通主机地址的含义不能混淆。
:::

## 3. 网络地址转换 NAT

网络地址转换 NAT 通常部署在私有网络与互联网之间的边界路由器上。它在数据报经过时修改 IPv4 地址，并维护内部地址与外部地址之间的映射，使使用私有地址的主机能够与公网通信。

### 3.1 NAT 的基本类型

- **静态 NAT**：预先建立一个私有地址与一个公网地址之间的固定映射，常用于需要从公网访问的内部服务器。
- **动态 NAT**：从公网地址池中临时选择一个地址，与内部私有地址建立一对一映射。
- **网络地址与端口转换 NAPT/PAT**：同时转换 IPv4 地址和传输层端口，使多台内部主机能够共享同一个公网 IPv4 地址。这是家庭和小型网络中最常见的形式。

严格区分时，基本 NAT 主要转换网络层地址，NAPT 还转换 TCP 或 UDP 端口；实际使用中常把二者统称为 NAT。

### 3.2 NAPT 的工作过程

假设内部主机建立如下连接：

```text
10.0.0.8:49152 → 198.51.100.20:443
```

边界设备可以把它转换为：

```text
203.0.113.5:40001 → 198.51.100.20:443
```

并在转换表中保存映射：

| 内部本地地址 | 内部全局地址 |
| --- | --- |
| `10.0.0.8:49152` | `203.0.113.5:40001` |

外发时，NAPT 修改源 IPv4 地址和源端口；返回分组到达后，根据目的公网地址和端口查找映射，再恢复为内部主机的私有地址和端口。不同内部连接使用不同的公网端口号，因此可以共享同一个公网地址。

NAT 修改 IPv4 首部后必须更新 IPv4 首部校验和。NAPT 修改端口时，还需要更新 TCP 校验和；对于 UDP，若原校验和非 0，也需要重新计算，因为传输层校验和通常还涉及包含 IP 地址的伪首部。IPv4 中 UDP 校验和为 0 表示发送方未启用 UDP 校验，此时经过 NAPT 后仍应保持为 0。

### 3.3 NAT 的作用与局限

NAT 可以缓解公网 IPv4 地址不足，使内部地址规划相对独立，并在一定程度上隐藏内部地址结构。但 NAT 不是防火墙，也不能替代访问控制和安全防护。

NAT 的主要局限包括：

- 修改了端到端通信中的网络层地址，破坏了 IP 的端到端透明性。
- 外部主机通常不能在没有静态映射或端口转发的情况下主动连接内部主机。
- 对在应用数据中携带 IP 地址或端口的协议，需要额外处理。
- 映射表会增加边界设备的状态维护和故障恢复负担。

::: warning 易错点
普通路由器转发时通常不改变源、目的 IPv4 地址；NAT 是明确进行地址转换的特殊边界功能。NAPT 能让多个内部连接共享一个公网地址，关键在于同时利用端口号区分映射。
:::

## 4. 网络层转发分组的过程

IPv4 分组转发包括主机选择下一跳和路由器逐跳处理两个部分。网络层首先根据目的 IPv4 地址确定下一跳，随后才利用 ARP 获取该下一跳在当前链路上的 MAC 地址。

### 4.1 直接交付与间接交付

源主机发送数据前，使用自己的子网掩码判断目的 IPv4 地址是否位于本地网络：

- **直接交付**：目的主机与源主机位于同一网络。源主机把目的主机作为下一跳，通过 ARP 获取目的主机的 MAC 地址并直接发送帧。
- **间接交付**：目的主机位于其他网络。源主机把默认网关作为下一跳，通过 ARP 获取默认网关接口的 MAC 地址，再把帧发送给网关。

间接交付时，IPv4 首部中的目的地址仍然是最终目的主机地址；首段链路上帧的目的 MAC 地址则是默认网关接口的 MAC 地址。

### 4.2 路由表与最长前缀匹配

转发表项通常包含目的网络前缀、下一跳、输出接口和度量值等信息。常见表项包括直连路由、静态路由、动态路由、主机路由和默认路由。

路由器用目的 IPv4 地址匹配转发表中的网络前缀，并优先选择最长前缀。例如，转发表中有：

```text
0.0.0.0/0       → 接口 1
10.0.0.0/8      → 接口 2
10.1.0.0/16     → 接口 3
```

目的地址 `10.1.2.3` 同时匹配三项，但 `/16` 前缀最长，因此选择接口 3。只有前缀长度相同时，才进一步根据度量值、管理距离或其他策略在候选路由中选择。

### 4.3 路由器的转发步骤

路由器收到一个 IPv4 分组时，通常按照以下顺序处理：

1. **接收帧**：输入接口检查数据链路层帧，确认帧能够接收后去除链路层首部和尾部，取出 IPv4 数据报。
2. **检查首部**：检查 IPv4 版本、首部长度、总长度和首部校验和等字段。首部校验错误的数据报通常直接丢弃。
3. **处理 TTL**：把 TTL 减 1。若结果为 0，则丢弃数据报并通常向源主机返回 ICMP 时间超过报文；否则更新首部校验和。
4. **查找转发表**：对目的 IPv4 地址执行最长前缀匹配，确定输出接口和下一跳。若没有匹配项且不存在默认路由，则丢弃数据报并通常返回 ICMP 目的不可达报文。
5. **处理 MTU**：若数据报大于输出链路 MTU，根据 DF 位决定进行 IPv4 分片还是丢弃并报告差错。
6. **解析下一跳地址**：若不知道下一跳的链路层地址，则通过 ARP 查询下一跳 IPv4 地址对应的 MAC 地址。
7. **重新封装并发送**：使用输出链路的数据链路层协议封装成新帧，填写新的链路层源、目的地址，然后从输出接口发送。

除 NAT 等特殊情况外，数据报逐跳转发时源、目的 IPv4 地址保持不变；TTL 和首部校验和会发生变化，链路层源、目的 MAC 地址则会在每一段链路上重新填写。

::: tip 转发题步骤
先根据目的 IPv4 地址和转发表确定输出接口及下一跳，再判断是否需要分片，最后解析下一跳 MAC 地址并重新封装。ARP 的对象是已经由路由表选出的下一跳，而不是在查路由之前对最终目的地址盲目广播。
:::

## 5. 地址解析协议（ARP）

地址解析协议 ARP 用于在一个 IPv4 局域网内，根据下一跳 IPv4 地址获得对应的 MAC 地址。ARP 解决的是网络层地址到当前链路数据链路层地址的映射问题。

### 5.1 ARP 的工作过程

当主机或路由器需要发送以太网帧时：

1. 先查询本机 ARP 高速缓存，检查是否已有下一跳 IPv4 地址到 MAC 地址的有效映射。
2. 若没有映射，则发送 ARP 请求。ARP 请求帧的目的 MAC 地址为广播地址 `FF:FF:FF:FF:FF:FF`，请求中说明目标 IPv4 地址。
3. 本地广播域中的各接口都能收到请求，但通常只有拥有目标 IPv4 地址的接口作出响应。
4. 目标接口通常以单播方式返回 ARP 应答，告知自己的 MAC 地址。
5. 请求方把映射写入 ARP 缓存，并使用该 MAC 地址封装待发送的帧。缓存表项通常具有生存时间，超时后需要重新解析。

ARP 报文直接封装在数据链路层帧中，不封装在 IP 数据报内。以太网中 ARP 的 EtherType 为 `0x0806`。由于 ARP 请求依赖本地广播，路由器不会把普通 ARP 请求转发到其他网络。

### 5.2 ARP 解析的是下一跳

| 目的主机位置 | ARP 查询的 IPv4 地址 | 得到的 MAC 地址 |
| --- | --- | --- |
| 与发送方在同一网络 | 最终目的主机地址 | 最终目的主机的 MAC 地址 |
| 与发送方不在同一网络 | 默认网关地址 | 默认网关接口的 MAC 地址 |
| 路由器向下一路由器转发 | 下一跳路由器接口地址 | 下一跳路由器接口的 MAC 地址 |
| 路由器向直连目的网络转发 | 最终目的主机地址 | 最终目的主机的 MAC 地址 |

因此，跨网络通信时，源主机不会使用 ARP 查询远端目的主机的 MAC 地址。远端 MAC 地址在源主机所在链路上没有意义，源主机只需要知道默认网关的 MAC 地址。

IPv6 不使用 ARP，而是使用基于 ICMPv6 的邻居发现协议完成类似功能。

::: warning 易错点
ARP 请求通常广播，ARP 应答通常单播；ARP 只能在当前链路或广播域内工作。ARP 解析的是下一跳地址，下一跳不一定是最终目的主机。
:::

## 6. 动态主机配置协议 DHCP

动态主机配置协议 DHCP 用于自动向主机提供 IPv4 地址和其他网络配置参数，例如子网掩码、默认网关、DNS 服务器和地址租用期。DHCP 是基于 UDP 的应用层协议，但它为主机配置网络层参数，因此通常与 IPv4 一起讨论。

DHCP 服务器使用 UDP 端口 67，客户端使用 UDP 端口 68。

### 6.1 地址分配方式

- **手工分配**：管理员预先把固定 IPv4 地址与特定客户端绑定，由 DHCP 服务器发放该地址。
- **自动分配**：服务器从地址池中选择一个地址，长期分配给客户端。
- **动态分配**：服务器以租约方式临时分配地址，租约到期后地址可以回收并重新使用，是最常见的方式。

### 6.2 DHCP 的基本过程

客户端首次接入网络时通常还没有可用 IPv4 地址，也不知道 DHCP 服务器位置，因此前几个报文常使用广播。典型过程简称 DORA：

| 阶段 | 报文 | 主要作用 |
| ---: | --- | --- |
| 1 | DHCP Discover | 客户端广播寻找可用 DHCP 服务器 |
| 2 | DHCP Offer | 服务器提供候选 IPv4 地址和配置参数 |
| 3 | DHCP Request | 客户端选择一个方案并请求使用该地址，同时通知其他服务器 |
| 4 | DHCP ACK | 被选择的服务器确认租约和最终配置 |

客户端最初可以使用 `0.0.0.0` 作为源 IPv4 地址、`255.255.255.255` 作为目的 IPv4 地址，从 UDP 端口 68 向服务器端口 67 发送 DHCP Discover。客户端获得地址后，还需要在租约到期前申请续租；若服务器拒绝请求，可以返回 DHCP NAK。

### 6.3 DHCP 中继代理

普通 IP 路由器不会转发本地广播，因此每个子网单独部署 DHCP 服务器会增加管理成本。DHCP 中继代理可以接收客户端广播，把请求以单播方式转发给其他网络中的 DHCP 服务器，并把服务器响应送回客户端。

中继代理会向服务器提供客户端所在网络的信息，使服务器能够从正确的地址池中选择地址。这样多个子网可以共享集中部署的 DHCP 服务器。

::: warning 易错点
DHCP 负责自动配置 IPv4 地址等参数，ARP 负责查询本地下一跳的 MAC 地址，DNS 负责把域名解析为 IP 地址，三者解决的问题不同。
:::

## 7. 网际控制报文协议 ICMP

网际控制报文协议 ICMP 是 IPv4 的辅助协议，用于报告部分网络层差错并进行网络探测。ICMP 报文封装在 IPv4 数据报的数据部分中，IPv4 首部的协议字段取值为 1；它不使用 TCP 或 UDP 端口。

ICMP 报文的公共部分包括类型、代码和校验和。类型说明报文大类，代码进一步说明具体原因。经典 ICMP 差错报文还携带引发差错的原 IPv4 首部及其数据部分的前 8 B，使源主机能够识别相关通信。

### 7.1 常见 ICMP 报文

| 报文 | 典型用途 |
| --- | --- |
| 目的不可达 | 没有可用路由、目的协议或端口不可达，或者需要分片但 DF=1 |
| 时间超过 | TTL 减为 0，或分片重组超时 |
| 参数问题 | IPv4 首部字段存在无法继续处理的问题 |
| 重定向 | 路由器通知主机在特定条件下使用更合适的下一跳 |
| 回显请求与回显应答 | 测试目的主机可达性并测量往返时间 |

ICMP 只能报告部分问题，不能负责纠正错误，也不能保证差错报文一定送达。收到 ICMP 差错报告后，源主机或上层协议决定如何处理。

### 7.2 ping 与 traceroute

- **ping**：通常发送 ICMP 回显请求，并等待目的主机返回回显应答，用于测试可达性和测量往返时间。未收到应答并不一定说明主机不可达，也可能是 ICMP 被过滤或响应超时。
- **traceroute/tracert**：依次发送 TTL 为 1、2、3 等递增值的探测分组。沿途路由器在 TTL 减为 0 时返回 ICMP 时间超过报文，从而暴露各跳地址。到达最终目的主机后的响应取决于实现，可能是 ICMP 端口不可达或回显应答。

### 7.3 不发送 ICMP 差错报文的典型情况

为避免差错报告形成递归或广播风暴，通常不对以下报文再发送 ICMP 差错报文：

- ICMP 差错报文本身。
- 非首片的 IPv4 分片。
- 以广播地址或组播地址为目的地址的数据报。
- 通过数据链路层广播或组播接收的数据报。
- 源地址无效、为未指定地址、广播地址或组播地址的数据报。

此外，IPv4 首部校验和错误的数据报通常直接丢弃，因为其源地址等首部内容不再可信。

::: warning 易错点
ICMP 封装在 IP 数据报中，但通常归入网络层辅助协议；它用于差错报告和网络探测，不提供可靠传输。ICMP 报文没有 TCP、UDP 端口号。
:::

::: tip 本节主线
IPv4 通过数据报首部携带地址、分片和生存时间等控制信息；CIDR 和子网掩码确定目的网络，最长前缀匹配决定下一跳，ARP 解析当前链路的下一跳 MAC 地址。NAT 转换私网与公网地址，DHCP 自动配置主机参数，ICMP 负责差错报告和网络探测。
:::
