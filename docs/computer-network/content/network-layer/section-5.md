<h1><center>第五节 IP 多播</center></h1>

IP 多播用于把同一份数据高效地发送给一组接收者。它介于单播和广播之间：发送方不需要为每个接收者分别发送一份数据，网络也不必把数据交付给广播范围内的所有节点。

## 1. 多播的概念

在 IP 多播中，一组希望接收同类数据的接口构成一个**多播组**，并由一个 IP 多播地址标识。发送方把数据报发送到该多播地址，沿途多播路由器根据接收者分布建立分发树，只在树的分支处复制数据报。

多播具有以下特点：

- 多播组成员可以动态加入或离开，同一个接口可以同时加入多个多播组。
- 多播组的成员可以分布在不同网络中，组成员数量和位置可以随时间变化。
- 发送方不必属于该多播组，也不需要知道每个接收者的单播地址。
- 一个多播组可以有一个或多个发送方，发送方的源 IP 地址必须是合法的单播地址。
- IP 多播仍然采用尽最大努力交付，不保证可靠、按序、无重复或所有组成员同时收到数据。

### 1.1 单播、广播与多播

| 通信方式 | 目的地址标识 | 接收范围 | 分组复制方式 |
| --- | --- | --- | --- |
| 单播 | 一个接口 | 一个指定接收接口 | 多个接收者通常需要分别发送 |
| 广播 | 一个广播范围内的全部接口 | 本地网络或指定广播域内所有节点 | 向广播范围内普遍交付 |
| 多播 | 一个多播组 | 已加入该组的接收接口 | 网络在多播分发树的分支处按需复制 |

多播适合网络电视、在线会议、实时行情、软件分发等一个或多个发送方对应多个接收者的场景。接收者越多，网络内多次单播造成的重复流量通常越明显，多播节省带宽的优势也越大。

### 1.2 IP 多播需要解决的问题

完整的 IP 多播需要三个层面的配合：

1. **多播编址**：使用 IP 多播地址标识接收者组。
2. **本地网络交付**：在以太网等局域网上，把 IP 多播地址映射为相应的硬件多播地址。
3. **跨网络转发**：主机与本地多播路由器通过 IGMP 管理组成员关系，多播路由器之间运行多播路由协议并建立分发树。

::: warning 易错点
IP 多播地址标识的是一组接收接口，而不是一台固定主机。它通常只能作为目的地址；多播数据报的源地址必须是单播地址。
:::

## 2. IP 多播地址

IPv4 多播地址原称 D 类地址，最高 4 bit 固定为 `1110`，地址范围为：

```text
224.0.0.0 ～ 239.255.255.255
```

也可以表示为：

```text
224.0.0.0/4
```

最高 4 bit 固定后，剩余 28 bit 用于标识多播组。多播地址不再划分传统的网络号和主机号，也不能像普通单播地址那样分配给某个接口作为单播源地址。

### 2.1 常见 IPv4 多播地址范围

::: info 408 复习定位
本节核心是掌握 IPv4 多播地址属于 `224.0.0.0/4` 以及多播地址标识接收者组。下面各子范围的具体用途属于拓展了解，用于帮助理解地址的使用场景，不要求逐项背诵。
:::

| 地址范围 | 主要用途 |
| --- | --- |
| `224.0.0.0/24` | 本地网络控制多播，路由器不把这些分组转发到其他网络 |
| `232.0.0.0/8` | 源特定多播 SSM 地址范围 |
| `239.0.0.0/8` | 管理域范围多播，可在组织内部使用，作用类似私有范围 |
| 其他已分配范围 | 根据协议、应用和管理机构的分配规则使用 |

本地网络控制范围中的常见地址包括：

- `224.0.0.1`：本地网络上的所有支持 IP 多播的系统。
- `224.0.0.2`：本地网络上的所有多播路由器。

这些地址仅用于当前链路，普通路由器不会把目的地址属于 `224.0.0.0/24` 的数据报转发到其他链路。

### 2.2 多播组与组成员

多播地址表示逻辑接收者组。一个接口加入某个组，表示它希望接收发往该组地址的数据报；离开该组后，所在网络的多播路由器可以在确认没有其他成员时停止向该网络转发相应数据。

某些多播地址由标准长期保留给特定协议，但“永久分配的多播地址”不表示组成员永久不变。地址的用途可以固定，实际接口仍然可以根据协议规则加入或离开。

作为拓展了解，在传统任意源多播 ASM 中，接收者主要按照组地址 $G$ 订阅数据；在源特定多播 SSM 中，接收者可以明确指定希望接收来自源 $S$、发送到组 $G$ 的流量。多播路由状态常用 $(*,G)$ 或 $(S,G)$ 表示。

::: warning 易错点
IPv4 多播地址共有 28 bit 组标识，但以太网多播 MAC 映射只使用其中低 23 bit，因此 IP 多播地址与以太网多播 MAC 地址不是一一对应关系。
:::

## 3. 在局域网上进行硬件多播（拓展了解）

::: info 408 大纲定位
现行大纲对 IP 多播明确要求的是“多播的概念”和“IP 多播地址”。本节及下一节用于补充多播在局域网和跨网络中的实现过程；若按现行大纲复习，应以理解原理为主，不必背诵协议版本和具体多播路由协议的细节。
:::

IPv4 多播数据报在以太网上传输时，需要把目的 IPv4 多播地址映射为目的以太网多播 MAC 地址。IPv4 多播使用的以太网 MAC 地址范围为：

```text
01:00:5E:00:00:00 ～ 01:00:5E:7F:FF:FF
```

该范围的前 25 bit 固定，后 23 bit 由 IPv4 多播地址的低 23 bit 直接映射得到：

```text
IPv4 多播组标识： [高 5 bit] [低 23 bit]
                              │
                              └──────────────┐
以太网多播地址：  [固定 25 bit] [复制低 23 bit]
固定 25 bit：00000001 00000000 01011110 0
             01       00       5E
```

换算时可以保留 IPv4 多播地址第二个字节的低 7 bit，再把第三、第四个字节原样放入 MAC 地址。例如：

```text
IPv4 多播地址：239.1.2.3
第二字节低 7 bit：1
以太网多播地址：01:00:5E:01:02:03
```

### 3.1 映射不是一一对应

IPv4 多播地址具有 28 bit 组标识，而以太网映射只保留低 23 bit，丢弃了高 5 bit。因此：

$$
2^{28-23}=2^5=32
$$

个不同的 IPv4 多播地址可能映射为同一个以太网多播 MAC 地址。

网卡即使根据 MAC 地址过滤多播帧，也可能接收到并非本机所加入 IP 多播组的帧。因此接收方仍需要在 IP 层检查完整的 IPv4 多播目的地址，把不属于本机订阅组的数据报丢弃。

### 3.2 交换机中的多播转发

普通二层交换机若不知道哪些端口连接了多播组成员，可能在所属 VLAN 内把多播帧向多个端口泛洪。支持 **IGMP Snooping** 的交换机可以监听主机与多播路由器之间的 IGMP 报文，建立组地址与交换机端口之间的关系，从而只向可能存在接收者的端口转发多播帧。

IGMP Snooping 是交换机的数据链路层优化功能，不等同于主机与多播路由器运行的 IGMP，也不代替跨网络的多播路由协议。

::: warning 易错点
IPv4 多播到以太网 MAC 的映射只取 IP 地址的低 23 bit，所以硬件地址过滤不能完全确定 IP 多播组。接收主机还必须在 IP 层再次过滤。
:::

## 4. IGMP 与多播路由协议（拓展了解）

多播通信中需要解决两个不同问题：

- 当前局域网中是否存在某个多播组的接收者，由 IGMP 协调主机和直接连接的多播路由器。
- 多播数据报应在路由器之间沿哪些链路转发，由多播路由协议建立和维护多播分发树。

### 4.1 IGMP 的作用

网际组管理协议 IGMP 用于 IPv4 主机向本地多播路由器报告组成员关系。IGMP 只在主机与其直接连接的多播路由器之间工作，不负责计算跨越多个网络的多播路径。

IGMP 报文直接封装在 IPv4 数据报中，IPv4 协议字段取值为 2，不使用 TCP 或 UDP 端口。

多播路由器通常只需要知道某个接口连接的网络中是否至少存在一个组成员，不需要知道每个成员的准确身份和数量。只要该网络还有成员，路由器就应保留相应转发分支。

### 4.2 IGMP 的基本工作过程

1. **加入多播组**：主机在某接口加入多播组时，主动发送成员关系报告，使本地多播路由器尽快知道该网络存在接收者。
2. **成员查询**：多播路由器周期性发送成员关系查询，询问本地网络中哪些多播组仍有成员。
3. **成员报告**：组成员在随机等待时间后发送成员关系报告。IGMPv1、IGMPv2 中，若某主机先听到同组其他成员的报告，可以抑制自己的报告，减少重复报文。
4. **离开多播组**：IGMPv2 主机可以发送离组报文。路由器再进行特定组查询；若没有收到任何成员报告，就可以删除该接口上的组成员状态。

IGMPv1 主要支持查询和成员报告；IGMPv2 增加离组报文和特定组查询；IGMPv3 支持源过滤，使主机能够指定希望接收或排除哪些源的多播流量，并为源特定多播提供支持。

### 4.3 多播路由与反向路径转发

多播路由器需要建立无环的多播分发树，使数据报只向能够到达组成员的接口转发。与单播只查询目的地址不同，多播转发通常需要同时考虑源地址 $S$、组地址 $G$ 和分组到达的接口。

**反向路径转发 RPF** 是多播转发和防环的重要基础：

1. 路由器收到源为 $S$ 的多播数据报后，查询单播路由表，判断到达源 $S$ 的最优反向路径应使用哪个接口。
2. 若多播数据报正是从该接口到达，则通过 RPF 检查，可以向多播树上的其他接口转发。
3. 若从其他接口到达，则认为它可能是重复分组或由环路产生，直接丢弃。

RPF 使用的是“返回源的最佳单播路径”来检查多播分组的入接口，并不表示把多播数据报真的反向发送给源。

### 4.4 多播分发树

- **源树或最短路径树**：以某个多播源为根，为每个源分别建立到接收者的树。路径通常较优，但路由器需要保存较多 $(S,G)$ 状态。
- **共享树**：以选定的核心路由器或汇合点为根，多个源共享一棵树。能够减少状态，但路径可能不是每个源到接收者的最短路径。

在接收者分布较密集的网络中，可以先把多播流量洪泛到较大范围，再由没有组成员的分支发送剪枝信息，这称为**洪泛与剪枝**。接收者较稀疏时，通常让路由器显式加入共享树或源树，避免先向整个网络洪泛。

### 4.5 常见多播路由协议

| 协议 | 基本思想 |
| --- | --- |
| DVMRP | 结合距离向量信息和 RPF，采用洪泛与剪枝建立源树 |
| MOSPF | 在 OSPF 链路状态数据库基础上加入组成员信息，计算多播最短路径树 |
| PIM-DM | 协议无关多播密集模式，适合接收者较密集场景，使用洪泛与剪枝 |
| PIM-SM | 协议无关多播稀疏模式，使用汇合点建立共享树，适合接收者稀疏场景 |

PIM 中的“协议无关”表示它不依赖某一种特定的单播路由协议，而是利用现有单播路由表完成 RPF 检查；它并不是不需要单播路由信息。

::: warning 易错点
IGMP 不在路由器之间计算多播路径，只管理本地网络的组成员关系；多播路由协议才负责在路由器之间建立分发树。RPF 检查的是分组是否从通往源的正确反向接口到达。
:::

::: tip 本节主线
IP 多播用一个多播地址标识接收者组，在以太网上把 IPv4 多播地址的低 23 bit 映射到 `01:00:5E` 多播 MAC。IGMP 告诉本地多播路由器哪些组仍有接收者，多播路由协议再利用 RPF 和分发树把数据跨网络送到相应成员。
:::
