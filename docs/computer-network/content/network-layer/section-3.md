<h1><center>第三节 IPv6</center></h1>

## 1. IPv6 的特点

IPv6 是为解决 IPv4 地址空间不足并改进网络层处理方式而设计的网际协议。它仍然提供无连接、尽最大努力交付的数据报服务，并没有因为地址更长而自动变成可靠传输协议。

IPv6 的主要特点包括：

1. **地址空间更大**：IPv6 地址长度为 128 bit，理论上具有 $2^{128}$ 个地址，远大于 IPv4 的 32 bit 地址空间。
2. **基本首部固定**：IPv6 基本首部固定为 40 B，删除或调整了 IPv4 中部分字段，便于路由器快速处理。
3. **采用扩展首部**：分片、路由选择、安全和其他可选功能不放在基本首部中，而是通过一个或多个扩展首部实现。
4. **取消首部校验和**：IPv6 基本首部没有首部校验和，路由器无须因逐跳修改首部而重新计算校验和。差错检测由数据链路层和传输层等其他层次负责。
5. **路由器不进行分片**：IPv6 路由器遇到过大的数据报时将其丢弃，并向源主机返回 ICMPv6“分组过大”报文；需要分片时，由源主机使用分片扩展首部完成。
6. **支持流的标识**：基本首部中的流标签可以标识属于同一数据流的分组，便于实施特定的转发或服务质量策略，但流标签本身不等于带宽或时延保证。
7. **取消广播**：IPv6 不定义广播地址，原来部分广播功能由组播完成；IPv6 还支持任播。
8. **支持自动配置**：主机可以利用无状态地址自动配置等机制获得 IPv6 地址和必要的网络参数，也可以使用 DHCPv6 等有状态配置方式。

IPv6 的基本首部虽然固定，但长度为 40 B，大于无选项的 IPv4 首部 20 B。因此，“IPv6 简化首部”是指字段组织和路由器处理得到简化，不是说 IPv6 基本首部的字节数更少。

::: warning 易错点
IPv6 仍然是尽最大努力交付；更大的地址空间、固定基本首部和取消首部校验和都不表示它能够保证可靠、按序或无差错交付。
:::

## 2. IPv6 数据报的基本首部

::: info 408 大纲定位
现行大纲明确要求掌握 IPv6 的主要特点和 IPv6 地址。基本首部是理解这些特点的支撑内容，应重点掌握 IPv6 与 IPv4 的结构性差异；各字段的位数和作用以理解为主。
:::

IPv6 数据报由固定 40 B 的基本首部、零个或多个扩展首部以及上层协议数据组成：

$$
\text{IPv6 数据报}=\text{基本首部}+\text{扩展首部}+\text{上层协议数据}.
$$

IPv6 基本首部包含 8 个字段：

| 字段 | 长度 | 作用 |
| --- | ---: | --- |
| 版本 Version | 4 bit | 固定为 6，表示 IPv6 |
| 通信量类 Traffic Class | 8 bit | 区分不同类别或优先级的流量，并可携带拥塞相关信息 |
| 流标签 Flow Label | 20 bit | 标识具有相同处理需求的一组分组 |
| 有效载荷长度 Payload Length | 16 bit | 表示基本首部之后的字节数，包括扩展首部和上层数据 |
| 下一个首部 Next Header | 8 bit | 指明紧随其后的扩展首部或上层协议 |
| 跳数限制 Hop Limit | 8 bit | 每经过一个路由器减 1，减为 0 时丢弃数据报 |
| 源地址 Source Address | 128 bit | 标识发送接口的 IPv6 地址 |
| 目的地址 Destination Address | 128 bit | 标识目的接口或目的接口组的 IPv6 地址 |

### 2.1 重要字段

- **有效载荷长度**不包含 40 B 的 IPv6 基本首部，但包含所有扩展首部。计算普通 IPv6 数据报总长度时，应在有效载荷长度上再加 40 B。
- **下一个首部**的作用类似链式指针。若基本首部后面是扩展首部，它指出扩展首部的类型；每个扩展首部再指出下一个扩展首部或 TCP、UDP、ICMPv6 等上层协议。
- **跳数限制**相当于 IPv4 的 TTL。它按经过的路由器数量递减，用于防止数据报因路由环路而无限转发。
- **流标签**用于标识数据流，但是否提供特殊处理仍取决于网络设备和配置，不能仅凭流标签推断网络已经预留资源。

### 2.2 扩展首部

IPv6 把可选功能移出基本首部，由扩展首部按需组成首部链。常见扩展首部包括逐跳选项首部、路由首部、分片首部、目的选项首部，以及认证首部和封装安全载荷首部等。

除逐跳选项首部外，扩展首部通常要等数据报到达其所标识的目的节点后才处理。逐跳选项首部是例外，沿途节点在被明确配置时可以检查和处理它；未作这种配置的转发路由器通常仍只处理固定格式的基本首部。扩展首部属于 IPv6 数据报的一部分，并计入有效载荷长度。

### 2.3 IPv6 分片

IPv6 基本首部没有 IPv4 中的标识、标志和片偏移字段。需要分片时，源主机添加分片扩展首部；中间路由器不能替源主机对 IPv6 数据报分片。

当下一段链路的 MTU 小于待转发数据报时，IPv6 路由器丢弃该数据报，并返回 ICMPv6“分组过大”报文，其中携带下一跳能够接受的 MTU。源主机据此减小数据报或实施源端分片，这也是路径 MTU 发现的基础。

| IPv4 首部中的内容 | IPv6 中的处理方式 |
| --- | --- |
| 首部长度 | 基本首部固定为 40 B，不再需要该字段 |
| 首部校验和 | 取消 |
| 标识、标志、片偏移 | 移入分片扩展首部 |
| 选项 | 改由扩展首部承载 |
| TTL | 改称跳数限制 Hop Limit |
| 协议字段 | 改为下一个首部 Next Header |

::: warning 易错点
“IPv6 不分片”是不准确的。正确说法是：IPv6 路由器不进行中途分片，但源主机仍可以使用分片扩展首部进行分片，分片最终由目的主机重组。
:::

## 3. IPv6 地址

IPv6 地址长度为 128 bit，通常分成 8 组，每组 16 bit，并用十六进制数表示。各组之间使用冒号分隔。例如：

```text
2001:0db8:0000:0000:0000:ff00:0042:8329
```

IPv6 地址标识的是网络接口，而不是抽象的整台主机。一台主机或路由器可以有多个接口，一个接口也可以同时配置多个 IPv6 地址。

### 3.1 IPv6 地址的简化表示

IPv6 地址可以使用两条压缩规则：

1. **省略前导零**：每组十六进制数开头的零可以省略，但不能省略组末尾的有效零。
2. **双冒号压缩**：一段连续的全零组可以压缩为 `::`。为保证地址能够唯一还原，一个 IPv6 地址中最多只能使用一次 `::`。

例如：

```text
完整写法：2001:0db8:0000:0000:0000:ff00:0042:8329
省略前导零：2001:db8:0:0:0:ff00:42:8329
双冒号压缩：2001:db8::ff00:42:8329
```

还原含 `::` 的地址时，应补入若干个 `0000`，使地址最终恢复为 8 组。若地址中已经写出 $n$ 组，则 `::` 代表 $8-n$ 个连续的全零组。

IPv6 前缀采用斜线记法。例如 `2001:db8:1234:5678::/64` 表示前 64 bit 为网络前缀。IPv6 不使用 IPv4 的点分十进制子网掩码表示法。

### 3.2 IPv6 地址类型

IPv6 主要使用单播、组播和任播三种地址类型：

- **单播地址**：标识一个接口，发送到单播地址的数据报交付给该接口。
- **组播地址**：标识一组接口，发送到组播地址的数据报交付给该组中相应范围内的所有成员。IPv6 组播地址以 `FF00::/8` 为前缀。
- **任播地址**：同一个地址分配给多个接口，发送到该地址的数据报通常交付给路由意义上最近的一个接口。任播地址使用单播地址的格式，不能仅凭地址外观判断它是否被用作任播。

IPv6 没有广播地址，不能把组播地址简单称为广播地址。组播强调只向加入相应组的接口交付，而广播通常面向某个广播范围内的所有节点。

### 3.3 常见单播地址

| 地址或前缀 | 含义 |
| --- | --- |
| `::/128` | 未指定地址，表示节点尚未获得有效地址，不能作为正常目的地址使用 |
| `::1/128` | 环回地址，只在本机内部使用 |
| `FE80::/10` | 链路本地单播地址，只在当前链路范围内有效，路由器不转发到其他链路 |
| `FC00::/7` | 唯一本地单播地址，用于组织内部通信，通常不在全球互联网中路由 |
| `2000::/3` | 当前全球单播地址的主要分配范围，可在互联网中进行全局路由 |

链路本地地址在 IPv6 邻居发现、路由器发现等过程中具有重要作用。即使接口还没有获得全球单播地址，也通常能够利用链路本地地址在本链路通信。

::: warning 易错点
`::` 是未指定地址，`::1` 才是环回地址；`::` 压缩规则在一个地址中只能使用一次。IPv6 的任播没有独立的特殊地址格式，它使用分配给多个接口的单播地址。
:::

## 4. 从 IPv4 向 IPv6 过渡（拓展了解）

IPv4 与 IPv6 的首部格式和地址长度不同，二者不能仅靠修改版本字段直接兼容。由于现有 IPv4 网络无法一次性全部替换，过渡阶段需要让两种协议长期共存。现行 408 大纲未单独列出过渡技术，本节作为拓展了解；复习时重点区分双协议栈、隧道和协议转换的基本思路即可。

### 4.1 双协议栈

双协议栈是指同一主机或路由器同时实现 IPv4 和 IPv6，并同时配置相应地址：

- 与 IPv4 节点通信时使用 IPv4。
- 与 IPv6 节点通信时使用 IPv6。
- 主机可以根据 DNS 返回的 A 记录和 AAAA 记录、目的地址以及网络连通性选择使用哪一种协议。

双协议栈发送的是独立的 IPv4 数据报或 IPv6 数据报，不是把一个 IPv6 首部直接改写成 IPv4 首部。它要求通信路径上的相关节点支持所选择的协议，因此会在过渡期增加地址配置和网络管理的复杂度。

### 4.2 隧道技术

当两个 IPv6 网络之间隔着只支持 IPv4 的网络时，可以建立 IPv6-over-IPv4 隧道：

1. 隧道入口把完整的 IPv6 数据报作为数据，封装在一个 IPv4 数据报中。
2. IPv4 网络中的路由器只根据外层 IPv4 首部转发，不需要理解内层 IPv6 首部。
3. 隧道出口去除外层 IPv4 首部，恢复原始 IPv6 数据报并继续按 IPv6 转发。

外层 IPv4 源、目的地址标识隧道两端，内层 IPv6 源、目的地址仍标识原始通信双方。封装会增加额外首部开销，并减小隧道路径上的有效载荷空间，因此必须注意 MTU 和分片问题。

### 4.3 协议转换（拓展）

若一端只支持 IPv6、另一端只支持 IPv4，仅有双协议栈或隧道并不能直接完成端到端通信，此时可以在边界设备上进行协议和地址转换。NAT64 配合 DNS64 是常见方案之一：转换设备在 IPv6 与 IPv4 地址及首部之间建立映射，DNS64 可以为只有 IPv4 地址的目的节点合成可供 IPv6 主机使用的地址信息。

协议转换需要修改网络层首部，有时还要处理传输层校验和及应用数据中的地址信息，因而并非对所有协议都完全透明。它是实际过渡方案的补充，不应与双协议栈或隧道混淆。

| 方法 | 核心做法 | 主要适用场景 |
| --- | --- | --- |
| 双协议栈 | 节点同时运行 IPv4 和 IPv6，按通信对象选择协议 | 通信双方及路径能够支持同一种 IP 协议 |
| 隧道技术 | 把一种协议的数据报封装在另一种协议的数据报中 | 同类网络跨越不支持该协议的中间网络 |
| 协议转换 | 在 IPv4 与 IPv6 地址和首部之间进行转换 | IPv6-only 与 IPv4-only 节点通信 |

::: warning 易错点
双协议栈是“选择 IPv4 或 IPv6”，隧道是“把完整数据报封装后穿越异构网络”，协议转换是“改写两种协议的地址和首部”。IPv6-in-IPv4 隧道中的 IPv4 网络只处理外层 IPv4 首部。
:::

::: tip 本节主线
IPv6 用 128 bit 地址扩大地址空间，以固定 40 B 基本首部和扩展首部链简化处理；它取消广播和基本首部校验和，分片只由源主机实施。IPv4 与 IPv6 在过渡期主要通过双协议栈、隧道和必要的协议转换实现共存。
:::
