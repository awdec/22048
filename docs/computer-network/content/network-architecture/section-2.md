<h1><center>第二节 计算机网络体系结构与参考模型</center></h1>

## 1. 分层思想

计算机网络把复杂的通信任务划分为若干相对独立的层次。每层向上一层提供服务，并使用下一层提供的服务。

分层能够降低系统设计复杂度、促进标准化和模块复用，也会带来协议首部开销、处理开销和部分功能重复。

## 2. 协议、接口与服务

- **协议**：对等实体之间通信所遵循的规则集合。
- **接口**：相邻层之间交换信息的位置和规则。
- **服务**：下层通过接口向上层提供的功能。

协议由三个基本要素组成：

- **语法**：规定数据和控制信息的格式。
- **语义**：规定字段含义以及通信双方应采取的动作。
- **同步**：规定事件发生的先后顺序和速度匹配关系。

协议是“水平”的，约束不同系统中的对等实体；服务是“垂直”的，由下层通过接口提供给上层。

## 3. 实体、服务访问点与数据单元

实现某一层功能的活动元素称为实体，同一层的通信实体称为对等实体。相邻层通过服务访问点交换信息。

数据在发送端逐层封装：上层协议数据单元作为下层的数据部分，下层添加本层首部，部分数据链路层协议还会添加尾部。接收端则逐层解封装并向上交付数据。

## 4. OSI 七层参考模型

| 层次 | 主要功能 | 典型数据单元 |
| --- | --- | --- |
| 应用层 | 为用户应用提供网络服务 | 报文 |
| 表示层 | 数据表示、压缩和加密 | 报文 |
| 会话层 | 建立、管理和同步会话 | 报文 |
| 传输层 | 实现端到端的进程通信 | 报文段/用户数据报 |
| 网络层 | 路由选择与分组转发 | 数据报/分组 |
| 数据链路层 | 成帧、差错控制与介质访问 | 帧 |
| 物理层 | 在介质上传输比特 | 比特 |

OSI 模型概念清晰、层次完整，常用于理解网络功能划分，但互联网实际广泛采用 TCP/IP 协议体系。

## 5. TCP/IP 参考模型

TCP/IP 参考模型通常分为：

1. 应用层。
2. 传输层。
3. 网际层。
4. 网络接口层。

TCP/IP 的应用层对应 OSI 的应用层、表示层和会话层；网际层大致对应 OSI 网络层；网络接口层涵盖数据链路层和物理层的功能。

## 6. 五层参考模型

教学中常把 TCP/IP 的网络接口层拆分为数据链路层和物理层，形成应用层、传输层、网络层、数据链路层和物理层五层模型。

| 层次 | 核心任务 | 常用标识或地址 |
| --- | --- | --- |
| 应用层 | 定义具体网络应用 | 域名、URL 等 |
| 传输层 | 实现进程到进程通信 | 端口号 |
| 网络层 | 跨网络选路与转发 | IP 地址 |
| 数据链路层 | 相邻节点间传输帧 | MAC 地址 |
| 物理层 | 透明传输比特流 | 无逻辑地址 |

## 7. OSI 与 TCP/IP 模型比较

- OSI 先提出完整参考模型，再定义相应协议；TCP/IP 从已有协议实践中总结出体系结构。
- OSI 明确区分服务、接口和协议；早期 TCP/IP 对这些概念的区分不如 OSI 严格。
- OSI 网络层支持面向连接和无连接通信，传输层主要面向连接；TCP/IP 网际层采用无连接 IP，传输层同时提供面向连接的 TCP 和无连接的 UDP。
