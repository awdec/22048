<h1><center>第二节 计算机网络体系结构</center></h1>

本节先说明复杂网络为什么需要分层以及数据如何逐层传递，再辨析协议、服务和接口，最后比较 ISO/OSI 参考模型、TCP/IP 参考模型与教学中常用的五层模型。

## 1. 计算机网络分层结构

### 1.1 分层的基本思想

计算机网络需要协调不同设备、链路和应用之间的通信，直接设计一个包含全部功能的整体系统会非常复杂。分层结构把完整的通信任务划分为若干相对独立的层次，每一层只处理一类明确的问题。

分层时通常遵循以下原则：

- 每层实现一种相对独立的功能，层数应适中。
- 每层功能的选择应有利于协议标准化。
- 相邻层之间具有清晰的接口，层间交换的信息应尽量少。
- 下层向上层提供服务，上层使用下层提供的服务。
- 一层内部实现方式的变化不应影响其他层，只要它提供的服务和接口保持不变。

将计算机网络的各层及其协议的集合称为**网络体系结构**。体系结构描述网络“应当完成什么”，各层协议和设备的具体实现描述“如何完成”。

### 1.2 实体与对等实体

**实体**是能够发送或接收信息的硬件或软件进程。实现第 $n$ 层功能的实体称为 $n$ 层实体，分别位于不同系统中、处于同一层的实体称为**对等实体**。

- 对等实体之间按照本层协议进行逻辑通信。
- 相邻层实体之间通过接口使用或提供服务。
- 除物理层外，对等实体之间通常不存在直接的物理连接，数据必须经过下层逐层传递。

### 1.3 数据单元

分层结构中常见的数据单元包括：

- **服务数据单元 SDU**：上层交给本层处理的数据。
- **协议控制信息 PCI**：本层为实现协议功能而添加的控制信息，通常表现为首部，某些协议还会添加尾部。
- **协议数据单元 PDU**：对等实体之间按照本层协议交换的数据单位。

三者之间的基本关系为：

$$
\mathrm{PDU}_n=\mathrm{SDU}_n+\mathrm{PCI}_n.
$$

本层的 PDU 交给下一层后，通常成为下一层的 SDU。由于分段、合并等操作的存在，SDU 与 PDU 并不一定始终是一一对应的关系。

### 1.4 封装与解封装

发送端的数据从高层向低层传递。每一层把上层数据作为本层 SDU，并添加本层控制信息，形成 PDU，这一过程称为**封装**。数据链路层除首部外还可能添加尾部，物理层最终把数据转换为比特流在传输介质上传送。

接收端按照相反方向从低层向高层处理数据。每一层检查并去除本层控制信息，再把数据交付给上一层，这一过程称为**解封装**。

在常用五层模型中，各层 PDU 的典型名称如下：

| 层次 | 典型协议数据单元 |
| --- | --- |
| 应用层 | 报文 |
| 传输层 | 报文段（TCP）或用户数据报（UDP） |
| 网络层 | IP 数据报或分组 |
| 数据链路层 | 帧 |
| 物理层 | 比特流 |

### 1.5 分层的优点与代价

| 优点 | 代价 |
| --- | --- |
| 降低系统设计与理解难度 | 逐层添加首部或尾部会产生传输开销 |
| 各层相对独立，便于开发、维护和升级 | 数据经过多层处理会产生时间和计算开销 |
| 便于标准化，促进不同厂商设备互操作 | 不同层可能重复实现检错、流量控制等功能 |
| 有利于模块复用和故障定位 | 严格分层有时会限制跨层优化 |

## 2. 计算机网络协议、接口、服务等概念

### 2.1 协议

**网络协议**是控制两个或多个对等实体进行通信的规则集合。协议规定对等实体“如何通信”，是一种**水平关系**。

协议由三个基本要素组成：

| 要素 | 规定内容 | 示例 |
| --- | --- | --- |
| 语法 | 数据与控制信息的格式或结构 | 字段长度、编码方式、报文格式 |
| 语义 | 各字段的含义以及需要完成的动作 | 地址代表什么、收到请求后如何响应 |
| 同步 | 事件的执行顺序和速度匹配关系 | 何时发送、何时应答、超时后如何处理 |

协议必须由通信双方共同遵守。只有报文格式相同而处理规则不同，或者处理规则相同而交互顺序不一致，都不能完成正确通信。

### 2.2 服务

**服务**是下层通过层间接口向紧邻的上层提供的一组功能。服务描述上层“可以获得什么”，是一种**垂直关系**；上层只需要知道如何使用服务，不必了解下层实现服务的具体过程。

从建立连接的方式看，服务可分为：

- **面向连接服务**：通信前先建立连接，通信过程中维护连接状态，结束后释放连接，适合连续传输。例如 TCP 提供的可靠字节流服务。
- **无连接服务**：通信前不建立专用连接，每个数据单元独立传送，适合突发或短报文。例如 IP 和 UDP 提供的服务。

服务还可以按可靠性分为可靠服务和不可靠服务。**面向连接不必然等于可靠，无连接也不必然等于不可靠**；是否可靠取决于协议是否提供确认、重传、排序等机制。

### 2.3 接口与服务访问点

**接口**是同一系统中相邻层之间交换信息的位置及应遵守的规则。上层通过接口调用下层服务，下层通过接口向上层交付结果。

同一系统中相邻两层实体交换信息的逻辑位置称为**服务访问点 SAP**。SAP 用于标识上层实体访问下层服务的位置。例如，传输层的端口可以看作应用进程访问传输层服务的一种服务访问点。

::: details 拓展：服务原语
上层使用服务时可以通过服务原语表达操作。典型服务原语包括：

- **请求 Request**：服务用户请求服务提供者完成某项操作。
- **指示 Indication**：服务提供者通知另一端服务用户发生了某个事件。
- **响应 Response**：服务用户对收到的指示作出回应。
- **证实 Confirmation**：服务提供者把请求的执行结果告知最初的请求方。
:::

### 2.4 协议、服务与接口的关系

| 概念 | 作用对象 | 关系方向 | 回答的问题 |
| --- | --- | --- | --- |
| 协议 | 不同系统中的对等实体 | 水平 | 对等实体如何通信 |
| 服务 | 相邻层中的下层与上层 | 垂直 | 下层向上层提供什么功能 |
| 接口 | 同一系统中的相邻层 | 垂直 | 上层从何处、按什么规则使用服务 |

下层实体使用更低层提供的服务，并与另一系统中的对等实体遵循本层协议进行逻辑通信，从而向上层提供服务。协议可以改变，只要服务内容和接口保持不变，上层通常不需要随之改变。

::: warning 易错点
协议并不等于服务。协议是对等实体之间的通信规则，服务是下层向上层提供的功能，接口则是上层使用这些服务的边界。上层只能使用相邻下层的服务，不能直接调用跨层服务。
:::

## 3. ISO/OSI 参考模型和 TCP/IP 参考模型

### 3.1 ISO/OSI 七层参考模型

国际标准化组织（ISO）提出的 OSI（开放系统互连）参考模型把网络通信功能划分为七层。OSI 是一种概念清晰的理论模型，主要用于描述功能分层和指导标准化，不是因特网实际采用的协议体系。

| 层次 | 主要功能 |
| --- | --- |
| 应用层 | 为应用进程提供访问 OSI 环境的手段 |
| 表示层 | 数据格式转换、加密解密、压缩解压 |
| 会话层 | 建立、管理和同步会话，设置同步点 |
| 传输层 | 提供端到端通信、复用分用、差错恢复和流量控制 |
| 网络层 | 路由选择、分组转发和拥塞控制 |
| 数据链路层 | 成帧、差错控制、流量控制和介质访问控制 |
| 物理层 | 在传输介质上透明地传输比特流 |

OSI 模型中，应用层、表示层和会话层面向信息处理，传输层负责端到端通信，网络层、数据链路层和物理层负责数据在网络中的传输。

::: tip 横向记忆
应用层定义业务，表示层统一表示，会话层管理会话，传输层定位进程，网络层选择路径，数据链路层传输帧，物理层传输比特。
:::

### 3.2 TCP/IP 四层参考模型

TCP/IP 参考模型来自因特网协议的实际应用，通常划分为四层：

| TCP/IP 层次 | 主要功能 | 典型协议 |
| --- | --- | --- |
| 应用层 | 直接为用户应用提供网络服务，同时承担表示和会话相关功能 | HTTP、DNS、FTP、SMTP、DHCP |
| 传输层 | 提供进程到进程的端到端通信 | TCP、UDP |
| 网际层 | 使用统一的 IP 地址实现跨网络分组传输与路由选择 | IP、ICMP、IGMP |
| 网络接口层 | 负责主机接入具体网络并在链路上传输数据 | Ethernet、Wi-Fi、PPP |

TCP/IP 参考模型没有单独设置表示层和会话层，相关功能由应用层协议、应用程序或其他层的具体协议实现；其网络接口层也没有严格区分数据链路层和物理层。

### 3.3 OSI 与 TCP/IP 的层次对应

| OSI 参考模型 | TCP/IP 模型 | 五层教学模型 |
| --- | --- | --- |
| 应用层 | 应用层 | 应用层 |
| 表示层 | 应用层 | 应用层 |
| 会话层 | 应用层 | 应用层 |
| 传输层 | 传输层 | 传输层 |
| 网络层 | 网际层 | 网络层 |
| 数据链路层 | 网络接口层 | 数据链路层 |
| 物理层 | 网络接口层 | 物理层 |

教学中常把 TCP/IP 的网络接口层拆分为数据链路层和物理层，形成**五层模型**。五层模型既保留 OSI 清晰的分层思想，又贴近 TCP/IP 的实际协议体系，是学习计算机网络时最常使用的模型。

端口号、IP 地址和 MAC 地址属于 TCP/IP 与常见局域网中的标识：端口号用于传输层定位进程，IP 地址用于网络层跨网络寻址，MAC 地址用于数据链路层的一段链路内交付。二层交换机主要工作在数据链路层，路由器主要工作在网络层；这些是五层教学模型中的常见实例，不是 OSI 参考模型本身规定的专有地址或设备。

### 3.4 OSI 与 TCP/IP 的比较

| 对比项 | ISO/OSI 参考模型 | TCP/IP 参考模型 |
| --- | --- | --- |
| 形成过程 | 先提出参考模型，再定义相应协议 | 先有实际协议，再总结出模型 |
| 层次数量 | 七层 | 四层 |
| 概念划分 | 明确区分服务、接口和协议 | 早期对三者的区分不如 OSI 严格 |
| 服务方式（408 传统教材口径） | 网络层支持面向连接和无连接通信，传输层按面向连接通信记忆 | 网际层的 IP 提供无连接、尽最大努力交付；传输层的 TCP 面向连接，UDP 无连接 |
| 实际应用 | 主要用于理论分析和功能划分 | 是互联网事实上的协议体系 |

两种模型不是相互排斥的：OSI 更适合解释“各层应承担什么功能”，TCP/IP 更适合说明互联网“实际使用哪些协议以及如何协同工作”。

::: warning 408 应试口径与标准演进
408 传统教材和题库通常把 OSI 传输层概括为只提供面向连接服务，选择题按这一口径作答。现行 ISO/IEC 7498-1（对应 ITU-T X.200）已经包含无连接运输模式，因此不能把传统应试结论理解为现代 OSI 标准永远只允许面向连接通信。
:::
