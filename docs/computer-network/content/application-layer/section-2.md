<h1><center>第二节 域名系统</center></h1>

域名系统 DNS 是 Internet 使用的分布式、层次化命名系统。它最基本的作用是把便于人使用的域名转换为 IP 地址，也可以保存别名、邮件服务器和权威域名服务器等信息。

## 1. 层次域名空间

### 1.1 域名树

DNS 把域名空间组织成一棵倒置的树，最顶端是根域，根域以下依次划分顶级域、二级域以及更低层次的子域。

```text
                       根域 .
                 /        |        \
               com       org       cn          顶级域
                |                    |
             example                edu         二级或下级域
                |                    |
               www                example
                                     |
                                    www
```

域名由若干个标签组成，标签之间用点分隔。域名层次从右向左逐级升高。例如：

```text
www.example.edu.cn.
```

- 最右侧的空标签表示根域，书写时末尾的点通常省略。
- `cn` 是国家和地区顶级域。
- `edu.cn` 是 `cn` 域下的教育类域。
- `example.edu.cn` 是继续划分的下级域。
- `www` 可以是主机名，也可以对应继续划分的子域。

末尾明确写出根域点的完整名称称为**完全限定域名 FQDN**。日常书写的 `www.example.edu.cn` 通常仍按完整域名理解，只是省略最后的点。

域名不区分英文字母大小写；同一 IP 地址可以对应多个域名，一个域名也可以对应多个 IP 地址，因此域名与 IP 地址不一定是一一对应关系。

### 1.2 顶级域

常见顶级域可以分为：

- **通用顶级域**：如 `com`、`org`、`net`、`edu` 等。
- **国家和地区顶级域**：如中国的 `cn`、英国的 `uk` 等。
- **基础设施域**：用于 Internet 基础设施管理，例如反向解析使用的 `arpa` 域。

顶级域以下可以继续划分子域。域名层次反映的是命名与管理关系，不直接表示主机之间的物理位置、网络拓扑或路由远近。

### 1.3 域、区与授权

**域**是域名树中某个节点及其所有后代构成的命名空间。为了进行分布式管理，DNS 又把域名空间划分为若干个**区**，每个区由相应的权威域名服务器负责。

域与区不一定完全相同：

- 如果一个域没有把子域委派出去，该区通常包含这个域及其全部子域信息。
- 如果某个子域被委派给其他管理者，父区只保留指向该子域权威服务器的委派信息，不再保存该子域内部的全部记录。

因此，DNS 的分布式管理依靠逐级授权实现，不需要由一台中心服务器保存全世界所有域名记录。

### 1.4 资源记录

DNS 分布式数据库中的基本数据项称为**资源记录 RR**，常用形式可以表示为：

$$
(\text{Name},\text{Value},\text{Type},\text{TTL}).
$$

- `Name`：记录所对应的域名。
- `Value`：记录值，其含义由类型决定。
- `Type`：资源记录类型。
- `TTL`：记录允许被缓存的时间。

常见资源记录包括：

| 类型 | 主要作用 |
| --- | --- |
| A | 把域名映射到 IPv4 地址 |
| AAAA | 把域名映射到 IPv6 地址 |
| NS | 指明某个域或区的权威域名服务器 |
| CNAME | 把别名映射到规范域名 |
| MX | 指明负责接收该域电子邮件的邮件服务器及其优先级 |
| PTR | 用于从 IP 地址到域名的反向解析 |

::: warning 易错点
域名按从右向左的顺序逐级升高；DNS 中的域和区不是必然相同。子域被委派后，父区通常只保存委派信息，而不是该子域中的全部主机记录。
:::

## 2. 域名服务器

DNS 使用分布在全球各处的域名服务器共同保存和查询资源记录。按照在解析过程中的作用，主要包括根域名服务器、顶级域名服务器、权威域名服务器和本地域名服务器。

### 2.1 根域名服务器

根域名服务器位于域名解析层次的最高层，保存各顶级域权威服务器的委派信息。收到无法直接回答的查询时，根服务器通常返回相应顶级域服务器的信息，引导查询方继续查找。

根域名服务器并不保存 Internet 中每台主机的 IP 地址，也不需要逐个查询所有下级服务器。它的主要作用是提供进入相应顶级域的查询入口。

“根服务器”表示逻辑上的根服务，不等于全球只有一台物理服务器。实际系统通过多个服务器实例和分布式部署提高性能与可靠性。

### 2.2 顶级域名服务器

顶级域名服务器负责相应顶级域，例如 `com` 或 `cn`。它通常保存下一级已注册域的委派信息，并向查询方返回这些域的权威域名服务器地址。

例如，查询 `www.example.com` 时，`com` 顶级域服务器一般不会直接保存该主机的最终地址，而是告诉查询方负责 `example.com` 的权威服务器在哪里。

### 2.3 权威域名服务器

权威域名服务器保存某个区的权威数据，能够对该区中的域名记录给出权威回答。一个区通常配置多个权威服务器，以提高可用性。

- **主域名服务器**保存和维护区数据的原始版本。
- **辅助域名服务器**从主服务器或其他权威服务器复制区数据，能够独立回答查询，并在主服务器故障时继续提供服务。

主、辅助服务器的区别主要在于区数据的来源，不表示辅助服务器返回的回答不具有权威性。

### 2.4 本地域名服务器

本地域名服务器也称本地 DNS 服务器或递归解析器，通常由网络服务提供商、学校、单位或公共 DNS 服务提供。主机可以通过 DHCP 或手工配置获得其地址。

本地域名服务器的主要功能是：

1. 接收本网络中主机提出的域名查询。
2. 检查自身缓存，命中时直接返回结果。
3. 缓存未命中时，代表主机向其他 DNS 服务器继续查询。
4. 把查询结果返回主机，并按照 TTL 缓存记录。

本地域名服务器对用户非常重要，但它通常不属于根域、顶级域和各权威域构成的授权层次。它扮演的是查询代理和缓存服务器角色。

### 2.5 各类服务器的关系

| 服务器 | 主要保存或提供的信息 | 典型作用 |
| --- | --- | --- |
| 根域名服务器 | 顶级域的委派信息 | 指向相应顶级域服务器 |
| 顶级域名服务器 | 下一级注册域的委派信息 | 指向相应权威服务器 |
| 权威域名服务器 | 所负责区的权威资源记录 | 返回最终记录或权威否定回答 |
| 本地域名服务器 | 查询缓存及解析状态 | 代表客户查询并缓存结果 |

::: warning 易错点
根域名服务器通常只提供顶级域的转介，不保存所有主机地址；本地域名服务器负责递归解析和缓存，但通常不是全球授权层次中的一级域名服务器。
:::

## 3. 域名解析过程

域名解析是根据域名查找相应资源记录的过程。主机中的 DNS 客户程序通常称为解析器；它先检查本地已有信息，再把查询交给配置的本地域名服务器。

### 3.1 递归查询与迭代查询

**递归查询**请求被查询服务器代替查询方继续完成域名解析。当服务器接受并提供递归服务时，应返回最终查询结果或明确的失败结果，而不是只返回下一台服务器的转介信息。DNS 服务器也可以不提供或拒绝递归服务。

```text
查询方 ──查询──> 被查询服务器 ──继续查询其他服务器
查询方 <─最终结果─ 被查询服务器 <─获得结果
```

**迭代查询**允许被查询服务器返回当前知道的最佳信息。如果它没有最终答案，就返回下一步应联系的服务器，查询方再自行发送新的查询。

```text
查询方 ──查询──> 服务器 A
查询方 <─转介─── 服务器 A
查询方 ──查询──> 服务器 B
查询方 <─答案─── 服务器 B
```

典型情况下：

- 主机向本地域名服务器发送递归查询，希望本地服务器返回最终答案。
- 本地域名服务器向根、顶级域和权威服务器发送迭代查询，根据转介逐级查找。

递归和迭代描述的是服务器如何处理某次查询，不是两种不同的 DNS 协议；具体服务器是否提供递归服务取决于配置和访问策略。

### 3.2 典型解析过程

假设主机要解析 `www.example.com`，本地缓存及各级缓存均未命中，典型过程如下：

1. 主机中的应用把域名交给操作系统解析器。解析器先检查浏览器缓存、操作系统缓存和本地主机配置等已有信息。
2. 若未找到，主机向配置的本地域名服务器发送查询，通常要求递归解析。
3. 本地域名服务器检查缓存；未命中时向根域名服务器查询。
4. 根服务器返回 `com` 顶级域名服务器的转介信息。
5. 本地域名服务器向 `com` 顶级域名服务器查询。
6. 顶级域名服务器返回 `example.com` 权威域名服务器的转介信息。
7. 本地域名服务器向该权威域名服务器查询 `www.example.com`。
8. 权威服务器返回相应的 A、AAAA 或其他资源记录。
9. 本地域名服务器按照 TTL 缓存结果，并把最终答案返回主机。

```text
主机 ───────────────> 本地 DNS
                        |
                        |──> 根服务器 ──> com 顶级域服务器信息
                        |──> com 服务器 ─> example.com 权威服务器信息
                        |──> 权威服务器 ─> www.example.com 的最终记录
主机 <─────────────── 本地 DNS
```

如果查询结果是 CNAME 记录，本地域名服务器还需要继续解析该别名所指向的规范域名，直到获得客户所需的地址记录或其他最终结果。

在上述无缓存的简化场景中，主机与本地服务器、本地服务器与根服务器、顶级域服务器和权威服务器各进行一次查询与响应，共形成四组请求—响应。实际题目若给出缓存、更多域级或别名，应按实际访问的服务器重新计算，不能机械套用固定次数。

### 3.3 DNS 缓存

主机、本地域名服务器以及其他解析服务器都可以缓存查询结果。缓存记录在 TTL 有效期内可以直接使用，具有以下作用：

- 减少域名解析时延。
- 降低根、顶级域和权威服务器的查询负载。
- 减少网络中的 DNS 报文数量。
- 在短时间内提高重复查询的可用性。

缓存并不永久有效。TTL 到期后，解析器需要重新查询；在权威记录刚刚修改但旧缓存尚未过期时，用户可能暂时得到旧结果。

缓存内容不一定只是最终的 A 或 AAAA 记录，也可能包括顶级域或权威服务器的 NS 和地址信息。因此，即使最终地址记录没有命中，本地域名服务器也可能利用已有转介缓存跳过根服务器或部分查询层次。

### 3.4 DNS 使用的传输服务

经典 DNS 使用端口 53，可以使用 UDP 或 TCP：

- 普通查询和较短响应通常使用 UDP，以减少连接建立和首部开销。
- UDP 响应被截断时，查询方可以改用 TCP 重新查询。
- 经典 DNS 区域传送使用 TCP，UDP 不用于区域传送。

因此，“DNS 只使用 UDP”是错误的。DNS 是应用层协议，UDP 或 TCP 是它根据通信需求选择的传输层服务。

::: tip 解析题步骤
先检查题目是否给出本地或服务器缓存，再判断主机到本地 DNS 是递归还是迭代查询，最后沿根、顶级域和权威服务器逐级画出实际访问链路。只有真正发生的查询和响应才计入报文或 RTT 数量。
:::

::: tip 本节主线
DNS 用层次域名空间组织名称，以根、顶级域和权威服务器分布保存数据；主机通常把递归查询交给本地 DNS，本地 DNS 再利用缓存或通过迭代查询获得最终结果。
:::
