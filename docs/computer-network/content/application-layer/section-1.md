<h1><center>第一节 网络应用模型</center></h1>

网络应用模型描述应用进程之间如何组织和协作。408 主要考查客户/服务器模型和 P2P 模型；二者属于应用层的组织方式，不是物理拓扑，也不限定必须使用 TCP 或 UDP。

## 1. 客户/服务器模型

### 1.1 基本概念

客户/服务器模型简称 **C/S 模型**。通信双方分为客户进程和服务器进程：

- **客户进程**主动向服务器发起请求，请求获得数据或服务。
- **服务器进程**通常长期运行，在约定的地址和端口上等待请求，并对客户请求进行处理和响应。

这里的“客户”和“服务器”描述的是应用进程在一次应用通信中的角色，不是对计算机硬件的永久分类。同一台主机可以同时运行客户进程和服务器进程，一个进程在不同应用中也可能承担不同角色。

```text
客户 1 ──请求──>             ──响应──> 客户 1
客户 2 ──请求──>   服务器    ──响应──> 客户 2
客户 3 ──请求──>             ──响应──> 客户 3
```

### 1.2 通信过程

典型的 C/S 通信过程如下：

1. 服务器进程启动并绑定服务器地址和服务端口，等待客户请求。
2. 客户进程获得服务器的地址和端口，主动向服务器发送请求；若使用 TCP，还要先建立传输连接。
3. 服务器接收请求，完成计算、查询或资源访问等处理。
4. 服务器向客户返回响应。应用可以结束通信，也可以保持会话并继续交换数据。

服务器通常使用熟知端口或登记端口提供服务，便于客户找到它；客户端一般使用操作系统临时分配的端口。服务器地址通常较稳定，客户可以间歇上线并使用动态 IP 地址。

“服务器等待、客户主动”是应用进程的角色关系，不表示服务器只能发送响应。建立通信关系后，服务器也可以根据应用协议主动向客户发送数据。

### 1.3 主要特点

1. **角色相对固定**：服务器提供服务，客户请求服务；客户之间通常不直接交换该应用的数据。
2. **资源和管理相对集中**：核心数据、用户状态、权限控制等通常由服务器统一维护。
3. **服务器需要较稳定的可达性**：服务器通常长期在线，并具有客户可以发现的域名或地址。
4. **服务器承担主要服务压力**：客户数量增加时，服务器的计算能力、存储能力和接入带宽需要相应扩展。
5. **便于统一控制**：身份认证、数据备份、软件升级和安全策略较容易集中实施。

现代 C/S 系统中的“服务器”不一定是一台物理主机。大型应用通常使用服务器集群、负载均衡、数据中心或内容分发节点共同提供服务，但从客户进程的角度看，仍属于向服务提供方请求服务的 C/S 模型。

### 1.4 优点与局限

| 方面 | 表现 |
| --- | --- |
| 管理 | 数据和权限集中，便于维护、备份和一致性控制 |
| 服务质量 | 服务资源相对稳定，较容易实施性能监控和容量规划 |
| 安全控制 | 容易在服务器侧统一认证、授权和审计 |
| 系统成本 | 服务器、机房和接入带宽可能需要较高投入 |
| 可扩展性 | 客户增加会提高服务器负载，需要升级或横向扩展服务器 |
| 可靠性 | 单服务器可能形成单点故障，通常需要冗余和容错设计 |

Web、DNS、FTP和电子邮件等应用都大量采用 C/S 交互。一个完整系统还可能组合多个层次的 C/S 关系，例如浏览器访问 Web 服务器，而 Web 服务器又作为客户访问数据库或其他后端服务。

::: warning 易错点
C/S 模型中的服务器可能由集群构成，因此“采用 C/S”不等于整个系统只有一台服务器；服务器集中提供服务，也不表示底层网络采用集中式拓扑。
:::

## 2. P2P 模型

### 2.1 基本概念

P2P 是 **Peer-to-Peer** 的缩写，通常译为对等模型。在 P2P 模型中，通信节点称为对等方，每个对等方既可以请求其他节点的服务，也可以向其他节点提供服务。

```text
        对等方 A
       /       \
  对等方 B ─── 对等方 C
       \       /
        对等方 D
```

纯 P2P 应用不依赖始终在线的中心服务器完成核心数据交换。对等方可以直接通信，其角色会随具体交互而改变：下载资源时相当于客户，向其他节点上传资源时相当于服务器。

### 2.2 主要特点

1. **对等方角色灵活**：同一节点可以同时请求和提供资源，没有永久固定的客户、服务器划分。
2. **资源分布在多个节点上**：计算能力、存储空间、内容和上传带宽由大量对等方共同提供。
3. **节点动态性较强**：对等方可以随时加入或退出，地址也可能发生变化，这种频繁变化称为节点动态性或节点波动。
4. **具有自扩展性**：新对等方在带来服务需求的同时，通常也带来上传带宽、存储或计算能力。
5. **需要资源发现机制**：系统必须帮助节点找到拥有所需资源的其他对等方，并在节点变化时更新相关信息。

自扩展性并不表示 P2P 的容量可以无限增长。若大量节点只下载而不提供资源，或者节点上传带宽很低、频繁离线，系统性能仍会下降。

### 2.3 纯 P2P 与混合 P2P

- **纯 P2P**：资源发现、数据交换和控制功能主要都由对等方协作完成，没有负责核心功能的中心服务器。
- **混合 P2P**：使用中心服务器完成登录认证、节点登记、索引查询或协调，但实际资源数据主要在对等方之间直接传输。

因此，系统中出现中心服务器并不能单独证明它是 C/S 模型。判断时应观察核心资源由谁提供、主要数据在谁之间传输。若中心服务器只负责索引和协调，而资源由对等方直接交换，通常仍属于混合 P2P。

### 2.4 优点与局限

| 方面 | 表现 |
| --- | --- |
| 可扩展性 | 新节点通常同时贡献资源，具有较强自扩展性 |
| 服务成本 | 可以利用对等方资源，减轻中心服务器和中心带宽压力 |
| 容错能力 | 资源存在多个副本时，单个节点退出不一定中断服务 |
| 管理 | 节点分散且动态变化，统一管理、升级和审计较困难 |
| 资源发现 | 需要维护节点和资源位置信息，查找与协调更复杂 |
| 安全与可信 | 恶意节点、虚假资源、隐私泄露和版权控制等问题更突出 |
| 服务质量 | 节点能力、在线时间和网络条件不同，性能可能不稳定 |

P2P 文件分发是典型应用。一个节点下载到部分数据后即可向其他节点上传这些数据，使系统总体上传能力随参与节点增加而增长。

### 2.5 C/S 与 P2P 的比较

| 对比项 | C/S 模型 | P2P 模型 |
| --- | --- | --- |
| 节点角色 | 客户与服务器角色相对固定 | 对等方既请求服务又提供服务 |
| 核心资源 | 主要由服务器提供和管理 | 分布在多个对等方上 |
| 节点通信 | 客户主要与服务器通信 | 对等方之间可以直接通信 |
| 地址与在线状态 | 服务器通常地址稳定、长期在线 | 对等方常间歇上线、地址可能变化 |
| 扩展方式 | 扩容服务器或增加服务器节点 | 新对等方通常同时贡献资源 |
| 管理控制 | 相对集中、容易统一管理 | 分散，管理与安全控制较复杂 |
| 主要风险 | 服务器瓶颈和单点故障 | 节点波动、资源发现和可信问题 |

实际网络应用可以把两种模型结合使用，不能只根据是否存在某台服务器机械判断。分析题应先识别应用进程之间的服务关系，再判断核心数据传输是以服务器为中心，还是主要发生在对等方之间。

::: warning 易错点
P2P 描述的是应用层组织方式，不等于网络物理拓扑中的点对点链路，也不表示每两个节点之间都存在直接物理连接。C/S 和 P2P 都可以运行在相同的 TCP/IP 网络之上，并根据应用需求选择 TCP 或 UDP。
:::

::: tip 本节主线
C/S 模型由相对稳定的服务器集中提供服务，便于管理但可能形成瓶颈；P2P 模型由对等方共同提供和获取资源，具有自扩展性，但资源发现、管理和安全更复杂。
:::
