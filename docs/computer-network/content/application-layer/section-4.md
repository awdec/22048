<h1><center>第四节 电子邮件</center></h1>

电子邮件系统采用存储转发方式传递邮件。发送方和接收方不必同时在线，邮件可以先保存在邮件服务器中，再由接收方读取。

## 1. 电子邮件系统的组成结构

### 1.1 用户代理

用户代理 UA 是用户收发和管理电子邮件的应用程序，主要功能包括：

- 编辑邮件正文并填写发件人、收件人和主题等信息。
- 添加或保存附件。
- 向邮件服务器提交待发送邮件。
- 从邮箱读取、回复、转发和管理邮件。

桌面邮件客户端、手机邮件应用以及浏览器中的 Web 邮件界面都可以承担用户代理的功能。使用 Web 邮件时，浏览器与 Web 邮件服务器之间通常使用 HTTP 或 HTTPS，但邮件服务器之间仍可使用 SMTP 传输邮件。

### 1.2 邮件服务器

邮件服务器是电子邮件系统的核心，主要负责：

1. 接收用户代理提交的待发送邮件。
2. 根据收件人域名找到目标邮件服务器。
3. 使用 SMTP 向其他邮件服务器发送或转发邮件。
4. 接收其他服务器传来的邮件，并保存到相应用户邮箱。
5. 向用户提供邮箱访问服务。

邮件服务器通常维护两类重要存储结构：

- **邮件发送队列**：暂存尚未成功发送的邮件。目标服务器暂时不可达时，发送服务器可以稍后重试。
- **用户邮箱**：保存已经到达某个用户、等待用户读取和管理的邮件。

一台邮件服务器既可以充当 SMTP 客户，也可以充当 SMTP 服务器：向外发送邮件时是 SMTP 客户，接收其他服务器连接时是 SMTP 服务器。

### 1.3 邮件协议

电子邮件的不同阶段使用不同协议：

| 阶段 | 典型协议 | 作用 |
| --- | --- | --- |
| 用户提交邮件 | SMTP | 把邮件从用户代理推送到发送方邮件服务器 |
| 服务器之间传输 | SMTP | 把邮件从发送方服务器推送到接收方服务器 |
| 用户读取邮件 | POP3 | 从接收方邮件服务器下载邮件 |
| Web邮件访问 | HTTP或HTTPS | 浏览器访问Web邮件系统 |

SMTP负责发送和转发，POP3负责用户读取邮箱，二者不能相互替代。

### 1.4 完整邮件传输过程

假设 `alice@example.com` 向 `bob@example.net` 发送邮件，典型过程如下：

1. Alice 使用用户代理编辑邮件，并把邮件提交给 `example.com` 的发送方邮件服务器。
2. 发送方邮件服务器把待发送邮件放入发送队列。
3. 发送方服务器查询 DNS 中 `example.net` 的 MX 记录，获得该域的接收邮件服务器名称，再解析其 IP 地址。
4. 发送方邮件服务器作为 SMTP 客户，与接收方邮件服务器建立 TCP 连接并推送邮件。
5. 接收方邮件服务器把邮件保存到 Bob 的邮箱。
6. Bob 的用户代理使用 POP3 读取邮件；若使用 Web 邮件，则由浏览器通过 HTTP 或 HTTPS 访问 Web 邮件服务器。

```text
发送方用户代理
       |
     SMTP
       v
发送方邮件服务器 ───── SMTP ─────> 接收方邮件服务器
                                      |
                                    POP3
                                      v
                                接收方用户代理
```

若接收方邮件服务器暂时不可达，发送方服务器通常保留邮件并重试，而不是要求发送方用户始终在线。这就是电子邮件的存储转发特征。

::: warning 易错点
发送方邮件服务器通过DNS的MX记录寻找接收域的邮件服务器；收件人离线不会阻止服务器接收邮件，邮件可以先保存在收件人的服务器邮箱中。
:::

## 2. 电子邮件格式与 MIME

### 2.1 邮件信封与邮件内容

一封邮件在传输时可以区分为**SMTP信封**和**邮件内容**：

- SMTP信封包含实际投递使用的发件地址和收件地址，由SMTP命令传递。
- 邮件内容由邮件首部和邮件正文组成，是用户最终阅读和保存的消息。

SMTP信封中的投递地址不一定与邮件首部中的`From`、`To`完全相同。例如，邮件转发、邮件列表和密送都可能使信封收件人与首部显示地址不同。

### 2.2 邮件首部与正文

电子邮件内容的基本结构是：

```text
首部字段 1: 字段值
首部字段 2: 字段值
...

邮件正文
```

首部和正文之间必须有一个空行。常见首部字段包括：

| 字段 | 作用 |
| --- | --- |
| `From` | 表示邮件内容中显示的发件人 |
| `To` | 表示主要收件人 |
| `Cc` | 表示抄送收件人 |
| `Subject` | 邮件主题 |
| `Date` | 邮件创建或发送日期 |
| `Message-ID` | 标识一封邮件消息 |

邮件首部属于邮件内容格式，不等于SMTP命令。SMTP的`MAIL FROM`、`RCPT TO`用于实际投递，首部中的`From`、`To`主要供用户代理显示和处理。

### 2.3 MIME的作用

传统Internet邮件格式主要适合传输ASCII文本，难以直接表示中文等非ASCII文本、图片、音频和二进制附件。多用途Internet邮件扩展MIME在原有邮件格式上增加内容描述和编码规则，使电子邮件能够携带多种类型的数据。

MIME扩展的是**邮件内容的表示格式**，不是新的邮件传输协议。经过MIME组织和编码后的邮件仍可通过SMTP传输，并由POP3等协议读取。

### 2.4 MIME首部字段

常见MIME相关字段包括：

| 字段 | 作用 |
| --- | --- |
| `MIME-Version` | 表明邮件使用的MIME版本，通常为`1.0` |
| `Content-Type` | 指明内容的媒体类型、子类型及字符集等参数 |
| `Content-Transfer-Encoding` | 指明内容为了适应邮件传输而采用的编码方式 |
| `Content-Disposition` | 指明内容以内联方式显示还是作为附件处理，并可给出文件名 |

常见`Content-Type`示例：

- `text/plain`：纯文本。
- `text/html`：HTML格式文本。
- `image/jpeg`：JPEG图像。
- `application/pdf`：PDF文件。
- `multipart/mixed`：正文和附件等多个不同部分的组合。
- `multipart/alternative`：同一内容的多种可选表示，例如纯文本和HTML版本。

### 2.5 内容传输编码与多部分邮件

MIME可以使用Base64或Quoted-Printable等方式，把原本不适合传统邮件传输的数据转换为可安全传输的文本形式：

- **Base64**常用于二进制附件。
- **Quoted-Printable**适合大部分字符属于ASCII、仅少数字符需要编码的文本。

这些编码是数据表示转换，不是加密，也不负责保证机密性。

多部分邮件使用边界字符串把各部分分隔开，每一部分都可以具有自己的`Content-Type`和编码方式。例如，一封邮件可以同时包含纯文本正文、HTML正文和多个附件。

::: warning 易错点
MIME不负责把邮件从一台服务器送到另一台服务器；它只规定邮件内容如何描述和编码。Base64是编码而不是加密，邮件首部地址也不一定等于SMTP信封中的实际投递地址。
:::

## 3. SMTP 和 POP3

### 3.1 SMTP的特点

简单邮件传输协议SMTP用于发送和转发邮件，具有以下特点：

- 采用客户/服务器模型并使用TCP。
- 属于推送协议，由SMTP客户主动把邮件推送给SMTP服务器。
- 采用命令—响应方式交互，服务器使用状态码和文本说明返回处理结果。
- 可以在一条TCP连接上连续传送多封邮件。
- 经典408模型中，SMTP服务器使用TCP端口25。

发送方用户代理向邮件服务器提交邮件，以及邮件服务器之间转发邮件，都可以使用SMTP。SMTP本身不用于让收件人从邮箱下载邮件。

### 3.2 SMTP工作过程

SMTP通信通常包括连接建立、邮件传送和连接释放三个阶段。一次简化交互如下：

```text
客户端：EHLO client.example
服务器：250 ...
客户端：MAIL FROM:<alice@example.com>
服务器：250 ...
客户端：RCPT TO:<bob@example.net>
服务器：250 ...
客户端：DATA
服务器：354 ...
客户端：邮件首部、空行和邮件正文
客户端：<CRLF>.<CRLF>
服务器：250 ...
客户端：QUIT
服务器：221 ...
```

- `EHLO`或`HELO`用于客户向服务器表明身份并开始会话。
- `MAIL FROM`给出SMTP信封发件地址。
- `RCPT TO`给出一个信封收件地址；多个收件人可以使用多条该命令。
- `DATA`表示随后发送邮件内容。
- 单独一行的点，即`<CRLF>.<CRLF>`，表示邮件数据结束。
- `QUIT`请求结束SMTP会话。

SMTP传送失败时，发送方邮件服务器可以保留邮件并在稍后重试；永久失败时可以生成退信。

### 3.3 SMTP与MIME的关系

传统SMTP主要面向ASCII文本。MIME先在邮件内容中加入类型和编码信息，把非ASCII文本或二进制附件转换为适合邮件传输的形式；SMTP再把整个邮件内容传送给下一台服务器。

```text
原始正文和附件 ──MIME组织与编码──> 邮件内容 ──SMTP──> 接收服务器
```

因此，MIME解决“邮件内容如何表示”，SMTP解决“邮件如何发送和转发”。

### 3.4 POP3的特点

邮局协议第3版POP3用于用户代理从邮件服务器读取邮件，具有以下特点：

- 采用客户/服务器模型并使用TCP。
- 属于拉取协议，由用户代理主动连接邮件服务器并请求邮件。
- 经典端口为TCP 110。
- 协议简单，主要把邮件下载到客户端，可以选择在服务器保留或删除副本。
- 不负责发送方提交邮件，也不负责邮件服务器之间转发邮件。

### 3.5 POP3工作状态

POP3会话通常经历三个状态：

1. **授权状态**：客户连接服务器并进行用户认证，例如使用`USER`、`PASS`命令。
2. **事务处理状态**：客户查看、下载或标记删除邮件，常见命令包括`STAT`、`LIST`、`RETR`和`DELE`。
3. **更新状态**：客户发送`QUIT`结束会话，服务器执行已确认的删除等更新操作。

`DELE`通常只是把邮件标记为待删除；正常进入更新状态后，服务器才真正执行删除。因此，POP3并不是收到`DELE`命令时立即无条件删除邮件。

POP3可以采用“下载并删除”或“下载并保留服务器副本”等使用方式。它适合把邮件下载到本地管理，但对服务器端多文件夹管理和多设备同步的支持相对有限。

### 3.6 SMTP与POP3的比较

| 对比项 | SMTP | POP3 |
| --- | --- | --- |
| 主要作用 | 提交、发送和服务器间转发邮件 | 用户从服务器读取邮件 |
| 数据方向 | 客户向服务器推送 | 客户从服务器拉取 |
| 传输层协议 | TCP | TCP |
| 经典服务器端口 | 25 | 110 |
| 典型通信双方 | 用户代理到发送服务器、邮件服务器到邮件服务器 | 接收方用户代理到接收邮件服务器 |
| 是否负责附件格式 | 否，附件由MIME组织和编码 | 否，只读取已经存储的邮件内容 |

::: info 端口说明
408题目通常按照SMTP端口25、POP3端口110作答。实际邮件系统还可能使用专门的邮件提交端口或加密端口，但这些不影响两种协议在考纲中的基本作用。
:::

::: tip 本节主线
用户代理负责编辑和读取邮件，邮件服务器负责存储转发；MIME扩展邮件内容格式，SMTP把邮件推送到服务器或下一台邮件服务器，POP3把邮箱中的邮件拉取到接收方用户代理。
:::
