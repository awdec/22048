<h1><center>第五节 万维网</center></h1>

万维网 WWW 是运行在 Internet 之上的分布式超媒体信息系统。它使用统一的资源标识方式组织网页和其他对象，浏览器与 Web 服务器通过 HTTP 请求和传送这些资源。

## 1. 万维网的概念与组成结构

### 1.1 万维网的基本概念

万维网把分布在不同服务器上的文本、图片、音频、视频和程序等资源组织成相互关联的信息空间。

- **超文本**是在文本中包含指向其他资源链接的文档。
- **超媒体**把链接机制扩展到图片、音频、视频等多种媒体。
- **超链接**使用户可以从当前资源跳转到另一资源。

WWW 是 Internet 上的一种应用，不等同于 Internet 本身。Internet 提供网络互连和数据传输基础，WWW 则利用 DNS、TCP或其他传输机制以及 HTTP 提供Web资源访问服务。

### 1.2 万维网的组成

万维网主要由 Web 客户程序、Web 服务器、Web 资源、URL、HTTP 和 HTML 等部分组成：

| 组成部分 | 主要作用 |
| --- | --- |
| Web客户程序 | 通常是浏览器，解释URL、发送HTTP请求、接收资源并呈现页面 |
| Web服务器 | 监听客户请求，查找或生成资源并返回HTTP响应 |
| Web资源 | HTML文档、样式表、脚本、图片、音视频或动态生成的数据等 |
| URL | 标识访问资源所使用的方案、服务器和资源路径 |
| HTTP | 规定客户请求资源和服务器返回响应的报文与交互规则 |
| HTML | 描述网页内容、结构和超链接，不负责网络传输 |

WWW采用客户/服务器模型。浏览器通常主动发起请求，Web服务器等待并处理请求；大型网站虽然可能使用服务器集群、负载均衡和内容分发节点，应用交互仍可以表现为Web客户向服务端请求资源。

### 1.3 网页与对象

一个网页通常由一个基本HTML文档和若干被引用对象组成，例如CSS文件、JavaScript文件和图片。每个对象都可以具有独立URL。

浏览器首先获得基本HTML文档，再解析其中的引用并继续请求所需对象。因此，“访问一个网页”不一定只产生一次HTTP请求。

```text
基本HTML文档
 ├── 样式表 style.css
 ├── 脚本 app.js
 ├── 图片 logo.png
 └── 图片 banner.jpg
```

网页是面向用户呈现的整体，对象是通过HTTP单独请求和传输的资源，二者不能机械地视为同一概念。

### 1.4 URL

统一资源定位符URL用于说明访问资源的方式和位置，常见结构为：

```text
scheme://host:port/path?query#fragment
```

例如：

```text
https://www.example.com:443/search?q=network#result
```

| 部分 | 示例 | 作用 |
| --- | --- | --- |
| 方案scheme | `https` | 指明访问资源所使用的协议或方式 |
| 主机host | `www.example.com` | 指明服务器，域名通常需要通过DNS解析为IP地址 |
| 端口port | `443` | 指明服务器进程；使用默认端口时可以省略 |
| 路径path | `/search` | 标识服务器上的资源或处理入口 |
| 查询query | `q=network` | 向服务器传递查询参数 |
| 片段fragment | `result` | 标识资源内部位置，通常由浏览器处理，不随HTTP请求发送给服务器 |

HTTP默认端口为80，HTTPS默认端口为443。URL标识的是资源，不要求该资源一定对应服务器文件系统中的一个静态文件；服务器也可以根据请求动态生成响应内容。

### 1.5 Web访问过程

浏览器首次访问一个HTTP URL时，典型过程如下：

1. 浏览器解析URL，得到方案、服务器名称、端口和资源路径。
2. 检查浏览器缓存、操作系统缓存或代理缓存，判断能否直接使用已有资源。
3. 若需要访问服务器，通过DNS把服务器域名解析为IP地址。
4. 按所使用的HTTP版本建立相应传输关系；408经典模型通常分析基于TCP的HTTP/1.0或HTTP/1.1。
5. 浏览器发送HTTP请求。
6. Web服务器处理请求并返回HTTP响应。
7. 浏览器解析收到的HTML文档，继续请求其中引用的其他对象。
8. 浏览器综合HTML、样式表、脚本和媒体对象呈现页面。

```text
输入URL → 查询DNS → 建立连接 → 发送HTTP请求
                              ↓
呈现页面 ← 获取嵌入对象 ← 解析HTML ← 接收HTTP响应
```

若使用HTTPS，在经典TCP模型中还要在建立TCP连接后进行TLS安全协商，再传输HTTP报文。DNS、连接建立、请求响应和对象传输会共同构成页面访问时延。

::: warning 易错点
WWW不是Internet的同义词，HTML也不是传输协议。URL负责标识资源，HTTP负责请求和传输资源，HTML主要负责描述网页内容与结构。
:::

## 2. 超文本传输协议

超文本传输协议HTTP是Web客户与Web服务器之间交换请求和响应的应用层协议。408经典模型重点分析HTTP/1.0和HTTP/1.1，它们通常使用TCP提供可靠传输。

### 2.1 HTTP的主要特点

1. **客户/服务器方式**：客户发送请求，服务器返回响应。
2. **请求—响应协议**：一次应用交互由HTTP请求和相应的HTTP响应组成。
3. **无状态**：HTTP协议本身不要求服务器自动记住此前请求的应用会话状态。
4. **报文格式明确**：请求报文包含方法、目标和首部，响应报文包含状态码、首部和响应内容。
5. **可传输多种对象**：对象类型由`Content-Type`等首部说明，不仅限于HTML文本。
6. **支持持续连接和缓存**：可以复用传输连接，并利用缓存减少重复传输。

HTTP无状态不表示服务器不能实现登录会话。应用可以使用Cookie、会话标识或令牌把多次请求关联起来；这些状态机制建立在HTTP报文之上。

HTTP无状态也不表示每次请求都必须建立新TCP连接。是否保存应用会话状态与是否复用传输连接是两个不同问题。

### 2.2 HTTP请求报文

HTTP/1.x请求报文通常由请求行、若干首部行、空行和可选消息体组成：

```text
GET /index.html HTTP/1.1
Host: www.example.com
User-Agent: ExampleBrowser
Accept: text/html

```

请求行包含：

```text
方法 请求目标 HTTP版本
```

常见请求方法包括：

| 方法 | 主要作用 |
| --- | --- |
| `GET` | 获取指定资源，查询参数常写在URL中 |
| `HEAD` | 获取与 `GET` 响应相对应的元数据，不返回响应内容；响应首部通常与 `GET` 相同，但允许省略仅在生成响应内容时才能确定的字段 |
| `POST` | 向服务器提交数据，数据通常放在请求消息体中 |
| `PUT` | 在服务器允许时创建或替换指定资源 |
| `DELETE` | 在服务器允许时删除指定资源 |

请求消息体是可选的。`GET`通常不使用消息体，而`POST`经常携带表单或其他提交数据；请求方法本身并不能代替服务器的权限检查。

### 2.3 HTTP响应报文

HTTP/1.x响应报文通常由状态行、若干首部行、空行和可选消息体组成：

```text
HTTP/1.1 200 OK
Content-Type: text/html
Content-Length: 1250

...响应内容...
```

状态行包含：

```text
HTTP版本 状态码 原因短语
```

状态码的第一位表示响应类别：

| 类别 | 含义 | 常见示例 |
| --- | --- | --- |
| `1xx` | 提示信息 | `100 Continue` |
| `2xx` | 请求成功 | `200 OK` |
| `3xx` | 重定向或缓存相关处理 | `301 Moved Permanently`、`304 Not Modified` |
| `4xx` | 客户端请求错误 | `400 Bad Request`、`403 Forbidden`、`404 Not Found` |
| `5xx` | 服务器处理错误 | `500 Internal Server Error`、`503 Service Unavailable` |

状态码说明的是本次请求的处理结果，不能只看是否收到响应来判断资源是否获取成功。例如，`404`也是一个格式正常的HTTP响应，但表示目标资源未找到。

### 2.4 非持续连接与持续连接

**非持续HTTP**通常为每个Web对象分别建立一条TCP连接。典型HTTP/1.0默认采用非持续连接：

```text
建立TCP连接 → 请求对象1 → 返回对象1 → 关闭连接
建立TCP连接 → 请求对象2 → 返回对象2 → 关闭连接
```

**持续HTTP**允许在同一条TCP连接上连续传输多个HTTP请求和响应。HTTP/1.1默认使用持续连接，可以减少重复握手、连接管理和TCP慢开始带来的开销。

持续连接又可以区分：

- **非流水线方式**：收到前一个响应后再发送下一个请求。
- **流水线方式**：不等待前一个响应就连续发送多个请求，服务器仍按相应规则返回响应。

持续连接只解决连接复用问题，不会让HTTP核心协议自动记住用户身份或购物车状态。

### 2.5 HTTP访问时延

设浏览器与Web服务器之间的往返时间为RTT，忽略DNS查询、对象传输时间、TLS协商和并行连接：

- 建立一条TCP连接约需要1个RTT。
- TCP连接建立后，从发送HTTP请求到收到响应首字节约需要1个RTT。
- 因此，使用非持续HTTP获得一个对象通常至少约需：

$$
2\mathrm{RTT}+\text{对象传输时间}.
$$

如果串行获取$N$个对象，并且每个对象都单独建立连接，在上述简化条件下约需$2N\mathrm{RTT}$，再加所有对象的传输时间。若采用并行连接、持续连接或流水线，请求时间应按题目给出的方式重新分析。

Web时延题通常还要加上DNS解析时间。若域名解析依次访问多个DNS服务器，应把实际经历的DNS往返时间与HTTP阶段时延相加。

### 2.6 Cookie

Cookie使Web应用能够把多次无状态HTTP请求关联到同一用户或会话。典型机制包括四个部分：

1. 服务器在HTTP响应中发送`Set-Cookie`首部。
2. 浏览器保存Cookie数据。
3. 浏览器在后续匹配的请求中发送`Cookie`首部。
4. 服务器可以根据Cookie值查询服务器端会话数据。

Cookie可用于保持登录状态、购物车、个性化设置和访问统计。Cookie本身只是客户保存并按规则返回的一段数据，不等于服务器的全部会话状态，也不天然保证身份安全。

::: warning 易错点
Cookie用于在应用层关联多次请求，持续连接用于复用底层传输连接。关闭TCP连接后Cookie仍可以保留；使用持续连接也不表示HTTP自动变成有状态协议。
:::

### 2.7 Web缓存与条件请求

Web缓存保存已经获得的响应对象。缓存可以位于浏览器、代理服务器或其他中间节点：

1. 客户先向缓存请求对象。
2. 若缓存中有新鲜副本，缓存直接返回对象。
3. 若没有副本，缓存向源服务器请求对象，返回给客户并保存副本。
4. 若副本可能过期，缓存可以发送条件请求验证资源是否改变。

常见条件请求首部包括`If-Modified-Since`或`If-None-Match`：

- 资源没有改变时，服务器可返回`304 Not Modified`，通常不重新发送完整对象。
- 资源已经改变时，服务器返回新的对象，例如使用`200 OK`及消息体。

Web缓存可以缩短响应时间、减少出口链路流量并降低源服务器负载，但缓存策略不当也可能使用户短期内看到旧内容。

### 2.8 HTTPS与HTTP版本（拓展了解）

HTTPS是在HTTP与传输层之间使用TLS保护通信，通常使用端口443，可以提供传输加密、完整性保护和服务器身份认证。HTTPS仍然使用HTTP的请求—响应语义，不是与HTTP无关的另一套网页内容格式。

不同HTTP版本的传输方式有所不同：

- HTTP/1.0默认采用非持续TCP连接。
- HTTP/1.1默认采用持续TCP连接。
- HTTP/2仍通常运行在一条TCP连接上，并使用二进制分帧和多路复用。
- HTTP/3运行在基于UDP的QUIC之上，不再直接使用TCP。

408经典计算题通常以HTTP/1.0或HTTP/1.1为背景。题目未说明HTTP/2、HTTP/3或TLS时，不应自行加入相应握手和传输规则。

::: tip 本节主线
浏览器使用URL定位资源，通过DNS找到Web服务器，再使用HTTP请求基本HTML文档和其中引用的对象。HTTP采用请求—响应方式且本身无状态，可以通过持续连接减少连接开销、通过Cookie关联会话、通过缓存减少重复传输。
:::
