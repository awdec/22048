<h1><center>第五节 万维网</center></h1>

## 1. 万维网的组成

万维网 WWW 是由相互链接的超文本文档和资源组成的分布式信息系统。浏览器作为 Web 客户端，通过 URL 定位资源，使用 HTTP 与 Web 服务器交互。

核心概念包括：

- URL：标识资源位置。
- HTTP：规定请求和响应方式。
- HTML：描述网页内容和链接结构。

## 2. URL

统一资源定位符通常采用以下形式：

```text
scheme://host:port/path?query#fragment
```

其中方案指定访问协议，主机名通过 DNS 解析为 IP 地址，端口标识服务器进程，路径和查询参数标识具体资源。

HTTP 默认端口为 80，HTTPS 默认端口为 443。

## 3. HTTP 特点

HTTP 是无状态的请求—响应协议。服务器默认不自动保存客户端的应用会话状态，但可以使用 Cookie、会话标识和令牌建立状态关联。

常见请求方法包括 GET、HEAD、POST、PUT 和 DELETE。常见状态码类别：

- 2xx：请求成功。
- 3xx：重定向或缓存相关响应。
- 4xx：客户端错误。
- 5xx：服务器错误。

## 4. HTTP 报文

HTTP 请求报文由请求行、首部行、空行和可选实体主体组成；响应报文由状态行、首部行、空行和可选实体主体组成。

请求行包含方法、资源路径和 HTTP 版本；状态行包含 HTTP 版本、状态码和原因短语。

## 5. 非持续连接与持续连接

- **非持续 HTTP**：每个对象通常单独建立 TCP 连接。
- **持续 HTTP**：多个对象复用同一连接，减少握手、慢开始和连接管理开销。

忽略 DNS、对象传输时间和并行连接时，非持续 HTTP 获取一个对象通常至少约需 $2RTT$：一个 RTT 建立 TCP 连接，一个 RTT 发送请求并收到响应首字节。

HTTP/1.1 默认使用持续连接。持续连接与 HTTP 是否保存应用状态是两个不同维度。

## 6. Cookie

Cookie 机制通常包含：

- 服务器响应中的 `Set-Cookie` 首部。
- 客户端保存的 Cookie 数据。
- 后续请求中的 `Cookie` 首部。
- 服务器端可能维护的关联数据库。

Cookie 可以用于会话登录、个性化和状态跟踪，也需要注意隐私和安全属性。

## 7. Web 缓存

代理缓存可以就近返回对象，降低响应时延和出口链路负载。缓存可以使用 `If-Modified-Since` 或实体标签发起条件请求。

资源未修改时，服务器可返回 `304 Not Modified`，客户端继续使用本地缓存副本，无须重新传输完整对象。

## 8. Web 访问过程

浏览器首次访问一个 URL 时，典型过程包括：

1. 解析 URL 并查询 DNS。
2. 与服务器建立传输连接。
3. 发送 HTTP 请求。
4. 接收 HTTP 响应和资源。
5. 解析页面并继续请求嵌入对象。

::: warning 易错点
HTTP 无状态表示协议本身不自动保存应用会话，不表示 TCP 连接必须每次断开；持续连接和 Cookie 解决的是不同问题。
:::
