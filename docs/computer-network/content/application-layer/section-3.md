<h1><center>第三节 文件传输协议</center></h1>

文件传输协议 FTP 用于在不同主机之间可靠地传输文件。它采用客户/服务器模型，在一个会话中把命令与响应和实际传输的数据分开，分别使用独立的 TCP 连接。

## 1. FTP 的工作原理

### 1.1 功能与特点

FTP 为远程文件访问提供以下基本功能：

- 从服务器下载文件或向服务器上传文件。
- 浏览远程目录和获得文件列表。
- 改变工作目录，并根据服务器权限创建、删除或重命名文件。
- 在不同类型主机之间传送文本文件或二进制文件。

FTP 具有以下特点：

1. **采用客户/服务器模型**：FTP 客户主动访问 FTP 服务器，由服务器完成身份验证并提供文件服务。
2. **使用 TCP**：控制信息和文件数据都要求可靠、按序传输，因此FTP不使用UDP承载这两类连接。
3. **控制与数据分离**：控制命令和服务器响应通过控制连接传输，文件内容和目录列表通过数据连接传输。
4. **具有会话状态**：服务器通常需要记录用户身份、当前工作目录和传输参数等信息。
5. **支持连续操作**：一次登录后，客户可以在同一控制会话中依次执行多次目录操作和文件传输。

FTP 只能在双方权限允许的范围内操作远程文件。它提供的是应用层文件传输与远程文件操作规则，不负责底层路由或链路传输。

### 1.2 客户端与服务器端的进程

FTP 两端都可以从逻辑上分为协议解释和数据传输两部分：

- **协议解释进程**负责控制连接，解释命令并生成响应。
- **数据传输进程**负责建立数据连接并传送文件内容或目录列表。

```text
FTP 客户端                                      FTP 服务器

客户协议解释进程 ===== 控制连接 ===== 服务器协议解释进程
客户数据传输进程 ===== 数据连接 ===== 服务器数据传输进程
```

这种结构使控制连接可以在整个会话中持续存在，而数据传输进程根据具体任务建立和关闭数据连接。

### 1.3 典型工作过程

一次典型 FTP 会话按以下步骤进行：

1. FTP 服务器启动，在 TCP 端口 21 等待客户的控制连接请求。
2. 客户端主动与服务器端口 21 建立 TCP 控制连接。
3. 客户通过控制连接发送用户名、口令等登录信息，服务器返回相应状态。
4. 客户发送目录操作或文件传输命令。
5. 双方根据主动模式或被动模式建立数据连接。
6. 通过数据连接传输文件内容或目录列表，完成后通常关闭本次数据连接。
7. 控制连接继续保持，客户可以发起下一次操作。
8. 客户发送退出命令，会话结束后关闭控制连接。

```text
建立控制连接 → 登录 → 发送命令 → 建立数据连接
                             ↓
关闭控制连接 ← 退出 ← 继续操作 ← 完成一次数据传输
```

### 1.4 命令与响应

FTP 客户通过控制连接发送文本命令，服务器返回带状态码的响应。常见命令包括：

| 命令 | 基本作用 |
| --- | --- |
| `USER`、`PASS` | 提交用户名和口令 |
| `CWD` | 改变服务器端当前工作目录 |
| `LIST` | 请求目录列表，列表内容通过数据连接传输 |
| `RETR` | 从服务器下载指定文件 |
| `STOR` | 向服务器上传并保存文件 |
| `QUIT` | 结束 FTP 会话 |

命令和状态响应走控制连接，但 `LIST` 得到的目录列表以及 `RETR`、`STOR` 传输的文件内容走数据连接。不能因为目录列表是控制操作的结果，就误认为它也通过控制连接传输。

::: warning 易错点
FTP 的命令和响应与文件数据使用不同连接。控制连接负责组织会话，数据连接才承载文件内容和目录列表；两条连接都使用 TCP。
:::

## 2. 控制连接与数据连接

### 2.1 两条连接的区别

FTP 的控制连接和数据连接在用途、持续时间和端口使用上不同：

| 对比项 | 控制连接 | 数据连接 |
| --- | --- | --- |
| 主要内容 | 登录信息、FTP命令和服务器响应 | 文件内容或目录列表 |
| 传输层协议 | TCP | TCP |
| 建立时间 | FTP会话开始时 | 需要传输文件或列表时 |
| 持续时间 | 通常贯穿整个FTP会话 | 通常每次传输任务单独建立，完成后关闭 |
| 发起方 | 始终由客户端主动建立 | 主动模式由服务器发起，被动模式由客户端发起 |
| 服务器端口 | 固定使用TCP端口21 | 主动模式经典模型通常使用端口20；被动模式使用服务器临时端口 |

FTP 把控制连接和数据连接分离，称为**带外传送控制信息**：控制信息不混在文件数据流中，而是通过另一条独立连接传输。

### 2.2 控制连接

客户端使用一个临时端口，主动连接服务器 TCP 端口 21。控制连接建立后通常一直保持到用户退出 FTP 会话。

控制连接用于：

- 用户登录和身份验证。
- 设置传输参数。
- 改变目录和执行文件操作命令。
- 协商主动模式或被动模式所需的数据连接参数。
- 返回操作是否成功以及其他状态信息。

即使一次数据传输已经结束，控制连接仍可继续使用，不必重新登录。后续文件传输通常重新建立新的数据连接。

### 2.3 主动模式

主动模式的核心是：**服务器主动建立数据连接**。

1. 客户端首先主动建立到服务器端口 21 的控制连接。
2. 客户端选择一个本地数据端口，通过控制连接把该端口信息告诉服务器。
3. 在 408 使用的经典模型中，服务器从 TCP 端口 20 主动连接客户端指定的数据端口。
4. 双方通过该连接传输文件或目录列表，完成后关闭数据连接。

```text
控制连接：客户端临时端口 ─────────────> 服务器端口 21
数据连接：客户端指定端口 <───────────── 服务器端口 20
                                服务器主动发起
```

由于主动模式要求外部服务器反向连接客户端，客户端侧的 NAT 或防火墙可能把该入站连接拦截。

::: warning 易错点
服务器端口 20 是经典主动模式下服务器建立数据连接时通常使用的端口，不是所有 FTP 数据连接都固定使用端口 20。
:::

### 2.4 被动模式

被动模式的核心是：**客户端主动建立数据连接**。

1. 控制连接仍由客户端连接服务器端口 21。
2. 客户端通过控制连接请求进入被动模式。
3. 服务器选择并监听一个临时数据端口，再通过控制连接把该端口信息返回客户端。
4. 客户端使用本地临时端口，主动连接服务器告知的数据端口。
5. 双方通过该连接传输数据，完成后关闭数据连接。

```text
控制连接：客户端临时端口 ─────────────> 服务器端口 21
数据连接：客户端临时端口 ─────────────> 服务器临时端口
                                客户端主动发起
```

被动模式的两条连接都由客户端从内部向外发起，因此通常更容易穿越客户端侧 NAT 和防火墙，也是实际网络中常见的工作方式。

### 2.5 主动模式与被动模式的比较

| 对比项 | 主动模式 | 被动模式 |
| --- | --- | --- |
| 控制连接发起方 | 客户端 | 客户端 |
| 控制连接服务器端口 | 21 | 21 |
| 数据连接发起方 | 服务器 | 客户端 |
| 数据连接服务器端口 | 经典模型通常为20 | 服务器选择的临时端口 |
| 客户端防火墙影响 | 服务器需要反向连接客户端，更容易被拦截 | 两条连接均由客户端发起，通常更容易通过 |

主动和被动描述的只是**数据连接的建立方式**。无论采用哪一种模式，控制连接都由客户端主动连接服务器端口21，两种模式的数据传输都使用TCP。

::: tip 端口判断方法
先判断题目问的是控制连接还是数据连接：控制连接的服务器端固定为21；再判断数据连接模式，主动模式由服务器从经典端口20连接客户端，被动模式由客户端连接服务器临时端口。
:::

::: tip 本节主线
FTP 用长期存在的控制连接传输命令和响应，用按任务建立的数据连接传输文件或目录列表。主动与被动模式的核心区别是数据连接由服务器还是客户端发起。
:::
