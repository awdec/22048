<h1><center>第一节 数据链路层的功能</center></h1>

数据链路层利用物理层提供的比特传输能力，为网络层提供相邻节点之间的数据传输服务。它的基本任务可以概括为：管理链路、封装成帧、实现透明传输、进行流量控制，并根据协议需要完成差错检测与可靠传输。

## 1. 数据链路层所处的地位

数据链路层位于网络层与物理层之间：

- 向上接收网络层交付的数据报，并向网络层提供链路上的数据传输服务。
- 向下使用物理层提供的比特传输服务，把帧转换为比特流送入传输介质。
- 传输单位是**帧**，通常负责一段链路上相邻节点之间的逐跳传输，而不是源主机到目的主机之间的端到端传输。

网络层数据报在不同链路上传输时，需要使用相应的数据链路层协议重新封装。帧通常只在当前链路上有意义；到达路由器后，原帧被解封装，网络层处理其中的数据报，再为下一段链路封装成新的帧。

### 1.1 物理链路与数据链路

- **物理链路**：节点之间实际存在的物理通路，如一段双绞线、光纤或无线信道。
- **数据链路**：在物理链路基础上增加数据链路层协议和控制机制后形成的逻辑数据通道。

::: warning 易错点
“链路”强调物理通路，“数据链路”还包含实现数据传输所需的协议控制。数据链路层处理的是相邻节点之间的帧，传输层处理的才是进程之间的端到端通信。
:::

### 1.2 向网络层提供的服务

根据是否建立连接以及是否使用确认机制，数据链路层可以提供以下三类服务：

| 服务类型 | 是否建立连接 | 是否确认 | 适用情况 |
| --- | --- | --- | --- |
| 无确认的无连接服务 | 否 | 否 | 链路误码率较低，或可靠性由上层保证 |
| 有确认的无连接服务 | 否 | 是 | 链路误码率较高，需要逐帧确认 |
| 有确认的面向连接服务 | 是 | 是 | 需要按序、可靠地传输帧 |

具体协议采用哪种服务取决于链路特点和设计目标，并非所有数据链路层协议都保证可靠交付。

## 2. 链路管理

链路管理是对数据链路的建立、维持和释放进行控制，使通信双方保持一致的链路状态。

- **建立链路**：确认通信双方已经就绪，并协商必要的链路参数。
- **维持链路**：维护链路状态，协调数据与控制信息的交换，监测链路是否正常。
- **释放链路**：通信结束后终止逻辑连接并释放相关状态和资源。
- **异常处理**：链路出现故障或状态失步时进行复位、重建或释放。

建立、维持和释放主要针对面向连接的数据链路。无连接的数据链路不需要在传输每个帧之前建立逻辑连接，但仍可能需要完成接口启用、参数配置和状态监测等管理工作。

## 3. 封装成帧与透明传输

### 3.1 封装成帧

物理层传输的是连续比特流，数据链路层需要把网络层数据报封装成一个个能够独立识别和处理的帧。典型的帧结构可以表示为：

$$
\text{帧}=\text{首部}+\text{数据部分}+\text{尾部}.
$$

- **首部**通常包含地址、帧界定或协议控制等信息。
- **数据部分**通常承载网络层数据报。
- **尾部**常包含用于差错检测的帧校验序列。

封装成帧必须解决**帧定界**问题，即使接收方能够从连续比特流中准确识别每个帧的开始和结束。常见方法包括字符计数法、字节填充法、零比特填充法和违规编码法，具体原理见[第二节“组帧”](./section-2)。

### 3.2 透明传输

透明传输是指无论数据部分出现什么字符或比特组合，数据链路层都能原样传输，不会把数据误认为帧边界或其他控制信息。这里的“透明”表示上层不需要感知链路层为传输数据所做的特殊处理，并不表示数据被隐藏或加密。

当数据中出现与帧定界符相同的内容时，发送方可以插入转义字节或填充比特；接收方在交付网络层之前删除这些附加内容，从而恢复原始数据。

::: warning 易错点
封装成帧解决“如何划分帧”的问题，透明传输解决“数据内容与控制标志冲突”的问题。填充内容由发送端链路层加入，并由接收端链路层删除，不会作为原始数据交付给网络层。
:::

## 4. 流量控制

流量控制协调发送方与接收方的处理速度，防止发送方连续发送过多帧，导致接收方来不及处理或缓冲区溢出。

- **停止—等待机制**：发送方每发送一个帧就等待接收方允许继续发送，控制简单但链路利用率可能较低。
- **滑动窗口机制**：允许发送方在规定的窗口范围内连续发送多个帧，在控制未确认帧数量的同时提高链路利用率。

数据链路层的流量控制通常作用于相邻节点之间，并以帧为控制单位；传输层的流量控制作用于端系统之间，作用范围和控制对象不同。

流量控制也不同于拥塞控制：流量控制主要解决接收方处理能力不足的问题，拥塞控制主要解决网络中通信量超过网络承载能力的问题。停止—等待和滑动窗口的具体工作过程见[第四节“流量控制与可靠传输机制”](./section-4)。

## 5. 差错检测与可靠传输

链路传输中的差错可以分为两类：

- **位错**：帧中的一个或多个比特发生翻转。
- **帧错**：出现帧丢失、重复或失序等情况。

### 5.1 差错检测

发送方在帧中加入检错冗余，接收方根据约定的检错规则判断帧是否可能出错。奇偶校验和循环冗余校验 CRC 是常见的检错方法；海明码等纠错编码还能在一定范围内定位和纠正错误，具体见[第三节“差错控制”](./section-3)。

检错只能说明接收方是否发现错误。未检测到错误不等于帧在理论上绝对无错，检测到错误也不等于数据已经自动恢复。

### 5.2 可靠传输

可靠传输要求接收方最终获得无差错、不丢失、不重复且通常按序的数据。除差错检测外，协议通常还需要综合使用：

- **序号**：区分新帧与重复帧，并判断帧的顺序。
- **确认 ACK 或否认 NAK**：反馈帧的接收结果。
- **超时计时器**：处理数据帧或确认帧丢失的情况。
- **重传**：重新发送出错或超时未确认的帧。

这类“发现问题后请求重传”的机制统称为自动重传请求 ARQ。停止—等待协议、后退 $N$ 帧协议和选择重传协议都是典型的可靠传输协议。

::: warning 易错点
差错检测不等于可靠传输。只使用 CRC 并丢弃错误帧只能降低错误帧被接收的概率；要实现可靠交付，还需要序号、确认、计时器和重传等机制。以太网通常检测并丢弃错误帧，但不在数据链路层负责重传，因此不能笼统地说所有数据链路层协议都提供可靠传输。
:::

::: tip 本节主线
数据链路层先把网络层数据报封装成能够定界且可透明传输的帧，再通过流量控制协调收发速度，并根据协议需求利用检错编码和重传机制提高链路传输的可靠性。
:::
