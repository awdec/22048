<h1><center>第二节 组帧</center></h1>

## 1. 组帧的目的

物理层提供连续的比特流，数据链路层需要把它划分为一个个相互独立的帧。每个帧通常包含首部、数据和尾部，首尾控制信息用于寻址、差错检测和边界识别。

组帧方法既要让接收方准确找到帧边界，又要保证数据部分可以透明地包含任意比特组合。

## 2. 字符计数法

帧首部使用一个计数字段表示帧的字节数，接收方根据长度确定帧结束位置。

该方法实现简单，但计数字段一旦出错，接收方会失去当前帧边界，并可能影响后续多个帧的同步。

## 3. 字节填充法

协议使用特殊标志字节表示帧的开始和结束。当数据中出现标志字节或转义字节时，发送方在其前面插入转义字节；接收方收到后删除转义字节，恢复原始数据。

字节填充适合以字节为单位组织的链路协议。PPP 在异步链路上使用类似方法实现透明传输。

## 4. 比特填充法

比特填充使用特殊比特串 `01111110` 标识帧边界。发送方扫描数据部分，每出现连续 5 个 `1` 就自动插入一个 `0`；接收方发现连续 5 个 `1` 后的 `0` 时将其删除。

这样可以保证数据中不会出现与帧边界相同的比特串，实现面向比特的透明传输。

## 5. 违规编码法

某些物理层编码只使用部分信号组合表示正常数据，数据链路层可以使用未被采用的“违规”信号组合标记帧边界。

该方法不需要在数据中插入额外字符或比特，但依赖物理层编码存在可用的冗余信号。

## 6. 帧同步与透明传输

- **帧同步**：接收方能从连续比特流中识别每个帧的开始和结束。
- **透明传输**：无论数据部分出现何种字符或比特组合，都不会被误认为控制标志。

填充只在发送端链路层增加，接收端链路层会在向上交付前将其删除，因此上层看到的仍是原始数据。

::: warning 易错点
比特填充只检查数据和需要透明传输的字段，不修改真正的帧定界标志；接收方删除的是发送方在连续 5 个 `1` 后插入的 `0`。
:::
