<h1><center>第七节 广域网</center></h1>

广域网通过远距离链路连接不同地区的主机、路由器和局域网。数据链路层在广域网点对点链路上仍然负责封装成帧、透明传输和差错检测，点对点协议 PPP 是 408 要求掌握的典型广域网数据链路层协议。

## 1. 广域网的基本概念

### 1.1 广域网的定义与特点

广域网 WAN 覆盖较大的地理范围，可以跨越城市、地区甚至国家。它通常利用运营商提供的通信线路、点对点链路或交换网络，把分布在不同地点的局域网和端系统连接起来。

广域网通常具有以下特点：

- 覆盖范围较大，传播距离长，传播时延通常高于局域网。
- 通信设施可能由电信运营商建设和维护，用户通过接入链路使用广域网服务。
- 链路类型和底层技术可能不同，需要路由器完成不同网络之间的分组转发。
- 既可以使用专用点对点链路，也可以使用由多个用户共享的分组交换网络。

广域网不是某一种具体协议或拓扑，而是一类按覆盖范围和用途划分的网络。因特网连接大量异构网络，是全球性的互联网，不能简单地把它等同于某一个广域网。

### 1.2 广域网的组成

从传统结构看，广域网可以分为：

- **端系统**：产生和接收数据的主机或局域网。
- **接入设备**：把用户网络连接到广域网的路由器或其他设备。
- **交换节点**：在广域网内部接收并转发分组，典型设备是路由器。
- **通信链路**：连接接入设备和交换节点的有线或无线传输通路。

两个相邻节点之间的点对点链路不由多个站点竞争使用，因此不需要 CSMA/CD、CSMA/CA 或令牌传递等多点介质访问控制。点对点链路仍需要数据链路层协议规定帧格式、透明传输、链路配置和差错检测。

### 1.3 广域网与局域网的区别

| 对比项 | 局域网 | 广域网 |
| --- | --- | --- |
| 覆盖范围 | 房间、楼宇或园区等有限区域 | 城市、地区或更大范围 |
| 建设与管理 | 通常由一个组织自行建设和管理 | 常使用运营商提供的线路和服务 |
| 典型链路 | 以太网、无线局域网 | 点对点链路、运营商分组交换网络 |
| 主要关注 | 局部帧交换、广播域和介质访问 | 远距离传输、异构链路和分组转发 |
| 典型数据链路协议 | IEEE 802.3、IEEE 802.11 | PPP 等点对点链路协议 |

局域网和广域网都可能使用数据链路层协议，二者不是分别对应某一个固定网络层次。局域网可以通过路由器接入广域网，网络层数据报经过不同链路时会被重新封装为相应的数据链路层帧。

::: warning 易错点
广域网强调覆盖范围和远距离互连，不表示它只工作在网络层；广域网中的每一段链路仍然需要物理层和数据链路层协议。点对点链路不需要解决多站点争用问题，但仍需要组帧和差错检测。
:::

## 2. 点对点协议

点对点协议 PPP 是面向字节的广域网数据链路层协议，用于在两个直接相连的节点之间封装和传输网络层数据报。它可以运行在同步或异步的串行链路上，也曾广泛用于拨号接入和专线连接。

### 2.1 PPP 的主要功能

PPP 主要提供：

- 定义点对点链路上的帧格式和透明传输方法。
- 使用 FCS 检测帧中的位错。
- 建立、配置、测试和终止数据链路。
- 协商链路参数和可选的身份认证方式。
- 在同一条链路上封装多种网络层协议，并配置相应的网络层参数。

PPP 设计目标是简单和通用，它不提供序号、确认、重传和流量控制。检测到错误的帧通常直接丢弃，需要可靠传输时由上层协议负责。

### 2.2 PPP 的组成

PPP 由三部分组成：

1. **封装方法**：规定如何把网络层数据报封装到 PPP 帧中，并通过协议字段区分不同的上层协议。
2. **链路控制协议 LCP**：建立、配置、测试和终止 PPP 链路，协商最大接收单元 MRU、认证方式等链路参数。
3. **网络控制协议 NCP**：一组分别服务于不同网络层协议的控制协议，用于配置和启用相应的网络层协议。例如，IP 控制协议 IPCP 用于配置 IPv4 参数。

LCP 处理“链路本身如何工作”，NCP 处理“链路承载的网络层协议如何工作”，两者不能混淆。

### 2.3 PPP 帧格式

PPP 使用与 HDLC 相似的帧结构：

| 字段 | 典型长度 | 典型取值或作用 |
| --- | ---: | --- |
| 标志 Flag | 1 B | 固定为 `0x7E`，标识帧的开始或结束 |
| 地址 Address | 1 B | 默认固定为 `0xFF`，不表示实际站点地址 |
| 控制 Control | 1 B | 默认固定为 `0x03`，表示无编号帧 |
| 协议 Protocol | 通常 2 B | 标识信息字段承载的数据或控制协议 |
| 信息 Information | 通常 0～1500 B | 承载网络层数据报或控制信息 |
| 帧校验序列 FCS | 2 B 或 4 B | 使用 CRC 检测帧中的位错 |
| 标志 Flag | 1 B | 固定为 `0x7E`，标识帧结束 |

PPP 是点对点协议，不需要利用地址字段选择不同接收站。在未协商地址和控制字段压缩时，地址字段固定为 `0xFF`，控制字段固定为 `0x03`。协议字段使 PPP 能够复用 IPv4、IPv6、LCP 和不同 NCP 等多种数据或控制协议。

信息字段的默认最大长度为 1500 B，实际最大接收单元可以通过 LCP 协商。PPP 帧没有单独的长度字段，接收方依靠标志字段识别帧边界。

::: warning 易错点
PPP 帧虽然包含地址字段，但它不用于点对点链路上的寻址；该字段通常固定为 `0xFF`。PPP 的协议字段用于说明信息字段承载的内容，不是以太网中的源或目的 MAC 地址。
:::

### 2.4 PPP 的透明传输

PPP 使用 `0x7E` 作为帧定界标志，因此必须防止两个标志字段之间的帧内容形成与定界标志相同的模式。同步链路和异步链路采用不同的透明传输方法。

#### 2.4.1 异步链路的字节填充

异步链路按字节处理，使用转义字节 `0x7D`：

- 帧内容中出现 `0x7E` 时，转换为 `0x7D 0x5E`。
- 帧内容中出现 `0x7D` 时，转换为 `0x7D 0x5D`。

其基本规则是在原字节前插入 `0x7D`，并把原字节与 `0x20` 进行异或。接收方遇到 `0x7D` 后，对下一字节执行逆变换，恢复原始数据。

#### 2.4.2 同步链路的零比特填充

同步链路按比特处理。发送方在两个标志字段之间扫描帧内容，每出现连续 5 个 `1` 就插入一个 `0`；接收方删除连续 5 个 `1` 后的填充 `0`，从而避免数据中出现与 `01111110` 相同的定界模式。

字节填充和零比特填充的详细原理见[第二节“组帧”](./section-2)。

### 2.5 PPP 链路的工作阶段

PPP 链路通常经历以下阶段：

1. **链路静止**：物理链路尚未建立或不可用。
2. **链路建立**：物理链路可用后，通信双方使用 LCP 分组协商链路参数。
3. **认证**：若 LCP 协商要求认证，则执行 PAP、CHAP 等认证过程；此阶段可以省略。
4. **网络层协议配置**：使用相应的 NCP 配置并启用网络层协议。
5. **数据通信**：链路进入开放状态，传输网络层数据报。
6. **链路终止**：使用 LCP 终止链路，随后释放物理连接。

只有 LCP 完成链路配置，并且所需的 NCP 已成功打开后，对应的网络层协议才能正常传输数据。

### 2.6 PPP 的差错处理

PPP 使用 FCS 进行差错检测：

- FCS 校验正确的帧可以继续处理并向上交付。
- FCS 校验失败、帧格式错误或长度非法的帧通常直接丢弃。
- PPP 不为数据帧编号，也不返回数据帧 ACK，不负责超时重传。

因此，PPP 提供的是有检错能力但不保证可靠交付的数据链路服务。FCS 只能降低错误帧被接收的概率，不能处理帧丢失、重复和失序。

::: warning 易错点
PPP 会建立和配置逻辑链路，但“建立链路”不等于“提供可靠传输”。PPP 具有组帧、透明传输和检错功能，却没有实现可靠传输所需的序号、确认、计时器和重传机制。
:::

::: tip 判断方法
看到默认地址 `0xFF`、默认控制字段 `0x03`、标志 `0x7E`、LCP 和 NCP，应判断为 PPP；看到“能检错但不重传”，也符合 PPP 的特点。
:::
