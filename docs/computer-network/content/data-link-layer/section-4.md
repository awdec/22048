<h1><center>第四节 流量控制与可靠传输机制</center></h1>

## 1. 流量控制

流量控制限制发送方发送数据的速度或数量，使接收方有足够时间处理并释放缓冲区。常见机制包括停止—等待和滑动窗口。

可靠传输还需要处理数据帧或确认帧丢失、出错和重复，通常综合使用：

- 差错检测。
- 确认 ACK 或否认 NAK。
- 序号。
- 超时计时器。
- 出错或超时后的重传。

## 2. 停止—等待协议

发送方每发送一个数据帧就停止并等待确认，收到正确 ACK 后才发送下一帧。使用 1 位序号即可区分相邻的新帧与重传帧。

若数据帧发送时延为 $T_d$，单程传播时延为 $T_p$，忽略确认帧发送时延，则信道利用率为：

$$
U=\frac{T_d}{T_d+2T_p}.
$$

传播时延较大时，停止—等待协议的利用率很低。

## 3. 滑动窗口协议

滑动窗口允许发送方在未收到确认前连续发送多个帧，实现流水线传输。发送窗口限制未确认帧的数量，接收窗口规定当前可以接收的序号范围。

若序号字段有 $n$ 位：

- 停止—等待：$W_T=1$，$W_R=1$。
- 后退 N 帧 GBN：$W_T\le2^n-1$，$W_R=1$。
- 选择重传 SR：通常 $W_T=W_R\le2^{n-1}$。

## 4. 后退 N 帧 GBN

GBN 接收方只按序接收帧，丢弃失序帧，并累计确认最后一个连续正确帧。某帧超时后，发送方重传该帧以及它之后的全部未确认帧。

GBN 实现简单、接收缓存需求小，但一个帧错误可能导致多个已正确到达的帧被重新发送。

## 5. 选择重传 SR

SR 接收方可以缓存窗口内的失序帧并分别确认。某个帧出错或超时时，发送方只重传该帧。

SR 减少了不必要的重传，但发送与接收双方需要维护更复杂的窗口、计时器和缓存。窗口不能超过序号空间的一半，否则可能混淆新帧和旧帧。

## 6. 流水线协议利用率

发送窗口为 $W$，数据帧发送时延为 $T_d$，单程传播时延为 $T_p$，忽略确认帧发送时延时：

$$
U=\min\left(1,\frac{WT_d}{T_d+2T_p}\right).
$$

窗口足够大时，发送方可以在等待最早确认的期间持续发送，使链路保持忙碌。

::: warning 易错点
GBN 的接收窗口为 1，不缓存失序帧；SR 可以缓存并分别确认失序帧。两者的发送窗口上限不同，根本原因是要避免新旧序号混淆。
:::
