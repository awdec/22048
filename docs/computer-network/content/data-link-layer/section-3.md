<h1><center>第三节 差错控制</center></h1>

## 1. 差错类型

- **位错**：帧中的某些比特发生翻转。
- **帧错**：出现帧丢失、重复或失序。

检错编码主要发现位错；序号、确认、超时和重传等可靠传输机制还用于处理帧丢失与重复。

## 2. 奇偶校验

奇偶校验增加一个校验位，使整个码字中 `1` 的数量保持为奇数或偶数。它能检测奇数个位错误，但不能定位错误，也不能检测所有偶数个位错误。

## 3. 循环冗余校验 CRC

设待发送数据为 $D$，生成多项式对应的比特串为 $G$，其最高次数为 $r$：

1. 在 $D$ 后补 $r$ 个 `0`。
2. 使用模 2 除法除以 $G$。
3. 取得 $r$ 位余数 $R$。
4. 发送码字 $D\|R$。

接收端使用同一个生成多项式除收到的码字。余数为 $0$ 只表示没有检测到错误，不保证传输绝对无错。

模 2 加减均等价于异或，不产生进位和借位。CRC 余数位数等于生成多项式的最高次数，即生成比特串长度减 1。

## 4. 海明码

海明码利用多个校验位组成校验结果，可以定位并纠正一位错误。若信息位数为 $k$，校验位数为 $r$，要纠正一位错误，需要满足：

$$
2^r\ge k+r+1.
$$

校验位放在编号为 $1,2,4,8,\ldots$ 的位置，每个校验位负责一组位置。接收端根据各校验组结果组成错误位置编号。

## 5. 检错与纠错

检错码只判断数据是否可能出错，发现错误后通常丢弃或请求重传；纠错码利用更多冗余信息直接推断并修正一定范围内的错误。

增加编码冗余可以增强差错处理能力，但也会降低有效数据率，因此应根据链路误码率、重传代价和实时性要求选择方案。

::: warning 易错点
CRC 通常用于检错而不是直接纠错；接收端 CRC 余数非零说明检测到错误，余数为零不等于理论上绝对没有错误。
:::
