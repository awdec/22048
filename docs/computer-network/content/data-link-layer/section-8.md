<h1><center>第八节 数据链路层设备</center></h1>

以太网交换机是典型的数据链路层设备，它根据 MAC 地址学习和转发帧。共享式以太网则使用集线器等物理层设备连接站点，所有站点共同竞争同一传输介质。理解二者在转发方式、带宽、双工方式和冲突域方面的差异，是本节的重点。

## 1. 以太网交换机

### 1.1 交换机的基本原理

以太网交换机工作在数据链路层，本质上是一个多端口网桥。它识别以太网帧边界，检查源 MAC 地址和目的 MAC 地址，并根据 MAC 地址表决定帧应从哪个端口转发。

交换机具有以下特点：

- 每个端口连接一个独立的以太网网段，划分独立的冲突域。
- 不同端口之间可以同时转发多个帧，提高网络的并行传输能力。
- 每个端口通常独享端口带宽，不需要与其他端口平均分享。
- 点对点链路通常使用全双工通信，不产生冲突，也不使用 CSMA/CD。
- 默认不能隔离同一 VLAN 内的广播，配置 VLAN 后可以划分广播域。

交换机与传统网桥的基本转发原理相同。网桥通常端口较少、早期多由软件处理；交换机可以看成端口更多、转发性能更高的多端口网桥。

### 1.2 MAC 地址表

交换机内部维护 MAC 地址表，也称转发表。动态表项通常包含：

| 字段 | 含义 |
| --- | --- |
| MAC 地址 | 所学习到的源 MAC 地址 |
| 端口 | 到达该 MAC 地址所使用的交换机端口 |
| VLAN | 该地址所属的 VLAN |
| 老化信息 | 表项的更新时间或剩余有效时间 |

MAC 地址表保存的是“某个 MAC 地址可以通过哪个端口到达”，而不是完整的端到端路径。交换机通常按照 VLAN 分别维护转发信息；同一个 MAC 地址在不同 VLAN 中可以形成不同表项。

动态表项具有老化时间。如果一段时间内没有再次收到来自该源地址的帧，表项会被删除，以适应主机移动、端口变化和网络拓扑变化。

### 1.3 自学习过程

交换机采用**逆向学习**：收到帧时，根据帧的源 MAC 地址学习主机所在端口。

设交换机从端口 $P$ 收到一个帧，其源地址为 $S$，交换机会：

1. 在 MAC 地址表中查找 $S$。
2. 若不存在 $S$，建立“$S\rightarrow P$”的动态表项。
3. 若 $S$ 已存在但端口发生变化，将表项更新为端口 $P$。
4. 若表项仍对应端口 $P$，刷新其老化时间。

交换机依据**源地址学习位置**，依据**目的地址决定转发方向**。它不会因为在目的地址字段中看到某个地址，就学习该地址位于入端口。

::: warning 易错点
自学习一定先查看源 MAC 地址。目的 MAC 地址只能用来查询转发表，不能据此判断目的主机位于帧的入端口。
:::

### 1.4 帧的转发、泛洪与过滤

完成源地址学习后，交换机查询目的 MAC 地址，并根据查询结果处理帧：

1. **已知单播且目的端口不同于入端口**：只向查到的目的端口定向转发。
2. **已知单播且目的端口等于入端口**：过滤该帧，不再从其他端口转发。
3. **未知单播**：向除入端口外、属于同一 VLAN 的其他相关端口泛洪。
4. **广播帧**：向除入端口外、属于同一 VLAN 的其他相关端口泛洪。
5. **需要泛洪的组播帧**：在没有更精确组播转发信息时，也只在所属 VLAN 内泛洪。

泛洪不等于向所有 VLAN 发送。交换机始终把 VLAN 作为二层广播范围，不会把普通二层广播或未知单播泛洪到其他 VLAN。

例如，初始 MAC 地址表为空，主机 A 连接端口 1，主机 B 连接端口 2：

- A 首次向 B 发送帧时，交换机先学习“A $\rightarrow$ 端口 1”。由于尚不知道 B 的位置，交换机泛洪该帧。
- B 向 A 返回帧时，交换机学习“B $\rightarrow$ 端口 2”。此时 A 的位置已知，因此只向端口 1 定向转发。
- 此后 A 与 B 之间的单播帧通常可以直接定向转发，不再泛洪。

### 1.5 交换方式

以太网交换机常见的帧交换方式有：

- **存储转发式**：先接收完整帧并检查 FCS，确认帧格式和校验结果后再转发。它能够丢弃检测到的错误帧，也便于连接不同速率的端口，但转发时延相对较大。
- **直通交换式**：读取到目的 MAC 地址并确定输出端口后就开始转发，不必等待完整帧到达。转发时延较小，但无法在开始转发前完成整个帧的 FCS 校验，可能转发错误帧。

存储转发式的转发时延通常大于直通交换式，但“是否存储完整帧”不会改变交换机依据 MAC 地址学习和转发的基本原理。

### 1.6 冲突域与广播域

- **冲突域**：交换机的每个端口划分一个独立冲突域；使用全双工点对点链路时，端口上实际上不会发生冲突。
- **广播域**：普通二层交换机默认不能隔离广播域。同一 VLAN 内的广播帧会被泛洪，每个 VLAN 构成一个独立广播域。

交换机扩大了网络可以并行通信的范围，但不会自动阻止广播传播。需要隔离广播域时，应使用 VLAN 或三层设备。VLAN 原理见[第六节“局域网”](./section-6)。

::: tip 交换机转发题步骤
先根据源 MAC 地址更新表项，再查询目的 MAC 地址，最后判断定向转发、泛洪还是过滤；若题目给出 VLAN，还必须把转发范围限制在帧所属 VLAN 内。
:::

## 2. 共享式以太网

### 2.1 共享式以太网的概念

共享式以太网由多个站点共同使用同一传输介质或同一集线器。任意站点发送的物理信号都会到达共享介质上的其他站点，同一时刻通常只能有一个站点成功发送。

早期总线形以太网直接使用同轴电缆作为共享介质；使用集线器的双绞线以太网在物理结构上是星形，但集线器把各端口连接成同一个共享信道，因此逻辑结构仍是总线形。

### 2.2 集线器的工作方式

集线器是物理层的多端口中继器。某个端口收到信号后，集线器对信号进行再生，并复制到除接收端口外的所有其他端口。

集线器：

- 只处理物理信号和比特流，不识别帧边界。
- 不检查源、目的 MAC 地址，也不维护 MAC 地址表。
- 不能定向转发或过滤帧，所有站点的网卡都可能看到被复制的信号。
- 不检查 FCS，由噪声造成的错误比特和冲突影响也可能传播到其他端口。

目的主机是否接收帧，由各主机网卡在数据链路层检查目的 MAC 地址后决定。集线器的详细原理见[第二章第三节“物理层设备”](../physical-layer/section-3)。

### 2.3 共享带宽与 CSMA/CD

集线器的所有端口共享集线器的标称带宽。例如，连接在 100 Mbit/s 集线器上的多个站点共同竞争 100 Mbit/s 信道，而不是每个站点各自拥有 100 Mbit/s 带宽。

“共享带宽”不表示带宽始终平均分配给各站点。某个站点单独发送时可以使用全部信道；多个站点同时有数据时需要竞争信道，并因冲突和退避降低实际吞吐量。

共享式以太网通常采用半双工通信和 CSMA/CD：站点发送前监听信道，发送时继续检测冲突，检测到冲突后停止发送并执行二进制指数退避。其介质访问过程见[第五节“介质访问控制”](./section-5)。

### 2.4 共享式以太网的网络范围

使用总线或集线器连接的所有站点：

- 属于同一个冲突域，任意两个站点同时发送都可能发生冲突。
- 属于同一个广播域，集线器不能隔离链路层广播。
- 共享总带宽，不能进行多个相互独立的并行单播传输。

集线器扩大的是物理覆盖范围，不会把网络划分成多个冲突域或广播域。要划分冲突域需要使用网桥或交换机，要划分广播域需要使用 VLAN 或三层设备。

### 2.5 交换式与共享式以太网对比

| 对比项 | 交换式以太网 | 共享式以太网 |
| --- | --- | --- |
| 典型中心设备 | 二层交换机 | 集线器 |
| 设备工作层次 | 数据链路层 | 物理层 |
| 处理单位 | 帧 | 比特信号 |
| 转发依据 | MAC 地址表 | 不依据地址，向其他端口复制信号 |
| 端口带宽 | 每端口通常独享 | 所有端口共享 |
| 双工方式 | 通常全双工 | 半双工 |
| 冲突域 | 每端口独立；全双工时无冲突 | 所有端口属于同一个 |
| 广播域 | 每个 VLAN 一个 | 默认一个 |
| CSMA/CD | 全双工时不使用 | 使用 |
| 错误帧处理 | 存储转发式可以检查 FCS 并丢弃 | 集线器不识别帧，继续复制信号 |
| 并行传输 | 多个端口可以同时通信 | 同一时刻通常只有一个站点成功发送 |

::: warning 易错点
交换机隔离冲突域，但默认不隔离同一 VLAN 内的广播域；集线器既不隔离冲突域，也不隔离广播域。未知单播的泛洪只是交换机暂时不知道目的端口，不表示交换机退化成物理层集线器。
:::
