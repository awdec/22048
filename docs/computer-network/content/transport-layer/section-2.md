<h1><center>第二节 UDP</center></h1>

## 1. UDP 的特点

用户数据报协议 UDP 提供无连接的传输层服务，主要特点包括：

- 发送数据前不建立连接。
- 尽最大努力交付，不保证可靠、按序或无重复。
- 面向报文，保留应用层报文边界。
- 首部固定为 8 字节，控制开销小。
- 支持一对一、一对多、多对一和多对多通信。

UDP 没有拥塞控制机制，应用可以按照自身需求控制发送时机和速率，但仍应避免造成网络拥塞。

## 2. UDP 报文格式

UDP 首部由四个 16 位字段组成：

- 源端口。
- 目的端口。
- UDP 长度。
- UDP 校验和。

UDP 长度包括 8 字节首部和数据部分。源端口在不需要回复时可以为 0，目的端口用于接收端分用。

## 3. UDP 校验和

UDP 校验和覆盖 UDP 首部和数据，并在计算时加入伪首部。伪首部包含源 IP、目的 IP、协议号和 UDP 长度等信息，用于检查数据是否被误投递。

伪首部只参与校验和计算，不会作为 UDP 报文的一部分在网络上传输。

校验和采用反码运算。接收端计算结果不正确时通常丢弃该 UDP 数据报。

在 IPv4 中，UDP 校验和字段允许为全 0，表示发送方没有计算校验和；在 IPv6 的普通 UDP 通信中，UDP 校验和必须使用。若计算出的 UDP 校验和恰为全 0，则字段以全 1 发送，以免与“未使用校验和”混淆。

## 4. 面向报文

UDP 对应用层交付的每个报文分别添加首部，既不合并多个报文，也不把一个报文拆成多个 UDP 数据报。接收端一次读取通常对应一个完整 UDP 报文。

应用程序需要选择合适的报文大小；过大的 UDP 数据报可能导致 IP 分片，任何一个分片丢失都会使整个数据报无法重组。

## 5. UDP 的应用

UDP 适合强调低时延、交互简单或由应用自行控制可靠性的场景，例如：

- DNS 查询。
- 实时音视频。
- 网络管理和监控。
- 在线游戏的部分实时数据。
- 基于 UDP 实现自定义可靠传输的应用协议。

应用可以在 UDP 之上增加序号、确认、重传、拥塞控制等机制实现所需可靠性。

::: warning 易错点
UDP 无连接不等于没有端口和差错检测；UDP 可以承载可靠应用协议，但可靠性需要由应用层或其上的协议自行实现。
:::
