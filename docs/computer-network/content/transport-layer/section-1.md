<h1><center>第一节 传输层提供的服务</center></h1>

传输层位于应用层与网络层之间。它利用网络层提供的主机到主机通信能力，为不同主机中的应用进程提供端到端的逻辑通信。

## 1. 传输层的功能

### 1.1 进程到进程的逻辑通信

网络层根据 IP 地址把分组交付到目的主机，传输层还要根据端口号把数据交付给目的主机中的具体应用进程。因此：

- 网络层实现**主机到主机**的逻辑通信。
- 传输层实现**进程到进程**的逻辑通信。
- 数据链路层实现一段链路上**相邻节点之间**的数据传输。

所谓端到端通信，是指传输层功能主要由通信两端的主机实现。普通路由器负责网络层的路由与转发，通常不参与两端进程之间的传输连接管理和可靠传输。

### 1.2 传输层的主要功能

1. **寻址**：使用端口号标识主机中的应用进程或应用服务。
2. **复用与分用**：发送端允许多个应用进程共用网络层服务，接收端把数据交付给正确的应用进程。
3. **封装、分段与重组**：传输层把应用数据封装为传输层报文。TCP 将应用层字节流划分为 TCP 报文段，并在接收端按序重组；UDP 保留应用报文边界，通常把一次应用交付的数据封装为一个 UDP 用户数据报，UDP 本身不把一个用户数据报分割为多个 UDP 用户数据报。
4. **差错检测**：通过传输层校验和检测传输过程中出现的比特差错。TCP 和 UDP 都具有校验和字段。
5. **连接管理**：面向连接的传输协议负责连接的建立、数据传输和连接释放。
6. **提供不同质量的服务**：根据所采用的协议，可以进一步提供可靠传输、按序交付、流量控制和拥塞控制等功能。

其中，寻址、复用、分用和差错检测是理解传输层的基础；可靠传输、流量控制和拥塞控制并不是所有传输层协议都必须提供。例如，TCP 提供这些机制，而 UDP 不提供可靠交付、流量控制和拥塞控制。

### 1.3 传输层与网络层的关系

| 对比项 | 网络层 | 传输层 |
| --- | --- | --- |
| 通信对象 | 主机到主机 | 应用进程到应用进程 |
| 主要地址 | IP 地址 | 端口号，与 IP 地址共同定位通信端点 |
| 典型数据单位 | IP 数据报或分组 | TCP 报文段、UDP 用户数据报 |
| 实现位置 | 主机和路由器 | 通信端主机 |
| 主要任务 | 路由选择与分组转发 | 复用与分用，以及协议所提供的端到端控制 |

传输层可以在尽最大努力交付的 IP 服务之上，由端系统使用序号、确认、重传和窗口等机制实现可靠传输。因此，“网络层不可靠”并不意味着上层不能获得可靠服务。

::: warning 易错点
传输层的“端到端”是应用进程之间的逻辑通信，不表示两端之间存在一条专用物理链路；传输层协议也不会替代网络层进行路由选择。
:::

## 2. 传输层的寻址与端口

### 2.1 端口号

一台主机可以同时运行多个网络应用，仅凭目的 IP 地址只能找到主机，不能确定应把数据交给哪个应用。传输层使用**端口号**完成进程级寻址。

TCP 和 UDP 的端口号字段均为 16 bit，取值范围为 $0\sim 65535$。端口号通常分为：

| 端口范围 | 名称 | 主要用途 |
| --- | --- | --- |
| $0\sim 1023$ | 熟知端口或系统端口 | 分配给常见的服务器应用；端口 0 通常保留 |
| $1024\sim 49151$ | 登记端口 | 分配给已登记的应用或服务 |
| $49152\sim 65535$ | 动态端口或私有端口 | 通常由客户端临时选择，也称临时端口 |

服务器进程通常在约定的熟知端口或登记端口上等待请求；客户端进程通常由操作系统临时分配一个未使用的端口。服务器向客户端返回数据时，原请求报文中的源端口就成为返回报文的目的端口。

端口号具有以下特点：

- 端口号只在本主机内具有标识作用，不是全网唯一的进程编号。
- TCP 和 UDP 具有相互独立的端口号空间，相同数值的 TCP 端口与 UDP 端口不是同一个通信端点。
- 端口号与应用进程通常不是简单的一一对应关系。一个进程可以使用多个套接字，一个服务器端口也可以同时服务多个 TCP 连接。
- 端口是逻辑概念，不是交换机、路由器上的物理接口。

部分常见应用层协议的默认端口如下：

::: info 408 复习定位
现行大纲要求掌握传输层寻址与端口，但没有逐项规定必须背诵的端口表。应优先掌握大纲所列应用协议涉及的常用端口；Telnet、TFTP、SNMP 等端口可作为拓展了解。
:::

| 应用层协议 | 默认端口 | 传输层协议 |
| --- | --- | --- |
| FTP | 21；主动方式的数据连接通常使用 20 | TCP |
| Telnet | 23 | TCP |
| SMTP | 25 | TCP |
| DNS | 53 | 通常使用 UDP，必要时使用 TCP |
| DHCP | 服务器 67，客户端 68 | UDP |
| TFTP | 69 | UDP |
| HTTP | 80 | TCP |
| POP3 | 110 | TCP |
| SNMP | 161；陷阱报文通常使用 162 | UDP |

### 2.2 复用与分用

**复用**发生在发送端：多个应用进程可以把数据交给传输层，传输层为数据添加包含源端口和目的端口等信息的首部，再统一交给网络层发送。

**分用**发生在接收端：传输层检查到达报文中的端口及相关地址信息，把数据交付给对应的套接字和应用进程。

- UDP 分用主要依据目的 IP 地址和目的端口号。同一个 UDP 套接字可以接收不同源主机发送来的用户数据报。
- TCP 必须区分不同的连接，通常依据源 IP 地址、源端口号、目的 IP 地址和目的端口号组成的四元组进行分用。

因此，两个客户端可以同时访问同一服务器的同一个 TCP 服务端口。虽然目的 IP 地址和目的端口号相同，但只要客户端的源 IP 地址或源端口号不同，TCP 就能把它们识别为不同连接。

### 2.3 套接字与连接标识

传输层的一个通信端点通常用 IP 地址和端口号的组合表示，称为**套接字地址**：

$$
\text{套接字地址}=(\text{IP 地址},\text{端口号}).
$$

实际分用时还要区分所使用的传输层协议，因为 TCP 和 UDP 的端口号空间彼此独立。

一个 TCP 连接由通信双方的套接字地址共同确定，即通常所说的四元组：

$$
(\text{源 IP 地址},\text{源端口号},\text{目的 IP 地址},\text{目的端口号}).
$$

::: tip 识别方法
IP 地址解决“把数据送到哪台主机”，端口号解决“把数据交给主机中的哪个应用”，IP 地址与端口号共同定位一个传输层通信端点。
:::

## 3. 无连接服务与面向连接服务

### 3.1 无连接服务

无连接服务在发送数据前不建立传输连接，也不需要在通信结束后释放连接。每个报文独立处理，协议不保存端到端连接状态。

UDP 是 Internet 传输层的无连接协议，具有以下特点：

- 不进行连接建立和连接释放，控制开销小、发送时延低。
- 面向报文，保留应用层交付数据的报文边界。
- 协议本身不保证数据一定到达，也不保证按序到达或只到达一次。
- 不提供可靠传输、流量控制和拥塞控制，但仍使用校验和进行差错检测。
- 应用程序如果需要可靠性，可以在应用层自行增加确认、重传等机制。

### 3.2 面向连接服务

面向连接服务在正式传输数据前先建立逻辑连接，通信过程中维护连接状态，数据传输结束后再释放连接。

TCP 是 Internet 传输层的面向连接协议，具有以下特点：

- 每条连接只能有两个端点，提供点对点、全双工通信。
- 面向字节流，不保留应用层报文的天然边界。
- 使用序号、确认和重传等机制实现可靠、按序、无重复的字节流交付。
- 使用滑动窗口实现流量控制，并通过拥塞控制调节向网络注入数据的速率。
- 建立和释放连接需要交换控制报文，协议首部与状态维护的开销较大。

TCP 连接是由端系统维护的逻辑关系，不是电路交换中的专用物理连接。不同 TCP 连接仍然共享底层分组交换网络及链路带宽。

### 3.3 两类服务的比较

| 对比项 | 无连接服务 | 面向连接服务 |
| --- | --- | --- |
| 代表协议 | UDP | TCP |
| 数据传输前 | 不建立连接 | 先建立连接 |
| 通信状态 | 不维护端到端连接状态 | 维护连接状态 |
| 数据组织 | 面向报文 | 面向字节流 |
| 可靠性 | 协议本身不保证可靠交付 | 提供可靠、按序、无重复交付 |
| 流量控制 | 不提供 | 提供 |
| 拥塞控制 | 不提供 | 提供 |
| 通信开销 | 较小 | 较大 |
| 典型场景 | 对实时性或简单性要求较高，或由应用自行控制可靠性 | 对数据完整、按序到达要求较高 |

连接方式与可靠性是两个不同维度。抽象地说，面向连接不必然等于可靠、无连接也不代表应用最终一定不可靠；但在 408 所考查的 Internet 传输层中，应掌握 **UDP 是无连接、不可靠的数据报服务，TCP 是面向连接、可靠的字节流服务**。

::: warning 易错点
UDP 的“不可靠”表示它不提供确认、重传、按序交付等可靠传输机制，不表示它完全不检测差错；TCP 的“面向连接”表示端系统维护逻辑连接状态，不表示底层网络为它建立了专用线路。
:::

::: tip 本节主线
网络层把数据送到目的主机，传输层利用端口号和套接字把数据交给目的进程，并通过复用与分用支持多个应用同时通信。UDP 提供无连接服务，TCP 提供面向连接服务。
:::
