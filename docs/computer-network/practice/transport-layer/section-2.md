<h1><center>第二节 UDP</center></h1>

::: info 例 1
UDP 数据部分为 $1000\text{ B}$，UDP 数据报总长度是多少？
:::

::: details 解析
UDP 首部固定为 8 字节：
$$
1000+8=1008\text{ B}.
$$
:::

::: info 例 2
UDP 校验和计算使用的伪首部是否会在网络上传输？
:::

::: details 解析
不会。伪首部只在发送端和接收端参与校验和计算，用于检查源、目的 IP、协议号和 UDP 长度等信息，不属于实际 UDP 报文。
:::

::: info 例 3
UDP 面向报文意味着什么？
:::

::: details 解析
UDP 保留应用报文边界。应用每交付一个报文，UDP 就形成一个独立数据报，既不把多个报文合并，也不把一个报文拆成多个 UDP 数据报。
:::

::: info 例 4
UDP 本身不保证可靠，应用还能否基于 UDP 实现可靠传输？
:::

::: details 解析
可以。应用协议可以自行加入序号、确认、重传、流量控制和拥塞控制等机制，但这些能力不是 UDP 本身提供的。
:::

::: info 例 5
为什么 DNS 的简单查询常使用 UDP？
:::

::: details 解析
UDP 无须建立连接、首部开销小，适合一次请求对应一次响应的短交互。若报文过大、需要可靠连接或发生特定情况，DNS 也可以使用 TCP。
:::

::: info 例 6
一个过大的 UDP 数据报经过 IPv4 网络时可能带来什么问题？
:::

::: details 解析
它可能被 IP 层分片。任一分片丢失都会导致整个 UDP 数据报无法重组，增加丢包和重传代价，因此应用通常应控制报文大小。
:::

::: info 例 7
IPv4 的 UDP 校验和字段为全 0 表示什么？IPv6 的普通 UDP 通信能否这样做？
:::

::: details 解析
在 IPv4 中，全 0 表示发送方没有计算 UDP 校验和；IPv6 的普通 UDP 通信必须使用 UDP 校验和，不能用全 0 表示省略校验。
:::
