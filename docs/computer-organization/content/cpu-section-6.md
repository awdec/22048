<h1><center>第六节 指令流水线</center></h1>

指令流水线把一条指令的执行过程划分为若干阶段，并让多条指令的不同阶段在时间上重叠。它利用时间并行性提高指令吞吐率，是现代处理器提高性能的基本技术之一。

本节以经典 MIPS 五级流水线为统一分析模型：

$$
\text{IF}
\longrightarrow
\text{ID}
\longrightarrow
\text{EX}
\longrightarrow
\text{MEM}
\longrightarrow
\text{WB}
$$

实际处理器的流水级数量和每级功能可能不同，做题时应以题目给出的数据通路、转发路径和分支判定阶段为准。

## 1. 指令流水线的基本概念

### 1.1 流水线的基本思想

非流水方式在前一条指令全部完成后，才开始下一条指令；流水方式允许多条指令重叠执行。例如：

| 时钟周期 | 指令 `I1` | 指令 `I2` | 指令 `I3` |
| ---: | --- | --- | --- |
| 1 | IF |  |  |
| 2 | ID | IF |  |
| 3 | EX | ID | IF |
| 4 | MEM | EX | ID |
| 5 | WB | MEM | EX |
| 6 |  | WB | MEM |
| 7 |  |  | WB |

流水线需要先经历**建立或充满**过程；最后一条指令进入后，还要经历**排空**过程。稳定运行时，理想单发射流水线可以接近每个时钟周期完成一条指令。

### 1.2 吞吐率与单条指令延迟

- 吞吐率表示单位时间内完成的指令数。
- 单条指令延迟表示一条指令从进入流水线到完成所经历的时间。

流水线主要提高吞吐率，通常不会缩短单条指令延迟。由于增加了流水寄存器延迟，单条指令的总延迟甚至可能略有增加。

对理想单发射流水线：

$$
IPC_{ideal}=1,\qquad CPI_{ideal}=1
$$

其中 `IPC` 是平均每周期完成的指令数，`CPI` 是平均每条指令所需的时钟周期数。

### 1.3 流水线时钟周期

设流水线有 $k$ 个阶段，第 $i$ 个阶段的组合逻辑延迟为 $t_i$，流水寄存器的附加延迟为 $d$，则时钟周期至少为：

$$
T_{clk}\geq\max(t_1,t_2,\ldots,t_k)+d
$$

因此，流水线性能受到最慢阶段限制。各阶段延迟越均衡，流水线硬件利用率通常越高。

### 1.4 理想执行时间

在阶段耗时相等、没有停顿且每周期只发射一条指令的理想情况下，$k$ 级流水线执行 $n$ 条指令需要：

$$
T_{pipe}=(k+n-1)T_{clk}
$$

若共有 $s$ 个额外停顿周期，则：

$$
T_{pipe}=(k+n-1+s)T_{clk}
$$

若非流水处理器顺序完成各阶段，且一条指令的时间为 $\sum_{i=1}^{k}t_i$，则执行 $n$ 条指令的时间为：

$$
T_{nonpipe}=n\sum_{i=1}^{k}t_i
$$

加速比应使用实际时间计算：

$$
S=\frac{T_{nonpipe}}{T_{pipe}}
$$

只有在各阶段完全均衡、忽略流水寄存器开销和各种停顿时，当 $n$ 很大，最大加速比才接近流水级数 $k$。

### 1.5 吞吐率和效率

执行 $n$ 条指令的平均吞吐率为：

$$
TP=\frac{n}{T_{pipe}}
$$

理想流水线稳定后的最大吞吐率为：

$$
TP_{max}=\frac{1}{T_{clk}}
$$

对于各段等长、无停顿的 $k$ 级流水线，效率可以表示为：

$$
E=\frac{S}{k}=\frac{n}{k+n-1}
$$

效率反映各流水段的平均利用程度。指令数量较少、阶段不均衡或停顿较多时，效率都会下降。

## 2. 流水线的基本实现

### 2.1 经典五级流水线

| 流水级 | 英文名称 | 主要功能 |
| --- | --- | --- |
| IF | Instruction Fetch | 根据 `PC` 取指令，并形成顺序后继地址 |
| ID | Instruction Decode / Register Fetch | 译码、读取源寄存器、扩展立即数 |
| EX | Execute / Address Calculation | ALU 运算、有效地址计算或分支比较 |
| MEM | Memory Access | 读写数据存储器 |
| WB | Write Back | 把结果写回寄存器组 |

并非每条指令都在每一级完成有效工作。例如，寄存器加法通常不访问数据存储器，但仍要经过或占用对应的流水时隙，以保持统一的流水推进方式。

### 2.2 流水寄存器

相邻流水级之间需要设置流水寄存器，在时钟边沿保存本级输出，供下一级在下一周期使用：

| 流水寄存器 | 典型保存内容 |
| --- | --- |
| `IF/ID` | 机器指令、`PC+4` |
| `ID/EX` | 源寄存器值、扩展立即数、寄存器编号、控制信号 |
| `EX/MEM` | ALU 结果、Store 数据、目的寄存器编号、控制信号 |
| `MEM/WB` | 主存读出数据或 ALU 结果、目的寄存器编号、写回控制 |

流水寄存器不仅传送数据，还要把后续阶段需要的寄存器编号和控制信号随指令一起向后传递。否则，指令到达 `MEM` 或 `WB` 时将无法判断应执行何种操作或写入哪个寄存器。

### 2.3 时钟驱动与阶段推进

每个时钟周期内：

1. 各流水级使用本级流水寄存器中的输入完成组合逻辑操作；
2. 周期结束时，结果写入下一级流水寄存器；
3. 下一周期，各级同时处理新的输入。

正常推进时，多条指令每周期向后移动一级。出现冒险时，控制逻辑可以冻结部分流水寄存器、禁止 `PC` 更新、向后级注入空操作，或清除错误路径指令。

### 2.4 资源配置

为了让多个流水级并行工作，数据通路必须避免不必要的硬件争用。例如：

- IF 需要取指，MEM 可能需要访问数据，因此经典模型通常分离指令存储器和数据存储器，或使用独立的指令 Cache、数据 Cache；
- ID 需要读取寄存器，WB 可能同时写寄存器，因此寄存器组要支持规定数量的读写端口和相应时序；
- `PC+4` 与 EX 中的 ALU 运算若需要并行，通常要配置独立的地址加法器或其他通路。

流水线不是只增加流水寄存器就能实现，还需要数据通路、控制信号和资源端口共同支持阶段并行。

### 2.5 控制信号的流水化

控制器通常在 ID 阶段根据机器指令生成后续阶段需要的控制信号，并把它们分组送入流水寄存器：

- EX 控制：ALU 操作、第二操作数选择等；
- MEM 控制：主存读、主存写、分支控制等；
- WB 控制：寄存器写使能、写回数据选择等。

发生停顿或冲刷时，可以把有关控制信号置零，使该流水位置表现为空操作或气泡。

## 3. MIPS 指令集的流水段分析

本节采用经典 32 位 MIPS 核心指令作为示例，假定指令定长 $4$ 字节、采用 load-store 结构，并在 EX 阶段完成条件分支比较。若题目给出其他实现，应以题设为准。

### 3.1 R 型算术逻辑指令

以：

```text
add $t0, $t1, $t2
```

为例，其语义为：

$$
R[t0]\leftarrow R[t1]+R[t2]
$$

| 流水级 | 主要操作 |
| --- | --- |
| IF | 取出 `add` 指令，计算 `PC+4` |
| ID | 译码，读取 `$t1、$t2` |
| EX | ALU 完成加法 |
| MEM | 不访问数据存储器，传递 ALU 结果 |
| WB | 把 ALU 结果写入目的寄存器 `$t0` |

此类写通用寄存器的 R 型算术逻辑指令，其目的寄存器来自 `rd` 字段。并非所有 R 型指令都会写 `rd`，应结合具体指令功能判断。

### 3.2 立即数算术指令

以：

```text
addi $t0, $t1, 8
```

为例：

| 流水级 | 主要操作 |
| --- | --- |
| IF | 取指并形成 `PC+4` |
| ID | 读取 `$t1`，对立即数进行符号扩展 |
| EX | ALU 计算 `$t1 + 8` |
| MEM | 传递 ALU 结果 |
| WB | 把结果写入 `$t0` |

I 型算术指令的目的寄存器通常来自 `rt` 字段。立即数采用符号扩展还是零扩展，应由具体指令语义决定。

### 3.3 Load 指令

```text
lw $t0, 12($t1)
```

| 流水级 | 主要操作 |
| --- | --- |
| IF | 取指并形成 `PC+4` |
| ID | 读取基址寄存器 `$t1`，符号扩展位移量 `12` |
| EX | 计算有效地址 $EA=R[t1]+12$ |
| MEM | 从数据存储器读取 $M[EA]$ |
| WB | 把读出数据写入 `$t0` |

Load 的目的寄存器是 `rt`。数据直到 MEM 阶段末尾才产生，这一时刻决定了紧随其后的相关指令能否通过转发直接取得数据。

### 3.4 Store 指令

```text
sw $t0, 12($t1)
```

| 流水级 | 主要操作 |
| --- | --- |
| IF | 取指并形成 `PC+4` |
| ID | 读取基址 `$t1` 和待存数据 `$t0`，符号扩展位移量 |
| EX | 计算有效地址 $EA=R[t1]+12$ |
| MEM | 把 `$t0` 的值写入 $M[EA]$ |
| WB | 不写通用寄存器 |

Store 在 ID 阶段读出的待存数据必须随指令经过流水寄存器传到 MEM 阶段。Store 没有通用寄存器写回，但仍可能需要数据转发以取得最新的待存值。

### 3.5 条件分支指令

```text
beq $t0, $t1, LABEL
```

在本节采用的模型中：

| 流水级 | 主要操作 |
| --- | --- |
| IF | 取分支指令并形成 `PC+4` |
| ID | 读取 `$t0、$t1`，符号扩展分支位移 |
| EX | 比较两个寄存器，并计算或选择分支目标地址 |
| MEM | 通常无数据存储器操作 |
| WB | 不写通用寄存器 |

分支目标地址为：

$$
Target=(PC+4)+(\operatorname{SignExt}(imm_{16})\ll2)
$$

如果直到 EX 阶段末尾才能确定分支是否跳转，那么此前已经进入 IF、ID 的顺序后继指令可能属于错误路径，需要冲刷。若处理器在 ID 阶段提前比较，分支代价会不同。

### 3.6 无条件跳转指令

对经典 MIPS 的：

```text
j TARGET
```

目标地址可由 `PC+4` 的高位和指令中的 26 位目标字段形成：

$$
Target=\{(PC+4)_{31:28},\ instr_{25:0},\ 00\}
$$

跳转通常不需要 ALU 数据运算和通用寄存器写回。目标地址在哪一级形成、需要冲刷几条后续指令，由具体流水线实现决定。

### 3.7 各类指令对照

| 指令类型 | IF | ID | EX | MEM | WB |
| --- | --- | --- | --- | --- | --- |
| R 型 | 取指 | 读 `rs、rt` | ALU 运算 | 传递结果 | 写 `rd` |
| 立即数运算 | 取指 | 读 `rs`、扩展立即数 | ALU 运算 | 传递结果 | 写 `rt` |
| `lw` | 取指 | 读基址、扩展位移 | 计算 EA | 读主存 | 写 `rt` |
| `sw` | 取指 | 读基址和待存数据 | 计算 EA | 写主存 | 无 |
| `beq` | 取指 | 读两个源寄存器 | 比较并决定转移 | 无 | 无 |
| `j` | 取指 | 形成或传递目标 | 视实现而定 | 无 | 无 |

分析某条 MIPS 指令时，应持续跟踪三类信息：数据值、目的寄存器编号以及后续阶段需要的控制信号。

## 4. 流水线的冒险与处理

流水线冒险（Hazard）是指下一条指令不能在预定时钟周期正常执行的情况，分为结构冒险、数据冒险和控制冒险。

### 4.1 停顿、气泡和冲刷

| 操作 | 含义 |
| --- | --- |
| 停顿（Stall） | 暂停某些流水级、`PC` 或流水寄存器的更新 |
| 气泡（Bubble） | 在流水线中插入不改变体系结构状态的空操作 |
| 冲刷（Flush） | 使已经进入流水线的错误路径或无效指令失效 |

典型数据冒险处理会冻结 `PC` 和 `IF/ID`，同时向 `ID/EX` 注入空控制信号；分支预测错误则通常需要冲刷错误路径指令。

### 4.2 结构冒险

结构冒险是多条指令在同一周期争用同一个硬件资源。例如：

- IF 取指和 MEM 访问数据共用一个单端口存储器；
- 多条指令同时需要一个非流水化乘法器；
- 寄存器组读写端口不足。

处理方法包括：

- 增加或复制硬件资源；
- 使用多端口部件；
- 分离指令存储器和数据存储器；
- 由硬件插入停顿；
- 由编译器进行指令调度，错开资源使用时间。

### 4.3 数据相关与数据冒险

| 相关类型 | 含义 | 性质 |
| --- | --- | --- |
| RAW（写后读） | 后指令要读取前指令尚未写出的值 | 真数据相关 |
| WAR（读后写） | 后指令可能先写，破坏前指令尚未读取的旧值 | 反相关 |
| WAW（写后写） | 两条指令写同一位置，写入次序可能颠倒 | 输出相关 |

在经典顺序发射、顺序执行、固定五级 MIPS 流水线中，寄存器读取统一在 ID、写回统一在 WB，主要出现的是 RAW 冒险；WAR 和 WAW 通常在乱序执行或不同执行延迟的流水线中才会成为实际冒险。

### 4.4 数据转发

数据转发又称旁路，把尚未写回寄存器组的结果直接送到后续指令需要的功能部件输入。例如：

```text
add $t0, $t1, $t2
sub $t3, $t0, $t4
```

第一条指令的 ALU 结果在 EX 阶段末尾已经产生，可以从 `EX/MEM` 或后续流水寄存器转发到第二条指令的 EX 输入，不必等待 WB 写回 `$t0`。

转发控制必须同时判断：

- 前面指令是否会写寄存器；
- 目的寄存器编号是否等于当前指令的源寄存器编号；
- 数据此时是否已经产生；
- 多个候选结果中哪一个更新。

转发不能消除所有停顿，其效果取决于结果产生阶段和使用阶段。

### 4.5 Load-use 冒险

```text
lw  $t0, 0($t1)
add $t2, $t0, $t3
```

在经典五级流水线中，`lw` 的数据到 MEM 阶段末尾才产生，而紧随其后的 `add` 原本需要在同一周期的 EX 阶段开始时使用该数据。即使具有常见转发通路，通常仍需停顿一个周期：

| 周期 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
| ---: | --- | --- | --- | --- | --- | --- | --- |
| `lw` | IF | ID | EX | MEM | WB |  |  |
| `add` |  | IF | ID | 停顿 | EX | MEM | WB |

停顿后，Load 数据可以从 `MEM/WB` 等位置转发给 `add` 的 EX 输入。若题目给出的存储器时序或转发路径不同，所需停顿数也可能不同。

### 4.6 编译器调度

编译器可以把与相关链无关的指令移动到等待位置，以减少硬件停顿。例如，在不改变程序语义的前提下，把一条独立指令安排在 `lw` 与其使用者之间。

编译器必须保持数据依赖、异常行为和存储访问语义，不能任意交换可能互相影响的指令。

### 4.7 控制冒险

分支、跳转、异常和中断会改变 `PC`，使处理器无法立即确定下一条应取指令，形成控制冒险。

常见处理方法：

- 在结果确定前停止取指；
- 默认预测不跳转或采用其他静态预测；
- 使用动态分支预测；
- 提前计算目标地址和分支条件；
- 采用延迟分支，由编译器填充分支延迟槽；
- 预测错误时冲刷流水线并从正确地址重新取指。

若分支频率为 $f_b$，预测错误率为 $p_m$，每次预测错误的代价为 $P$ 个周期，则仅考虑分支预测错误时，平均 CPI 可近似为：

$$
CPI\approx CPI_{ideal}+f_b\times p_m\times P
$$

若还存在结构和数据停顿，应继续加上相应的平均停顿周期。

### 4.8 实际 CPI

对单发射流水线，可以概括为：

$$
CPI_{actual}
=
CPI_{ideal}
+
\text{平均结构停顿}
+
\text{平均数据停顿}
+
\text{平均控制停顿}
$$

流水线越深，理想时钟周期可能越短，但冒险处理、分支错误和流水寄存器开销的影响通常也越明显。

## 5. 高级流水线技术

现行 408 主要要求理解超标量和动态流水线的基本概念，不要求掌握复杂调度算法的电路实现。

### 5.1 超流水线（扩展）

超流水线进一步细分原有流水级，以缩短每一级的组合逻辑延迟并提高时钟频率。

特点：

- 主要依靠增加流水级数提高时钟频率；
- 单个周期内不一定发射多条指令；
- 流水寄存器开销、分支预测错误代价和级间不均衡问题更加突出。

### 5.2 超标量处理器

超标量处理器配置多条并行执行通路，使一个时钟周期可以取出、发射或完成多条指令。若发射宽度为 $W$，理想情况下：

$$
IPC_{max}\leq W
$$

超标量处理器需要同时解决多条指令之间的数据依赖、资源分配和控制转移问题。实际 IPC 通常低于理论发射宽度。

必须区分：超流水线主要增加阶段深度，超标量主要增加同一周期的并行发射宽度。

### 5.3 动态流水线与乱序执行

动态调度处理器在运行时检查操作数是否就绪和执行部件是否空闲，使满足条件的后续指令可以越过被阻塞的前序指令先执行。

典型过程可以概括为：

$$
\text{按序取指/译码}
\longrightarrow
\text{动态调度与可能的乱序执行}
\longrightarrow
\text{按序提交体系结构结果}
$$

按序提交有助于维持程序可见的指令顺序和精确异常。具体处理器也可能采用不同的前端和提交组织，以上是常见抽象模型。

### 5.4 寄存器重命名（扩展）

寄存器重命名把指令中数量有限的体系结构寄存器映射到更多物理寄存器，从而消除由名称复用造成的：

- WAR 反相关；
- WAW 输出相关。

寄存器重命名不能消除 RAW 真相关，因为后指令确实需要前指令产生的数据。

### 5.5 动态分支预测和推测执行（扩展）

动态分支预测根据历史行为预测分支方向和目标，使处理器沿预测路径继续取指和执行。预测正确可以减少控制停顿；预测错误则必须撤销错误路径产生的未提交结果并重新取指。

推测执行的结果通常要等到相关条件确认后才能提交为体系结构可见状态，以保证程序语义和精确异常。

### 5.6 高级技术对照

| 技术 | 主要目标 | 关键代价或问题 |
| --- | --- | --- |
| 超流水线 | 细分阶段，提高时钟频率 | 流水更深、分支代价和寄存器开销增加 |
| 超标量 | 每周期并行发射多条指令 | 资源、依赖检查和调度复杂 |
| 乱序执行 | 让就绪指令绕过阻塞指令 | 需要动态调度和有序提交机制 |
| 寄存器重命名 | 消除 WAR、WAW 名称相关 | 需要物理寄存器和映射管理 |
| 分支预测 | 减少控制冒险停顿 | 预测错误需要冲刷和恢复 |

## 6. 408 常见考法与易错点

| 考查内容 | 分析要点 |
| --- | --- |
| 流水线时间 | 计算充满、稳定、排空和额外停顿周期 |
| 时钟周期 | 取最慢流水级延迟并加流水寄存器开销 |
| 性能指标 | 计算吞吐率、加速比、效率、IPC 和 CPI |
| MIPS 流水段 | 跟踪数据、寄存器编号和控制信号 |
| 冒险判断 | 区分结构、RAW/WAR/WAW 数据和控制冒险 |
| 转发与停顿 | 判断数据产生阶段、使用阶段和转发路径 |
| 分支代价 | 根据判定阶段、预测错误率和冲刷周期计算 |
| 高级技术 | 重点理解超标量和动态流水线的基本概念；超流水线、寄存器重命名等用于扩展辨析 |

常见错误包括：

- 认为流水线一定能缩短单条指令延迟；
- 不计流水寄存器开销，直接把时钟周期写成各段延迟平均值；
- 无条件认为流水线最大加速比等于流水级数；
- 忘记流水线的充满和排空时间；
- 认为 MIPS 中每类指令在五个阶段都完成有效工作；
- 混淆 `lw` 的 `rt` 写回与 `sw` 不写通用寄存器；
- 认为转发可以消除所有 RAW 停顿；
- 在经典五级顺序 MIPS 中把 WAR、WAW 当成主要冒险；
- 混淆停顿、气泡和冲刷；
- 脱离题目给出的分支判定阶段计算控制冒险代价；
- 认为超流水线和超标量是同一个概念；
- 认为寄存器重命名可以消除 RAW 真相关；
- 只比较 CPI，不同时考虑时钟周期和指令条数。

## 7. 本节小结

分析指令流水线时可以采用统一步骤：

1. 明确流水级功能、阶段延迟和流水寄存器位置；
2. 按指令类型跟踪各阶段中的数据和控制信号；
3. 检查结构资源、数据依赖和 `PC` 控制；
4. 根据转发路径、停顿和冲刷规则画出时空图；
5. 统计总周期数，再计算 CPI、吞吐率或加速比。

经典五级 MIPS 是理解流水线的基础模型：IF 取指、ID 译码读寄存器、EX 运算或计算地址、MEM 访存、WB 写回。高级流水线技术仍围绕同一目标展开，即在保持程序语义和精确异常的前提下，让更多指令更充分地重叠执行。
