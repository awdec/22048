<h1><center>第五节 异常和中断机制</center></h1>

异常和中断机制使 CPU 能够处理正常顺序执行之外的事件。发生事件后，处理器按照体系结构规定保存必要状态、转入相应处理程序，并在事件可恢复时返回原程序继续执行。

本节的知识主线为：

$$
\text{事件来源与基本概念}
\longrightarrow
\text{异常和中断分类}
\longrightarrow
\text{检测、响应、处理与返回}
$$

## 1. 异常和中断的基本概念

### 1.1 异常

异常（Exception）通常由当前指令的执行或 CPU 内部事件引起，与当前指令具有确定的同步关系。例如：

- 取到非法指令；
- 整数除数为零；
- 访问地址不对齐或违反存储保护；
- 缺页；
- 执行系统调用或断点指令。

“同步”表示在给定相同程序和机器状态时，异常通常会在执行同一条指令时出现，并不是说异常只能在某个固定时钟沿被检测。

### 1.2 中断

本节所说的中断（Interrupt）主要指外部中断，即由 CPU 外部设备或硬件事件提出的异步请求。例如：

- I/O 设备完成一次操作；
- 定时器到期；
- 外部硬件故障或电源事件；
- 其他处理器或外部控制器发出请求。

“异步”表示中断请求的发生时间通常不由当前执行的机器指令决定。CPU 可以在指令执行过程中检测到请求，但一般选择在规定的指令边界上响应可接受的外部中断。

### 1.3 异常和中断的联系与区别

| 比较项目 | 异常 | 外部中断 |
| --- | --- | --- |
| 主要来源 | 当前指令或 CPU 内部事件 | CPU 外部设备或硬件事件 |
| 与当前指令的关系 | 同步，有确定关系 | 异步，通常无确定关系 |
| 检测时机 | 指令执行的有关阶段 | 可在运行过程中提出并被采样 |
| 返回位置 | 取决于故障、陷阱等类型 | 通常返回顺序后继指令 |
| 是否可屏蔽 | 多数异常不能按普通外部中断方式屏蔽 | 可分为可屏蔽和不可屏蔽 |
| 典型例子 | 缺页、非法指令、系统调用 | I/O、时钟、外部故障中断 |

异常和中断都可能使控制流转入操作系统或固件中的处理程序，通常都需要保存返回位置和必要的处理器状态。但事件来源、响应条件和返回语义不同，不能只因为处理流程相似就把二者视为同一概念。

### 1.4 请求、响应与处理

需要区分三个阶段：

| 阶段 | 含义 |
| --- | --- |
| 请求或检测 | 外部设备提出中断请求，或 CPU 检测到异常条件 |
| 响应 | CPU 接受事件、保存规定状态并把处理程序入口写入 `PC` |
| 处理 | 处理程序保存其他现场、识别和处理原因，最后返回或终止程序 |

“中断请求出现”不等于“CPU 已经响应”。请求可能因为中断屏蔽、优先级不足或 CPU 尚未到达可响应边界而暂时保留。

### 1.5 断点与现场

**断点**是事件处理结束后需要返回的程序位置，通常体现为保存的 `PC` 值；**现场**是恢复程序运行所需的处理器状态，可能包括：

- 通用寄存器；
- `PC` 和 `PSW`；
- 栈指针；
- 必要的地址、控制或浮点状态寄存器。

保存断点只是保存现场的一部分。硬件通常自动保存体系结构规定的最小状态，处理程序再用软件保存其将要改写的其他寄存器；确切分工由 ISA 和异常中断入口机制规定。

### 1.6 中断向量

中断向量用于确定处理程序入口。典型的向量中断过程为：

1. 硬件得到异常号或中断类型号；
2. 以该编号索引中断向量表；
3. 从表项取得处理程序入口地址或入口描述信息；
4. 把最终入口地址写入 `PC`。

中断向量不是处理程序本身。不同体系结构中的向量表项可能直接保存入口地址，也可能保存包含入口、权限等信息的描述符。

## 2. 异常和中断的分类

### 2.1 异常的分类

按照发生原因、保存的断点和可恢复性，异常通常分为故障、陷阱和终止。

#### 故障（Fault）

故障通常在指令执行完成前被检测。若处理成功，可以重新执行引发故障的指令，因此保存的断点一般指向故障指令。

典型例子是缺页故障：操作系统把所需页面调入主存并更新页表后，重新执行原访存指令。

#### 陷阱（Trap）

陷阱又称自陷，通常是程序有意执行特定指令，或在指令执行完成后报告的事件。返回时一般从该指令的顺序后继位置继续执行。

典型例子包括：

- 系统调用；
- 调试断点；
- 某些受控的算术检测事件。

历史上某些体系结构把产生陷阱的指令称为“软件中断指令”，但从同步性和当前大纲的分类角度看，它属于异常或陷阱，不是外部异步中断。

#### 终止（Abort）

终止通常由严重硬件错误或无法恢复的一致性问题引起，处理程序难以可靠地确定或恢复引发事件的指令，因此一般不能返回原程序继续执行。

具体事件属于故障、陷阱还是终止，最终由 ISA 的异常语义规定，不能仅凭事件名称判断。

### 2.2 外部中断的分类

#### 可屏蔽中断

可屏蔽中断可以由中断允许位或中断屏蔽字控制。屏蔽表示 CPU 暂不响应该类请求，并不一定表示外部设备撤销请求。

I/O 完成中断、部分定时器中断通常属于可屏蔽中断，但具体规定取决于系统设计。

#### 不可屏蔽中断

不可屏蔽中断不能被普通中断允许位屏蔽，通常用于需要及时处理的严重硬件事件。但“不可屏蔽”不表示处理器在任何微操作中间都必须立即转移控制，响应仍要遵守体系结构规定的安全边界。

### 2.3 向量中断与非向量中断

| 类型 | 确定处理程序入口的方式 |
| --- | --- |
| 向量中断 | 由硬件提供中断向量、类型号或可直接形成入口的信息 |
| 非向量中断 | 先进入公共或固定入口，再由软件查询中断源并分派 |

向量中断通常能更快找到对应处理程序，但需要相应的向量生成和向量表机制。

### 2.4 按来源分类

外部中断还可以按来源分为：

- I/O 设备中断；
- 时钟或定时器中断；
- 外部硬件故障中断；
- 处理器间中断等。

同一事件可以同时属于多个分类维度。例如，某个 I/O 中断既是外部中断，也可能是可屏蔽的向量中断。

### 2.5 中断优先级

多个中断请求同时存在时，系统需要确定响应顺序和能否嵌套：

| 优先级 | 含义 |
| --- | --- |
| 响应优先级 | 多个请求同时等待时，CPU 优先接受哪一个，通常由硬件排队或仲裁决定 |
| 处理优先级 | 某中断处理程序运行时，哪些其他中断能够打断它，可通过屏蔽字等机制调整 |

响应优先级通常是固定的硬件顺序；处理优先级可以借助中断屏蔽机制进行调整。因此，响应优先级高不一定意味着在所有软件处理中都具有更高的嵌套优先级。

## 3. 异常和中断响应过程

异常和中断的完整处理可以分为事件检测、响应条件判断、硬件响应、软件处理和返回五个阶段。

### 3.1 事件检测

- 异常由取指、译码、执行、访存等部件在有关阶段检测。
- 外部中断请求由中断控制器或 CPU 的中断输入接口采样和记录。

流水线中不同指令可能在相近时间产生多个事件，处理器需要按照指令顺序和异常优先级确定首先处理哪个事件。

### 3.2 外部中断的响应条件

CPU 响应可屏蔽外部中断通常需要满足：

1. 存在有效且尚未撤销或处理的中断请求；
2. 中断允许状态允许响应该类中断；
3. 请求的优先级高于当前允许响应的级别；
4. CPU 已到达体系结构规定的可响应时刻，通常是一条指令执行结束后的边界；
5. CPU 不处于禁止接受该类中断的特殊状态。

不可屏蔽中断不受普通屏蔽位控制，但仍需按照处理器规定进入响应流程。同步异常通常由指令语义决定是否必须处理，不能简单套用外部可屏蔽中断的全部响应条件。

### 3.3 硬件响应过程

CPU 接受异常或中断后，硬件通常完成以下工作中的规定部分：

1. 确定当前指令应当完成、重新执行还是终止；
2. 保存断点或规定的返回地址；
3. 保存 `PSW` 或必要的处理器状态；
4. 切换到规定的处理器模式，并按需要修改中断允许或优先级状态；
5. 取得异常或中断处理程序入口；
6. 把入口地址写入 `PC`，开始取处理程序的第一条指令；
7. 对需要应答的外部中断源发出响应信号。

可以概括为：

$$
\text{接受事件}
\longrightarrow
\text{保存断点和规定状态}
\longrightarrow
\text{取得入口地址}
\longrightarrow
PC\leftarrow\text{处理程序入口}
$$

硬件自动保存哪些状态、保存到专用寄存器还是栈、是否自动关闭可屏蔽中断，都由具体 ISA 规定，不能把某一种处理器的入口序列当成通用规则。

### 3.4 软件处理过程

异常或中断处理程序通常执行：

1. 保存处理程序将要使用的通用寄存器和其他现场；
2. 根据异常原因寄存器、类型号或设备状态识别事件来源；
3. 完成相应处理，例如服务 I/O、调入缺页、终止错误进程；
4. 清除、确认或重新使能有关事件源；
5. 在允许嵌套时设置适当的中断屏蔽状态；
6. 恢复软件保存的现场；
7. 执行异常或中断返回指令。

处理程序必须先保存后续仍需恢复的状态，再使用这些寄存器。事件源若未被正确清除或确认，返回后可能立即再次产生请求。

### 3.5 返回过程

异常或中断返回指令通常以受控方式恢复：

- 原处理器模式；
- 原中断允许和优先级状态；
- 原 `PC` 或规定的返回位置；
- 其他由硬件入口机制保存的状态。

它通常不能简单地用普通过程调用的 `RET` 代替，因为普通返回一般不会完整恢复特权级和 `PSW`。

不同事件的返回位置通常为：

| 事件类型 | 典型返回位置 |
| --- | --- |
| 故障 | 引发故障的当前指令，以便重新执行 |
| 陷阱 | 已完成指令的顺序后继指令 |
| 外部中断 | 被中断程序的下一条待执行指令 |
| 终止 | 通常不返回原程序 |

### 3.6 精确异常（扩展）

精确异常要求处理器在异常入口呈现一个明确的体系结构状态：

- 以体系结构规定的异常断点为界，断点之前应完成的指令均已提交结果；
- 断点之后的指令没有留下不应出现的体系结构状态修改；
- 保存的断点能够明确指出应重新执行或继续执行的位置。

对故障而言，引发故障的指令通常尚未完成，应能重新执行；对陷阱而言，引发陷阱的指令通常已经完成，返回位置是其顺序后继指令。

这一要求使操作系统能够可靠地恢复程序。流水线或乱序执行处理器内部可以提前或并行执行多条指令，但对软件呈现的异常状态仍应符合体系结构规定。

### 3.7 中断嵌套

若处理程序运行期间允许响应另一个更高处理优先级的中断，就形成中断嵌套。支持嵌套通常需要：

- 分层保存每一级断点和现场；
- 设置合适的中断屏蔽字或当前优先级；
- 保证高优先级事件处理完成后，按后进先出顺序恢复先前现场。

若处理程序尚未保存必要现场就开放中断，新中断可能破坏原处理程序状态。因此，允许嵌套的时机必须谨慎安排。

## 4. 408 常见考法与易错点

| 考查内容 | 分析要点 |
| --- | --- |
| 异常与中断 | 根据事件来源和同步性判断 |
| 异常分类 | 根据返回位置与可恢复性区分故障、陷阱和终止 |
| 中断分类 | 区分可屏蔽/不可屏蔽、向量/非向量中断 |
| 响应条件 | 检查请求、允许位、优先级和可响应时刻 |
| 断点与现场 | 断点只是现场的一部分，区分硬件和软件保存 |
| 中断向量 | 区分类型号、向量表项和处理程序本身 |
| 优先级 | 区分响应优先级与处理优先级 |
| 返回位置 | 故障通常重执行，陷阱和外部中断通常继续后继指令 |

常见错误包括：

- 把所有名为“软件中断”的指令都归为外部异步中断；
- 认为外部中断请求一出现，CPU 就在任意微操作中间立即跳转；
- 认为所有异常都能处理后返回原程序；
- 认为缺页后从下一条指令继续，而不是重新执行引发缺页的指令；
- 把中断向量、中断类型号和中断处理程序混为一谈；
- 认为屏蔽中断等于设备已经撤销中断请求；
- 认为不可屏蔽中断可以在任意时刻破坏当前硬件状态；
- 把保存断点等同于保存全部现场；
- 认为异常中断返回可以一律使用普通函数返回指令；
- 混淆响应优先级和处理优先级；
- 把 DMA 当成一种中断。DMA 是外设与主存之间的数据传送机制，但完成或出错时可以用中断通知 CPU。

## 5. 本节小结

异常和中断都通过受控的控制转移处理特殊事件，但判断方法不同：异常通常与当前指令同步，外部中断通常与当前指令异步。

分析相关问题时，应依次确定：

$$
\text{事件来源}
\longrightarrow
\text{事件类别}
\longrightarrow
\text{是否允许响应}
\longrightarrow
\text{保存何种状态}
\longrightarrow
\text{处理程序入口}
\longrightarrow
\text{返回位置}
$$

故障、陷阱和终止的核心区别在于异常发生阶段、可恢复性及返回位置；外部中断的核心则是请求、屏蔽、优先级、向量和指令边界上的响应。
