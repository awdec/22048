<h1><center>第一节 I/O 接口</center></h1>

## 1. I/O 接口的功能


| 功能 | 解决的问题 | 典型实现 |
| --- | --- | --- |
| 地址译码 | CPU 当前访问哪个接口、哪个端口 | 地址译码与片选逻辑 |
| 命令控制 | CPU 如何启动和控制外设 | 控制寄存器、时序控制逻辑 |
| 数据缓冲 | 主机和外设速度不匹配 | 输入、输出数据寄存器或缓冲区 |
| 状态反馈 | CPU 如何知道设备是否就绪或出错 | 状态寄存器 |
| 格式转换 | 两侧数据与信号形式不同 | 串并转换、电平和编码转换 |
| 请求产生 | 如何通知 CPU 或 DMA 控制器 | 中断请求、DMA 请求逻辑 |

## 2. I/O 接口的基本结构

### 2.1 总体结构

- 数据缓冲寄存器：暂存 CPU 与外设之间传送的数据
- 状态寄存器：记录接口及外设的当前状态
- 控制寄存器：保存 CPU 发给外设的控制命令

### 2.2 主机侧接口

I/O 接口的主机侧通常连接系统总线或系统互连，接收以下信息：

| 信息 | 典型方向 | 作用 |
| --- | --- | --- |
| 地址 | CPU 或当前总线主设备到接口 | 选择接口及其内部端口 |
| 数据 | 双向 | 传送输入数据、输出数据、状态或控制字 |
| 读写控制 | 主设备到接口 | 说明本次访问方向 |
| 中断请求 | 接口到 CPU | 通知设备就绪、完成或出错 |
| DMA 请求 | 接口到 DMA 控制器 | 请求成批数据传送 |

### 2.3 外设侧接口

外设侧信号通常可以归纳为：

- **数据信息**：外设输入或输出的数据；
- **状态信息**：就绪、忙、完成、故障等；
- **控制信息**：启动、停止、复位、传送允许等。

系统总线侧和外设侧的信号格式不必相同。I/O 接口正是通过缓冲、转换和控制逻辑把两侧连接起来。

### 2.4 数据端口

数据端口保存 CPU 与外设之间传送的数据。根据传送方向，可以设置：

- 输入数据寄存器；
- 输出数据寄存器；
- 可双向使用的数据寄存器。

输入数据寄存器在 CPU 读取前应保持数据稳定；输出数据寄存器在外设取走前应保持 CPU 写入的数据。读取或写入后是否自动清除某些状态位，由具体接口规定。

### 2.5 状态端口

状态端口主要由 CPU 读取，用于判断外设当前状态。典型状态字可以抽象为：

| 状态位 | 含义示例 |
| --- | --- |
| READY | 可以进行下一次数据传送 |
| BUSY | 设备正在工作 |
| DONE | 一次操作已经完成 |
| ERROR | 操作出错 |
| IRQ | 存在待处理的中断请求 |

### 2.6 控制端口

控制端口主要由 CPU 写入，用于保存命令或工作方式。典型控制内容包括：

- 启动或停止；
- 复位；
- 输入或输出方向；
- 数据格式或工作模式；
- 中断允许；
- 错误恢复命令。

控制端口中的命令可以由接口立即执行，也可以先保存在控制寄存器中，再由控制逻辑按时序作用于外设。

### 2.7 地址译码和控制逻辑

地址译码逻辑根据地址及读写控制信号产生端口选择信号；控制逻辑负责：

- 控制寄存器的读出和写入；
- 产生外设侧控制时序；
- 更新状态位；
- 协调数据缓冲；
- 在需要时产生中断或 DMA 请求。

对 CPU 而言，访问接口的典型过程为：

$$
\text{给出端口地址}
\longrightarrow
\text{地址译码}
\longrightarrow
\text{选择端口}
\longrightarrow
\text{完成读或写}
$$

### 3.1 数据传送方式

### 3.2 主机访问 I/O 设备的控制方式

## 4. I/O 接口及其编址

这里的“接口编址”实质上是为接口中 CPU 可访问的 I/O 端口分配地址。CPU 根据端口地址、读写方向和控制信号选择相应寄存器。

### 4.1 统一编址

统一编址也称**存储器映射 I/O**。I/O 端口与主存单元共同使用同一个地址空间，CPU 使用访存类指令访问 I/O 端口。

基本特点：

- 不需要设置专门的 I/O 指令；
- 可以使用体系结构允许的访存寻址方式访问端口；
- 主存和 I/O 地址由统一地址译码逻辑区分；
- I/O 端口会占用统一地址空间中的一部分地址。

例如，若把某接口的数据、状态和控制端口分别映射到地址 $A$、$A+4$、$A+8$，CPU 可以通过相应的 Load、Store 指令进行访问。这里假定端口宽度和对齐要求使相邻端口间隔为 4 B，实际偏移由具体体系结构决定。

存储器映射 I/O 虽然使用访存指令，但 I/O 端口具有设备语义，读取或写入可能引起状态变化，不能把它简单看成普通 RAM。

### 4.2 独立编址

独立编址也称**隔离 I/O**。I/O 端口使用独立于主存的 I/O 地址空间，CPU 使用专门的输入、输出指令访问端口。

基本特点：

- I/O 地址不占用主存地址空间；
- 指令系统需要提供专门的 I/O 指令；
- 通常使用专门的 I/O 读写控制信号；
- 可用于 I/O 的寻址方式和操作往往不如统一编址灵活。

例如，某些体系结构使用输入指令从 I/O 端口读取数据，使用输出指令向 I/O 端口写入数据。端口号与同数值的主存地址属于不同地址空间，二者不会因为数值相同而指向同一个对象。

若独立 I/O 地址空间使用 $n$ 位端口地址，则理论上最多可以表示：

$$
2^n
$$

个 I/O 端口地址。

### 4.3 两种编址方式对比

| 比较项目 | 统一编址 | 独立编址 |
| --- | --- | --- |
| 地址空间 | I/O 端口与主存共享 | I/O 端口使用独立空间 |
| 访问指令 | 访存类指令 | 专门 I/O 指令 |
| 是否占用主存地址范围 | 是 | 否 |
| 寻址和数据处理能力 | 通常较灵活 | 通常较受限 |
| 控制信号 | 可按存储器映射规则识别 | 通常有专门 I/O 读写控制 |
| 指令系统要求 | 不必增加专门 I/O 指令 | 必须支持 I/O 指令 |

“统一”指地址空间统一，不表示主存与 I/O 端口的硬件行为相同；“独立”指地址空间独立，不表示 I/O 接口不与系统总线连接。
