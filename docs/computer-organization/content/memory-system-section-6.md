<h1><center>第六节 虚拟存储器</center></h1>

虚拟存储器建立在主存—辅助存储器层次之上。它通过硬件地址转换和操作系统管理，让每个程序使用独立、统一的虚拟地址空间，而程序当前活跃的部分才需要驻留在主存中。虚拟地址范围中可以存在尚未映射的空洞，并不要求全部地址都连续映射到物理主存。

本节的知识主线为：

$$
\text{虚拟存储基本概念}
\longrightarrow
\text{页式、段式和段页式组织}
\longrightarrow
\text{地址转换与缺失处理}
\longrightarrow
\text{与 Cache 对比}
$$

## 1. 虚拟存储器的基本概念

### 1.1 虚拟地址与物理地址

程序和 CPU 在执行过程中使用的地址称为**虚拟地址**，也称逻辑地址；主存储器实际接收的地址称为**物理地址**，也称实地址。

| 地址 | 含义 |
| --- | --- |
| 虚拟地址 | 程序所处虚拟地址空间中的地址 |
| 物理地址 | 主存中实际存储单元的地址 |
| 虚拟地址空间 | 一个进程能够形成的全部虚拟地址范围 |
| 物理地址空间 | 机器能够寻址的主存地址范围 |

虚拟地址空间的大小由虚拟地址位数决定，物理地址空间的大小由物理地址位数决定。虚拟地址空间可以大于实际安装的主存容量，但虚拟存储器并不会让所有虚拟地址对应的数据同时存在于主存中。

### 1.2 地址转换

CPU 产生虚拟地址后，存储管理部件 MMU 根据页表或段表等转换结构，把虚拟地址转换为物理地址：

$$
\text{虚拟地址}
\xrightarrow{\text{MMU 和转换表}}
\text{物理地址}
\longrightarrow
\text{主存访问}
$$

地址转换由硬件与操作系统共同支持：

- 硬件完成常规地址转换、权限检查，并在转换失败时产生异常；
- 操作系统建立和维护地址映射，在缺页或缺段时调入内容，并执行替换、保护和回收。

### 1.3 虚拟存储器的作用

虚拟存储器不仅用于扩展程序可用的地址空间，还具有以下作用：

- 让程序的虚拟地址布局不必与物理主存位置相同；
- 只把当前需要的部分调入主存，提高主存利用率；
- 为不同进程提供相互隔离的地址空间；
- 通过权限位实现读、写、执行保护；
- 允许多个进程共享代码页、共享库或共享数据区域；
- 简化程序装入、重定位和内存分配。

### 1.4 局部性与按需调入

虚拟存储器能够有效工作，同样依赖时间局部性和空间局部性。程序在一段时间内只集中访问少量页面或段，因此系统只需把当前活跃部分保留在主存中。

按需调入的基本思想是：

- 第一次访问尚未驻留主存的页面或段时产生异常；
- 操作系统从辅助存储器调入所需内容；
- 之后对该内容的访问可以直接在主存中完成；
- 主存空间不足时，选择暂时不活跃的内容换出。

如果程序缺乏局部性并频繁发生页面换入换出，会出现抖动，系统性能会显著下降。

### 1.5 转换、缺失与异常

需要区分三个概念：

- **TLB 未命中**：TLB 中没有所需页表项，需要继续查询页表，不一定缺页；
- **页表命中**：页表项表明页面已经在主存，可以完成地址转换；
- **缺页**：页表项表明页面不在主存，需要操作系统从外存调入。

因此：

$$
\text{TLB 未命中}
\not\Rightarrow
\text{缺页}
$$

而权限不足、地址越界等情况虽然也会产生异常，但不属于“所需页面不在主存”导致的缺页。

## 2. 页式虚拟存储器

页式虚拟存储器把虚拟地址空间划分为大小相等的**虚拟页**，把物理主存划分为同样大小的**页框**，也称物理页框。任意虚拟页可以装入任意空闲页框。

### 2.1 页、页框和地址格式

由于页和页框大小相同，虚拟地址和物理地址具有相同位数的页内偏移字段：

$$
\text{虚拟地址}
=
\underbrace{\text{虚拟页号 VPN}}_{\text{用于查页表}}
\quad
\underbrace{\text{页内偏移}}_{d\text{ 位}}
$$

$$
\text{物理地址}
=
\underbrace{\text{物理页框号 PPN}}_{\text{页表给出}}
\quad
\underbrace{\text{页内偏移}}_{d\text{ 位}}
$$

若页面大小为 $P=2^d$ 字节并按字节编址，则页内偏移占 $d$ 位。

对虚拟地址 $VA$：

$$
VPN
=
\left\lfloor\frac{VA}{P}\right\rfloor,
\qquad
Offset=VA\bmod P
$$

页表给出物理页框号 $PPN$ 后：

$$
PA=PPN\times P+Offset
$$

地址转换只替换页号，页内偏移在转换前后保持不变。

### 2.2 页表与页表项

页表记录虚拟页号到物理页框号的映射。每个进程通常拥有自己的页表，页表存放在主存中，页表基址寄存器保存当前页表的起始位置。

页表项常包含：

| 字段 | 作用 |
| --- | --- |
| 物理页框号 | 指明虚拟页当前位于哪个页框 |
| 存在位或有效位 | 表明该页当前是否驻留主存；具体名称按题目定义 |
| 修改位 | 表明页面调入后是否被写过，换出时决定是否写回外存 |
| 访问位 | 记录页面近期是否被访问，可辅助页面替换 |
| 保护位 | 控制页面是否允许读、写或执行 |

有些体系结构会分别设置“地址映射是否合法”的有效位和“页面是否驻留主存”的存在位。408 题目常用一个有效位表示是否在主存，做题时应服从题目的字段定义。

### 2.3 基本地址转换过程

不考虑 TLB 时，页式地址转换过程如下：

1. CPU 产生虚拟地址，拆分出 VPN 和页内偏移。
2. 用 VPN 索引当前进程的页表。
3. 检查页表项的存在位和访问权限。
4. 页面在主存且权限合法时，取得物理页框号 PPN。
5. 将 PPN 与原页内偏移拼接，形成物理地址。
6. 使用物理地址访问主存或物理地址 Cache。

例如，页面大小为 $4\text{ KiB}=2^{12}\text{ B}$，虚拟地址为 `0x12345ABC`，则：

$$
VPN=0x12345,
\qquad
Offset=0xABC
$$

若页表查得物理页框号为 `0x2A6C`，则物理地址为：

$$
PA=0x02A6CABC
$$

### 2.4 TLB

TLB 是 Translation Lookaside Buffer，通常译为快表。它保存近期使用的一部分页表项，是页表的高速缓存，不保存程序的普通指令和数据。

含 TLB 的地址转换过程如下：

1. 用 VPN 查询 TLB。
2. TLB 命中且权限合法时，直接得到 PPN。
3. TLB 未命中时，查询主存中的页表。
4. 若页表项表明页面在主存，把相应转换装入 TLB，再访问目标数据。
5. 若页表项表明页面不在主存，产生缺页异常。

| 情况 | 含义 | 是否缺页 |
| --- | --- | --- |
| TLB 命中 | 快表中已有有效地址转换 | 否 |
| TLB 未命中、页表项存在 | 需要查询页表并回填 TLB | 否 |
| TLB 未命中、页表项不存在 | 页面不在主存 | 是 |

::: warning TLB 命中不等于 Cache 命中
TLB 命中只说明快速获得了物理页框号；真正访问的指令或数据是否在 Cache 中，还要由 Cache 的标记和有效位另行判断。
:::

### 2.5 含 TLB 的访问时间

在简化的串行访问模型中，设查询 TLB 需要 $T_L$，访问一次主存需要 $T_M$，TLB 命中率为 $h$，并假设采用一级页表且不发生缺页：

- TLB 命中：$T_L+T_M$；
- TLB 未命中：$T_L+2T_M$，其中一次访问页表，一次访问目标数据。

平均访问时间为：

$$
EAT
=
h(T_L+T_M)
+
(1-h)(T_L+2T_M)
$$

即：

$$
EAT=T_L+(2-h)T_M
$$

如果页表为多级、TLB 与 Cache 并行查询，或者题目对各级时间有不同定义，应按照题设重新列式，不能机械套用该公式。

### 2.6 缺页处理

当页表项表明所需页面不在主存时，MMU 触发缺页异常，操作系统接管处理：

1. 保存发生缺页时的处理器状态。
2. 检查虚拟地址是否合法以及访问权限是否正确。
3. 在辅助存储器中找到所需页面。
4. 若有空闲页框，直接分配；否则选择一个牺牲页面。
5. 若牺牲页面的修改位为 $1$，先把它写回外存。
6. 把所需页面读入选定页框。
7. 更新页表，并使相关旧 TLB 项失效或更新。
8. 恢复进程并重新执行引发缺页的指令。

缺页需要访问外存，其代价通常远高于 TLB 未命中和 Cache 未命中。因此虚拟存储器设计必须尽量降低缺页率。

页面替换常用 FIFO、LRU 或 Clock 等思想，但具体替换算法属于操作系统的重点；计算机组成原理主要关注访问位、修改位以及硬件如何支持缺页检测和地址转换。

### 2.7 多级页表（扩展）

虚拟地址空间较大时，单级页表可能占用大量连续主存。多级页表把虚拟页号进一步划分为多级索引，只为实际使用的虚拟地址区域建立下级页表。

例如，两级页表的虚拟地址可以划分为：

$$
\text{一级页号}
\quad
\text{二级页号}
\quad
\text{页内偏移}
$$

多级页表能够减少未使用地址区域对应的页表空间，但 TLB 未命中时可能需要多次访问页表。TLB 可以把最终页表项缓存起来，减少多级查询的平均开销。

### 2.8 页面大小的影响（扩展）

| 页面增大后的影响 | 说明 |
| --- | --- |
| 页表项数量减少 | 相同虚拟空间需要的虚拟页数减少 |
| 页内偏移位数增加 | 页号位数相应减少 |
| 一次缺页传输量增大 | 有利于连续访问，但缺页服务时间可能增加 |
| 页内碎片可能增加 | 页末未使用空间可能更多 |
| TLB 覆盖范围增大 | 相同 TLB 项数可以覆盖更大的地址范围 |

页面大小同样需要在页表开销、局部性、缺页代价和内部碎片之间折中。

## 3. 段式虚拟存储器

段式虚拟存储器按照程序的逻辑结构划分地址空间。一个程序可以包含代码段、数据段、堆栈段和共享段等，每个段的长度可以不同。

### 3.1 段式地址结构

段式虚拟地址由段号和段内偏移组成：

$$
\text{虚拟地址}
=
\underbrace{\text{段号}}_{s}
\quad
\underbrace{\text{段内偏移}}_{d}
$$

段号用于索引段表，段内偏移表示目标内容在该段中的相对位置。

### 3.2 段表与段表项

段表基址寄存器指向当前进程的段表。段表项通常包含：

| 字段 | 作用 |
| --- | --- |
| 段基址 | 该段在主存中的起始物理地址 |
| 段长或界限 | 规定合法段内偏移范围 |
| 存在位 | 表明该段当前是否在主存 |
| 保护信息 | 规定段的读、写、执行权限 |
| 共享信息 | 支持多个进程共享同一逻辑段 |

不同段可以具有不同长度和不同权限。例如，代码段可以只读并允许执行，数据段可以允许读写。

### 3.3 段式地址转换

段式地址转换过程如下：

1. 根据段号索引段表，取得相应段表项。
2. 检查段号是否合法、段是否在主存以及访问权限。
3. 检查段内偏移是否满足：

$$
0\leq d<\text{段长}
$$

4. 检查通过后，形成物理地址：

$$
PA=\text{段基址}+d
$$

若段内偏移不小于段长，就发生越界异常，不能继续形成物理地址。

例如，某段基址为 `0x40000`，段长为 `0x3000`，段内偏移为 `0x120`，则：

$$
PA=0x40000+0x120=0x40120
$$

该偏移小于段长，因此访问合法。

### 3.4 段式存储的特点

优点：

- 分段与程序的逻辑结构一致；
- 便于按段进行保护和共享；
- 每个段可以独立增长或改变权限；
- 段内地址从 $0$ 开始，便于程序模块化。

缺点：

- 段长不固定，物理主存需要为每个段分配连续空间；
- 段的装入和换出会产生外部碎片；
- 可能需要通过紧凑等方法整理零散空闲空间；
- 可变长度段的分配与替换比固定大小分页复杂。

纯分段基本避免了固定页面末尾产生的页内碎片，但会产生外部碎片。

## 4. 段页式虚拟存储器

段页式虚拟存储器先按照程序的逻辑结构分段，再把每个段划分为大小相同的页。它试图同时获得分段便于保护、共享的优点和分页便于离散分配的优点。

### 4.1 段页式地址结构

段页式虚拟地址由三部分组成：

$$
\text{虚拟地址}
=
\underbrace{\text{段号}}_{s}
\quad
\underbrace{\text{段内页号}}_{p}
\quad
\underbrace{\text{页内偏移}}_{d}
$$

- 段号选择该段对应的段表项；
- 段内页号选择该段页表中的页表项；
- 页内偏移在地址转换前后保持不变。

### 4.2 段表和页表

段页式系统中，每个进程有一张段表，每个段通常拥有自己的页表。

段表项通常保存：

- 该段页表的物理基址；
- 该段包含的页数或段长；
- 存在位和保护信息。

页表项通常保存：

- 物理页框号；
- 存在位、修改位和访问位；
- 页级保护或其他控制信息。

### 4.3 段页式地址转换

不考虑 TLB 时，地址转换过程如下：

1. 用段号查询段表，获得该段页表的基址和段长信息。
2. 检查段号、段内页号和访问权限是否合法。
3. 用段内页号查询该段的页表。
4. 检查目标页是否在主存；若不在则产生缺页异常。
5. 从页表项取得物理页框号。
6. 将物理页框号与页内偏移拼接，形成物理地址。

可以概括为：

$$
\text{段号}
\longrightarrow
\text{段表}
\longrightarrow
\text{该段页表基址}
$$

$$
\text{段内页号}
\longrightarrow
\text{页表}
\longrightarrow
\text{物理页框号}
$$

$$
\text{物理页框号}
+
\text{页内偏移}
\longrightarrow
\text{物理地址}
$$

TLB 可以缓存最终的地址转换结果，减少段表和页表的多次查询开销。

### 4.4 段页式计算示例

设虚拟地址为 $32$ 位，其中段号占 $8$ 位、段内页号占 $12$ 位、页内偏移占 $12$ 位，则：

- 页面大小为 $2^{12}\text{ B}=4\text{ KiB}$；
- 最多可以表示 $2^8=256$ 个段；
- 每段最多包含 $2^{12}=4096$ 页；
- 每段最大虚拟长度为 $4096\times4\text{ KiB}=16\text{ MiB}$。

若某虚拟地址的段号为 $3$、段内页号为 $5$、页内偏移为 `0x2A0`，段表和页表最终查得物理页框号为 `0x1234`，则：

$$
PA=0x1234\times0x1000+0x2A0=0x12342A0
$$

### 4.5 段页式存储的特点

优点：

- 保留分段所体现的程序逻辑结构；
- 可以按段设置保护和共享；
- 每个段按页装入，不要求整个段在物理主存中连续存放；
- 使用固定大小页框，避免纯分段的外部碎片。

缺点：

- 地址转换需要查询段表和页表，过程更复杂；
- 需要同时维护段表和多张页表；
- 每段最后一页仍可能产生页内碎片；
- TLB 未命中时，转换表访问开销可能较大。

### 4.6 段页式与多级页表的区别（扩展）

两者的地址都可能被划分为多个索引字段，但含义不同：

| 对比项 | 段页式 | 多级页表 |
| --- | --- | --- |
| 最高层字段 | 表示程序的逻辑段 | 表示虚拟页号的一部分 |
| 各区域长度 | 不同段可以具有不同长度 | 仍属于统一分页地址空间 |
| 保护和共享 | 便于按逻辑段设置 | 通常按页设置 |
| 下级结构 | 每个段拥有相应页表 | 上级页表指向下级页表 |

不能因为地址中都有多个索引字段，就把段页式理解成普通多级页表。

## 5. 虚拟存储器与 Cache 的比较

> **关联理解：**现行 408 大纲分别要求 Cache 和虚拟存储器的基本原理，但没有把二者比较列为独立考点。本部分用于串联两个存储层次，重点是区分地址转换、命中判断和缺失处理。

虚拟存储器和 Cache 都利用局部性原理，并通过在相邻层次之间保存数据副本改善存储系统效果，但二者解决的问题和管理方法不同。

### 5.1 基本对比

| 对比项 | Cache | 虚拟存储器 |
| --- | --- | --- |
| 所处层次 | CPU—主存 | 主存—辅助存储器 |
| 主要目的 | 缓解 CPU 与主存的速度差异 | 扩展可用地址空间，并支持保护、共享和重定位 |
| 交换单位 | 主存块与 Cache 行 | 页、段或段内页 |
| 地址映射 | 主存块映射到 Cache 行或组 | 虚拟页、段映射到物理页框或主存区域 |
| 管理主体 | 主要由硬件自动管理 | MMU 与操作系统共同管理 |
| 命中判断依据 | 有效位和 Tag | TLB、页表或段表中的转换与存在信息 |
| 未命中后访问层次 | 主存 | 辅助存储器 |
| 缺失处理 | 通常由硬件完成 | 通常触发异常，由操作系统完成 |
| 缺失代价 | 相对较小 | 很大，可能涉及磁盘或 SSD I/O |
| 替换结果 | 可能把脏 Cache 块写回主存 | 可能把修改页面写回外存 |
| 程序地址空间 | 不负责改变程序看到的地址空间 | 建立虚拟地址到物理地址的转换 |

### 5.2 相同点

- 都利用时间局部性和空间局部性；
- 都只在较快层保存较慢层中的一部分内容；
- 都需要地址映射、有效状态和替换机制；
- 修改过的副本在被替换时都可能需要写回下一层；
- 容量、块大小或页面大小以及替换策略都会影响性能。

### 5.3 关键区别

Cache 的核心目标是提高访存速度，即使没有 Cache，程序仍可使用相同的主存物理地址运行，只是访问更慢。

虚拟存储器会改变程序使用地址的方式。CPU 产生虚拟地址，必须经过地址转换才能得到用于访问物理主存的地址；页面不在主存时还需要操作系统从外存调入。

Cache 未命中通常是正常硬件事件，处理时间较短；缺页需要异常处理和外存访问，代价可相差多个数量级。因此页面替换比 Cache 替换更强调避免错误淘汰活跃内容。

### 5.4 TLB、Cache 和页表的关系

在采用物理地址 Cache 的简化模型中，一次访存的基本路径为：

$$
\text{虚拟地址}
\longrightarrow
\text{TLB 或页表}
\longrightarrow
\text{物理地址}
\longrightarrow
\text{Cache}
\longrightarrow
\text{主存}
$$

三个结构保存的内容不同：

| 结构 | 保存的主要内容 |
| --- | --- |
| TLB | 虚拟页号到物理页框号的近期转换 |
| 页表 | 虚拟页到物理页框的完整或分级映射及控制信息 |
| 数据 Cache | 主存中近期使用的指令或数据块 |

因此：

- TLB 命中不保证数据 Cache 命中；
- TLB 未命中不等于缺页；
- Cache 未命中不表示页面不在主存；
- 只有页表或段页结构表明页面不在主存时才发生缺页。

实际处理器还可能采用虚拟索引、物理标记等优化，使 TLB 与 Cache 的部分查询并行进行；408 基础题通常按题目给出的串行或并行模型计算。

## 6. 408 常见考法与易错点

| 考点 | 解题入口 |
| --- | --- |
| 虚拟与物理地址 | 分清程序产生的地址和主存实际使用的地址 |
| 页式地址划分 | 页大小决定页内偏移位数，其余为虚拟页号 |
| 页式地址转换 | 页表替换页号，页内偏移保持不变 |
| TLB | 先判断 TLB 是否命中，再判断页表项是否存在 |
| 缺页处理 | 检查存在位、修改位、调页和页表更新过程 |
| 段式转换 | 先检查偏移是否小于段长，再用基址加偏移 |
| 段页式转换 | 依次查询段表和页表，最后拼接页框号与偏移 |
| Cache 对比 | 区分两者的层次、目的、交换单位和缺失处理者 |

特别注意：

- 虚拟地址由 CPU 产生，物理地址用于访问主存。
- 页大小等于页框大小，所以页内偏移在地址转换前后不变。
- TLB 保存页表项或地址转换，不保存普通程序数据。
- TLB 未命中后可能在页表中找到有效映射，不一定发生缺页。
- 缺页与地址越界、权限异常的原因不同。
- 段式地址转换必须进行段长越界检查，合法偏移满足 $0\leq d<\text{段长}$。
- 纯分段可能产生外部碎片；分页和段页式可能产生页内碎片。
- 多级页表仍然是分页，不能与段页式混为一谈。
- 缺页代价远高于 Cache 未命中，二者不能使用相同数量级的访问时间分析。
- 修改页面被换出时需要写回外存，未修改页面通常可以直接丢弃其主存副本。

## 7. 本节小结

虚拟存储器的核心是把程序使用的虚拟地址转换成主存使用的物理地址，并只让当前活跃内容驻留主存：

$$
\text{页式：虚拟页号查页表，保留页内偏移}
$$

$$
\text{段式：段号查段表，基址加合法段内偏移}
$$

$$
\text{段页式：段号查段表，页号查页表，保留页内偏移}
$$

做题时应先识别存储管理方式，再划分地址字段，按照 TLB、页表或段表的查询顺序判断命中、缺页、越界和最终物理地址。
