<h1><center>第三节 数据通路的功能和基本结构</center></h1>

数据通路是 CPU 中执行数据传送与数据加工的部件及其连接。机器指令被分解成微操作后，控制器通过控制信号驱动数据通路，使数据在寄存器、运算部件和主存接口之间流动。

可以把二者的分工概括为：

$$
\text{数据通路决定“数据能够怎样流动和加工”}
$$

$$
\text{控制器决定“何时让哪条通路完成何种操作”}
$$

## 1. 数据通路的功能

### 1.1 数据传送

数据通路要支持 CPU 内部及 CPU 与主存之间的信息传送，包括：

- 寄存器之间传送数据；
- 从寄存器读取操作数并把结果写回寄存器；
- 在 `PC、IR、MAR、MDR` 等专用寄存器之间传送信息；
- 通过主存接口读取机器指令和数据，或把数据写入主存。

例如：

$$
R_1\leftarrow R_2
$$

表示把 `R2` 的内容送入 `R1`。这里改变的是 `R1`，`R2` 的内容通常保持不变。

### 1.2 数据加工

数据通路通过 ALU、移位器和扩展部件等完成数据加工，例如：

- 算术和逻辑运算；
- 逻辑移位和算术移位；
- 符号扩展或零扩展；
- 比较并产生状态标志；
- 计算有效地址和转移目标地址。

例如：

$$
R_1\leftarrow R_2+R_3
$$

需要把 `R2、R3` 送入 ALU，选择加法功能，再把结果写入 `R1`。

### 1.3 支持指令执行

取指、运算、访存和控制转移都依赖数据通路。例如：

| 指令或阶段 | 典型数据流 |
| --- | --- |
| 取指 | `PC → MAR → 主存 → MDR → IR` |
| 算术逻辑指令 | `源寄存器 → ALU → 目的寄存器` |
| Load | `有效地址 → MAR → 主存 → MDR → 目的寄存器` |
| Store | `源寄存器 → MDR → 主存`，同时把有效地址送入 `MAR` |
| 转移 | `目标地址形成部件或 ALU → PC` |

一条指令能否在一个时钟周期内完成、需要多少个微操作以及哪些微操作能够并行，都受到数据通路组织方式的影响。

## 2. 数据通路的组成

数据通路通常由状态存储部件、运算部件、互连部件和主存接口部件组成。

### 2.1 状态存储部件

| 部件 | 主要作用 |
| --- | --- |
| 通用寄存器组 `GPR` | 保存操作数、地址和中间结果 |
| `PC` | 保存下一条待取指令地址 |
| `IR` | 保存当前正在译码或执行的指令 |
| `MAR` | 保存当前主存访问地址 |
| `MDR` | 暂存从主存读出或准备写入主存的信息 |
| `PSW` 或标志寄存器 | 保存运算产生的条件码及有关处理器状态 |
| 暂存寄存器 `Y、Z` 等 | 暂存 ALU 输入或结果，通常对机器级程序不可见 |

寄存器在时钟边沿或写使能有效时保存新值，使不同微操作之间能够传递中间状态。

### 2.2 运算部件

常见运算部件包括：

- ALU：完成算术、逻辑、比较等操作；
- 移位器：完成逻辑移位和算术移位；
- 加法器或增量器：用于 `PC` 更新、地址计算等常用操作；
- 符号扩展和零扩展部件：把较短操作数扩展到数据通路宽度；
- 状态标志生成电路：产生零、符号、进位、溢出等标志。

是否为 `PC` 单独设置加法器，是数据通路的设计选择。设置专用加法器可以提高并行性，但会增加硬件资源。

### 2.3 互连部件

互连部件负责在数据通路各部件之间传送信息，常见形式包括：

- 内部总线；
- 点到点专用连接；
- 多路选择器；
- 总线驱动和输出门；
- 寄存器组的读端口和写端口。

传统图中可以用三态门控制哪个部件驱动总线；在许多集成电路实现中，相同的逻辑选择功能也可以由多路选择器完成。分析题目时应依据给出的结构图判断，而不是只凭元件名称判断。

### 2.4 主存接口部件

在经典模型中，CPU 通常通过 `MAR、MDR` 和读写控制信号与主存交换信息：

$$
MAR\leftarrow\text{主存地址}
$$

$$
\text{读：}\quad MDR\leftarrow M[MAR]
$$

$$
\text{写：}\quad M[MAR]\leftarrow MDR
$$

若主存速度慢于 CPU，控制器还要等待存储器完成信号或插入等待周期。`MAR、MDR` 在具体结构图中可能被画在 CPU 内部，也可能被视为主存接口的一部分，其逻辑功能不变。

### 2.5 控制信号

控制信号不负责保存或加工数据，但它们决定数据通路执行什么动作。常见控制信号包括：

| 控制信号 | 作用 |
| --- | --- |
| `Rout` | 允许指定寄存器把内容送上内部通路 |
| `Rin` | 允许指定寄存器接收并保存输入数据 |
| `ALUop` | 选择 ALU 的运算功能 |
| `MUXsel` | 选择多路选择器的输入 |
| `Read、Write` | 控制主存读写 |
| `PCWrite` | 允许更新 `PC` |
| `FlagWrite` | 允许更新状态标志 |

控制器发出的是微命令，数据通路在微命令作用下完成相应微操作。

## 3. 数据通路的组织与分类

### 3.1 按互连方式分类

数据通路按 CPU 内部部件的连接方式，可以分为总线结构和专用结构：

| 组织方式 | 连接特点 | 典型特征 |
| --- | --- | --- |
| 单总线结构 | 多个部件共享一条内部总线 | 硬件少，冲突多，并行性较低 |
| 多总线结构 | 设置两条或更多内部总线 | 可同时传送多个操作数，并行性较高 |
| 专用结构 | 根据功能设置点到点连接或选择网络 | 传送灵活、并行性高，但连接和控制较复杂 |

实际处理器常采用混合结构。例如，寄存器组通过两个读端口和一个写端口连接 ALU，同时 `PC、MAR、MDR` 之间又设置部分专用通路。

### 3.2 单总线、双总线和三总线

- 单总线结构在一个时刻通常只能传送一个源数据。
- 双总线结构可让 ALU 同时得到两个源操作数，但结果写回可能还要占用其中一条总线。
- 三总线结构常用两条总线读取两个源操作数，用第三条总线写回结果。

三总线寄存器组可抽象为：

$$
R_2\xrightarrow{A\text{ 读端口}}ALU,\qquad
R_3\xrightarrow{B\text{ 读端口}}ALU,\qquad
ALU\xrightarrow{C\text{ 写端口}}R_1
$$

因此，`R1←R2+R3` 可能在一个时钟周期内完成。是否真的能单周期完成，还要检查 ALU 延迟、寄存器写入时序和其他资源约束。

### 3.3 内部总线与系统总线

CPU 内部总线连接的是 CPU 内部寄存器和运算部件；系统总线或系统互连用于连接 CPU、主存和 I/O 接口。二者作用范围不同，不能因为都称为“总线”就混为一谈。

### 3.4 组织方式的权衡

| 比较项目 | 单总线 | 多总线 | 专用结构 |
| --- | --- | --- | --- |
| 硬件连接 | 少 | 较多 | 通常最多、最有针对性 |
| 数据传送并行性 | 低 | 较高 | 高 |
| 暂存寄存器需求 | 通常较多 | 相对较少 | 取决于具体连接 |
| 微操作步数 | 通常较多 | 较少 | 可针对常用操作减少 |
| 控制复杂度 | 相对较低 | 较高 | 较高 |
| 灵活性 | 共享性好 | 较好 | 对既定功能高效，修改结构较困难 |

数据通路越宽、端口越多或专用连接越多，通常越容易并行传送数据，但硬件面积、布线和控制复杂度也会增加。

## 4. 单总线结构的数据通路

### 4.1 基本结构

单总线结构中，多个寄存器和 ALU 共享一条 CPU 内部总线。每个可输出部件通过输出控制把数据送上总线，每个可写部件通过输入控制从总线接收数据。

单总线必须遵守：

- 同一时刻只能有一个部件驱动总线，否则会发生总线冲突；
- 同一总线值可以在一个节拍内被多个目的寄存器同时接收；
- 没有直接连接的两个部件之间必须通过总线和必要的暂存寄存器传送；
- 能否在同一节拍读、运算并写入，要根据组合逻辑延迟和寄存器时序判断。

### 4.2 寄存器传送

完成：

$$
R_1\leftarrow R_2
$$

可以在一个节拍发出：

```text
R2out，R1in
```

`R2out` 使 `R2` 驱动总线，`R1in` 使 `R1` 在规定时刻接收总线数据。该操作不会清空 `R2`。

如果要同时完成：

$$
R_1\leftarrow R_2,\qquad R_3\leftarrow R_2
$$

只要结构允许，可以同时发出：

```text
R2out，R1in，R3in
```

因为总线上仍然只有 `R2` 一个数据源。

### 4.3 单总线上的 ALU 运算

ALU 进行双操作数运算时需要同时获得两个输入，但单总线一次只能传送一个源数据，因此通常设置输入暂存寄存器 `Y` 和结果暂存寄存器 `Z`。

完成：

$$
R_1\leftarrow R_2+R_3
$$

可采用：

| 节拍 | 控制信号 | 完成的微操作 |
| --- | --- | --- |
| `T0` | `R2out，Yin` | $Y\leftarrow R_2$ |
| `T1` | `R3out，ALU=ADD，Zin` | $Z\leftarrow Y+R_3$ |
| `T2` | `Zout，R1in` | $R_1\leftarrow Z$ |

`T0` 和 `T1` 不能合并为让 `R2、R3` 同时输出，因为二者会争用同一条总线。`Y、Z` 是数据通路内部暂存寄存器，通常对机器级程序不可见。

### 4.4 单总线上的取指操作

假设 `PC` 的顺序更新也使用共享 ALU，并且常数 $L$ 可以经总线或 ALU 输入选择器送入运算端，取指可以按题目给出的结构安排为类似过程：

| 节拍 | 典型微操作 |
| --- | --- |
| `T0` | $MAR\leftarrow PC$，同时把 $PC$ 保存到 `Y`（结构允许时） |
| `T1` | 发出主存读；送入常数 $L$，令 $Z\leftarrow Y+L$ |
| `T2` | $PC\leftarrow Z$；等待主存完成并令 $MDR\leftarrow M[MAR]$ |
| `T3` | $IR\leftarrow MDR$ |

这里 $L$ 是指令长度对应的地址增量。实际节拍数取决于：

- `PC` 能否同时送入 `MAR` 和 `Y`；
- 主存数据是否经内部总线进入 `MDR`；
- 主存是否需要等待周期；
- 是否另设 `PC` 增量器或专用通路。

因此，不能脱离给定数据通路图死记唯一的取指微操作序列。

### 4.5 单总线上的访存操作

读取主存数据并写入 `R1` 可抽象为：

```text
MAR ← EA
发出 Read，等待主存完成
MDR ← M[MAR]
R1  ← MDR
```

把 `R1` 写入主存可抽象为：

```text
MAR ← EA
MDR ← R1
发出 Write：M[MAR] ← MDR
```

`MAR←EA` 与 `MDR←R1` 能否并行，取决于 `EA` 和 `R1` 是否需要在同一时刻占用单总线。若二者都只能通过同一总线传送，就必须分开安排。

## 5. 专用结构的数据通路

### 5.1 基本思想

专用结构为常用数据传送设置点到点连接或专门的选择网络，使数据不必全部经过同一条共享总线。例如：

- `PC` 到 `MAR` 设置直接通路；
- `MDR` 到 `IR` 设置直接通路；
- 寄存器组的两个读端口分别连接 ALU 的两个输入；
- ALU 结果通过专门写回通路连接寄存器组；
- `PC` 设置独立增量器。

专用结构不等于每两个部件之间都必须直接相连。为了控制连接数量，通常使用多路选择器从多个候选输入中选择一个。

### 5.2 典型运算通路

若寄存器组有两个读端口和一个写端口，则：

$$
R_1\leftarrow R_2+R_3
$$

可以使用以下控制：

```text
A 端口选择 R2
B 端口选择 R3
ALUop 选择 ADD
写端口选择 R1，并使能写入
```

两个源操作数通过不同通路同时到达 ALU，结果再经写回通路进入 `R1`，不需要像单总线结构那样先把一个源操作数写入 `Y`。

### 5.3 并行微操作

若通路和功能部件相互独立，专用结构可以在同一节拍完成多个微操作，例如：

$$
MAR\leftarrow PC,\qquad PC\leftarrow PC+L
$$

前提是 `PC` 输出能同时到达 `MAR` 和独立增量器，而且更新后的 `PC` 不会破坏 `MAR` 所需的旧值。判断微操作能否并行时，应同时检查：

1. 是否具有所需连接；
2. 是否争用同一功能部件或写端口；
3. 源数据是否在节拍开始时已经有效；
4. 写入时序是否满足要求。

### 5.4 特点与局限

专用结构的典型优点：

- 数据传送并行性高；
- 常用微操作所需节拍数少；
- 可以针对关键路径优化性能。

典型代价：

- 数据连接、多路选择器和端口数量增加；
- 控制信号更多，控制逻辑更复杂；
- 硬件面积和布线成本较高；
- 修改或扩展数据通路时可能需要重新设计连接。

现代处理器通常综合使用多端口寄存器组、局部总线、专用连接和选择网络，因此实际结构往往是多种组织方式的组合。

## 6. 408 常见考法与易错点

| 考查内容 | 分析要点 |
| --- | --- |
| 部件识别 | 判断寄存器、ALU、总线、多路选择器和主存接口的作用 |
| 微操作序列 | 根据给定连接写出寄存器传送和运算步骤 |
| 控制信号 | 把每个微操作转换为输出、输入、ALU 和主存控制信号 |
| 总线冲突 | 判断同一节拍是否有多个部件同时驱动单总线 |
| 并行操作 | 检查连接、功能部件、端口、数据依赖和写入时序 |
| 周期数 | 根据数据通路限制统计完成一条指令所需节拍数 |
| 结构比较 | 比较单总线、多总线和专用结构的成本与并行性 |

常见错误包括：

- 把数据通路等同于控制器，认为数据通路能自行决定操作时刻；
- 认为单总线在一个节拍内可以由多个源同时驱动；
- 认为单总线只能有一个目的寄存器接收数据；
- 忽略 ALU 双操作数运算对 `Y` 等输入暂存寄存器的需要；
- 看到一组微操作在语义上互不影响，就直接判定能够并行，而不检查硬件连接和资源冲突；
- 把 CPU 内部总线和连接 CPU、主存、I/O 的系统总线混淆；
- 认为专用结构完全不需要多路选择器或共享部件；
- 脱离题目给出的数据通路，死记一套固定微操作序列；
- 混淆 `Load` 与 `Store` 的数据传送方向。

## 7. 本节小结

分析数据通路可以采用统一步骤：

1. 找出数据的源部件和目的部件；
2. 检查两者之间是否存在直接或间接连接；
3. 确定是否需要 ALU、暂存寄存器或主存接口；
4. 按数据依赖和资源冲突划分节拍；
5. 为每个微操作写出相应控制信号。

单总线结构硬件简单但传送冲突较多，专用结构并行性高但连接和控制复杂。无论采用哪种组织方式，正确答案都必须由题目给出的实际数据通路和时序约束推出。
