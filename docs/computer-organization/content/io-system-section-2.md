<h1><center>第二节 I/O 方式</center></h1>

I/O 方式研究 CPU、主存与外设之间如何组织数据传送。选择 I/O 方式时主要考虑三个问题：

1. 外设未就绪时，CPU 是否必须等待；
2. 每个数据是否都要经过 CPU 执行指令搬运；
3. 外设能否在控制部件管理下直接与主存交换数据。

现行 408 要求掌握程序查询、程序中断和 DMA 三种方式。它们并不是简单的“旧方式到新方式”，而是在硬件成本、CPU 开销、响应及时性和数据规模之间作出不同权衡。

## 1. 程序查询方式

### 1.1 基本原理

程序查询方式也称轮询方式。CPU 通过程序读取 I/O 接口的状态端口，判断设备是否就绪；设备未就绪时继续查询，设备就绪后由 CPU 执行数据传送指令。

基本过程为：

$$
\text{启动设备}
\longrightarrow
\text{读取状态}
\longrightarrow
\text{判断就绪}
\longrightarrow
\text{CPU 传送数据}
$$

程序查询方式依靠软件查询状态，不要求接口主动发出中断请求，硬件结构相对简单。

### 1.2 输入过程

以一个输入设备为例：

1. CPU 向控制端口写入启动命令；
2. 外设开始准备数据；
3. CPU 反复读取状态端口；
4. 若就绪位无效，CPU 继续查询；
5. 若就绪位有效，CPU 读取数据端口；
6. 数据先进入 CPU 寄存器，需要时再由程序写入主存；
7. CPU 按接口规定清除状态或启动下一次传送。

数据通路可以概括为：

$$
\text{外设}
\longrightarrow
\text{I/O 接口数据端口}
\longrightarrow
\text{CPU 寄存器}
\longrightarrow
\text{主存}
$$

最后一步是否需要执行，取决于程序是否要把数据保存在主存中。

### 1.3 输出过程

输出过程通常为：

1. CPU 查询输出接口是否可以接收新数据；
2. 接口未就绪时继续等待或查询；
3. 接口就绪后，CPU 把数据写入输出数据端口；
4. 接口把数据送给外设；
5. 外设处理完成后更新状态。

数据通路可以概括为：

$$
\text{主存或 CPU 寄存器}
\longrightarrow
\text{CPU}
\longrightarrow
\text{I/O 接口数据端口}
\longrightarrow
\text{外设}
$$

输入和输出都由 CPU 执行指令完成每次数据传送，因此数据会经过 CPU 的数据通路。

### 1.4 轮询程序

简化的输入轮询程序可以表示为：

~~~text
向控制端口写入启动命令
repeat
    读取状态端口
until READY = 1
读取数据端口
保存或处理数据
~~~

接口状态位在读取数据后是否自动清除、是否要由软件显式清除，取决于具体接口，不能一概而论。

### 1.5 查询间隔与查询顺序（基础补充）

连续忙等待会尽快发现设备就绪，但会占用大量 CPU 时间。若程序隔一段时间再查询一次，可以降低查询开销，但会增加设备就绪到 CPU 开始处理之间的延迟。

当程序依次查询多个设备时，查询顺序会形成一种软件优先次序：排在前面的设备通常更早获得检查机会。但实际响应还取决于各设备的就绪时刻和查询程序。

### 1.6 特点与适用场景

优点：

- 接口和控制逻辑简单；
- 软件流程直观，容易实现；
- 不需要中断控制或 DMA 控制器；
- 在等待时间很短、设备数量少时开销可以接受。

缺点：

- 忙等待期间 CPU 难以执行其他有效工作；
- 每个数据都需要 CPU 执行指令传送；
- 设备很慢或就绪时间不确定时，CPU 利用率较低；
- 高速成批传送会产生大量查询和搬运指令。

适合场景：

- 简单或低成本系统；
- 数据量较少、等待时间较短；
- 启动阶段或某些不便使用中断的场合；
- 对响应时间可预测且 CPU 没有其他任务的控制场景。

不能笼统地认为程序查询在任何情况下都低效。若设备几乎立即就绪，轮询可能比进入和退出中断更直接；是否合适取决于等待时间、数据量和系统负载。

## 2. 程序中断方式

### 2.1 基本原理

程序中断方式中，CPU 启动外设后可以继续执行原程序。外设就绪、操作完成或发生错误时，由 I/O 接口提出中断请求；CPU 在满足响应条件时暂停当前程序，转去执行中断服务程序。

$$
\text{CPU 启动外设}
\longrightarrow
\text{CPU 执行其他程序}
\longrightarrow
\text{接口提出中断请求}
\longrightarrow
\text{CPU 执行中断服务程序}
$$

中断方式减少了 CPU 等待设备的时间，但数据传送通常仍由 CPU 在中断服务程序中执行。它没有实现外设与主存之间完全脱离 CPU 的直接成批传送。

### 2.2 中断请求与响应条件

I/O 接口通常在设备就绪、传送完成或发生错误时设置相应状态，并提出中断请求。CPU 响应一个可屏蔽外部中断通常需要：

- 存在有效且尚未处理的中断请求；
- CPU 处于允许响应中断的状态；
- 该中断源未被屏蔽；
- 中断优先级满足当前响应条件；
- CPU 到达体系结构规定的中断响应时点。

外部可屏蔽中断通常在一条指令执行结束后、下一条指令开始前响应，而不是在任意微操作中间立即转移。中断请求何时被检测、是否锁存以及精确响应规则由具体体系结构规定。

### 2.3 程序中断的完整过程

程序中断过程可以分为请求、硬件响应和软件处理三个阶段。

#### 中断请求

1. 外设完成准备或发生事件；
2. I/O 接口设置状态位；
3. 接口向 CPU 提出中断请求。

#### 硬件响应

CPU 决定响应后，硬件通常需要：

1. 对中断进行判优并发出中断响应；
2. 保存断点，即保存被中断程序的后继指令地址；
3. 按体系结构规定保存或更新程序状态；
4. 暂时禁止某些中断或设置相应屏蔽状态；
5. 取得中断服务程序入口地址并写入 PC。

硬件自动保存哪些内容由体系结构规定。不能默认所有通用寄存器都由硬件自动保存。

#### 软件处理

中断服务程序通常需要：

1. 保存尚未由硬件保存、且服务程序会破坏的寄存器现场；
2. 必要时识别具体中断源；
3. 读取状态，执行数据传送或错误处理；
4. 按接口要求清除中断请求或完成标志；
5. 恢复软件保存的现场；
6. 执行中断返回指令，恢复原程序。

应区分：

- **断点**：被中断程序恢复执行所需的 PC 值；
- **现场**：寄存器、程序状态等运行环境；
- **中断服务**：真正处理设备数据或事件的程序。

### 2.4 中断向量与中断源识别（关联复习）

中断服务程序入口可以通过不同方式确定：

- **向量中断**：硬件提供中断类型号、向量号或入口信息，CPU 据此取得服务程序入口；
- **非向量中断**：多个中断源可能进入公共入口，再由软件查询状态确定中断源。

“中断向量”在不同体系结构中可以指服务程序入口地址，也可以指用于查找入口地址的信息。做题时应服从题目定义。

向量中断通常能更快定位服务程序；非向量方式硬件可以较简单，但软件识别中断源需要额外时间。

### 2.5 中断优先级

多个中断源同时请求时，需要决定先响应哪个请求。应区分两类优先级：

| 优先级 | 解决的问题 |
| --- | --- |
| 响应优先级 | 多个请求同时到来时，CPU 先响应哪个 |
| 处理优先级 | 正在处理一个中断时，哪些新中断可以嵌套进入 |

响应优先级通常由硬件判优逻辑决定；处理优先级还受到中断屏蔽和是否允许中断嵌套的影响。二者可能相同，也可能不同。

### 2.6 中断屏蔽

中断屏蔽用于暂时禁止某些可屏蔽中断被 CPU 响应。接口或中断控制器可以具有中断允许位，CPU 还可以使用中断屏蔽字控制各中断源。

中断屏蔽字中的每一位通常对应一个中断源，但“1 表示屏蔽”还是“1 表示允许”没有统一规定，应以题目定义为准。

屏蔽一个中断通常表示暂不响应，并不一定意味着该请求被丢弃。接口可以保持请求标志，待解除屏蔽后再处理；具体行为仍由硬件规定。

### 2.7 多重中断

在一个中断服务程序执行期间，又出现新的中断请求，称为多重中断情形。

#### 单重中断

若处理中断期间关闭中断或屏蔽所有其他中断，则必须在当前服务结束后才能响应新的中断。其控制简单，但紧急事件的响应时间可能较长。

#### 中断嵌套

若服务程序在保存必要现场并设置好屏蔽关系后重新允许中断，则符合优先级条件的新请求可以打断当前中断服务程序，形成中断嵌套。

典型嵌套关系为：

$$
\text{主程序}
\rightarrow
\text{低优先级中断服务}
\rightarrow
\text{高优先级中断服务}
\rightarrow
\text{低优先级中断服务}
\rightarrow
\text{主程序}
$$

“高优先级中断一定能打断低优先级中断”并非无条件成立。还必须允许中断嵌套，并且新的中断没有被屏蔽。

为了正确嵌套，服务程序通常应先保护必要现场和设置屏蔽状态，再重新开中断；退出时按相反顺序恢复。

### 2.8 数据传送过程

以中断输入为例：

1. CPU 启动设备后执行其他程序；
2. 外设把数据送入接口数据端口；
3. 接口设置就绪状态并提出中断请求；
4. CPU 响应并进入中断服务程序；
5. 服务程序读取数据端口；
6. CPU 根据程序需要把数据写入主存；
7. 服务程序清除或确认接口状态后返回。

数据通路仍为：

$$
\text{外设}
\longrightarrow
\text{I/O 接口}
\longrightarrow
\text{CPU}
\longrightarrow
\text{主存}
$$

与程序查询的主要区别不是数据是否经过 CPU，而是 CPU 不必在设备准备期间持续轮询。

### 2.9 特点与适用场景

优点：

- CPU 与外设准备过程可以并行；
- 设备就绪后主动通知 CPU，减少忙等待；
- 对随机、低频或不可预测事件响应较及时；
- 多个设备可以通过优先级和屏蔽机制协调请求。

缺点：

- 需要中断请求、判优、入口定位等硬件支持；
- 每次中断都有响应、现场保护和返回开销；
- 数据传送通常仍由 CPU 逐次完成；
- 中断过于频繁会占用大量 CPU 时间。

适合场景：

- 键盘、鼠标等低速随机输入；
- 外设完成、错误和状态变化通知；
- 数据量较少、到达时间不确定的传送；
- 需要比周期性查询更及时响应的事件。

## 3. DMA 方式

### 3.1 基本原理

DMA（Direct Memory Access，直接存储器存取）方式允许外设在 DMA 控制器管理下直接与主存交换数据。数据不需要由 CPU 对每个字或字节执行输入、输出指令搬运，也不经过 CPU 的通用寄存器。

$$
\text{外设}
\longleftrightarrow
\text{I/O 接口或 DMA 数据通路}
\longleftrightarrow
\text{主存}
$$

CPU 仍要参与：

- 初始化 DMA 控制器；
- 启动设备和 DMA 传送；
- 必要时处理 DMA 错误；
- 传送结束后处理完成通知。

因此，DMA 是减少 CPU 对每个数据的参与，不是完全不需要 CPU，也不是绕过 I/O 接口、主存或系统互连。

### 3.2 DMA 控制器的基本组成

经典 DMA 控制器通常包含：

| 部件 | 主要作用 |
| --- | --- |
| 主存地址寄存器 | 保存当前或下一次传送的主存地址 |
| 传送计数器 | 保存剩余传送数量或累计传送数量 |
| 数据缓冲寄存器 | 暂存主存与外设之间传送的数据 |
| 设备地址寄存器 | 保存外设端口地址或设备选择信息，具体实现可选 |
| 控制寄存器 | 保存传送方向、数据宽度和 DMA 工作方式 |
| 状态寄存器 | 保存完成、忙和错误等状态 |
| 请求与应答逻辑 | 接收设备请求，并与 CPU 或总线控制逻辑协调 |
| 总线控制逻辑 | 获得总线后产生主存和 I/O 读写控制信号 |

不同系统可以合并或省略某些寄存器。例如，数据也可能通过专用通路直接传送，不一定在 DMA 控制器中长期保存；408 题目应以给出的结构为准。

### 3.3 DMA 初始化

传送开始前，CPU 通过程序设置 DMA 控制器，通常包括：

- 主存起始地址；
- 传送方向；
- 传送的数据个数或总字节数；
- 每次传送的数据宽度；
- 外设地址或通道；
- 采用的 DMA 传送方式；
- 完成或错误中断是否允许。

随后 CPU 启动外设和 DMA 控制器，并继续执行其他程序。

### 3.4 DMA 数据传送过程

典型 DMA 过程可以分为预处理、数据传送和后处理。

#### 预处理

1. CPU 初始化 DMA 控制器；
2. CPU 启动 I/O 设备；
3. 外设准备好数据或准备接收数据后，向 DMA 控制器提出请求。

#### 数据传送

1. DMA 控制器请求并获得总线或主存访问权；
2. DMA 控制器成为总线主设备或获得一次主存访问机会；
3. 按传送方向控制 I/O 接口和主存读写；
4. 完成一个数据单元或一批数据传送；
5. 修改主存地址寄存器；
6. 修改传送计数器；
7. 未达到结束条件时继续等待或发起下一次传送。

#### 后处理

1. 传送计数达到终止条件；
2. DMA 控制器停止传送并更新完成状态；
3. DMA 控制器释放占用的总线资源；
4. 若允许，向 CPU 发出完成或错误中断；
5. CPU 检查结果并执行后续处理。

DMA 结束时通常使用中断通知 CPU，但中断负责“报告完成”，不是让 CPU 重新逐个搬运已经传送的数据。

### 3.5 地址和计数器的变化

每完成一个数据单元，DMA 控制器通常自动更新主存地址和计数器：

$$
\text{主存地址}\leftarrow\text{主存地址}+\text{地址增量}
$$

$$
\text{剩余计数}\leftarrow\text{剩余计数}-1
$$

地址增量取决于编址单位和每次传送的数据量。例如，系统按字节编址、每次传送 4 B 时，连续存放的数据地址通常增加 4，而不是机械地增加 1。

有的计数器从传送总数递减到 0，有的从初值递增到终值，题目还可能规定计数器保存“实际数量”或“数量减 1”。计算时必须使用题目给出的计数规则。

### 3.6 DMA 的主存访问方式

#### 停止 CPU 访存方式

DMA 控制器获得总线后连续传送一批数据，在此期间 CPU 暂停通过相关总线访问主存。

特点：

- DMA 可以连续高速传送；
- 控制相对直接；
- CPU 可能在较长时间内无法访存；
- 适合要求连续传送的数据块。

这类方式也常称成组传送或突发传送，但具体术语应以题目为准。

#### 周期挪用方式

周期挪用也称周期窃取。DMA 控制器每次占用一个或少数几个主存周期完成数据传送，随后归还访问权。

特点：

- CPU 只在与 DMA 访存冲突时短暂停顿；
- DMA 和 CPU 交替竞争主存访问机会；
- DMA 的频繁访问仍会降低 CPU 可用的主存带宽；
- 适合持续但不必长期独占总线的传送。

“周期窃取”窃取的是总线或主存访问周期，不是让 CPU 执行一条 DMA 指令。

#### DMA 与 CPU 交替访存方式

系统把主存访问周期或总线时间片按固定规则分给 CPU 和 DMA。双方按预定节拍交替访问，通常不需要为每次传送临时进行竞争。

特点：

- CPU 和 DMA 获得访问机会的时刻较确定；
- 可以减少临时请求和仲裁开销；
- 需要主存速度和系统时序能够支持这种安排；
- 即使 DMA 暂时没有数据，也可能造成分配时隙利用不足。

> **扩展了解：**不同教材也可能把利用 CPU 不访存时段进行 DMA 传送称为透明 DMA。它与固定交替访存不完全相同，若题目使用该术语，应按照题目给出的时序判断。

### 3.7 三种主存访问方式对比

| 比较项目 | 停止 CPU 访存 | 周期挪用 | 交替访存 |
| --- | --- | --- | --- |
| DMA 占用特点 | 连续占用一段时间 | 每次占用少量周期 | 按固定时隙交替 |
| CPU 受影响 | 可能长时间不能访存 | 冲突时短暂停顿 | 可用访存时隙减少但较规律 |
| DMA 连续性 | 高 | 中 | 由分配节拍决定 |
| 控制特点 | 连续成组传送 | 需要请求和归还访问权 | 预先安排双方时隙 |

### 3.8 DMA 与程序中断的关系

DMA 和中断解决的问题不同：

| 方式 | 核心作用 |
| --- | --- |
| 程序中断 | 外设就绪或事件发生时通知 CPU，由 CPU 执行服务程序 |
| DMA | 让数据在外设与主存之间成批传送，CPU 不逐个搬运 |

DMA 传送过程中可以使用中断：

- 传送完成时通知 CPU；
- 发生错误时请求 CPU 处理；
- 某些系统在传送到一定进度时通知 CPU。

因此，使用 DMA 不排斥使用中断；“DMA 传送”和“DMA 完成中断”属于同一工作过程中的不同环节。

### 3.9 特点与适用场景

优点：

- CPU 不必为每个数据执行搬运指令；
- 适合高速、连续和大批量数据传送；
- 可以显著减少 CPU 的软件开销；
- 外设与主存之间的数据通路更直接。

缺点：

- 需要 DMA 控制器和总线控制逻辑；
- DMA 会占用主存和互连带宽；
- CPU 可能因总线或主存冲突而停顿；
- 初始化和完成处理存在固定开销，小数据量未必划算。

适合场景：

- 磁盘或固态存储器与主存之间的块传送；
- 网卡收发数据块；
- 音频、视频和高速数据采集；
- 其他高速或批量数据传送。

## 4. 三种 I/O 方式的比较与考法

### 4.1 总体比较

| 比较项目 | 程序查询 | 程序中断 | DMA |
| --- | --- | --- | --- |
| 设备未就绪时 CPU | 通常反复查询 | 执行其他程序 | 执行其他程序 |
| 谁发现设备就绪 | CPU 查询状态 | 接口发中断通知 CPU | 接口向 DMA 控制器请求 |
| 谁完成数据传送 | CPU | CPU 的中断服务程序 | DMA 控制器 |
| 数据是否经过 CPU 通用寄存器 | 通常经过 | 通常经过 | 不经过 |
| CPU 是否参与每个数据 | 是 | 通常是 | 否 |
| 典型传送粒度 | 少量数据 | 少量、随机数据或事件 | 数据块 |
| 硬件复杂度 | 低 | 中 | 高 |
| 主要 CPU 开销 | 查询和搬运 | 中断处理和搬运 | 初始化与完成处理 |
| 对主存/总线的影响 | CPU 正常访存完成传送 | CPU 正常访存完成传送 | DMA 与 CPU 竞争访问 |

表中的“通常”非常重要。具体系统可以在一次中断中传送多个数据，也可以为小块数据使用 DMA；应根据题目给出的接口、传送粒度和控制过程判断。

### 4.2 方式选择

可以按以下思路选择：

1. 等待很短、数据很少、硬件要求简单：程序查询；
2. 事件随机、数据量较少、希望 CPU 不忙等待：程序中断；
3. 数据量大、传送速度高、希望减少 CPU 逐个搬运：DMA。

不存在任何场景下都最优的方式。DMA 硬件和初始化有固定开销，中断过于频繁也会产生较大开销，轮询在事件即将发生或等待很短时可能更合适。

### 4.3 408 核心考点

| 考查内容 | 分析要点 |
| --- | --- |
| 程序查询 | 状态查询循环、数据通路和 CPU 忙等待 |
| 中断响应 | 响应条件、响应时点和硬件完成的工作 |
| 中断处理 | 现场保护、设备服务、恢复与返回 |
| 多重中断 | 中断嵌套条件、响应优先级与处理优先级 |
| 中断屏蔽 | 根据题目规定解释屏蔽字和允许关系 |
| DMA 控制器 | 主存地址、传送计数、控制状态和请求逻辑 |
| DMA 过程 | 初始化、请求、传送、地址计数更新和结束中断 |
| DMA 访存方式 | 区分停止 CPU 访存、周期挪用和交替访存 |
| 三方式比较 | 判断 CPU 是否等待、是否逐个搬运及数据通路 |

### 4.4 常见错误

- 认为程序查询方式完全不需要 I/O 接口；
- 认为轮询期间外设没有同时工作；
- 认为程序中断方式中数据可以不经过 CPU 直接进入主存；
- 把中断请求出现的时刻等同于 CPU 立即响应的时刻；
- 认为全部现场都一定由硬件自动保存；
- 混淆中断响应优先级和中断处理优先级；
- 认为高优先级中断无条件打断低优先级中断；
- 不看题目规定就固定认为屏蔽字中 1 表示屏蔽；
- 认为 DMA 完全不需要 CPU；
- 认为 DMA 数据必须经过 CPU 通用寄存器；
- 认为 DMA 不占用总线或主存周期；
- 把周期挪用理解为一次性占用整个数据块传送期间；
- 每传送一个数据就让 DMA 中断 CPU；
- 忽略按字节编址和传送宽度对 DMA 地址增量的影响；
- 认为使用 DMA 后不能再使用中断。

## 5. 本节小结

三种 I/O 方式的核心区别在于 CPU 等待程度和数据传送责任：

1. **程序查询**：CPU 查询状态并亲自传送每个数据，硬件简单但等待开销可能很大；
2. **程序中断**：设备就绪后通知 CPU，CPU 不必持续轮询，但数据通常仍由中断服务程序传送；
3. **DMA**：CPU 完成初始化和收尾，DMA 控制器负责外设与主存之间的成批传送。

分析题目时，先画出“外设—I/O 接口—CPU—主存”或“外设—I/O 接口/DMA—主存”的数据通路，再判断谁检查状态、谁搬运数据、谁占用总线以及何时通知 CPU。
