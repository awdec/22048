<h1><center>第一节 I/O 接口</center></h1>

外部设备在速度、数据格式、控制方式和电气特性等方面差异很大，通常不能直接由 CPU 控制。I/O 接口位于主机与外设之间，对主机提供相对统一的访问方式，对外设完成具体的控制与适配。

I/O 接口也常称为 **I/O 控制器**。CPU 通常不是直接操作外设的机械或物理部件，而是读取或写入 I/O 接口中的寄存器。

$$
\text{CPU、主存和系统总线}
\longleftrightarrow
\text{I/O 接口}
\longleftrightarrow
\text{外部设备}
$$

现行 408 的核心要求是掌握 I/O 接口的功能和基本结构，以及 I/O 端口及其编址。“I/O 接口的类型”用于帮助建立整体认识，不应与程序查询、中断、DMA 等 I/O 方式混淆。

## 1. I/O 接口的功能

### 1.1 设备选择与地址译码

一台计算机通常连接多个 I/O 接口，每个接口内部还可能有多个可访问寄存器。CPU 发出 I/O 地址后，接口中的地址译码逻辑需要判断：

1. 当前访问是否选中了本接口；
2. 访问的是数据、状态还是控制寄存器；
3. 当前操作是读还是写。

只有被选中的接口和端口才参与本次传送，其他接口不能同时驱动数据总线。

### 1.2 命令接收与设备控制

CPU 通过接口向外设发出启动、停止、复位、工作方式选择和中断允许等命令。接口把 CPU 写入控制端口的信息转换为外设能够识别的控制信号，并按照外设所需的时序组织操作。

接口负责完成命令译码和控制，但外设的具体动作仍由设备本身执行。例如，磁盘接口可以发出读写命令并报告完成状态，真正的介质访问由磁盘装置完成。

### 1.3 数据缓冲

CPU、主存和系统总线通常比许多外设快。I/O 接口通过数据缓冲寄存器暂存输入或输出数据，缓解速度不匹配：

- 输入时，外设先把数据送入接口，CPU 随后读取；
- 输出时，CPU 先把数据写入接口，外设随后取走。

缓冲只能暂时吸收速度差异，不能无限保存数据。若输入数据到达速度长期超过处理速度，仍可能发生溢出；若输出接口不能及时得到新数据，也可能发生下溢或设备等待。

### 1.4 状态保存与反馈

接口通过状态寄存器保存并向 CPU 报告设备状态，常见状态位包括：

- 就绪；
- 忙；
- 操作完成；
- 输入缓冲满或输出缓冲空；
- 出错；
- 中断请求。

CPU 可以主动读取状态，也可以在接口满足条件时通过中断请求通知 CPU。状态位的具体含义由接口规范规定，不能只根据位名猜测有效电平。

### 1.5 数据格式和信号转换

主机与外设的数据表示和传输形式可能不同，接口可以根据需要完成：

- 串行数据与并行数据之间的转换；
- 数据字长、字符格式或编码的适配；
- 电平和驱动能力转换；
- 外设侧时序与主机总线时序的协调。

并非每个接口都需要完成所有转换。具体功能取决于外设和接口协议。

### 1.6 传送控制与请求产生

接口需要协调数据何时可以被发送或接收，并可以根据实现需要：

- 配合程序查询方式提供就绪状态；
- 在操作完成或发生错误时提出中断请求；
- 为成批传送提出 DMA 请求。

程序查询、中断和 DMA 是第二节讨论的 I/O 方式。本节只需理解接口为这些方式提供状态、控制和请求信号，不应把 I/O 接口等同于某一种传送方式。

### 1.7 功能归纳

| 功能 | 解决的问题 | 典型实现 |
| --- | --- | --- |
| 地址译码 | CPU 当前访问哪个接口、哪个端口 | 地址译码与片选逻辑 |
| 命令控制 | CPU 如何启动和控制外设 | 控制寄存器、时序控制逻辑 |
| 数据缓冲 | 主机和外设速度不匹配 | 输入、输出数据寄存器或缓冲区 |
| 状态反馈 | CPU 如何知道设备是否就绪或出错 | 状态寄存器 |
| 格式转换 | 两侧数据与信号形式不同 | 串并转换、电平和编码转换 |
| 请求产生 | 如何通知 CPU 或 DMA 控制器 | 中断请求、DMA 请求逻辑 |

## 2. I/O 接口的基本结构

### 2.1 总体结构

典型 I/O 接口由端口寄存器、地址译码逻辑、总线接口逻辑和外设控制逻辑组成：

~~~text
                 I/O 接口
┌──────────────────────────────────────────┐
│  地址译码与片选逻辑                      │
│                                          │
│  数据端口      状态端口      控制端口    │
│      │             │             │        │
│  数据缓冲      状态检测      命令与时序   │
│          中断／DMA 请求逻辑（按需）      │
└──────────────────────────────────────────┘
      ⇅ 地址、数据、控制       ⇅ 数据、状态、控制
          系统总线                    外部设备
~~~

这是功能模型，不表示所有接口都必须使用完全相同的寄存器数量和物理布局。某些接口会分别设置输入、输出数据寄存器，也可能让状态和控制功能共享一个地址并通过读写方向区分。

### 2.2 主机侧接口

I/O 接口的主机侧通常连接系统总线或系统互连，接收以下信息：

| 信息 | 典型方向 | 作用 |
| --- | --- | --- |
| 地址 | CPU 或当前总线主设备到接口 | 选择接口及其内部端口 |
| 数据 | 双向 | 传送输入数据、输出数据、状态或控制字 |
| 读写控制 | 主设备到接口 | 说明本次访问方向 |
| 中断请求 | 接口到 CPU | 通知设备就绪、完成或出错 |
| DMA 请求 | 接口到 DMA 控制器 | 请求成批数据传送 |

中断和 DMA 信号是否存在，取决于接口支持的功能。简单接口可能只支持程序查询方式。

### 2.3 外设侧接口

外设侧信号通常可以归纳为：

- **数据信息**：外设输入或输出的数据；
- **状态信息**：就绪、忙、完成、故障等；
- **控制信息**：启动、停止、复位、传送允许等。

系统总线侧和外设侧的信号格式不必相同。I/O 接口正是通过缓冲、转换和控制逻辑把两侧连接起来。

### 2.4 数据端口

数据端口保存 CPU 与外设之间传送的数据。根据传送方向，可以设置：

- 输入数据寄存器；
- 输出数据寄存器；
- 可双向使用的数据寄存器。

输入数据寄存器在 CPU 读取前应保持数据稳定；输出数据寄存器在外设取走前应保持 CPU 写入的数据。读取或写入后是否自动清除某些状态位，由具体接口规定。

### 2.5 状态端口

状态端口主要由 CPU 读取，用于判断外设当前状态。典型状态字可以抽象为：

| 状态位 | 含义示例 |
| --- | --- |
| READY | 可以进行下一次数据传送 |
| BUSY | 设备正在工作 |
| DONE | 一次操作已经完成 |
| ERROR | 操作出错 |
| IRQ | 存在待处理的中断请求 |

“主要由 CPU 读取”不等于所有状态位绝对只读。有些接口允许软件通过写入特定位清除状态，具体规则必须服从接口规范。

### 2.6 控制端口

控制端口主要由 CPU 写入，用于保存命令或工作方式。典型控制内容包括：

- 启动或停止；
- 复位；
- 输入或输出方向；
- 数据格式或工作模式；
- 中断允许；
- 错误恢复命令。

控制端口中的命令可以由接口立即执行，也可以先保存在控制寄存器中，再由控制逻辑按时序作用于外设。

### 2.7 地址译码和控制逻辑

地址译码逻辑根据地址及读写控制信号产生端口选择信号；控制逻辑负责：

- 控制寄存器的读出和写入；
- 产生外设侧控制时序；
- 更新状态位；
- 协调数据缓冲；
- 在需要时产生中断或 DMA 请求。

对 CPU 而言，访问接口的典型过程为：

$$
\text{给出端口地址}
\longrightarrow
\text{地址译码}
\longrightarrow
\text{选择端口}
\longrightarrow
\text{完成读或写}
$$

### 2.8 I/O 端口的含义

I/O 端口是 CPU 可以通过地址访问的 I/O 接口寄存器或逻辑访问点。端口不是计算机机箱上的物理插孔。

一个 I/O 接口通常包含多个端口：

| 端口类型 | 主要方向 | 保存的信息 |
| --- | --- | --- |
| 数据端口 | 可读、可写或双向 | 输入、输出数据 |
| 状态端口 | 通常以读为主 | 就绪、忙、完成和错误状态 |
| 控制端口 | 通常以写为主 | 命令、模式和允许位 |

逻辑端口与物理寄存器不一定严格一一对应。例如，同一个端口地址在读操作时可以返回状态，在写操作时可以接收控制命令，因为读写控制信号能够进一步区分操作。

## 3. I/O 接口的类型

现行 408 没有把接口类型列为独立考点。本部分用于基础辨析，重点是明确分类依据，不要求记忆具体接口标准。

### 3.1 并行接口和串行接口

按外设侧数据传输格式可分为：

| 类型 | 基本方式 | 主要特点 |
| --- | --- | --- |
| 并行接口 | 多位数据通过多条数据线同时传送 | 线路较多，适合一定距离内的并行数据交换 |
| 串行接口 | 数据通过较少线路按时间顺序传送 | 线路少，通常需要串并转换 |

接口的串行或并行通常描述外设侧的数据传输形式，不表示 CPU 访问其端口时一定采用相同形式。例如，CPU 可以通过系统总线并行写入接口的数据寄存器，再由接口把数据转换为串行形式发送。

不能仅凭“串行”或“并行”判断速度高低。性能还取决于信号频率、通道数量、编码和协议开销。

### 3.2 同步接口和异步接口

按传送双方的时间协调方式可分为：

| 类型 | 协调方式 | 主要特点 |
| --- | --- | --- |
| 同步接口 | 依据共同的时钟或固定节拍 | 时序规整，适合速度和时延较确定的设备 |
| 异步接口 | 通过请求、应答等握手信号 | 能适应速度差异较大的设备 |

这里描述的是接口传送的定时方式。它与串行、并行属于不同分类维度，不能认为串行必然异步、并行必然同步。

### 3.3 可编程接口和固定功能接口（扩展）

- **可编程接口**允许 CPU 通过控制寄存器选择工作模式、传输参数或中断条件；
- **固定功能接口**主要按照预定逻辑工作，可由软件配置的内容较少。

“可编程”表示接口控制方式可以由软件配置，不表示接口能够像 CPU 一样执行任意程序。

### 3.4 通用接口和专用接口（扩展）

- **通用接口**可以通过配置服务于一类具有相近需求的设备；
- **专用接口**针对特定设备或应用设计，功能和时序更固定。

通用、专用与可编程、固定功能之间有联系，但不是完全相同的分类标准。

### 3.5 接口类型与 I/O 方式

程序查询、程序中断和 DMA 描述的是 CPU、主存与外设之间如何组织数据传送，属于 **I/O 方式**，不宜直接当作接口类型。

同一个接口可以同时支持：

- CPU 查询状态端口；
- 条件满足时提出中断请求；
- 成批传送时提出 DMA 请求。

因此，“采用中断方式”不等于存在一种只能用于中断的接口。

## 4. I/O 接口及其编址

这里的“接口编址”实质上是为接口中 CPU 可访问的 I/O 端口分配地址。CPU 根据端口地址、读写方向和控制信号选择相应寄存器。

### 4.1 端口地址与端口选择

假设某接口含数据、状态和控制三个端口，可以为它们分配不同地址：

| 端口 | 偏移量示例 | 典型访问 |
| --- | ---: | --- |
| 数据端口 | $0$ | 读输入数据或写输出数据 |
| 状态端口 | $1$ 或按字长对齐后的偏移 | 读取设备状态 |
| 控制端口 | $2$ 或按字长对齐后的偏移 | 写入控制命令 |

高位地址常用于选择接口，低位地址常用于选择接口内部端口，但这只是常见设计。具体哪些地址位参与译码由系统地址分配和接口实现决定。

若使用 $k$ 位地址区分端口，理论上最多可以形成：

$$
2^k
$$

个不同端口地址。它表示可区分的端口地址数量，不等于最多只能连接 $2^k$ 个物理外设。

### 4.2 统一编址

统一编址也称**存储器映射 I/O**。I/O 端口与主存单元共同使用同一个地址空间，CPU 使用访存类指令访问 I/O 端口。

基本特点：

- 不需要设置专门的 I/O 指令；
- 可以使用体系结构允许的访存寻址方式访问端口；
- 主存和 I/O 地址由统一地址译码逻辑区分；
- I/O 端口会占用统一地址空间中的一部分地址。

例如，若把某接口的数据、状态和控制端口分别映射到地址 $A$、$A+4$、$A+8$，CPU 可以通过相应的 Load、Store 指令进行访问。这里假定端口宽度和对齐要求使相邻端口间隔为 4 B，实际偏移由具体体系结构决定。

存储器映射 I/O 虽然使用访存指令，但 I/O 端口具有设备语义，读取或写入可能引起状态变化，不能把它简单看成普通 RAM。

### 4.3 独立编址

独立编址也称**隔离 I/O**。I/O 端口使用独立于主存的 I/O 地址空间，CPU 使用专门的输入、输出指令访问端口。

基本特点：

- I/O 地址不占用主存地址空间；
- 指令系统需要提供专门的 I/O 指令；
- 通常使用专门的 I/O 读写控制信号；
- 可用于 I/O 的寻址方式和操作往往不如统一编址灵活。

例如，某些体系结构使用输入指令从 I/O 端口读取数据，使用输出指令向 I/O 端口写入数据。端口号与同数值的主存地址属于不同地址空间，二者不会因为数值相同而指向同一个对象。

若独立 I/O 地址空间使用 $n$ 位端口地址，则理论上最多可以表示：

$$
2^n
$$

个 I/O 端口地址。

### 4.4 两种编址方式对比

| 比较项目 | 统一编址 | 独立编址 |
| --- | --- | --- |
| 地址空间 | I/O 端口与主存共享 | I/O 端口使用独立空间 |
| 访问指令 | 访存类指令 | 专门 I/O 指令 |
| 是否占用主存地址范围 | 是 | 否 |
| 寻址和数据处理能力 | 通常较灵活 | 通常较受限 |
| 控制信号 | 可按存储器映射规则识别 | 通常有专门 I/O 读写控制 |
| 指令系统要求 | 不必增加专门 I/O 指令 | 必须支持 I/O 指令 |

“统一”指地址空间统一，不表示主存与 I/O 端口的硬件行为相同；“独立”指地址空间独立，不表示 I/O 接口不与系统总线连接。

### 4.5 CPU 访问端口的过程

#### 读取状态端口

$$
\text{CPU 给出端口地址和读命令}
\longrightarrow
\text{接口译码并选中状态端口}
\longrightarrow
\text{状态字送到数据通路}
$$

#### 写入控制端口

$$
\text{CPU 给出端口地址、控制字和写命令}
\longrightarrow
\text{接口译码并选中控制端口}
\longrightarrow
\text{控制逻辑执行命令}
$$

#### 读取输入数据

CPU 通常先确认数据就绪，再读取数据端口：

$$
\text{读状态}
\longrightarrow
\text{判断就绪}
\longrightarrow
\text{读数据}
$$

程序查询方式会反复执行状态检查；中断方式由接口在满足条件时通知 CPU。二者访问的仍是接口端口。

### 4.6 编址计算示例

某存储器映射 I/O 接口有 3 个 32 位端口，系统按字节编址，并要求端口按 4 B 边界对齐。若接口基地址为 $4000\,1000\text{H}$，按数据、状态、控制的顺序分配，则端口地址可以是：

| 端口 | 地址 |
| --- | --- |
| 数据端口 | $4000\,1000\text{H}$ |
| 状态端口 | $4000\,1004\text{H}$ |
| 控制端口 | $4000\,1008\text{H}$ |

这里地址间隔为 4 B 是由“32 位端口、按字节编址、4 B 对齐”的题设共同决定的，不能对所有接口机械套用。

## 5. 408 核心考法与补充易错点

### 5.1 常见考法

| 考查内容 | 分析要点 |
| --- | --- |
| 接口功能 | 判断缓冲、译码、控制、状态和格式转换的作用 |
| 接口结构 | 识别数据、状态、控制寄存器及控制逻辑 |
| I/O 端口 | 区分端口、接口和物理外设 |
| 信息方向 | 判断地址、命令、状态和数据由谁发送 |
| 端口编址 | 比较统一编址和独立编址 |
| 地址译码 | 根据基地址、偏移和对齐要求确定端口地址 |
| I/O 方式关系 | 区分接口提供的信号与查询、中断、DMA 传送方式 |

### 5.2 常见错误

- 把 I/O 接口等同于外设本身；
- 把 I/O 端口理解为机箱上的物理插孔；
- 认为一个接口只能包含一个端口；
- 混淆数据端口、状态端口和控制端口的用途；
- 认为状态端口绝对只能读、控制端口绝对只能写；
- 看到两个寄存器使用相同地址就断定冲突，没有考虑读写方向；
- 认为统一编址需要专门 I/O 指令；
- 认为独立编址会占用主存地址范围；
- 把端口地址数量直接等同于物理外设数量；
- 忽略按字节编址和端口对齐对地址间隔的影响；
- 认为 DMA 不再需要 I/O 接口参与。

基础补充内容中还应注意：

- 把串行/并行接口分类与同步/异步定时分类混为一谈；
- 把程序查询、中断和 DMA 直接当作互斥的接口类型。

## 6. 本节小结

I/O 接口是主机与外设之间的控制和适配部件：

1. **功能**：完成地址译码、命令控制、数据缓冲、状态反馈、格式转换及必要的请求产生；
2. **结构**：以数据、状态和控制端口为核心，并包含地址译码、总线接口和外设控制逻辑；
3. **类型**：可以按串行/并行、同步/异步等维度分类，但不能与 I/O 方式混淆；
4. **编址**：CPU 实际访问的是接口中的 I/O 端口，可以采用统一编址或独立编址。

做题时先判断 CPU 访问的是哪个端口、采用何种编址方式，再结合读写方向分析数据、状态和控制信息的流动。
