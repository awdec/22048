<h1><center>第五节 高速缓冲存储器</center></h1>

高速缓冲存储器简称 Cache，位于 CPU 与主存之间，用来缓解 CPU 处理速度与主存访问速度之间的矛盾。Cache 保存主存中一部分数据的副本，并利用程序访问的局部性，使 CPU 的大部分访存请求能够在高速存储器中完成。

本节的知识主线为：

$$
\text{局部性原理}
\longrightarrow
\text{Cache 工作过程}
\longrightarrow
\text{映射与替换}
\longrightarrow
\text{写策略和一致性}
\longrightarrow
\text{容量与性能分析}
$$

## 1. 程序访问的局部性原理

程序在一段时间内通常只访问整个地址空间中的一小部分内容，这种现象称为程序访问的局部性。局部性是 Cache 能够提高访存性能的根本原因。

### 1.1 时间局部性

时间局部性是指最近访问过的指令或数据，在不久之后可能再次被访问。

典型情况包括：

- 循环体中的指令被反复执行；
- 循环变量和累加变量被多次读写；
- 函数中的局部变量在较短时间内重复使用；
- 同一个函数被连续或频繁调用。

Cache 保留近期访问过的主存块，使再次访问相同信息时能够直接命中。

### 1.2 空间局部性

空间局部性是指访问某个地址后，其附近地址中的信息可能很快被访问。

典型情况包括：

- CPU 顺序执行相邻指令；
- 程序按照存储顺序遍历数组；
- 连续访问结构体或记录中的相邻成员。

主存与 Cache 之间按块传送数据。CPU 访问某个字节或字时，包含它的一整个主存块会被调入 Cache，从而利用相邻地址的空间局部性。

### 1.3 局部性与程序访问方式

以按行存储的二维数组为例，按行遍历通常连续访问相邻地址，空间局部性较好；按列遍历会以较大的步长跨越地址，可能更频繁地访问不同 Cache 块。

局部性好坏取决于实际地址访问序列，而不只取决于源程序看起来是否使用了循环。

### 1.4 块大小与局部性

增大主存块大小可以一次带入更多相邻信息，有利于利用空间局部性，但块并非越大越好：

- 块越大，一次未命中需要传送的数据越多，未命中代价可能增大；
- Cache 数据容量不变时，块越大，Cache 行数越少；
- 行数减少可能增加不同主存块之间的竞争；
- 调入但未被访问的数据会浪费 Cache 空间和传输带宽。

因此，块大小需要在空间局部性、行数和未命中代价之间折中。

## 2. Cache 的基本工作原理

### 2.1 主存块与 Cache 行

主存被划分为大小相等的主存块，Cache 被划分为大小相等的 Cache 行。主存块与 Cache 行中的数据区大小相同，二者是主存与 Cache 之间交换信息的基本单位。

| 概念 | 含义 |
| --- | --- |
| 主存块 | 主存中一个固定大小的数据块 |
| Cache 行 | Cache 中保存一个主存块及其控制信息的位置 |
| 标记 Tag | 标识当前 Cache 行保存的是哪个主存块 |
| 有效位 | 表示 Cache 行中的内容是否有效 |
| 脏位 | 写回法中表示该行是否已被 CPU 修改 |
| 替换状态位 | 为 LRU、FIFO 等替换算法按行或按组记录必要状态 |

Cache 的数据阵列和控制状态通常包括：

$$
\text{有效位}
\quad
\text{脏位}
\quad
\text{标记}
\quad
\text{数据块}
\quad
\text{替换状态}
$$

并不是所有 Cache 都具有上述全部字段，而且替换状态可能属于整个组而不是某一行。例如，写直达 Cache 通常不需要脏位，直接映射 Cache 不需要在多个候选行之间维护替换顺序。

### 2.2 Cache 命中判断

CPU 给出主存地址后，Cache 根据地址中的索引字段查找候选行，并进行以下判断：

1. 检查候选行的有效位是否为 $1$；
2. 比较地址中的标记与 Cache 行中保存的标记；
3. 有效位为 $1$ 且标记相等时，访问命中；
4. 命中后根据块内地址选择所需字节或字。

只有标记相同但有效位为 $0$ 时仍然属于未命中，不能仅根据标记位判断。

### 2.3 读命中和读未命中

读命中时，Cache 直接把目标数据送给 CPU。

读未命中时，通常执行：

1. 根据映射方式确定目标 Cache 行或候选组；
2. 若存在无效行，优先使用无效行；
3. 若候选位置已满，按照替换算法选择牺牲行；
4. 若采用写回法且牺牲行为脏，需要先把它写回主存；
5. 从主存调入包含目标地址的完整主存块；
6. 更新标记、有效位和其他状态；
7. 把 CPU 所需的数据送出。

处理器可以等待整个主存块装入后再取得数据，也可以在关键字到达后先把所需字交给 CPU；具体优化取决于系统实现。

### 2.4 命中率与缺失率

Cache 命中率为：

$$
h
=
\frac{\text{命中次数}}{\text{总访问次数}}
$$

缺失率为：

$$
m=1-h
$$

一次访问是否命中取决于给定的地址序列、Cache 初始状态、块大小、容量、映射方式和替换算法，不能只根据某一个地址孤立判断长期命中率。

### 2.5 平均存储器访问时间

若 $T_C$ 是 Cache 命中时间，$m$ 是缺失率，$P$ 是未命中后额外付出的未命中代价，则平均存储器访问时间为：

$$
AMAT=T_C+mP
$$

若题目把未命中时的总访问时间记作 $T_{miss}$，其中已经包含第一次 Cache 查询时间，则也可以写为：

$$
AMAT
=
hT_C
+
(1-h)T_{miss}
$$

两种写法能否直接使用，取决于“未命中代价”是否已经包含 Cache 查询时间。列式前必须先确认题目中各时间量的定义。

### 2.6 Cache 缺失的基本类型（扩展）

| 缺失类型 | 产生原因 | 常见改进方向 |
| --- | --- | --- |
| 强制缺失 | 第一次访问某个主存块，Cache 中从未装入过它 | 预取或适当增大块大小 |
| 容量缺失 | 程序活跃数据总量超过 Cache 容量 | 增大 Cache 容量或改善程序局部性 |
| 冲突缺失 | 多个活跃主存块竞争同一行或同一组 | 提高相联度或调整数据布局 |

全相联映射在容量相同且使用理想替换时可以消除映射造成的冲突缺失，但仍然存在强制缺失和容量缺失。

## 3. Cache 和主存的映射方式

映射方式规定一个主存块能够放入哪些 Cache 行。

设：

- 主存地址为 $m$ 位，按字节编址；
- Cache 数据容量为 $C_D$ 字节；
- 主存块大小为 $B=2^b$ 字节；
- Cache 行数为 $L=C_D/B$；
- 每组有 $E$ 行，即 $E$ 路组相联；
- Cache 组数为 $S=L/E=2^s$。

以下地址字段计算均假设块大小、行数和组数为 $2$ 的整数次幂，这也是 408 计算题的常见设定。

对主存地址 $A$，主存块号为：

$$
j=\left\lfloor\frac{A}{B}\right\rfloor
$$

块内偏移为：

$$
A\bmod B
$$

### 3.1 直接映射

直接映射中，每个主存块只能放入唯一一行：

$$
\text{Cache 行号}=j\bmod L
$$

地址格式为：

$$
\underbrace{\text{标记}}_{m-\log_2L-b\text{ 位}}
\quad
\underbrace{\text{行号}}_{\log_2L\text{ 位}}
\quad
\underbrace{\text{块内地址}}_{b\text{ 位}}
$$

直接映射的特点：

- 硬件简单，只需比较一个候选行的标记；
- 命中判断速度快；
- 不需要在多个候选行中选择牺牲行；
- 多个频繁访问的主存块若映射到同一行，会产生较多冲突缺失。

### 3.2 全相联映射

全相联映射中，任意主存块都可以放入任意 Cache 行。

地址格式为：

$$
\underbrace{\text{标记}}_{m-b\text{ 位}}
\quad
\underbrace{\text{块内地址}}_{b\text{ 位}}
$$

全相联没有行号或组号字段。查找时需要把地址标记与所有有效 Cache 行的标记进行相联比较。

全相联的特点：

- 放置最灵活，冲突缺失最少；
- 标记比较电路复杂、硬件成本高；
- Cache 满时需要在全部行中执行替换算法；
- 适合容量较小、对冲突较敏感的结构。

### 3.3 组相联映射

组相联映射把 Cache 分成 $S$ 组，每组有 $E$ 行。主存块只能映射到唯一一组，但可以放在该组中的任意一行：

$$
\text{组号}=j\bmod S
$$

地址格式为：

$$
\underbrace{\text{标记}}_{m-s-b\text{ 位}}
\quad
\underbrace{\text{组号}}_{s\text{ 位}}
\quad
\underbrace{\text{块内地址}}_{b\text{ 位}}
$$

组相联是直接映射和全相联的折中：

- $E=1$ 时就是直接映射；
- $S=1$ 时就是全相联映射；
- 相联度越高，同组内需要并行比较的标记越多；
- 相联度提高通常可以减少冲突缺失，但可能增加命中时间、功耗和替换状态开销。

### 3.4 三种映射方式对比

| 映射方式 | 主存块的可放置位置 | 标记比较范围 | 是否需要替换选择 | 冲突缺失 |
| --- | --- | --- | --- | --- |
| 直接映射 | 唯一一行 | 一个候选行 | 不需要 | 较多 |
| 全相联 | 任意一行 | 全部 Cache 行 | 全局选择 | 最少 |
| $E$ 路组相联 | 指定组中的任意一行 | 该组的 $E$ 行 | 组内选择 | 居中 |

### 3.5 地址划分示例

设某计算机按字节编址，主存地址为 $32$ 位，Cache 数据容量为 $16\text{ KiB}$，主存块大小为 $64\text{ B}$。

Cache 行数为：

$$
L
=
\frac{16\text{ KiB}}{64\text{ B}}
=
\frac{2^{14}}{2^6}
=2^8
=256
$$

块内地址为 $6$ 位。

| 映射方式 | 组数或行数 | 索引位数 | 标记位数 | 地址格式 |
| --- | ---: | ---: | ---: | --- |
| 直接映射 | $256$ 行 | $8$ | $32-8-6=18$ | Tag 18位＋行号8位＋块内地址6位 |
| 全相联 | $1$ 组 | $0$ | $32-6=26$ | Tag 26位＋块内地址6位 |
| $4$ 路组相联 | $64$ 组 | $6$ | $32-6-6=20$ | Tag 20位＋组号6位＋块内地址6位 |

组号位数由组数决定，而不是由每组的路数直接决定。

## 4. Cache 中主存块的替换算法

当访问未命中、候选组已经没有无效行时，Cache 必须选择一个原有主存块作为牺牲块。

直接映射只有唯一目标行，不需要在多个候选行之间执行替换算法；全相联在全部行中选择，组相联只在目标组内选择。

### 4.1 随机替换算法

随机算法 Random 从候选行中随机选择一个牺牲块。

- 硬件实现简单；
- 不需要维护复杂访问历史；
- 不能利用程序访问历史预测未来使用情况；
- 在相联度较高时可以用较低成本取得可接受效果。

### 4.2 先进先出算法

先进先出算法 FIFO 替换最早进入候选集合的主存块。

- 需要记录各块进入 Cache 的先后顺序；
- Cache 命中通常不改变 FIFO 次序；
- 实现比精确 LRU 简单；
- 最早进入的块不一定是未来最少使用的块。

### 4.3 最近最少使用算法

最近最少使用算法 LRU 替换最长时间没有被访问的主存块。

- 利用时间局部性预测未来访问；
- 每次命中或装入后都要更新访问先后状态；
- 相联度较小时容易实现；
- 相联度较高时，精确维护访问顺序的硬件开销较大，实际系统可能采用近似 LRU。

### 4.4 最不经常使用算法

最不经常使用算法 LFU 替换一段统计时间内访问次数最少的主存块。

- 需要为候选块维护访问计数；
- 能保留访问频繁的块；
- 较早阶段积累的高计数可能使后来不再使用的块长期保留，因此实际使用时可能需要计数衰减。

### 4.5 FIFO 与 LRU 示例

设全相联 Cache 只能容纳 $3$ 个主存块，访问序列为：

$$
A,\ B,\ C,\ A,\ D
$$

装入 $A、B、C$ 后再次访问 $A$ 命中：

- FIFO 仍认为 $A$ 是最早进入的块，因此访问 $D$ 时替换 $A$；
- LRU 会把 $A$ 更新为最近使用，访问 $D$ 时替换最长时间未访问的 $B$。

做替换题时，应先在每次访问后更新算法状态，再处理下一次访问；若候选集合中存在无效行，应先填入无效行，不发生有效块替换。

## 5. Cache 的一致性问题

Cache 保存的是主存数据的副本。CPU 修改 Cache 中的数据后，必须规定何时更新主存；多核处理器中若同一数据同时存在于多个 Cache，还要保证不同副本之间不会长期不一致。

### 5.1 写命中的处理策略

#### 写直达法

写直达法又称全写法。CPU 写命中时，同时修改 Cache 和下一级存储器。

特点：

- Cache 与下一级存储器较容易保持一致；
- 不需要脏位；
- 每次写命中都产生下一级写操作，可能增加存储器和总线压力；
- 通常配合写缓冲，避免 CPU 长时间等待下一级写入完成。

#### 写回法

写回法只修改 Cache，并把该行的脏位置为 $1$。脏行被替换时必须把整个数据块写回下一级存储器；系统也可能因显式刷新或一致性操作提前写回脏行。

特点：

- 多次写同一块只需在替换时写回一次，能够减少下一级写流量；
- 每行需要脏位；
- 未写回前，Cache 中的数据比主存副本新；
- 替换脏块会增加未命中代价。

### 5.2 写未命中的处理策略

| 策略 | 处理方式 |
| --- | --- |
| 写分配 | 先把包含目标地址的主存块调入 Cache，再在 Cache 中完成写入 |
| 非写分配 | 不调入主存块，直接把数据写到下一级存储器 |

常见组合是：

- 写回法配合写分配；
- 写直达法配合非写分配。

这只是常见组合，不是逻辑上唯一允许的组合。写命中策略和写未命中策略是两个不同维度，必须分别判断。

### 5.3 多级 Cache 的一致性（扩展）

多级 Cache 中，同一个数据块可能同时存在于 L1、L2 或 L3 Cache。上一级修改数据后，需要通过包含关系、写策略或其他硬件机制保证下一级最终得到正确数据。

408 基础题通常重点考查写直达、写回、写分配、非写分配和脏位，不要求展开复杂的多级包含协议。

### 5.4 多核 Cache 一致性（扩展）

在多核系统中，各处理器核心可能拥有私有 Cache。同一个主存块如果存在多个副本，一个核心修改后，其他核心中的旧副本可能失效。

硬件通常采用监听或目录等机制，并通过使其他副本失效或更新副本来维护 Cache 一致性。具体的 MSI、MESI 等协议状态转换通常属于扩展内容；408 复习应首先理解“一处写入后，其他副本不能继续作为最新数据使用”这一基本问题。

### 5.5 I/O 与 Cache 一致性（扩展）

DMA 设备可以在不经过 CPU 普通访存指令的情况下读写主存。如果 CPU Cache 中还保留旧副本，或者写回 Cache 中的新数据尚未写入主存，就可能导致 CPU 与 I/O 设备看到不同内容。

系统可以通过硬件一致性支持，或在 DMA 前后执行必要的写回、失效等操作解决这一问题。该内容用于理解一致性概念，基础计算题一般不展开具体实现。

## 6. Cache 容量的计算举例

### 6.1 数据容量与总容量

题目所说的“Cache 容量”可能有两种含义：

- **数据容量**：所有 Cache 行的数据块部分之和；
- **总容量**：数据阵列、标记、有效位、脏位和替换状态等全部存储位之和。

若 Cache 有 $L$ 行，每行数据块为 $B$ 字节，则数据容量为：

$$
C_D=L\times B\text{ B}
$$

若每行标记为 $t$ 位，并设置 $v$ 个有效位和 $d$ 个脏位，暂不考虑替换状态，则总容量为：

$$
C_{total}
=
8C_D
+
L(t+v+d)
\text{ bit}
$$

组相联 Cache 还可能需要每组替换状态位。只有题目给出替换状态的编码方式，或者明确要求计算全部控制位时，才能确定这部分的准确位数。

### 6.2 直接映射容量计算

仍设主存地址为 $32$ 位、按字节编址，Cache 数据容量为 $16\text{ KiB}$，块大小为 $64\text{ B}$，采用直接映射和写直达法。每行有一个有效位，不设置脏位。

由前面的地址划分可知：

$$
L=256,
\qquad
t=18
$$

数据部分为：

$$
16\text{ KiB}\times8
=131072\text{ bit}
$$

标记和有效位为：

$$
256\times(18+1)
=4864\text{ bit}
$$

因此总容量为：

$$
C_{total}
=131072+4864
=135936\text{ bit}
$$

换算为字节：

$$
\frac{135936}{8}
=16992\text{ B}
$$

可见，标称的 $16\text{ KiB}$ 通常只是数据容量，实际硬件还要为标记和控制位付出额外存储开销。

### 6.3 四路组相联容量计算

若上述 Cache 改为 $4$ 路组相联、采用写回法，每行设置一个有效位和一个脏位，则：

$$
S=\frac{256}{4}=64,
\qquad
t=32-\log_2 64-\log_2 64=20
$$

暂不计替换状态位，总容量为：

$$
C_{total}
=131072
+256\times(20+1+1)
=136704\text{ bit}
$$

即：

$$
\frac{136704}{8}
=17088\text{ B}
$$

若题目还要求计算 LRU 等替换状态位，应根据每组的状态位数量再乘以组数并加入总容量。

### 6.4 容量题的解题顺序

1. 明确题目给的是数据容量还是包括标记在内的总容量。
2. 根据块大小求 Cache 行数。
3. 根据相联度求组数。
4. 根据主存地址格式求标记位数。
5. 判断每行是否需要有效位、脏位及其他控制位。
6. 判断替换状态按每行设置还是按每组设置。
7. 统一使用 bit 计算，最后再按要求换算单位。

## 7. Cache 的应用

### 7.1 多级 Cache（扩展）

现代处理器通常采用多级 Cache：

- L1 Cache 容量较小、速度最快，通常最靠近处理器核心；
- L2 Cache 容量更大、速度稍慢；
- L3 Cache 容量更大，常由多个核心共享；
- 主存位于 Cache 层次之后，容量更大但访问更慢。

多级 Cache 的平均访问时间可以逐层展开。若 $m_1$、$m_2$ 分别为 L1 和 L2 的局部缺失率，则一种常见写法为：

$$
AMAT
=
T_{L1}
+m_1
\left(
T_{L2}
+m_2T_M
\right)
$$

该公式假设 $T_M$ 是 L2 未命中后访问主存的额外代价。具体计算仍要服从题目对各级访问能否并行、时间是否包含前级查询的定义。

### 7.2 指令 Cache 与数据 Cache

处理器可以使用统一 Cache 同时保存指令和数据，也可以把它们分成指令 Cache 和数据 Cache。

分离的 L1 Cache 允许取指和数据访问并行进行，并可以分别针对指令流和数据流的特点设计；统一 Cache 的空间可以在指令和数据之间动态共享。实际处理器常在较高层使用分离的指令、数据 Cache，在较低层使用统一 Cache，但具体结构由实现决定。

### 7.3 Cache 与程序性能

程序的数据布局和访问顺序会影响 Cache 命中率。例如：

- 按存储顺序遍历数组通常具有较好的空间局部性；
- 重复使用已经调入 Cache 的数据可以利用时间局部性；
- 分块处理矩阵可以让工作数据在 Cache 中重复使用；
- 多个频繁访问的数据若反复映射到同一组，可能造成冲突抖动；
- 工作集超过 Cache 容量时，可能产生大量容量缺失。

分析程序访存题时，应先把数据元素转换为实际字节地址，再根据块大小、组数和映射方式判断块号、组号及命中情况。

### 7.4 Cache 参数的折中

| 参数变化 | 可能的收益 | 可能的代价 |
| --- | --- | --- |
| 增大 Cache 容量 | 减少容量缺失 | 面积、成本、功耗和命中时间可能增加 |
| 增大块大小 | 更好利用空间局部性 | 行数减少，未命中传输代价增大 |
| 提高相联度 | 减少冲突缺失 | 标记比较和替换逻辑更复杂 |
| 使用写回法 | 减少下一级写流量 | 需要脏位，脏块替换代价更高 |
| 使用多级 Cache | 同时兼顾低延迟和较大容量 | 层次控制及一致性更加复杂 |

Cache 设计追求的是平均访存性能，而不是孤立地把容量、块大小或相联度调到最大。

### 7.5 Cache 与软件可见性

普通程序通常不直接指定某个主存块放入哪一行，Cache 的查找、装入和替换主要由硬件自动完成，因此 Cache 对程序员通常透明。

“透明”不表示 Cache 对程序性能没有影响。程序的地址访问模式会改变命中率，操作系统和底层软件在 DMA、一致性或特殊内存区域中也可能需要执行 Cache 管理操作。

## 8. 408 常见考法与易错点

| 考点 | 解题入口 |
| --- | --- |
| 局部性 | 根据实际地址序列判断时间局部性和空间局部性 |
| 基本工作过程 | 按有效位、标记比较、替换、调块和写回顺序分析 |
| 地址划分 | 先求块内地址，再求行号或组号，最后求标记 |
| 映射位置 | 使用主存块号对行数或组数取模 |
| 替换算法 | 直接映射无需选择；组相联只在组内替换 |
| 写策略 | 分别判断写命中策略和写未命中策略 |
| 容量计算 | 区分数据容量和包含标记、控制位的总容量 |
| 平均访问时间 | 明确未命中代价是否包含已发生的 Cache 查询 |

特别注意：

- 主存块大小等于 Cache 行的数据区大小，不等于一整行的总位数。
- 按字节编址时，块内地址位数由块的字节数决定。
- 组号位数由组数决定，不是由路数决定。
- 直接映射中主存块位置唯一，不需要执行替换算法。
- 标记相等时还必须检查有效位，才能判断命中。
- 写回法需要脏位；写直达法通常不需要脏位。
- 写直达与写分配不是一组相反概念，应分别分析写命中和写未命中。
- Cache 数据容量通常不包含标记、有效位、脏位和替换状态位。
- 未命中时若牺牲行为脏行，写回时间也是未命中代价的一部分。
- Cache 命中率高不必然意味着 AMAT 一定更小，还要考虑命中时间和未命中代价。

## 9. 本节小结

Cache 的核心逻辑可以概括为：

$$
\text{局部性决定访问集中}
\longrightarrow
\text{映射方式决定放置位置}
\longrightarrow
\text{替换算法决定淘汰对象}
\longrightarrow
\text{写策略决定副本更新方式}
$$

处理 Cache 计算题时，建议使用统一顺序：确定地址和编址单位，计算块大小、行数和组数，划分标记、索引与块内地址，再结合有效位、替换状态和写策略模拟命中及缺失过程。
