<h1><center>第四节 CISC 和 RISC 的基本概念</center></h1>

CISC 和 RISC 是指令集体系结构的两种典型设计取向。二者都要实现数据传送、运算和控制转移等基本功能，主要区别在于：把完成复杂任务的工作更多交给硬件中的复杂指令，还是交给由简单指令组成的程序。

## 1. 复杂指令系统计算机（CISC）

### 1.1 CISC 的基本思想

CISC 是 **Complex Instruction Set Computer** 的缩写，即复杂指令系统计算机。其典型设计思想是提供数量较多、功能较强的指令，使一条机器指令能够完成若干较复杂的操作。

早期计算机的主存容量小、速度慢，编译技术也不成熟。用一条复杂指令代替多条简单指令，可以减少程序的指令条数和取指次数，并提高机器代码的紧凑程度。

“复杂”主要体现在指令功能、指令格式、寻址方式和执行过程等方面，并不只是指指令总数多。

### 1.2 CISC 的典型特征

- 指令系统通常较丰富，指令功能差异较大。
- 指令长度和格式可能不固定，不同指令包含的字段不同。
- 寻址方式较多，部分算术逻辑指令可以直接使用主存操作数。
- 不同指令的执行步骤和执行时间可能相差较大。
- 复杂指令的译码和控制逻辑较复杂，常采用微程序控制，也可以采用硬布线或混合方式。
- 一条复杂指令能完成较多工作，因此程序的动态指令条数可能较少，代码密度通常较高。

这些特征是传统 CISC 的典型倾向，并非每一种 CISC 处理器都同时具备全部特征。

### 1.3 CISC 指令的执行特点

某些 CISC 指令可以在一条指令中完成取数、运算和写回等多个步骤。以概念操作 `x = x + y` 为例，CISC 可能允许算术指令直接以主存单元为操作数，从而减少显式的装入、存储指令。

复杂指令可能被控制器分解为多个更基本的内部操作。若采用微程序控制，一条机器指令可以由一段微程序解释执行：

$$
\text{机器指令}\longrightarrow
\text{若干微指令}\longrightarrow
\text{若干微操作}
$$

微程序控制有利于实现和修改复杂控制，但通常需要访问控制存储器。不能据此断言“CISC 一定采用微程序控制”或“微程序控制一定只用于 CISC”。

### 1.4 CISC 的优势与局限

典型优势包括：

- 单条指令功能强，完成同一任务所需的机器指令条数可能较少。
- 程序代码通常较紧凑，可减少指令存储空间和部分取指开销。
- 保留并实现已有的复杂指令，有利于维持既有机器代码的二进制兼容；这些指令可以通过硬布线、微程序或内部操作分解等方式实现。

典型局限包括：

- 指令格式和执行过程不够规整，译码逻辑较复杂。
- 指令执行时间差异较大，流水线的划分和冲突处理更困难。
- 许多复杂指令的使用频率较低，却仍会增加硬件设计和验证成本。

## 2. 精简指令系统计算机（RISC）

### 2.1 RISC 的基本思想

RISC 是 **Reduced Instruction Set Computer** 的缩写，即精简指令系统计算机。其典型设计思想是保留经常使用、便于硬件高效实现的基本操作，用多条简单而规整的指令组合完成复杂任务。

RISC 中的“精简”强调指令功能和格式的规整，以及硬件执行路径的简化，不等同于“指令数量必须很少”。现代 RISC 指令集也可能包含较多扩展指令。

### 2.2 RISC 的典型特征

- 指令格式较少且比较规整，指令长度通常固定或以少数几种长度为主。
- 寻址方式较少，地址计算规则相对简单。
- 通常采用 load-store 结构，只有专门的访存指令访问主存。
- 算术逻辑运算主要在寄存器之间进行，通用寄存器数量通常较多。
- 常用指令的执行步骤较一致，便于进行流水线设计和提高指令吞吐率。
- 控制器通常适合采用硬布线控制，但这不是 RISC 的必要定义。
- 更依赖编译器进行寄存器分配、指令选择、指令调度等优化。

“一条 RISC 指令只用一个时钟周期”不是普遍规律。经典 RISC 强调简单指令具有规整的执行阶段；在流水线处理器中，不同指令的执行延迟仍可能不同，不能把流水线吞吐率和单条指令延迟混为一谈。

### 2.3 Load-store 结构

load-store 结构把访存和运算分开：

- `LOAD` 把主存数据读入寄存器。
- `STORE` 把寄存器数据写入主存。
- 算术逻辑指令主要读取寄存器操作数，并把结果写入寄存器。

例如：

```c
z = x + y;
```

可以抽象为：

```text
LOAD  R1, x
LOAD  R2, y
ADD   R3, R1, R2
STORE R3, z
```

这种设计使访存指令与运算指令的职责清晰，指令格式和数据通路更容易规整化，也便于流水线各阶段分工。

### 2.4 RISC 的优势与局限

典型优势包括：

- 指令译码和控制逻辑较规整，便于提高时钟频率和实现流水线。
- 常用指令的执行过程相似，有利于提高指令吞吐率。
- 大量通用寄存器可以减少中间结果的访存次数。
- 规整的指令形式有利于编译器分析和优化。

典型局限包括：

- 完成复杂操作可能需要更多机器指令。
- 若指令编码和编译优化不当，程序代码长度和取指次数可能增加。
- 性能较依赖编译器生成高质量的指令序列。

## 3. CISC 和 RISC 的比较

### 3.1 典型特征对比

| 比较项目 | CISC 的典型取向 | RISC 的典型取向 |
| --- | --- | --- |
| 指令功能 | 一条指令可完成较复杂操作 | 用简单指令组合完成复杂操作 |
| 指令数量 | 通常较多 | 经典设计中相对较少 |
| 指令格式 | 种类较多，规整性较弱 | 种类较少，格式较规整 |
| 指令长度 | 常采用变长指令 | 通常定长或以少数长度为主 |
| 寻址方式 | 通常较多 | 通常较少 |
| 主存操作数 | 多类指令可能访问主存 | 通常只有 load/store 指令访存 |
| 通用寄存器 | 传统设计中相对较少 | 通常较多 |
| 执行时间 | 不同指令之间差异可能较大 | 常用指令的执行过程较规整 |
| 控制器 | 常采用微程序或较复杂的混合控制 | 常适合硬布线控制 |
| 流水线 | 规整实现的难度通常较大 | 通常更便于流水线实现 |
| 代码密度 | 通常较高 | 可能需要更多指令，代码长度不一定更短 |
| 编译器作用 | 传统设计中硬件承担较多复杂操作 | 更依赖编译器组织和优化指令序列 |

表中描述的是传统、典型特征，不应当作绝对判据。例如，不能仅凭“指令数量多”就断定某个指令集一定属于 CISC。

### 3.2 指令条数、CPI 与性能

完成同一个程序时，CISC 的指令条数可能较少，但平均每条指令所需的时钟周期数可能较多；RISC 的指令条数可能较多，但指令执行过程通常更规整。

CPU 执行时间可表示为：

$$
T_{CPU}=IC\times CPI\times T_{clk}
$$

其中：

- $IC$ 是执行的指令条数；
- $CPI$ 是平均每条指令的时钟周期数；
- $T_{clk}$ 是时钟周期。

因此，不能只比较指令条数、CPI 或时钟频率中的某一个指标，也不能笼统地断言 CISC 与 RISC 中哪一类一定更快。实际性能还与微体系结构、存储层次、编译器和程序特征有关。

### 3.3 两类设计思想的融合

CISC 与 RISC 的界限在现代处理器中并非泾渭分明：

- 某些 CISC 处理器会把复杂机器指令译码成较简单的内部操作，再由类似流水线的执行部件处理。
- 某些 RISC 指令集也会加入乘除、向量或其他扩展指令，以提高特定任务的效率。

因此，CISC 和 RISC 更适合作为理解指令系统设计权衡的两种典型思想，而不是互不相容的严格分类。

## 4. 408 常见考法与易错点

| 考查内容 | 判断依据 |
| --- | --- |
| 指令格式 | CISC 常变长且格式较多，RISC 常定长且格式较少 |
| 寻址方式 | CISC 通常较多，RISC 通常较少 |
| 访存方式 | load-store 结构是 RISC 的典型特征 |
| 寄存器使用 | RISC 通常设置较多通用寄存器 |
| 控制器 | CISC 常采用微程序控制，RISC 常适合硬布线控制，但都不是绝对的 |
| 流水线 | RISC 的简单、规整指令通常更便于流水化 |
| 性能比较 | 应综合 $IC$、$CPI$ 和时钟周期，不能只看其中一项 |

常见错误包括：

- 把 RISC 理解成“指令总数越少越好”；
- 认为 RISC 的所有指令都只需一个时钟周期；
- 认为 CISC 一定使用微程序控制、RISC 一定使用硬布线控制；
- 认为 CISC 一定比 RISC 慢，或 RISC 一定比 CISC 快；
- 认为只有 CISC 才能完成复杂功能；
- 忽略 RISC 可能以更多简单指令换取规整执行；
- 把现代处理器中的 CISC、RISC 特征看成完全互斥。

## 5. 本节小结

CISC 倾向于用功能丰富的复杂指令减少程序指令条数并提高代码密度；RISC 倾向于用简单、规整的指令和 load-store 结构简化硬件执行路径，方便流水线和编译优化。

二者的核心是硬件复杂度、程序指令条数、代码密度、流水线效率和编译器工作之间的权衡。分析具体问题时，应依据题目给出的指令格式、寻址方式、访存规则和控制方式判断，避免使用绝对化结论。
