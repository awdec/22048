<h1><center>第二节 总线事务和定时</center></h1>

## 1. 总线事务

### 1.1 总线事务的基本概念

总线事务是总线上的主设备与从设备为完成一次特定操作而进行的完整信息交换。典型操作包括读、写和成组数据传送。

一次事务中通常存在以下角色：

| 角色 | 主要职责 | 典型设备 |
| --- | --- | --- |
| 主设备 | 发起事务，给出地址和操作命令 | CPU、DMA 控制器、具有主控能力的 I/O 控制器 |
| 从设备 | 识别地址并响应主设备的读写请求 | 主存、I/O 接口 |

主设备和从设备描述的是某次事务中的角色，不是设备永久不变的属性。例如，CPU 通常是主设备，DMA 控制器取得总线控制权后也可以成为主设备。

### 1.2 总线事务的基本阶段

经典共享总线上的一次事务通常可以抽象为：

$$
\text{请求与仲裁}
\longrightarrow
\text{地址与命令}
\longrightarrow
\text{数据传送}
\longrightarrow
\text{结束与释放}
$$

#### 地址与命令

获得使用权后，主设备给出从设备地址或主存地址，并发出读、写等控制命令。从设备通过地址译码判断自己是否被选中。

地址和命令可以占用独立线路，也可以与数据分时复用同一组线路。地址、数据复用能够减少信号线数量，但通常需要增加地址阶段。

#### 数据传送

数据方向取决于事务类型：

- 读事务中，从设备驱动数据，主设备接收；
- 写事务中，主设备驱动数据，从设备接收。

传送双方必须保证接收方采样数据时，数据已经有效并保持稳定。同步总线通过规定的时钟边沿完成采样，异步总线通过请求和应答信号确认。

#### 结束与释放

数据传送完成后，相关设备撤销地址、命令和应答信号。主设备可以释放总线，也可以在协议允许时继续发起下一个事务或继续突发传送。

### 1.4 读事务

读事务由主设备从从设备取得数据。典型过程为：

1. 主设备获得总线使用权；
2. 主设备给出地址和读命令；
3. 从设备译码地址并准备数据；
4. 从设备把有效数据送上数据总线；
5. 主设备在规定时刻接收数据；
6. 双方撤销相关信号，事务结束。

可以概括为：

$$
\text{主设备送地址和读命令}
\longrightarrow
\text{从设备送数据}
\longrightarrow
\text{主设备接收}
$$

读事务中最容易判断错误的是数据总线方向：地址和读命令仍由主设备发出，但真正的数据由从设备发往主设备。

典型读事务包括：

- CPU 从主存取指令；
- CPU 读取主存数据；
- CPU 读取 I/O 接口中的状态或数据；
- DMA 控制器读取主存或 I/O 接口。

### 1.5 写事务

写事务由主设备向从设备发送数据。典型过程为：

1. 主设备获得总线使用权；
2. 主设备给出地址和写命令；
3. 主设备把待写数据送上数据总线；
4. 从设备译码地址并在规定时刻接收数据；
5. 从设备在需要时返回完成或应答信号；
6. 双方撤销相关信号，事务结束。

可以概括为：

$$
\text{主设备送地址、写命令和数据}
\longrightarrow
\text{从设备接收}
$$

地址、写命令和数据不一定在同一时刻出现。具体顺序取决于总线协议：有的总线让地址和数据处在不同阶段，有的总线还允许地址阶段和前一事务的数据阶段重叠。

### 1.6 突发事务

突发事务在一次地址阶段之后连续传送多个数据单元。典型过程为：

1. 主设备给出起始地址、传送方向和突发长度等信息；
2. 主设备与从设备连续完成多个数据传送拍；
3. 地址通常按协议自动递增或按照规定次序变化；
4. 最后一个数据传送拍结束后释放事务。

若一次突发传送包含 $n$ 个数据拍，每拍传送 $D$ 字节，地址和控制阶段耗时 $T_a$，各数据拍总耗时为 $T_d$，则：

$$
B_{\text{有效}}=\frac{nD}{T_a+T_d}
$$

突发传送只支付一次或较少次数的寻址和控制开销，因此适合：

- Cache 块调入或写回；
- 主存连续数据访问；
- DMA 成批数据传送。

突发传送能提高连续数据的有效带宽，但不表示第一次数据的访问延迟一定降低。

### 1.7 分离事务

普通非分离事务中，主设备发出读请求后可能一直占用总线，等待从设备返回数据。分离事务把一次读操作拆成：

1. **请求事务**：主设备发送地址和读命令后释放总线；
2. **响应事务**：从设备准备好数据后重新申请并使用总线，把数据返回原请求者。

在等待从设备准备数据期间，其他设备可以使用总线，因此分离事务能够提高共享总线利用率。但系统必须保存请求者标识或事务编号，使响应能够与原请求正确对应，控制和缓冲也更复杂。

分离事务描述的是请求与响应的组织方式，不是同步定时、异步定时之外的第三种基本定时方式。

### 1.8 总线事务与 DMA

DMA 传送并非绕开总线，而是由 DMA 控制器代替 CPU 发起总线事务。其一般关系为：

$$
\text{DMA 请求总线}
\longrightarrow
\text{DMA 成为主设备}
\longrightarrow
\text{完成主存与 I/O 之间的数据传送}
\longrightarrow
\text{释放总线}
$$

## 2. 总线定时

### 2.1 同步定时

同步定时中，各设备以统一时钟为时间基准。协议预先规定哪个时钟周期给出地址、何时给出或接收数据、在哪个时钟边沿采样。

同步写事务中，主设备要保证地址、写命令和数据在从设备采样前已经稳定，并满足建立时间和保持时间要求。从设备可以在约定的时钟边沿接收数据。

同步定时的优点：

- 时序规整，控制逻辑相对简单；
- 各阶段边界明确，便于实现较高的数据传送率；
- 适合速度接近、传输延迟可预测的部件。

同步定时的局限：

- 固定节拍需要照顾较慢设备，快速设备可能被迫等待；
- 总线距离、负载和时钟偏斜会限制最高频率；
- 设备速度差异较大时，可能需要等待状态或桥接。

### 2.2 半同步定时

若从设备不能在规定周期内准备好数据，可以通过 **READY** 或 **WAIT** 等信号请求插入等待状态。基本过程为：

1. 主设备按同步方式给出地址和命令；
2. 从设备未就绪时发出等待指示；
3. 主设备保持必要信号，并插入一个或多个等待周期；
4. 从设备就绪后，双方在后续约定边沿完成数据传送。

若基本事务需要 $m$ 个时钟周期，插入 $k$ 个等待周期，则事务时间为：

$$
T_{\text{事务}}=(m+k)T_{clk}
$$

等待状态提高了对慢速设备的适应能力，但会增加访问延迟并降低有效带宽。

### 2.3 异步定时

异步定时不依赖预先规定的固定时钟节拍完成传送，而是由请求和应答信号协调双方动作。这里的“异步”强调接口传送由握手事件推进，不一定表示设备内部完全没有时钟。

典型的四相握手过程为：

1. 主设备给出地址、命令以及写事务所需的数据；
2. 主设备建立请求信号；
3. 从设备完成准备或接收后建立应答信号；
4. 主设备检测到应答后接收读数据，并撤销请求；
5. 从设备检测到请求撤销后撤销应答；
6. 双方信号恢复初始状态，事务结束。

可以概括为：

$$
\text{请求有效}
\longrightarrow
\text{应答有效}
\longrightarrow
\text{请求撤销}
\longrightarrow
\text{应答撤销}
$$

读事务中，从设备应在应答有效前保证读数据已经稳定；写事务中，主设备应在请求有效前或协议规定的时间给出稳定数据。

异步定时的优点：

- 能适应速度差异较大的设备；
- 每次事务可以按照从设备的实际响应时间结束；
- 不需要把所有设备约束在完全相同的固定节拍内。

异步定时的局限：

- 请求、应答及状态检测会增加控制开销；
- 接口逻辑比固定节拍控制复杂；

### 2.4 异步定时的互锁方式

#### 不互锁方式

主设备发出请求后，经过预定时间自行撤销；从设备发出应答后，也经过预定时间自行撤销。双方撤销信号都不等待对方，因此控制简单，但对设备响应时间和信号持续时间要求严格，可靠性较低。

#### 半互锁方式

一方信号的撤销依赖另一方信号，另一方仍按预定时间自行撤销。典型形式是主设备等待应答后才撤销请求，而从设备的应答经过规定时间后自行撤销。它的可靠性和控制复杂度介于不互锁与全互锁之间。

#### 全互锁方式

主设备收到应答后才撤销请求，从设备检测到请求撤销后才撤销应答。请求和应答的建立、撤销形成完整因果关系，能够适应较大的速度差异，可靠性较高，但握手步骤和控制开销也较多。


### 2.5 同步定时与异步定时对比

| 比较项目 | 同步定时 | 异步定时 |
| --- | --- | --- |
| 时间基准 | 统一时钟 | 请求和应答事件 |
| 阶段长度 | 通常固定，可插入等待周期 | 随实际响应时间变化 |
| 控制复杂度 | 相对较低 | 相对较高 |
| 速度适应性 | 更适合速度接近的设备 | 更适合速度差异较大的设备 |
| 额外信号 | 需要时钟，可能需要等待信号 | 需要握手信号 |
| 主要限制 | 时钟偏斜、慢设备拖长周期 | 握手开销、控制较复杂 |

不能笼统地认为同步一定快、异步一定慢。同步总线若频繁插入等待状态，有效传输率会下降；异步总线可以在设备很快响应时立即推进，但握手本身也会产生开销。
