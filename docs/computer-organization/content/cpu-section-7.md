<h1><center>第七节 多处理器的基本概念</center></h1>

当单个处理器核心受到功耗、散热和可利用指令级并行度等因素限制时，可以通过增加处理单元或硬件线程来开发更高层次的并行性。本节从指令流与数据流、硬件线程、处理器核心和存储器组织四个维度理解多处理器系统。

## 1. SISD、SIMD、MIMD 的基本概念

### 1.1 Flynn 分类

Flynn 分类按照一个计算机系统能够同时处理的**指令流数量**和**数据流数量**进行划分：

- 指令流是处理器执行的指令序列；
- 数据流是指令处理的操作数序列。

| 类型 | 英文全称 | 指令流 | 数据流 | 基本特点 |
| --- | --- | ---: | ---: | --- |
| SISD | Single Instruction, Single Data | 单 | 单 | 一个指令流依次处理一个数据流 |
| SIMD | Single Instruction, Multiple Data | 单 | 多 | 同一操作同时作用于多个数据元素 |
| MIMD | Multiple Instruction, Multiple Data | 多 | 多 | 多个处理单元独立执行不同指令流 |

完整分类中还有 MISD（多指令流、单数据流），但实际通用计算系统中较少见，408 重点掌握 SISD、SIMD 和 MIMD。

### 1.2 SISD

SISD 系统使用一个指令流处理一个数据流，传统单处理器是其典型形式。

SISD 不等于处理器内部完全没有并行性。单个指令流的处理器仍可使用：

- 指令流水线；
- 超标量多发射；
- 乱序执行；
- 多个功能部件。

这些技术主要开发同一指令流内部的指令级并行性，并不因为内部同时执行多条指令就自动变成 SIMD 或 MIMD。

### 1.3 SIMD

SIMD 用一个控制部件向多个处理单元或数据通道发出相同操作，使不同数据元素同时接受相同处理。

例如，计算两个数组的逐元素加法：

$$
C[i]=A[i]+B[i]
$$

多个运算通道可以在同一条加法指令控制下并行处理不同的下标。

SIMD 的典型特点：

- 适合向量、矩阵、图像和科学计算等数据并行任务；
- 一套指令控制多个数据通道，控制开销相对集中；
- 数据元素执行相同操作时效率高；
- 不同数据元素需要走不同控制分支时，部分通道可能空闲，效率下降。

阵列处理机和处理器中的向量/SIMD 扩展都体现了 SIMD 思想。具体系统可以在 MIMD 的每个处理核心内部继续使用 SIMD，分类维度并不互斥。

### 1.4 MIMD

MIMD 系统具有多个独立的指令执行单元，每个处理器或核心通常有自己的 `PC` 和体系结构寄存器，可以执行不同程序段并处理不同数据。

典型特点：

- 既能开发任务并行，也能执行数据划分后的并行任务；
- 各处理单元可以在不同控制流上独立运行；
- 灵活性较强，但需要解决任务划分、通信、同步和负载均衡问题；
- 可以采用共享内存，也可以采用分布式内存和消息传递。

多核处理器和多处理器系统通常属于 MIMD。一个 MIMD 核心内部还可能包含 SIMD 运算单元。

### 1.5 向量处理器

向量处理器提供以**向量**为操作对象的指令和硬件。一条向量指令可以对一组数据元素执行相同运算，例如：

$$
V_3 \leftarrow V_1+V_2
$$

该指令表示把向量寄存器 $V_1$ 和 $V_2$ 中的对应元素相加，并把结果写入 $V_3$。其基本组成通常包括：

- **向量指令**：用一条指令描述多个数据元素上的同类操作；
- **向量寄存器**：保存由多个数据元素组成的向量操作数和结果；
- **向量功能部件**：通常采用流水线方式连续处理各元素；
- **向量长度控制**：说明当前向量指令实际处理的元素个数。

向量处理器通过一条向量指令完成多个同类标量操作，可以减少取指和译码开销，并开发数据级并行性。它通常体现广义的 SIMD 思想，但不能理解为具有多个相互独立的指令流。多核 MIMD 处理器中的每个核心也可以带有向量运算部件。

### 1.6 三类结构对比

| 比较项目 | SISD | SIMD | MIMD |
| --- | --- | --- | --- |
| 控制流 | 一个 | 一个控制流控制多个数据通道 | 多个独立控制流 |
| 主要并行层次 | 单指令流内部 | 数据级并行 | 线程级或任务级并行 |
| 是否要求执行相同操作 | 不涉及多个处理单元 | 同一时刻通常相同 | 不要求相同 |
| 典型适用场景 | 通用顺序程序 | 规则的批量数据运算 | 多任务、并行程序和服务 |
| 主要限制 | 单一指令流的可用并行性 | 分支不一致和数据不规则 | 通信、同步和共享资源竞争 |

## 2. 硬件多线程的基本概念

### 2.1 硬件线程

硬件多线程使一个处理器核心保存两个或更多线程的体系结构状态，并让这些线程共享核心内部的执行资源。

每个硬件线程通常具有独立的：

- `PC`；
- 体系结构寄存器状态；
- 部分控制和异常状态。

线程之间通常共享：

- 流水线和执行部件；
- 一级或更低层 Cache 的全部或部分结构；
- 取指、译码、发射和访存带宽。

操作系统通常把每个可独立调度的硬件线程视为一个逻辑处理器。硬件线程切换由处理器直接完成，不等同于操作系统保存和恢复完整软件线程上下文的普通上下文切换。

### 2.2 硬件多线程的目的

当一个线程因 Cache 缺失、访存或其他长延迟事件停顿时，核心中的部分硬件资源可能空闲。硬件多线程通过执行其他线程来隐藏等待时间，提高流水线和执行部件的利用率。

硬件多线程主要提高核心的总体吞吐率，并不保证降低单个线程的执行时间。多个线程共享资源时还可能相互竞争，使单线程性能下降。

### 2.3 粗粒度多线程

粗粒度多线程通常在当前线程发生较长时间停顿时，才切换到另一个硬件线程。

特点：

- 线程切换频率较低；
- 能隐藏长延迟事件；
- 切换时可能需要清空或重新启动部分流水线；
- 对短停顿的隐藏效果有限。

### 2.4 细粒度多线程

细粒度多线程通常按时钟周期轮换选择不同硬件线程的指令进入流水线。

特点：

- 相邻周期可以来自不同线程；
- 能减少单个线程数据相关和访存等待造成的流水线空闲；
- 单个线程获得的发射周期减少，单线程完成时间可能增加；
- 需要快速选择线程并区分各线程的体系结构状态。

### 2.5 同时多线程

同时多线程（Simultaneous Multithreading，SMT）建立在超标量处理器之上，允许同一个时钟周期从多个硬件线程选择并发射指令。

SMT 可以用一个线程的独立指令填补另一个线程留下的发射槽，提高多个执行部件的利用率。但它需要更复杂的资源分配、依赖检查和公平性控制，线程之间也会竞争 Cache、执行单元和访存带宽。

### 2.6 三种多线程方式对比

| 比较项目 | 粗粒度 | 细粒度 | SMT |
| --- | --- | --- | --- |
| 切换或选择时机 | 长延迟事件发生时 | 通常每周期轮换 | 同一周期可选择多个线程 |
| 每周期指令来源 | 通常一个线程 | 通常一个线程 | 可以多个线程 |
| 依赖的处理器结构 | 单发射或多发射均可 | 常见于轮换发射 | 需要多发射能力 |
| 主要目标 | 隐藏长延迟 | 细粒度隐藏停顿 | 填满多个发射槽 |
| 控制复杂度 | 相对较低 | 较高 | 最高 |

硬件多线程与多核可以组合：一个处理器包含多个核心，每个核心又可以支持多个硬件线程。

## 3. 多核处理器的基本概念

### 3.1 多核处理器

多核处理器在一个处理器芯片或封装中集成多个相对独立的处理核心。每个核心通常具有自己的：

- 控制器和流水线；
- ALU、执行部件；
- `PC` 和体系结构寄存器；
- 私有的一级 Cache 或部分局部 Cache。

多个核心可能共享：

- 末级 Cache；
- 片上互连；
- 内存控制器和主存带宽；
- I/O 接口和功耗预算。

Cache 层次哪些私有、哪些共享没有统一答案，应以具体处理器或题目给出的结构为准。

### 3.2 多核与硬件多线程的区别

| 比较项目 | 多核 | 单核硬件多线程 |
| --- | --- | --- |
| 独立执行核心 | 多个 | 一个 |
| 执行部件 | 每核通常有自己的主要执行部件 | 多个线程主要共享同一核心执行部件 |
| 线程状态 | 每核至少一套 | 同一核心保存多套硬件线程状态 |
| 并行能力来源 | 复制或增加处理核心 | 提高单个核心内部资源利用率 |
| 资源竞争 | 主要竞争共享 Cache、内存和互连 | 还直接竞争同一核心的发射槽和执行单元 |

“四核八线程”通常表示四个物理核心，每个核心支持两个硬件线程，而不是八个完整物理核心。

### 3.3 多核系统的并行执行

操作系统可以把不同进程或线程调度到不同核心。并行程序还需要把任务划分成可并行部分，并通过共享内存或消息传递交换数据。

多核性能受以下因素限制：

- 程序中不可并行的串行部分；
- 线程创建、同步和通信开销；
- 任务划分不均造成的负载不平衡；
- Cache、主存带宽和片上互连竞争；
- Cache 一致性通信；
- 功耗和散热限制。

因此，核心数量增加不意味着程序性能按相同比例提高。

### 3.4 并行加速的上限（扩展）

若程序中比例为 $p$ 的部分可以在 $n$ 个核心上理想并行，其余 $1-p$ 必须串行，则 Amdahl 定律给出的理想加速比为：

$$
S(n)=\frac{1}{(1-p)+\frac{p}{n}}
$$

当 $n\rightarrow\infty$ 时：

$$
S_{max}=\frac{1}{1-p}
$$

该式用于说明串行部分对并行加速的限制。实际系统还会受到通信、同步和资源竞争等额外开销影响。

### 3.5 多核与 Flynn 分类

普通多核处理器的各核心具有独立 `PC`，能够执行不同指令流，因此整体通常属于 MIMD。若每个核心又支持向量指令，则同一系统可以同时体现：

- 核心之间的 MIMD；
- 核心内部的 SIMD；
- 单个核心上的硬件多线程。

这些术语描述不同层次，不能互相替代。

## 4. 共享内存多处理器的基本概念

### 4.1 共享地址空间

共享内存多处理器为多个处理器或核心提供统一的共享地址空间。各处理单元可以用普通 Load、Store 指令访问共享数据，并通过共享变量进行通信。

共享地址空间是逻辑概念，不要求所有主存芯片物理集中在同一个位置。与之相对，分布式内存系统中各处理器通常拥有独立地址空间，处理器之间主要通过显式消息传递通信。

### 4.2 对称多处理器

对称多处理器（Symmetric Multiprocessor，SMP）是典型共享内存 MIMD 系统，其处理器通常：

- 地位对等；
- 共享主存和 I/O 系统；
- 由同一个操作系统统一管理和调度；
- 可以执行相同的操作系统功能和用户程序。

“对称”强调处理器的地位和系统功能基本对等，不表示所有存储访问延迟必然完全相同。

经典的集中式 SMP 通常采用 UMA；可扩展共享内存系统也可能在保持处理器地位对等和统一地址空间的同时采用 NUMA。不同教材对 SMP 一词的使用范围可能略有差异，做题时应以题目给出的存储组织特征为准。

### 4.3 UMA 与 NUMA

> **关联理解：**现行 408 要求掌握共享内存多处理器和 SMP 的基本概念。UMA、NUMA 用于解释共享内存的物理组织差异，不要求脱离题设记忆复杂系统结构。

| 类型 | 英文全称 | 基本特点 |
| --- | --- | --- |
| UMA | Uniform Memory Access | 各处理器访问不同主存位置的时间大致相同 |
| NUMA | Non-Uniform Memory Access | 访问本地内存较快，访问其他节点的远程内存较慢 |

NUMA 系统把主存物理分布在不同处理器或节点附近，但仍向软件提供统一共享地址空间。数据放置会显著影响性能。

> **扩展了解：**若 NUMA 系统还由硬件维持多个 Cache 之间的一致性，通常称为 Cache-Coherent NUMA（CC-NUMA）。408 不要求掌握具体协议状态转换。

### 4.4 Cache 一致性问题

在共享内存多处理器中，各核心通常有私有 Cache。同一主存块可能同时存在于多个 Cache 中：

1. 核心 1 和核心 2 都缓存共享变量 `x`；
2. 核心 1 修改自己的 `x` 副本；
3. 若核心 2 的旧副本没有失效或更新，它可能继续读到旧值。

Cache 一致性机制的目标是协调同一存储位置的多个缓存副本，使各核心对该位置的写入具有一致的观察结果。常见基本思想是写入时使其他副本失效或更新，但本节不要求掌握具体一致性协议。

### 4.5 一致性、存储一致性模型与同步（扩展）

三个概念不能混淆：

| 概念 | 解决的问题 |
| --- | --- |
| Cache 一致性 | 同一个存储位置的多个缓存副本如何保持一致 |
| 存储一致性模型 | 不同核心观察多个存储操作顺序时应遵守什么规则 |
| 同步 | 程序如何协调临界区、事件先后和共享数据访问 |

即使硬件保证 Cache 一致性，多个线程没有正确同步地读写共享变量，仍然可能发生数据竞争。共享内存程序通常需要原子读改写指令、锁、屏障等同步机制。

### 4.6 共享内存系统的特点

典型优点：

- 处理器可以使用普通访存指令共享数据；
- 编程模型直观，适合细粒度通信；
- 操作系统可以统一管理存储和处理器资源。

典型限制：

- 多处理器可能争用主存带宽和互连；
- 私有 Cache 会带来一致性通信；
- 同步和锁竞争会降低并行度；
- 处理器数量增加后，集中式共享资源可能成为瓶颈；
- NUMA 中远程访问延迟较大，需要合理放置数据。

### 4.7 四个概念维度的关系

| 概念 | 描述的维度 |
| --- | --- |
| SISD、SIMD、MIMD | 同时存在的指令流和数据流数量 |
| 硬件多线程 | 一个核心保存和调度多少个硬件线程上下文 |
| 多核 | 一个处理器中包含多少个物理处理核心 |
| 共享内存多处理器 | 多个处理单元如何组织地址空间和通信 |

同一台计算机可以同时是 MIMD、多核、支持 SMT 的共享内存 NUMA 系统，并在每个核心内使用 SIMD 指令。描述系统时应明确讨论的是哪一个维度。

## 5. 408 常见考法与易错点

| 考查内容 | 分析要点 |
| --- | --- |
| Flynn 分类 | 根据指令流和数据流数量判断 SISD、SIMD、MIMD |
| 向量处理器 | 理解向量指令、向量寄存器和数据级并行的基本思想 |
| 硬件多线程 | 区分粗粒度、细粒度和 SMT |
| 多核结构 | 判断哪些资源通常每核私有、哪些可能共享 |
| 概念区分 | 区分物理核心、硬件线程和逻辑处理器 |
| 共享内存 | 核心掌握共享地址空间和 SMP；UMA、NUMA 用于关联辨析 |
| Cache 一致性 | 说明多个私有 Cache 副本产生旧值的原因 |

常见错误包括：

- 认为 SISD 处理器内部不能使用流水线或超标量技术；
- 把 SIMD 中的多个数据通道误认为多个独立指令流；
- 把向量处理器误认为具有多个相互独立的指令流；
- 认为 MIMD 只能采用共享内存；
- 把硬件线程数量直接等同于物理核心数量；
- 认为 SMT 中每个线程独占完整执行核心；
- 认为增加核心后所有程序都会自动获得线性加速；
- 认为多核处理器的所有 Cache 都必须共享或都必须私有；
- 认为 SMP 一定属于 UMA；
- 把物理分布但逻辑共享的 NUMA 内存误判为分布式地址空间；
- 认为 Cache 一致性已经自动解决了程序的数据竞争和同步问题；
- 混淆 Cache 一致性与存储一致性模型。

## 6. 本节小结

多处理器概念应从四个维度分别判断：

1. Flynn 分类用指令流和数据流区分 SISD、SIMD、MIMD；向量处理器用一条向量指令处理多个数据元素，体现数据级并行；
2. 硬件多线程在一个核心中保存多个线程状态并共享执行资源；
3. 多核处理器在一个处理器中集成多个独立核心；
4. 共享内存多处理器用统一地址空间支持处理器间通信，并需要解决同步和 Cache 一致性问题。

不同维度可以组合而不是互斥。做题时先判断题目讨论的是指令流、硬件线程、物理核心还是存储器组织，再选择相应概念。
