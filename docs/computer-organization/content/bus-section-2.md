<h1><center>第二节 总线事务和定时</center></h1>

总线把多个部件连接起来以后，还必须解决两个问题：

1. **总线事务**：一次完整的信息交换包含哪些阶段；
2. **总线定时**：主设备和从设备如何在正确时刻发送、接收信息。

总线事务描述“做什么”，总线定时描述“何时做”。同一种读事务可以采用同步定时，也可以采用异步定时；同一种定时方式也可以支持读、写或突发等不同事务。

## 1. 总线事务

### 1.1 总线事务的基本概念

总线事务是总线上的主设备与从设备为完成一次特定操作而进行的完整信息交换。典型操作包括读、写和成组数据传送。

一次事务中通常存在以下角色：

| 角色 | 主要职责 | 典型设备 |
| --- | --- | --- |
| 主设备 | 发起事务，给出地址和操作命令 | CPU、DMA 控制器、具有主控能力的 I/O 控制器 |
| 从设备 | 识别地址并响应主设备的读写请求 | 主存、I/O 接口 |

主设备和从设备描述的是某次事务中的角色，不是设备永久不变的属性。例如，CPU 通常是主设备，DMA 控制器取得总线控制权后也可以成为主设备。

### 1.2 总线事务的基本阶段

经典共享总线上的一次事务通常可以抽象为：

$$
\text{请求与仲裁}
\longrightarrow
\text{地址与命令}
\longrightarrow
\text{数据传送}
\longrightarrow
\text{结束与释放}
$$

#### 请求与仲裁（关联理解）

主设备需要使用共享总线时，可以先提出总线请求。若有多个主设备同时请求，由仲裁逻辑决定谁获得使用权。

仲裁不是所有题目中都必须单独计时：

- 主设备已经持有总线时，连续事务之间可能不再重复仲裁；
- 点到点互连不存在多个主设备争用同一物理通路的问题；
- 题目可能明确说明忽略仲裁时间。

因此，计算事务时间时应依据题目给出的阶段，不能擅自增加或删去仲裁开销。

#### 地址与命令

获得使用权后，主设备给出从设备地址或主存地址，并发出读、写等控制命令。从设备通过地址译码判断自己是否被选中。

地址和命令可以占用独立线路，也可以与数据分时复用同一组线路。地址、数据复用能够减少信号线数量，但通常需要增加地址阶段。

#### 数据传送

数据方向取决于事务类型：

- 读事务中，从设备驱动数据，主设备接收；
- 写事务中，主设备驱动数据，从设备接收。

传送双方必须保证接收方采样数据时，数据已经有效并保持稳定。同步总线通过规定的时钟边沿完成采样，异步总线通过请求和应答信号确认。

#### 结束与释放

数据传送完成后，相关设备撤销地址、命令和应答信号。主设备可以释放总线，也可以在协议允许时继续发起下一个事务或继续突发传送。

### 1.3 相关时间概念

| 概念 | 含义 |
| --- | --- |
| 时钟周期 | 同步系统中相邻有效时钟沿之间的时间 |
| 总线周期 | 完成一次基本总线操作所需的时间 |
| 数据传送拍 | 在数据阶段传送一个总线宽度数据的基本节拍 |
| 总线事务 | 为完成一次读、写或块传送而经历的完整过程 |
| 存储周期 | 存储器连续启动两次独立访问所允许的最小时间间隔 |
| 指令周期 | CPU 取出并执行完一条机器指令所需的时间 |

在简单总线中，一次事务可能只包含一个数据传送拍；在突发事务中，一次地址阶段之后可以跟随多个数据传送拍；在分离事务中，请求和响应甚至可以在时间上分开。

不同教材和总线协议对“总线周期”“传送周期”等术语的使用可能略有差异。解题时应优先采用题目给出的定义和时序图。

一条机器指令可能引起多次总线事务，例如取指、读取主存操作数和写回主存结果。但寄存器运算指令命中 Cache 时，不一定在执行阶段产生外部存储器总线事务。

### 1.4 读事务

读事务由主设备从从设备取得数据。典型过程为：

1. 主设备获得总线使用权；
2. 主设备给出地址和读命令；
3. 从设备译码地址并准备数据；
4. 从设备把有效数据送上数据总线；
5. 主设备在规定时刻接收数据；
6. 双方撤销相关信号，事务结束。

可以概括为：

$$
\text{主设备送地址和读命令}
\longrightarrow
\text{从设备送数据}
\longrightarrow
\text{主设备接收}
$$

读事务中最容易判断错误的是数据总线方向：地址和读命令仍由主设备发出，但真正的数据由从设备发往主设备。

典型读事务包括：

- CPU 从主存取指令；
- CPU 读取主存数据；
- CPU 读取 I/O 接口中的状态或数据；
- DMA 控制器读取主存或 I/O 接口。

### 1.5 写事务

写事务由主设备向从设备发送数据。典型过程为：

1. 主设备获得总线使用权；
2. 主设备给出地址和写命令；
3. 主设备把待写数据送上数据总线；
4. 从设备译码地址并在规定时刻接收数据；
5. 从设备在需要时返回完成或应答信号；
6. 双方撤销相关信号，事务结束。

可以概括为：

$$
\text{主设备送地址、写命令和数据}
\longrightarrow
\text{从设备接收}
$$

地址、写命令和数据不一定在同一时刻出现。具体顺序取决于总线协议：有的总线让地址和数据处在不同阶段，有的总线还允许地址阶段和前一事务的数据阶段重叠。

### 1.6 读事务与写事务对比

| 比较项目 | 读事务 | 写事务 |
| --- | --- | --- |
| 地址发出者 | 主设备 | 主设备 |
| 命令发出者 | 主设备 | 主设备 |
| 数据发出者 | 从设备 | 主设备 |
| 数据接收者 | 主设备 | 从设备 |
| 主要等待对象 | 等待从设备准备并返回数据 | 等待从设备能够接收或完成写入 |
| 典型操作 | 取指、Load、读 I/O | Store、写 I/O |

### 1.7 突发事务

突发事务在一次地址阶段之后连续传送多个数据单元。典型过程为：

1. 主设备给出起始地址、传送方向和突发长度等信息；
2. 主设备与从设备连续完成多个数据传送拍；
3. 地址通常按协议自动递增或按照规定次序变化；
4. 最后一个数据传送拍结束后释放事务。

若一次突发传送包含 $n$ 个数据拍，每拍传送 $D$ 字节，地址和控制阶段耗时 $T_a$，各数据拍总耗时为 $T_d$，则：

$$
B_{\text{有效}}=\frac{nD}{T_a+T_d}
$$

突发传送只支付一次或较少次数的寻址和控制开销，因此适合：

- Cache 块调入或写回；
- 主存连续数据访问；
- DMA 成批数据传送。

突发传送能提高连续数据的有效带宽，但不表示第一次数据的访问延迟一定降低。

### 1.8 分离事务（扩展）

普通非分离事务中，主设备发出读请求后可能一直占用总线，等待从设备返回数据。分离事务把一次读操作拆成：

1. **请求事务**：主设备发送地址和读命令后释放总线；
2. **响应事务**：从设备准备好数据后重新申请并使用总线，把数据返回原请求者。

在等待从设备准备数据期间，其他设备可以使用总线，因此分离事务能够提高共享总线利用率。但系统必须保存请求者标识或事务编号，使响应能够与原请求正确对应，控制和缓冲也更复杂。

分离事务描述的是请求与响应的组织方式，不是同步定时、异步定时之外的第三种基本定时方式。

### 1.9 总线事务与 DMA

DMA 传送并非绕开总线，而是由 DMA 控制器代替 CPU 发起总线事务。其一般关系为：

$$
\text{DMA 请求总线}
\longrightarrow
\text{DMA 成为主设备}
\longrightarrow
\text{完成主存与 I/O 之间的数据传送}
\longrightarrow
\text{释放总线}
$$

DMA 可以采用单字传送，也可以采用成组或突发传送。DMA 的详细工作过程属于 I/O 系统内容，本节只需理解主设备角色和总线事务的关系。

## 2. 总线定时

总线定时规定地址、数据和控制信号在时间上的建立、保持、采样及撤销关系，保证不同设备能够可靠交换信息。

408 的核心是同步定时和异步定时：

| 定时方式 | 主要协调依据 | 事务长度 |
| --- | --- | --- |
| 同步定时 | 统一时钟和约定的时钟边沿 | 通常由固定节拍决定，可插入等待状态 |
| 异步定时 | 请求、应答等握手信号 | 随设备实际响应时间变化 |

### 2.1 同步定时

同步定时中，各设备以统一时钟为时间基准。协议预先规定哪个时钟周期给出地址、何时给出或接收数据、在哪个时钟边沿采样。

某种简化同步读事务可以表示为：

| 时钟阶段 | 典型动作 |
| --- | --- |
| $T_1$ | 主设备给出地址和读命令 |
| $T_2$ | 从设备译码并准备数据 |
| $T_3$ | 从设备给出有效数据，主设备在约定边沿采样 |
| $T_4$ | 撤销信号，事务结束 |

以上只是一种抽象示例，并不是所有同步总线都固定使用四个阶段。题目若给出具体时序，应以题目为准。

同步写事务中，主设备要保证地址、写命令和数据在从设备采样前已经稳定，并满足建立时间和保持时间要求。从设备可以在约定的时钟边沿接收数据。

同步定时的优点：

- 时序规整，控制逻辑相对简单；
- 各阶段边界明确，便于实现较高的数据传送率；
- 适合速度接近、传输延迟可预测的部件。

同步定时的局限：

- 固定节拍需要照顾较慢设备，快速设备可能被迫等待；
- 总线距离、负载和时钟偏斜会限制最高频率；
- 设备速度差异较大时，可能需要等待状态或桥接。

### 2.2 带等待状态的同步定时

若从设备不能在规定周期内准备好数据，可以通过 **READY** 或 **WAIT** 等信号请求插入等待状态。基本过程为：

1. 主设备按同步方式给出地址和命令；
2. 从设备未就绪时发出等待指示；
3. 主设备保持必要信号，并插入一个或多个等待周期；
4. 从设备就绪后，双方在后续约定边沿完成数据传送。

若基本事务需要 $m$ 个时钟周期，插入 $k$ 个等待周期，则事务时间为：

$$
T_{\text{事务}}=(m+k)T_{clk}
$$

等待状态提高了对慢速设备的适应能力，但会增加访问延迟并降低有效带宽。有些教材把“统一时钟加等待信号”的方式称为**半同步通信**，它仍以同步时钟为基本时间尺度。

### 2.3 异步定时

异步定时不依赖预先规定的固定时钟节拍完成传送，而是由请求和应答信号协调双方动作。这里的“异步”强调接口传送由握手事件推进，不一定表示设备内部完全没有时钟。

典型的四相握手过程为：

1. 主设备给出地址、命令以及写事务所需的数据；
2. 主设备建立请求信号；
3. 从设备完成准备或接收后建立应答信号；
4. 主设备检测到应答后接收读数据，并撤销请求；
5. 从设备检测到请求撤销后撤销应答；
6. 双方信号恢复初始状态，事务结束。

可以概括为：

$$
\text{请求有效}
\longrightarrow
\text{应答有效}
\longrightarrow
\text{请求撤销}
\longrightarrow
\text{应答撤销}
$$

读事务中，从设备应在应答有效前保证读数据已经稳定；写事务中，主设备应在请求有效前或协议规定的时间给出稳定数据。

异步定时的优点：

- 能适应速度差异较大的设备；
- 每次事务可以按照从设备的实际响应时间结束；
- 不需要把所有设备约束在完全相同的固定节拍内。

异步定时的局限：

- 请求、应答及状态检测会增加控制开销；
- 接口逻辑比固定节拍控制复杂；

> **扩展了解：**实际工程实现还要处理信号传播、亚稳态、跨时钟域以及从设备始终不应答时的超时机制。

### 2.4 异步定时的互锁方式（扩展辨析）

经典教材常按照请求和应答信号的撤销是否依赖对方信号，把异步通信分为三类：

#### 不互锁方式

主设备发出请求后，经过预定时间自行撤销；从设备发出应答后，也经过预定时间自行撤销。双方撤销信号都不等待对方，因此控制简单，但对设备响应时间和信号持续时间要求严格，可靠性较低。

#### 半互锁方式

一方信号的撤销依赖另一方信号，另一方仍按预定时间自行撤销。典型形式是主设备等待应答后才撤销请求，而从设备的应答经过规定时间后自行撤销。它的可靠性和控制复杂度介于不互锁与全互锁之间。

#### 全互锁方式

主设备收到应答后才撤销请求，从设备检测到请求撤销后才撤销应答。请求和应答的建立、撤销形成完整因果关系，能够适应较大的速度差异，可靠性较高，但握手步骤和控制开销也较多。

| 方式 | 请求撤销是否等待应答 | 应答撤销是否等待请求撤销 | 适应速度差异 |
| --- | --- | --- | --- |
| 不互锁 | 否 | 否 | 较弱 |
| 半互锁 | 是（典型方式） | 否（典型方式） | 中等 |
| 全互锁 | 是 | 是 | 较强 |

判断互锁类型的关键不是背信号名称，而是查看一个信号的撤销是否以检测到另一个信号变化为条件。

### 2.5 同步定时与异步定时对比

| 比较项目 | 同步定时 | 异步定时 |
| --- | --- | --- |
| 时间基准 | 统一时钟 | 请求和应答事件 |
| 阶段长度 | 通常固定，可插入等待周期 | 随实际响应时间变化 |
| 控制复杂度 | 相对较低 | 相对较高 |
| 速度适应性 | 更适合速度接近的设备 | 更适合速度差异较大的设备 |
| 额外信号 | 需要时钟，可能需要等待信号 | 需要握手信号 |
| 主要限制 | 时钟偏斜、慢设备拖长周期 | 握手开销、控制较复杂 |

不能笼统地认为同步一定快、异步一定慢。同步总线若频繁插入等待状态，有效传输率会下降；异步总线可以在设备很快响应时立即推进，但握手本身也会产生开销。

### 2.6 时序题的分析方法

面对总线时序图或文字描述，可按以下步骤分析：

1. **确定事务类型**：读还是写，单次还是突发；
2. **确定数据方向**：谁驱动数据总线，谁采样数据；
3. **找到有效条件**：按哪个时钟边沿采样，或收到哪个应答后采样；
4. **统计时间阶段**：地址、数据、等待、应答和释放阶段是否重叠；
5. **计算总时间**：同步方式按周期数计算，异步方式按各阶段延迟计算；
6. **计算有效带宽**：用有效数据量除以全部事务时间。

#### 同步事务计算

若总线频率为 $f$，一个事务基本需要 $m$ 个时钟周期，并插入 $k$ 个等待周期，则：

$$
T_{\text{事务}}=\frac{m+k}{f}
$$

若每个事务传送 $D$ 字节，事务之间不能重叠，则有效带宽为：

$$
B_{\text{有效}}=\frac{D}{T_{\text{事务}}}
=D\frac{f}{m+k}
$$

例如，某 64 位同步总线工作在 $100\text{ MHz}$，一次读事务基本需要 3 个时钟周期，并插入 2 个等待周期。若每次传送 8 B，且事务之间不重叠，则：

$$
T_{\text{事务}}=(3+2)\times10\text{ ns}=50\text{ ns}
$$

$$
B_{\text{有效}}=\frac{8\text{ B}}{50\text{ ns}}=160\text{ MB/s}
$$

#### 异步事务计算

异步事务没有统一的固定周期数，应按照题目给出的信号传播和设备响应时间逐段相加：

$$
T_{\text{事务}}
=T_{\text{请求传递}}
+T_{\text{从设备响应}}
+T_{\text{应答传递}}
+T_{\text{撤销与恢复}}
$$

若某些阶段能够重叠，只计算关键时间路径，不能把所有延迟机械相加。若题目给出完整握手时序图，应从事务开始时刻量到双方恢复可发起下一事务的时刻。

### 2.7 定时分析中的建立时间与保持时间（扩展）

接收方在某个时刻采样数据时，数据不能恰好同时变化。通常要求：

- **建立时间**：在采样时刻之前，数据已经稳定的最短时间；
- **保持时间**：在采样时刻之后，数据仍需继续稳定的最短时间。

在同步时序题中，发送部件、组合逻辑、线路传播和接收寄存器共同决定时钟周期下限。可抽象为：

$$
T_{clk}
\geq
T_{\text{发送}}
+T_{\text{线路与组合逻辑}}
+T_{\text{建立}}
$$

若拓展题给出时钟偏斜、抖动或其他裕量，也应按题目定义计入关键路径；现行 408 不要求掌握复杂的物理总线设计。

## 3. 408 核心考法与补充易错点

### 3.1 常见考法

| 考查内容 | 分析要点 |
| --- | --- |
| 事务阶段 | 判断请求、地址、命令、数据和结束的先后关系 |
| 读写方向 | 读由从设备送数据，写由主设备送数据 |
| 周期辨析 | 区分时钟周期、总线周期、存储周期和指令周期 |
| 突发传送 | 一次地址阶段后包含多个数据传送拍 |
| 同步定时 | 按时钟边沿和等待周期分析 |
| 异步定时 | 按请求—应答的因果关系分析 |
| 时间与带宽 | 统计全部事务时间，再用有效数据量相除 |

### 3.2 常见错误

- 把总线事务和总线定时当成同一个概念；
- 认为主设备在读事务中也负责驱动读数据；
- 认为一次事务一定只传送一个总线宽度的数据；
- 把总线周期、时钟周期、存储周期和指令周期混为一谈；
- 认为同步定时的一次事务一定只占一个时钟周期；
- 插入等待周期后仍使用未等待时的理论带宽；
- 认为异步定时完全不需要时序约束；
- 计算突发传送时为每个数据拍重复加入一次地址阶段；
- 计算异步事务时间时忽略可重叠阶段或恢复时间。

关联或扩展内容中还应注意：

- 认为每次事务都必须重新仲裁，或计算时无条件忽略仲裁；
- 只看到请求和应答信号就断定为全互锁，没有分析信号撤销条件；
- 把分离事务误认为一种独立于同步、异步的基本定时方式。

## 4. 本节小结

总线事务和定时应分别理解：

1. **总线事务**规定一次信息交换的逻辑过程。读事务由从设备返回数据，写事务由主设备发送数据，突发事务在一次地址阶段后连续传送多个数据；
2. **总线定时**规定各信号的时间关系。同步定时依靠统一时钟，异步定时依靠请求和应答握手；
3. **性能计算**以完整事务为边界，把地址、数据、等待和恢复等实际经历的阶段纳入总时间。

做题时先判断事务类型和数据方向，再按时钟边沿或握手因果关系统计时间，最后计算传输延迟或有效带宽。
