<h1><center>第一节 计算机系统层次结构</center></h1>

本节从“系统由什么组成”出发，依次认识硬件、软件和系统层次，再从不同用户的视角理解各层接口，最后说明程序如何在计算机中运行。

## 1. 计算机系统的组成

一个完整的计算机系统由**硬件系统**和**软件系统**共同组成。

$$
\text{计算机系统}
=
\text{硬件系统}
+
\text{软件系统}
$$

| 组成 | 含义 | 典型例子 |
| --- | --- | --- |
| 硬件系统 | 构成计算机的物理设备，是软件运行的物质基础 | CPU、主存、硬盘、键盘、显示器 |
| 软件系统 | 指挥硬件完成任务的程序及其相关文档 | 操作系统、编译器、数据库管理系统、应用程序 |

硬件与软件相互依存：

- 没有硬件，软件无法运行。
- 没有软件，硬件难以完成有意义的任务。
- 同一种功能既可以由硬件实现，也可以由软件实现，这称为**软硬件功能的等价性**。

例如，乘法既可以由专用乘法器直接完成，也可以用多次加法的软件程序实现。通常，硬件实现速度快、成本高，软件实现灵活、成本低。

::: tip 核心理解
计算机系统性能是软硬件协同的结果，不能只根据某一个硬件部件判断整机能力。
:::

## 2. 计算机硬件

### 2.1 冯·诺依曼机的基本思想

现代通用计算机通常以冯·诺依曼结构为基础，其核心是**存储程序**思想：

1. 程序和数据都以二进制形式表示。
2. 程序和数据预先存放在存储器中，形式上没有区别，都是二进制信息。
3. 计算机在程序控制下自动、连续地取出并执行指令。
4. 指令通常由操作码和地址码组成。
5. 指令一般按其在存储器中的顺序执行，遇到转移指令时改变执行顺序。

$$
\text{指令}
=
\text{操作码}
+
\text{地址码}
$$

| 字段 | 作用 |
| --- | --- |
| 操作码 | 指明执行什么操作，如加、减、传送、转移 |
| 地址码 | 指明操作数、操作数地址或结果地址 |

::: warning 易错点
程序和数据在存储器中都用二进制表示，但 CPU 会根据取出信息时所处的阶段和指令的要求，判断它是指令还是数据。
:::

### 2.2 硬件的五大组成部分

冯·诺依曼计算机由运算器、控制器、存储器、输入设备和输出设备五部分组成。

| 部件 | 主要功能 |
| --- | --- |
| 运算器 | 完成算术运算和逻辑运算 |
| 控制器 | 取出并解释指令，发出控制信号，协调各部件工作 |
| 存储器 | 存放程序、原始数据、中间结果和最终结果 |
| 输入设备 | 将程序和数据转换为计算机能够接收的信息 |
| 输出设备 | 将计算结果转换为人或其他设备能够接收的信息 |

运算器和控制器通常集成在中央处理器中：

$$
\text{CPU}
=
\text{运算器}
+
\text{控制器}
$$

这是从基本功能角度进行的概括。实际 CPU 内部还包含寄存器等部件，现代处理器通常还集成 Cache、存储管理部件等结构。

现代计算机硬件可以进一步概括为 CPU、主存储器和 I/O 设备，它们通过总线或其他互连结构交换地址、数据和控制信息。

### 2.3 各部件的协同关系

计算机执行任务时，各部件并不是孤立工作的：

$$
\text{输入设备}
\longrightarrow
\text{主存储器}
\longleftrightarrow
\text{CPU}
\longrightarrow
\text{输出设备}
$$

- 输入设备把程序和数据送入计算机。
- 主存储器保存当前正在执行的程序及其数据。
- 控制器根据指令组织各部件工作。
- 运算器对数据进行处理。
- 结果可以写回主存，也可以通过输出设备送到外部。

## 3. 计算机软件

### 3.1 系统软件与应用软件

计算机软件按功能通常分为系统软件和应用软件。

| 类型 | 主要作用 | 典型例子 |
| --- | --- | --- |
| 系统软件 | 管理硬件资源，为其他软件提供运行环境和公共服务 | 操作系统、编译器、汇编程序、数据库管理系统 |
| 应用软件 | 面向具体应用领域，帮助用户完成特定任务 | 浏览器、办公软件、图像处理软件 |

操作系统是最重要的系统软件之一，负责管理 CPU、主存、文件和 I/O 设备等资源，并向应用程序提供系统调用等接口。

### 3.2 程序设计语言

程序设计语言从接近硬件到接近用户，可分为机器语言、汇编语言和高级语言。

| 语言 | 表示方式 | 与硬件的关系 | CPU 能否直接执行 |
| --- | --- | --- | --- |
| 机器语言 | 二进制机器指令 | 直接对应具体指令系统 | 能 |
| 汇编语言 | 助记符、寄存器名和标号 | 与具体指令系统密切相关 | 不能 |
| 高级语言 | 变量、表达式、函数和语句 | 更接近问题描述，机器相关性较弱 | 不能 |

三类语言的侧重点可以概括为：

- 高级语言描述“要解决什么问题”。
- 汇编语言描述“使用哪些机器级操作”。
- 机器语言给出“CPU 实际执行的二进制指令”。

### 3.3 翻译程序

除机器语言外，其他语言编写的程序都需要经过翻译或解释，最终通过执行机器指令来实现其功能。

| 程序 | 作用 |
| --- | --- |
| 编译程序 | 将高级语言源程序整体翻译成目标程序 |
| 解释程序 | 对源程序逐句翻译并立即执行，一般不生成独立目标程序 |
| 汇编程序 | 将汇编语言源程序翻译成机器语言目标程序 |
| 链接程序 | 将目标模块和所需库文件连接成可执行文件 |
| 装入程序 | 将可执行程序装入主存，为运行做好准备 |

典型的编译执行过程为：

$$
\text{高级语言源程序}
\longrightarrow
\text{编译与汇编}
\longrightarrow
\text{目标程序}
\longrightarrow
\text{链接}
\longrightarrow
\text{可执行程序}
\longrightarrow
\text{装入主存}
\longrightarrow
\text{执行}
$$

不同语言和编译系统的具体过程可能不同，但 CPU 最终执行的都是机器指令。

## 4. 计算机系统的层次结构

### 4.1 层次与虚拟机器

计算机系统是一个由硬件和软件共同构成的多级层次结构。每一层都建立在下一层的基础上，向上一层隐藏实现细节并提供更容易使用的功能。因此，各层都可以看成一台抽象的**虚拟机器**。

下面的 M0～M5 是教材中常用的一种说明模型，用于帮助理解系统抽象，并不是现行 408 大纲要求记忆的固定层次划分。由底层到高层，常见层次如下：

| 层次 | 虚拟机器 | 主要内容 | 实现方式 |
| --- | --- | --- | --- |
| M0 | 微程序机器 | 微指令、数据通路和控制信号 | 硬件或固件 |
| M1 | 传统机器 | 机器指令及其执行 | 硬件解释 |
| M2 | 操作系统机器 | 系统调用、进程、文件和虚拟存储等 | 机器语言程序解释 |
| M3 | 汇编语言机器 | 助记符、伪指令和符号地址 | 汇编程序翻译 |
| M4 | 高级语言机器 | 高级语言的语句和数据结构 | 编译程序或解释程序 |
| M5 | 应用语言机器 | 面向具体问题的应用功能 | 应用程序或专用软件实现 |

不同教材对层次数量和名称的划分可能略有不同，但核心关系不变：**下层实现上层，上层使用下层提供的接口**。

对于采用硬布线控制器的处理器，并不存在独立的微程序机器层，因此不能认为所有计算机都严格具有上述六个层次。

### 4.2 翻译与解释

高一层程序最终要转换为低一层能够理解的形式，基本方式有两种：

| 方式 | 特点 | 典型例子 |
| --- | --- | --- |
| 翻译 | 先把高层程序整体转换为低层程序，再执行转换后的程序 | 编译、汇编 |
| 解释 | 每遇到一条高层语句或指令，就执行一段低层程序来完成其功能 | 指令执行、解释器 |

机器指令通常由硬件直接解释执行；汇编语言通常经过汇编；高级语言既可以编译执行，也可以解释执行。

### 4.3 拓展：指令集体系结构——软硬件的接口

指令集体系结构（Instruction Set Architecture，ISA）规定了软件可以使用的机器级功能，例如：

- 指令的格式和功能。
- 数据类型和寄存器。
- 寻址方式。
- 可访问的存储空间。
- 异常和中断机制。

ISA 位于软件与硬件之间：硬件负责实现 ISA，系统软件和机器级程序使用 ISA。因此，ISA 是理解计算机系统层次结构的关键接口。

### 4.4 拓展：计算机系统结构、组成与实现

| 概念 | 关注的问题 | 例子 |
| --- | --- | --- |
| 计算机系统结构 | 机器对程序员表现出什么属性 | 指令系统、数据类型、寻址方式 |
| 计算机组成 | 这些属性在机器内部如何实现 | 数据通路、控制器、Cache 组织 |
| 计算机实现 | 使用什么器件和工艺制成 | 芯片工艺、电路设计、器件布局 |

简要地说：系统结构强调“程序员看得到什么”，计算机组成强调“内部怎样实现”，计算机实现强调“具体怎样制造”。

## 5. 计算机系统的不同用户

不同用户面对的是不同层次的虚拟机器，关注的接口也不同。

本部分用于辅助理解“同一计算机系统可呈现不同抽象层次”，不属于现行 408 大纲要求逐项记忆的内容。

| 用户 | 主要面对的层次 | 关注内容 |
| --- | --- | --- |
| 最终用户 | 应用语言机器 | 应用功能和交互界面，通常不关心底层细节 |
| 应用程序员 | 高级语言机器 | 语言、算法、库和应用程序接口 |
| 系统程序员 | 操作系统机器、汇编语言机器 | 系统调用、资源管理、编译工具和底层程序 |
| 汇编语言程序员 | 汇编语言机器、传统机器 | 指令、寄存器、地址和存储布局 |
| 机器语言程序员 | 传统机器 | 机器指令编码和 ISA |
| 硬件设计人员 | 微程序机器及逻辑电路 | 数据通路、控制器和电路实现 |

同一个操作在不同用户眼中有不同的抽象形式。例如，保存文件时：

1. 最终用户执行“保存”操作。
2. 应用程序调用操作系统提供的文件接口。
3. 操作系统管理文件、内存和 I/O 设备。
4. CPU 执行相应的机器指令。
5. 硬件控制器把数据写入存储设备。

层次结构让上层用户不必了解所有底层细节，也使系统各部分可以相对独立地设计和改进。

## 6. 计算机系统的工作原理

### 6.1 从源程序到可执行程序

用户编写的程序必须逐步转换为机器可以执行的形式：

$$
\text{问题与算法}
\longrightarrow
\text{高级语言程序}
\longrightarrow
\text{机器指令序列}
\longrightarrow
\text{装入主存}
$$

操作系统负责创建运行环境并把程序装入主存。程序开始运行后，CPU 根据程序计数器指出的地址取出指令。

### 6.2 指令的执行过程

一条指令的执行通常可概括为：

$$
\text{取指}
\longrightarrow
\text{译码}
\longrightarrow
\text{取数}
\longrightarrow
\text{执行}
\longrightarrow
\text{写回}
$$

1. **取指**：根据程序计数器给出的地址，从主存取出指令。
2. **译码**：控制器分析操作码，确定要完成的操作。
3. **取数**：根据需要取得寄存器或主存中的操作数。
4. **执行**：运算器或其他功能部件完成指定操作。
5. **写回**：将结果写入寄存器或主存，并确定下一条指令的地址。

并非每条指令都需要经历完整的取数或写回阶段，但都必须经过取指和译码。

### 6.3 存储程序控制

计算机能够自动工作的根本原因，是程序已经以指令序列的形式存放在主存中。CPU 持续重复“取指—译码—执行”的过程；遇到分支、中断或异常时，控制流可能转移到新的指令地址或相应的处理程序，处理完成后通常继续执行，直至程序结束。

$$
\text{存储程序}
+
\text{程序控制}
\Longrightarrow
\text{自动、连续地处理信息}
$$

::: tip 本节主线
用户需求经过软件层层转换，最终成为机器指令；机器指令存入主存后，由 CPU 逐条取出并执行，驱动硬件完成任务。
:::

### 6.4 408 常见考点与易错点

| 考点 | 应掌握的结论 |
| --- | --- |
| 系统组成 | 完整的计算机系统包括硬件和软件 |
| 冯·诺依曼机 | 核心思想是存储程序，采用控制流驱动方式 |
| 硬件组成 | 五大部件是运算器、控制器、存储器、输入设备和输出设备 |
| 软件分类 | 系统软件管理资源，应用软件解决具体问题 |
| 语言层次 | CPU 只能直接执行机器语言程序 |
| 翻译程序 | 编译、解释、汇编、链接和装入的作用不能混淆 |
| 系统层次 | 下层实现上层，上层使用下层提供的接口 |
| ISA | 是软件与硬件之间的重要接口 |
| 概念区分 | 系统结构关注程序员可见属性，组成关注内部实现 |

特别注意：

- 汇编语言是机器语言的符号化表示，但 CPU 不能直接执行汇编语言源程序。
- 控制器负责协调和控制，运算器负责算术运算与逻辑运算。
- 程序和数据都以二进制形式存储，二者不能仅凭二进制外形区分。
- 高级语言不一定只采用编译方式，也可能采用解释方式或混合方式。
- 主存中存放的是当前需要执行的程序和数据，长期保存通常由辅助存储器完成。

## 7. 本节小结

本节可以压缩为一条完整链路：

$$
\text{计算机系统}
\longrightarrow
\text{硬件与软件}
\longrightarrow
\text{多级虚拟机器}
\longrightarrow
\text{不同用户使用不同接口}
\longrightarrow
\text{机器指令驱动硬件工作}
$$

理解这条链路后，后续的指令系统、CPU、存储系统和 I/O 系统就不再是相互孤立的知识点，而是计算机系统各层如何协同实现程序执行的具体展开。
