<h1><center>第四节 控制器的功能和工作原理</center></h1>

控制器是 CPU 中产生控制信号的部件。它根据机器指令、处理器状态和时序信息，按照正确顺序向数据通路、主存及有关接口发出控制信号，使一系列微操作共同完成机器指令。

本节的知识主线为：

$$
\text{控制器的输入与输出}
\longrightarrow
\text{硬布线逻辑产生控制信号}
\longrightarrow
\text{微程序解释产生控制信号}
$$

## 1. 控制器的结构和功能

### 1.1 控制器的主要功能

控制器的核心功能包括：

1. 根据 `PC` 控制取指过程，把机器指令送入 `IR`；
2. 对 `IR` 中的操作码和有关字段进行译码；
3. 根据指令语义、执行阶段和状态条件安排微操作顺序；
4. 在正确时刻产生寄存器、ALU、总线和主存等部件所需的控制信号；
5. 根据条件码、异常、中断和外部应答等信息决定控制流程；
6. 一条指令完成后转入下一条指令的取指过程。

控制器负责“发出控制”，数据通路负责“执行传送和加工”。二者通过控制信号和状态反馈构成闭环。

### 1.2 控制器的输入

| 输入信息 | 主要作用 |
| --- | --- |
| 机器指令字段 | 操作码确定操作类型，寻址和寄存器字段影响具体控制过程 |
| 时钟、节拍或当前状态 | 确定当前处于哪一个执行时刻或控制步骤 |
| 条件码和状态标志 | 决定条件转移、溢出处理等控制分支 |
| 异常和中断请求 | 决定是否转入相应处理流程 |
| 主存或 I/O 应答 | 表示读写或外部操作是否完成 |
| 总线及其他部件状态 | 用于总线仲裁、等待和资源协调 |

控制器不能只根据操作码产生全部控制信号。同一条指令在不同执行步骤需要不同控制信号，条件转移等指令还要结合状态标志。

### 1.3 控制器的输出

控制器输出的控制信号又称微命令，常见类型包括：

- 寄存器输出和写入使能；
- ALU 功能选择和状态标志写入；
- 多路选择器选择；
- 内部总线驱动选择；
- 主存或 I/O 的读写控制；
- `PC` 更新和条件写入；
- 指令执行状态或控制步骤更新。

例如，在单总线数据通路中完成：

$$
R_1\leftarrow R_2+R_3
$$

需要依次发出类似控制：

```text
T0：R2out，Yin
T1：R3out，ALU=ADD，Zin
T2：Zout，R1in
```

控制器不仅要选择正确的信号，还要保证同一节拍内同时有效的信号彼此兼容。

### 1.4 微命令与微操作

| 概念 | 含义 | 示例 |
| --- | --- | --- |
| 微命令 | 控制器发出的一个基本控制信号 | `R2out、R1in、ALU=ADD` |
| 微操作 | 微命令作用下数据通路完成的基本操作 | $R_1\leftarrow R_2$ |

二者是“控制信号”与“受控动作”的关系。一个微操作可能需要多个微命令配合；若硬件资源不冲突且数据依赖允许，多个微操作可以在同一节拍并行完成。

### 1.5 控制器的基本组成

从逻辑功能看，控制器通常包含：

| 部件 | 作用 |
| --- | --- |
| 指令寄存器及译码部件 | 保存并分析当前机器指令 |
| 时序或状态部件 | 指示当前执行步骤，产生节拍或状态序列 |
| 控制信号形成部件 | 综合指令、状态和时序信息产生微命令 |
| 条件判断与顺序控制部件 | 根据标志和外部状态选择下一控制步骤 |

控制信号形成部件可以用组合逻辑电路直接实现，也可以用控制存储器中的微指令实现，由此形成硬布线控制器和微程序控制器两种典型方案。

## 2. 硬布线控制器

### 2.1 基本原理

硬布线控制器使用门电路、触发器、译码器和有限状态控制逻辑，直接根据输入条件产生控制信号。

某个控制信号 $C_i$ 可以抽象表示为：

$$
C_i=f(\text{操作码},\text{当前状态或节拍},\text{条件标志},\text{外部状态})
$$

例如，只有在当前指令为加法、执行进入指定节拍且相关条件满足时，ALU 加法选择和目的寄存器写入信号才会有效。

### 2.2 基本结构

硬布线控制器通常包含：

- 指令操作码译码器；
- 时序发生器或状态寄存器；
- 条件标志及外部信号输入；
- 组合逻辑控制网络；
- 必要的状态转移逻辑。

其工作过程可以概括为：

$$
\text{指令译码结果}
+
\text{当前时序状态}
+
\text{条件和外部状态}
\longrightarrow
\text{组合逻辑网络}
\longrightarrow
\text{控制信号}
$$

### 2.3 设计步骤

设计硬布线控制器时通常需要：

1. 根据指令功能和数据通路写出微操作序列；
2. 按数据依赖和资源冲突把微操作划分到不同节拍或状态；
3. 列出每个状态下需要发出的控制信号；
4. 确定状态转移条件；
5. 写出控制信号和下一状态的逻辑表达式；
6. 化简并实现相应组合逻辑和时序电路。

若数据通路改变，原有控制信号和微操作序列也可能需要重新设计。因此，控制器设计必须建立在确定的数据通路之上。

### 2.4 控制信号的形成

设操作码译码得到指令信号 `ADD、LOAD`，状态译码得到 `T0、T1、…`，条件标志为 `Z、C、…`，则某个寄存器写信号可以由若干乘积项相或形成，例如：

$$
R1_{in}
=
(ADD\cdot T_2)
+
(LOAD\cdot T_4)
$$

这只是逻辑示意。实际表达式取决于指令格式、数据通路、状态编码和控制信号是否高电平有效。

条件转移还要把执行状态和条件码加入控制逻辑。例如，设 `T_J、T_EQ` 分别表示两类转移指令更新 `PC` 的执行状态，则：

$$
PCWrite
=
(JMP\cdot T_J)
+
(BEQ\cdot T_{EQ}\cdot Z)
$$

### 2.5 特点

硬布线控制器的典型优点：

- 控制信号由逻辑电路直接产生，速度通常较快；
- 不需要为每个控制步骤访问控制存储器；
- 适合指令格式和执行过程较规整的处理器。

典型局限：

- 指令和状态较多时，组合逻辑会迅速复杂化；
- 修改指令功能或增加新指令通常需要修改硬件逻辑；
- 设计、验证和排错难度随控制复杂度增加。

硬布线常见于 RISC 风格设计，但不是 RISC 的必要条件；CISC 处理器也可以对常用指令采用硬布线或混合控制。

## 3. 微程序控制

### 3.1 基本思想

微程序控制把一组控制信号编码成微指令，并把完成机器指令所需的微指令序列存放在控制存储器中。执行一条机器指令时，微程序控制器依次取出并执行相应微指令。

层级关系为：

$$
\text{机器指令}
\longrightarrow
\text{对应的微程序或微程序段}
\longrightarrow
\text{若干微指令}
\longrightarrow
\text{若干微命令}
\longrightarrow
\text{若干微操作}
$$

取指过程通常由各机器指令共享的取指微程序完成，机器指令译码后再转入相应执行微程序入口。

### 3.2 基本概念

| 概念 | 含义 |
| --- | --- |
| 微命令 | 控制数据通路完成一个基本动作的控制信号 |
| 微操作 | 微命令作用下完成的基本数据传送或加工 |
| 微指令 | 在一个微周期内发出的一组微命令及有关顺序控制信息 |
| 微程序 | 完成一项机器指令功能的一段微指令序列 |
| 微周期 | 从控制存储器取出并执行一条微指令所需的时间 |
| 控制存储器 `CM` | 存放微程序的存储器，位于控制器内部 |

微指令不是机器指令，微程序也不是普通机器语言程序。机器指令通常保存在主存并由 `PC` 寻址，微指令保存在控制存储器并由微地址寄存器寻址。

### 3.3 微程序控制器的基本结构

| 部件 | 常用名称 | 作用 |
| --- | --- | --- |
| 控制存储器 | `CM` | 存放全部或主要微程序 |
| 控制存储器地址寄存器 | `CMAR`、`μPC` | 保存下一条待取微指令的地址 |
| 控制存储器数据寄存器 | `CMDR`、`μIR` | 保存当前取出的微指令 |
| 微地址形成部件 | 顺序控制逻辑 | 产生后继微地址 |
| 机器指令操作码映射部件 | 地址映射逻辑 | 由机器指令操作码形成相应微程序入口 |

必须区分：

- `PC` 寻址主存中的机器指令，`CMAR` 寻址控制存储器中的微指令；
- `IR` 保存机器指令，`CMDR` 保存微指令；
- 主存保存普通程序和数据，控制存储器保存微程序。

### 3.4 基本工作过程

微程序控制器执行一条微指令的典型过程为：

1. `CMAR` 给出微指令地址；
2. 从控制存储器读出微指令并送入 `CMDR`；
3. 微指令的操作控制字段产生微命令，驱动数据通路完成微操作；
4. 微地址形成部件根据顺序控制字段和有关条件形成后继微地址；
5. 后继微地址写入 `CMAR`，进入下一个微周期。

机器指令译码后，可以用操作码映射形成其执行微程序入口；执行微程序结束后，通常返回公共取指微程序入口。

### 3.5 微指令的基本格式

一条微指令通常包含：

$$
\text{微指令}
=
\text{操作控制字段}
+
\text{顺序控制字段}
$$

| 字段 | 作用 |
| --- | --- |
| 操作控制字段 | 指出当前微周期发出哪些微命令 |
| 顺序控制字段 | 给出或参与形成后继微地址及转移条件 |

有些微指令还把常数、判别条件或其他控制信息设置为独立字段。具体格式由微程序控制器设计决定。

### 3.6 微命令编码方法

#### 直接编码

操作控制字段中的每一位直接对应一个微命令：

$$
\text{某位为 }1
\Longrightarrow
\text{相应微命令有效}
$$

优点是无须复杂译码、并行性强；缺点是微指令字较长。

#### 字段直接编码

把互斥的微命令划入同一字段，用字段编码经译码后选择其中一个；可以并行的微命令应分到不同字段。

若某字段需要表示 $n$ 个互斥微命令，并保留一种“不发出本字段微命令”的状态，则字段至少需要：

$$
\left\lceil\log_2(n+1)\right\rceil
$$

位。字段直接编码缩短了微指令字，但增加了解码时间，并限制同一字段内微命令的并行发出。

#### 字段间接编码（扩展）

一个字段的含义还要结合另一个字段解释。它能进一步压缩编码，但译码更复杂、速度和并行性通常较低。

### 3.7 水平型和垂直型微指令

| 比较项目 | 水平型微指令 | 垂直型微指令 |
| --- | --- | --- |
| 一条微指令包含的微命令 | 较多，可并行发出 | 通常较少，类似机器指令操作码 |
| 微指令字长 | 较长 | 较短 |
| 微程序长度 | 通常较短 | 通常较长 |
| 译码 | 少或较简单 | 通常需要较多译码 |
| 并行操作能力 | 强 | 较弱 |
| 执行速度 | 通常较快 | 通常较慢 |

水平型、垂直型描述的是微指令整体的并行性和编码风格；直接编码、字段编码描述的是微命令字段的具体编码方法，二者有关联但不是完全相同的分类维度。

### 3.8 后继微地址的形成

后继微地址可以来自：

- `CMAR` 顺序加一；
- 微指令中直接给出的下址字段；
- 根据条件标志选择的微程序分支地址；
- 机器指令操作码映射得到的微程序入口；
- 异常、中断或其他外部条件对应的入口。

因此，微程序控制器除了产生操作控制信号，还必须解决“下一条执行哪条微指令”的顺序控制问题。

### 3.9 微程序控制的特点

典型优点：

- 控制逻辑规整，便于实现复杂指令；
- 修改或扩展控制功能通常比重新设计硬布线逻辑方便；
- 微程序设计与数据通路微操作序列对应清晰。

典型局限：

- 每个微周期通常需要访问控制存储器，速度一般低于直接硬布线控制；
- 控制存储器及微地址形成部件增加了硬件开销；
- 微指令编码和微程序组织会影响并行性与执行效率。

微程序控制常见于传统 CISC 设计，但并非 CISC 的唯一实现方式。现代处理器也可能把硬布线和微程序方法结合使用。

### 3.10 两类控制器的比较

| 比较项目 | 硬布线控制器 | 微程序控制器 |
| --- | --- | --- |
| 控制信号来源 | 组合逻辑和状态逻辑 | 控制存储器中的微指令 |
| 速度 | 通常较快 | 通常较慢 |
| 规整性 | 指令复杂时逻辑可能庞杂 | 微指令序列较规整 |
| 修改与扩展 | 通常需要修改硬件 | 通常可通过修改微程序实现，但受硬件和控制存储器性质限制 |
| 设计取向 | 常用于规整、高速控制 | 常用于较复杂控制 |
| 典型联系 | 常见于 RISC | 常见于 CISC |

表中的联系是传统典型取向，不是判断 CISC、RISC 的绝对标准。

## 4. 408 常见考法与易错点

| 考查内容 | 分析要点 |
| --- | --- |
| 控制器输入输出 | 从指令、时序、状态到控制信号建立对应关系 |
| 微命令与微操作 | 区分控制信号和数据通路动作 |
| 硬布线逻辑 | 根据微操作时序写出控制信号产生条件 |
| 微程序层级 | 理清机器指令、微程序、微指令、微命令和微操作 |
| 微程序控制器部件 | 区分 `PC/IR` 与 `CMAR/CMDR` |
| 微指令编码 | 判断互斥与相容微命令，计算字段所需位数 |
| 后继微地址 | 分析顺序、分支、映射和异常入口 |
| 控制器比较 | 比较速度、规整性、修改能力和适用取向 |

常见错误包括：

- 把微命令和微操作当成同一个概念；
- 认为一条机器指令只对应一条微指令；
- 认为微程序存放在主存中，或使用 `PC` 寻址；
- 混淆保存机器指令的 `IR` 与保存微指令的 `CMDR`；
- 在字段直接编码中把可以并行的微命令放进同一互斥字段；
- 计算编码位数时忘记为“不发出微命令”保留一种状态；
- 认为水平型微指令字短、并行性低；
- 认为微程序控制器修改任何功能都无须改变硬件；
- 认为 CISC 必须采用微程序控制、RISC 必须采用硬布线控制；
- 脱离数据通路结构编写控制信号和微操作时序。

## 5. 本节小结

控制器的核心任务是把机器指令的语义转换成按时序排列的控制信号：

$$
\text{机器指令和状态}
\longrightarrow
\text{控制步骤}
\longrightarrow
\text{微命令}
\longrightarrow
\text{数据通路微操作}
$$

硬布线控制器用逻辑电路直接产生控制信号，速度通常较快；微程序控制器从控制存储器读取微指令产生控制信号，结构规整且便于实现复杂控制。分析题目时，应先确定数据通路和微操作序列，再判断控制信号的产生方式。
