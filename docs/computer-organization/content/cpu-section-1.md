<h1><center>第一节 CPU 的功能和基本结构</center></h1>

中央处理器（Central Processing Unit，CPU）是解释并执行机器指令的核心部件。它按照指令系统的规定，从主存取出指令、分析指令、执行操作，并控制数据在寄存器、主存和 I/O 系统之间传送。

本节的知识主线为：

$$
\text{CPU 的功能}
\longrightarrow
\text{运算器与控制器}
\longrightarrow
\text{CPU 中的寄存器}
$$

## 1. CPU 的功能

CPU 的基本功能可以概括为指令控制、操作控制、时间控制、数据加工以及异常和中断处理。

### 1.1 指令控制

指令控制是指控制指令的执行顺序。正常情况下，CPU 按照程序计数器 `PC` 给出的地址顺序取指；遇到转移、调用、返回、异常或中断时，则按照相应规则修改 `PC`。

因此，指令控制主要解决：

- 下一条执行哪条指令；
- 顺序执行时如何更新 `PC`；
- 控制转移时如何形成目标地址。

### 1.2 操作控制

一条机器指令通常需要分解为若干微操作。操作控制是指根据指令操作码、寻址方式和当前状态，产生完成这些微操作所需的控制信号。

例如，一条加法指令可能需要控制：

1. 从寄存器或主存取得源操作数；
2. 选择 ALU 的加法功能；
3. 把运算结果写入目的寄存器；
4. 按规定更新状态标志。

操作控制解决的是“各部件执行什么操作”。

### 1.3 时间控制

各微操作必须按照正确的先后顺序和时间关系执行。时间控制是指利用时钟、节拍或状态信号，为各控制信号安排合适的发生时刻和持续时间。

例如，读取主存时必须先把地址送入地址接口，再发出读命令，待数据有效后才能接收数据。时间控制解决的是“各操作在什么时候发生”。

### 1.4 数据加工

CPU 通过运算器对数据进行加工，主要包括：

- 算术运算，如加、减、乘、除；
- 逻辑运算，如与、或、异或、取反；
- 移位、比较和地址计算；
- 产生零、符号、进位、溢出等状态标志。

数据加工解决的是“对数据进行什么变换”。

### 1.5 异常和中断处理

当程序执行中出现异常，或外部设备提出中断请求时，CPU 需要在满足响应条件后：

1. 暂停或终止当前程序的正常执行流程；
2. 保存断点和必要的处理器状态；
3. 转入相应的异常或中断处理程序；
4. 处理结束后按规定恢复或终止原程序。

本节只说明 CPU 具有该功能，具体分类和响应过程将在“异常和中断机制”一节讨论。

## 2. CPU 的基本结构

在组成原理的基本模型中，CPU 主要由**运算器**和**控制器**组成，二者通过寄存器和内部数据通路协同工作：

$$
\text{CPU}
=
\text{运算器}
+
\text{控制器}
+
\text{寄存器及内部数据通路}
$$

这里的“寄存器及内部数据通路”贯穿运算器和控制器，不必理解成与二者完全并列、彼此独立的第三个功能系统。

### 2.1 运算器

运算器负责接收操作数并完成数据加工。典型组成包括：

| 部件 | 主要作用 |
| --- | --- |
| 算术逻辑单元 `ALU` | 完成算术运算、逻辑运算、比较和部分移位操作 |
| 通用寄存器组 `GPR` | 保存操作数、地址和中间结果 |
| 累加器 `ACC` | 在累加器型结构中保存操作数和运算结果 |
| 暂存寄存器 | 暂存送入 ALU 的数据，对程序通常不可见 |
| 移位器 | 完成逻辑移位、算术移位等操作 |
| 状态标志电路 | 根据运算结果产生条件码或状态标志 |

ALU 是组合逻辑部件，主要负责计算，本身通常不负责长期保存结果；操作数和结果一般由寄存器保存。

### 2.2 控制器

控制器负责取出和解释指令，并产生控制整个计算机协调工作的控制信号。典型组成包括：

| 部件 | 主要作用 |
| --- | --- |
| 程序计数器 `PC` | 给出下一条待取指令的地址 |
| 指令寄存器 `IR` | 保存当前正在译码或执行的指令 |
| 指令译码器 | 识别操作码和有关指令字段 |
| 时序系统 | 产生时钟、节拍或状态时序 |
| 控制信号形成部件 | 根据指令、状态和时序产生各类控制信号 |

控制器的主要输入包括：

- `IR` 中的操作码和相关字段；
- 时钟和节拍信号；
- ALU 产生的状态标志；
- 异常、中断和总线反馈等外部状态。

控制器产生的信号可以控制寄存器读写、ALU 功能选择、内部总线选择、主存读写以及 `PC` 更新等操作。

### 2.3 内部数据通路

数据通路由执行数据传送或数据处理的部件及其连接构成，通常包括：

- 寄存器；
- ALU 和移位器；
- 内部总线或专用连接；
- 多路选择器；
- 与主存接口相连的地址、数据通路。

数据通路负责“数据能够从哪里流向哪里”，控制器负责“在什么时刻让哪条通路完成何种操作”。二者共同完成指令规定的功能。

### 2.4 CPU 与其他部件的联系

CPU 需要通过系统互连与主存和 I/O 系统交换信息：

| 信息类型 | 典型内容 |
| --- | --- |
| 地址信息 | 指令地址、数据地址、I/O 端口或映射地址 |
| 数据信息 | 机器指令、操作数和运算结果 |
| 控制信息 | 读、写、中断响应、总线请求与应答等信号 |

从逻辑关系看，CPU 发出地址和读写控制，数据则可能在 CPU 与主存或 I/O 接口之间双向传送。具体互连方式将在总线和输入输出系统中讨论。

## 3. CPU 中的寄存器

寄存器是 CPU 内部高速、小容量的存储部件，用于保存指令、地址、操作数、运算结果和处理器状态。不同 ISA 和微体系结构设置的寄存器不同，以下是组成原理中常用的抽象模型。

### 3.1 用户可见寄存器

用户可见寄存器是机器级程序能够通过指令显式或按约定使用的寄存器。

| 类型 | 作用 | 常见示例 |
| --- | --- | --- |
| 通用寄存器 | 保存数据、地址和中间结果 | `R0、R1、…` |
| 数据寄存器 | 主要保存运算数据 | 累加器 `ACC` |
| 地址寄存器 | 保存基址、变址、栈顶等地址 | 基址寄存器、变址寄存器、`SP` |
| 条件码寄存器 | 保存运算产生的条件标志 | 零、符号、进位、溢出标志 |

“用户可见”不等于普通程序可以不受限制地读写所有相关位。例如，程序状态字中的部分控制位可能只有特权程序才能修改。

通用寄存器可以减少中间结果对主存的访问次数，但寄存器的数量、位宽和用途由具体 ISA 规定。

### 3.2 控制和状态寄存器

控制和状态寄存器用于控制指令执行、主存访问以及处理器状态。常见寄存器如下：

| 寄存器 | 中文名称 | 主要作用 |
| --- | --- | --- |
| `PC` | 程序计数器 | 保存下一条待取指令的地址；取指后通常按顺序更新，转移时写入目标地址 |
| `IR` | 指令寄存器 | 保存当前正在译码或执行的指令 |
| `MAR` | 主存地址寄存器 | 保存当前要访问的主存单元地址 |
| `MDR`（或 `MBR`） | 主存数据寄存器（缓冲寄存器） | 暂存从主存读出的信息或准备写入主存的信息 |
| `PSW` | 程序状态字寄存器 | 保存条件码和中断允许、处理器模式等控制状态，具体字段由 ISA 规定 |

需要注意：

- 取指令和访问数据都可能使用 `MAR`、`MDR`，不能认为 `MDR` 只保存普通数据。
- 在简化模型中，`IR` 能保存一条完整指令；变长指令的实际处理器可能还设置指令缓冲等结构。
- `PC` 在取指前后保存的地址可能不同，涉及相对寻址时应以题目给出的时刻为准。
- `MAR`、`MDR` 在不同教材或硬件实现中可能被画在 CPU 内部，也可能被视为主存接口的一部分；它们的逻辑功能不变。

### 3.3 运算器中的专用寄存器

传统运算器模型还常使用以下专用寄存器：

| 寄存器 | 主要作用 |
| --- | --- |
| `ACC` | 累加器，保存一个操作数以及算术逻辑运算结果 |
| `MQ` | 乘商寄存器，在某些乘除运算中保存乘数、商或部分结果 |
| `X` | 操作数寄存器，保存送入 ALU 的一个操作数 |
| 暂存寄存器 | 保存内部微操作的中间值，通常不属于 ISA 可见状态 |

并非所有 CPU 都设置名称和功能完全相同的 `ACC、MQ、X`。现代通用寄存器型 CPU 常由通用寄存器和内部暂存结构承担相应功能；做题时应按照题目给出的数据通路判断。

### 3.4 主要寄存器的宽度关系

在 408 常见简化模型中，可以用寄存器功能推断其最低宽度要求：

| 寄存器 | 宽度通常取决于 |
| --- | --- |
| `PC` | 指令地址空间以及指令编址规则 |
| `MAR` | 可直接表示的主存地址范围 |
| `MDR` | CPU 与主存一次传送的信息宽度 |
| `IR` | 一条指令需要保存的编码宽度；变长指令系统应按题设处理 |
| `ACC、GPR` | 机器支持的基本运算数据宽度 |

若主存按字节编址，`MAR` 为 $n$ 位，则理论上最多可表示 $2^n$ 个不同的字节地址；若每个地址对应一个字，则表示的是 $2^n$ 个存储字。不能在未确认编址单位时直接把地址数量换算成字节容量。

### 3.5 取指过程中寄存器的配合

以简化的定长指令模型为例，取指过程可抽象为：

$$
MAR\leftarrow PC
$$

$$
MDR\leftarrow M[MAR]
$$

$$
IR\leftarrow MDR
$$

$$
PC\leftarrow PC+L
$$

其中 $L$ 是一条指令在当前编址方式下占用的地址单位数。该过程体现了几个寄存器的分工：`PC` 提供指令地址，`MAR` 对接主存地址，`MDR` 暂存取回的指令，`IR` 保存当前指令。

具体数据通路可能把部分传送合并或并行执行，`PC` 的更新时间也由处理器设计决定，做计算题时应使用题目给出的微操作序列。

## 4. 408 常见考法与易错点

| 考查内容 | 分析要点 |
| --- | --- |
| CPU 功能 | 区分指令控制、操作控制、时间控制、数据加工和中断处理 |
| 基本结构 | 区分运算器、控制器、寄存器和数据通路的作用 |
| 寄存器功能 | 重点区分 `PC、IR、MAR、MDR、ACC、PSW` |
| 用户可见性 | 根据 ISA 和题设判断寄存器能否由机器指令使用 |
| 寄存器位数 | 根据地址范围、编址单位、指令长度或数据宽度判断 |
| 取指数据流 | 跟踪 `PC→MAR→主存→MDR→IR` 的信息传送 |

常见错误包括：

- 认为 ALU 能长期保存运算结果，忽略寄存器的存储作用；
- 混淆操作控制与时间控制，前者决定“做什么”，后者决定“何时做”；
- 认为 `PC` 在所有时刻都保存当前正在执行指令的地址；
- 把 `IR` 中的指令内容和 `MAR` 中的主存地址混淆；
- 认为 `MDR` 只能传送普通数据，不能传送机器指令；
- 未确认按字还是按字节编址，就根据 `MAR` 位数直接计算字节容量；
- 把 `ACC、MQ、X` 当成所有 CPU 都必须设置的寄存器；
- 把程序状态字简单等同于条件码，忽略其中可能包含的控制状态。

## 5. 本节小结

CPU 的工作可以沿着三条线理解：

1. 功能上，CPU 负责控制指令执行、产生操作与时序控制、加工数据并处理异常和中断；
2. 结构上，运算器负责“算”，控制器负责“控”，数据通路负责连接和传送；
3. 状态上，寄存器分别保存指令、地址、数据、结果和程序状态。

后续分析指令执行过程时，应持续跟踪三项信息：当前控制信号要求哪个部件工作、数据沿哪条通路传送、结果写入哪个寄存器。
