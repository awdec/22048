<h1><center>第一节 指令系统</center></h1>

机器指令是处理器能够识别并执行的二进制命令，一台计算机所能执行的全部机器指令及其使用规则构成指令系统。指令系统位于软件和硬件的交界处：编译器按照指令系统生成机器代码，处理器按照同一套规则解释并执行机器代码。

本节的知识主线为：

$$
\text{指令集体系结构}
\longrightarrow
\text{指令基本格式}
\longrightarrow
\text{操作码编码}
\longrightarrow
\text{指令类型}
$$

## 1. 指令集体系结构

### 1.1 ISA 的基本概念

指令集体系结构简称 ISA，是软件能够观察和使用的计算机硬件接口。ISA 不只是一张指令名称表，还规定了机器级程序必须遵守的基本规则。

ISA 通常包括：

| 内容 | 说明 |
| --- | --- |
| 指令及其功能 | 处理器支持哪些数据传送、运算和控制操作 |
| 指令格式与编码 | 指令包含哪些字段，各字段如何编码 |
| 数据类型和数据宽度 | 支持字节、整数、浮点数、向量等哪些数据形式 |
| 程序员可见寄存器 | 通用寄存器、程序计数器、状态寄存器等 |
| 寻址方式 | 如何在指令中表示立即数、寄存器和存储器操作数 |
| 存储器模型 | 地址空间、编址单位、字节序和对齐要求等 |
| 控制转移和异常 | 分支、调用、返回、中断和异常的体系结构行为 |
| 特权级和系统状态 | 普通程序与操作系统可执行的操作范围 |

ISA 决定机器级程序“可以要求处理器做什么”，但不规定处理器内部必须“怎样做”。

### 1.2 ISA 与微体系结构

微体系结构是某个处理器实现 ISA 的具体内部组织，例如：

- 数据通路和控制器如何设计；
- 采用单周期、多周期还是流水线；
- Cache 容量和级数如何配置；
- 指令是否乱序执行；
- 同时设置多少个执行部件。

同一种 ISA 可以有多种不同的微体系结构实现。只要实现遵守相同 ISA，同一份机器代码原则上就能得到相同的体系结构结果，但执行时间、功耗和内部过程可以不同。

::: warning ISA 不等于具体 CPU
ISA 是软硬件接口规范，CPU 是该规范的一种实现。不能用某一款处理器的 Cache 大小、流水级数或内部总线宽度定义整个 ISA。
:::

### 1.3 ISA 对软件和硬件的意义

从软件角度看：

- 编译器把高级语言程序转换为 ISA 规定的机器指令；
- 汇编器把助记符转换成机器指令编码；
- 操作系统使用特权指令管理处理器和系统资源；
- 程序通过寄存器、存储器地址和控制转移完成运算。

从硬件角度看：

- 取指部件必须识别指令边界；
- 译码部件必须解释操作码和其他字段；
- 数据通路必须取得操作数并完成规定操作；
- 控制部件必须产生符合 ISA 语义的状态变化；
- 异常和中断机制必须保存并恢复规定的体系结构状态。

ISA 是软硬件兼容的基础，但完整的软件二进制兼容通常还需要相同的操作系统接口、调用约定和目标文件格式，这些规则一般归入 ABI，而不完全由 ISA 单独决定。

## 2. 指令的基本格式

### 2.1 指令的组成字段

一条机器指令至少需要说明“执行什么操作”，并根据指令需要说明“操作数在哪里”和“结果写到哪里”。典型指令可以抽象为：

$$
\text{指令}
=
\text{操作码字段}
+
\text{地址码或操作数字段}
+
\text{其他控制字段}
$$

| 字段 | 作用 |
| --- | --- |
| 操作码 OP | 指明执行加法、传送、转移等哪一种操作 |
| 地址码 | 指明寄存器编号、存储器地址或地址形成信息 |
| 寻址方式字段 | 说明地址码应按立即、直接、间接等哪种方式解释 |
| 立即数 | 直接给出操作数本身 |
| 位移量 | 与 PC、基址寄存器或变址寄存器共同形成有效地址 |
| 功能子字段 | 在主操作码确定大类后，进一步区分具体操作 |

地址码不一定是主存地址。它可能是寄存器编号、立即数、位移量、端口号，也可能需要结合寻址方式才能得到有效地址。

### 2.2 指令长度

指令长度是一条指令包含的二进制位数，也称指令字长。它与机器字长、存储字长和数据总线宽度不是同一个概念。

| 设计 | 特点 |
| --- | --- |
| 定长指令字 | 所有指令长度相同，便于确定边界、取指、译码和流水处理 |
| 变长指令字 | 不同指令长度不同，编码紧凑，但确定边界和译码更复杂 |

一条指令可能等于一个机器字，也可能短于或长于机器字。题目没有明确说明时，不能直接把指令字长等同于机器字长。

### 2.3 按显式地址数划分指令格式

根据指令中显式给出的地址码个数，可以分为三地址、二地址、一地址和零地址指令。

#### 三地址指令

典型格式为：

$$
OP\quad D,\ S_1,\ S_2
$$

其功能可表示为：

$$
D\leftarrow S_1\ OP\ S_2
$$

两个源操作数和结果位置分别给出，表达清晰，但地址字段较多，指令编码较长。

#### 二地址指令

典型格式为：

$$
OP\quad D,\ S
$$

其功能常表示为：

$$
D\leftarrow D\ OP\ S
$$

目的地址同时保存一个源操作数，因此节省地址字段，但会覆盖原目的操作数。不同 ISA 对源、目的操作数的书写顺序可能不同，应按题设解释。

#### 一地址指令

典型格式为：

$$
OP\quad A
$$

在累加器型机器中，另一个操作数和结果位置可以隐含在累加器 ACC 中：

$$
ACC\leftarrow ACC\ OP\ M[A]
$$

一地址指令也可能是一元操作指令，此时只需要一个显式操作数，并不一定使用累加器。

#### 零地址指令

零地址指令没有显式地址码，操作数和结果位置由指令语义隐含。例如，栈式机器中的加法从栈顶弹出两个操作数，将结果重新压入栈顶。

无操作 NOP、停机等不需要普通数据操作数的指令也可以采用零地址格式。因此，“零地址”表示没有显式地址字段，不表示指令一定没有操作对象或状态变化。

### 2.4 地址数与指令长度的关系

在指令字长固定时：

- 地址码越多，留给操作码和其他控制字段的位数越少；
- 地址码越少，可以使用更长的操作码表示更多操作；
- 地址数减少可能需要增加指令条数或使用隐含寄存器；
- 地址数增加可以减少中间结果搬移，但单条指令编码更长。

若指令长度为 $L$ 位，操作码为 $k$ 位，共有若干地址和控制字段，则必须满足：

$$
L
=
k
+
\sum_i a_i
+
\text{其他字段位数}
$$

其中 $a_i$ 表示第 $i$ 个地址或操作数字段所占位数。

## 3. 定长操作码指令格式

### 3.1 基本原理

定长操作码是指所有指令的操作码字段具有相同位数，并位于规定位置。

若操作码长度为 $k$ 位，则理论上最多可以表示：

$$
2^k
$$

种不同操作。若部分编码被保留给扩展、非法指令或特殊用途，实际可用操作码数量会少于 $2^k$。

例如，操作码为 $6$ 位时，最多可以形成：

$$
2^6=64
$$

种操作码编码。

### 3.2 定长操作码示例

设某 ISA 使用 $16$ 位定长指令字，采用二地址寄存器指令格式：

$$
\underbrace{OP}_{6\text{ 位}}
\quad
\underbrace{R_d}_{5\text{ 位}}
\quad
\underbrace{R_s}_{5\text{ 位}}
$$

则：

- $6$ 位操作码最多表示 $64$ 种操作；
- 每个 $5$ 位寄存器字段最多选择 $2^5=32$ 个寄存器；
- 指令总长度为 $6+5+5=16$ 位。

如果 ISA 实际只有 $50$ 种这类指令，其余 $14$ 个操作码可以保留给将来扩展或判定为非法编码。

### 3.3 定长操作码的特点

优点：

- 操作码位置和长度固定，译码简单；
- 容易并行提取操作码及其他字段；
- 控制逻辑规整，便于流水线处理；
- 各指令的操作码比较关系明确。

缺点：

- 各种指令都使用同样长的操作码，编码利用率不一定高；
- 操作码太短会限制操作种类；
- 操作码太长又会压缩地址码、立即数或位移量字段。

### 3.4 定长操作码与定长指令字的区别

定长操作码描述的是操作码字段长度是否一致，定长指令字描述的是整条指令长度是否一致，二者不是同一个概念。

- 指令字可以定长，而不同指令使用不同长度的扩展操作码；
- 指令字也可以变长，但每种格式开头仍使用固定宽度的主操作码；
- 做题时必须分别确认“操作码是否定长”和“指令字是否定长”。

## 4. 扩展操作码指令格式

### 4.1 基本思想

扩展操作码是在指令字长固定时，利用地址数减少后空出的字段逐级扩大操作码。

其基本规律是：

- 地址数较多的指令使用较短操作码；
- 地址数较少的指令可以使用更长操作码；
- 上一级必须预留部分编码，作为下一级扩展操作码的前缀；
- 任一短操作码都不能成为另一条有效长操作码的前缀，否则译码会产生歧义。

扩展操作码提高了固定指令字中编码空间的利用率，但会使操作码长度和译码过程不再完全统一。

### 4.2 逐级扩展方法

设固定指令字由一个 $n$ 位基本操作码和三个 $a$ 位地址字段组成：

$$
\underbrace{OP}_{n\text{ 位}}
\quad
\underbrace{A_1}_{a\text{ 位}}
\quad
\underbrace{A_2}_{a\text{ 位}}
\quad
\underbrace{A_3}_{a\text{ 位}}
$$

分配步骤如下：

1. 从 $2^n$ 个基本操作码中分配若干个三地址指令，并预留部分编码。
2. 每个预留的 $n$ 位前缀与原 $A_1$ 字段组合，可扩展成 $n+a$ 位二地址操作码。
3. 从二地址扩展编码中继续预留前缀，与原 $A_2$ 字段组合，可形成 $n+2a$ 位一地址操作码。
4. 继续利用原 $A_3$ 字段，可形成 $n+3a$ 位零地址操作码。

每保留一个上一级操作码前缀，就可以为下一级提供 $2^a$ 个更长编码；若其中还要继续向下扩展，就不能把这些编码全部分配完。

### 4.3 十六位扩展操作码示例

设指令字长为 $16$ 位，基本操作码和每个地址字段均为 $4$ 位：

$$
\underbrace{OP}_{4}
\quad
\underbrace{A_1}_{4}
\quad
\underbrace{A_2}_{4}
\quad
\underbrace{A_3}_{4}
$$

可以采用如下分配方案：

| 指令格式 | 操作码形式 | 可分配数量 | 剩余地址字段 |
| --- | --- | ---: | --- |
| 三地址 | `0000～1110` | $15$ | $A_1,A_2,A_3$ |
| 二地址 | `1111 0000～1111 1110` | $15$ | $A_2,A_3$ |
| 一地址 | `1111 1111 0000～1111 1111 1110` | $15$ | $A_3$ |
| 零地址 | `1111 1111 1111 0000～1111 1111 1111 1111` | $16$ | 无 |

分配过程为：

- 四位编码 `1111` 没有作为三地址指令，而是留给二地址指令扩展；
- 八位编码 `1111 1111` 没有作为二地址指令，而是留给一地址指令扩展；
- 十二位编码 `1111 1111 1111` 没有作为一地址指令，而是留给零地址指令；
- 到零地址层次已经没有更少的地址格式，因此最后 $4$ 位可以全部用于区分 $16$ 条零地址指令。

总指令数为：

$$
15+15+15+16=61
$$

这里的 $61$ 条指令具有不同长度的操作码，但所有指令字仍然是 $16$ 位。

### 4.4 扩展操作码容量约束

若基本操作码为 $n$ 位，每个地址字段均为 $a$ 位，分别需要 $N_3、N_2、N_1、N_0$ 条三地址、二地址、一地址和零地址指令，则合法的前缀编码分配必须满足：

$$
\frac{N_3}{2^n}
+
\frac{N_2}{2^{n+a}}
+
\frac{N_1}{2^{n+2a}}
+
\frac{N_0}{2^{n+3a}}
\leq1
$$

该式反映每类指令占用的编码空间比例，但实际构造时还要逐级保留完整前缀，不能只看总数满足不等式就随意分配。

408 计算题更稳妥的方法是逐级计算：

1. 先从基本操作码中扣除三地址指令。
2. 把剩余前缀数乘以 $2^a$，得到二地址层可用编码数。
3. 扣除二地址指令后，再乘以 $2^a$ 扩展到一地址层。
4. 继续相同步骤直到零地址层。

### 4.5 扩展操作码易错点

- 已经分配给某类指令的操作码不能再作为其他指令的前缀。
- 要继续向更少地址的格式扩展，就必须在当前层保留未使用编码。
- 操作码扩展占用的是原地址字段，因此扩展后显式地址数会减少。
- 扩展操作码不等于变长指令字，整个指令仍可保持定长。
- 题目要求“至少”或“至多”多少条时，要注意是否必须为下一层预留编码。

## 5. 指令的类型

### 5.1 数据传送类指令

数据传送指令在寄存器、主存和立即数之间复制或交换数据，例如：

- 取数 Load；
- 存数 Store；
- 寄存器间传送 Move；
- 立即数装入；
- 压栈和出栈；
- 地址装入。

数据传送通常不改变数据的数值，但可能更新状态寄存器，具体行为由 ISA 规定。

### 5.2 算术运算类指令

算术指令完成数值运算，例如：

- 加、减、乘、除；
- 加一、减一；
- 带进位加法和带借位减法；
- 求负、比较；
- 定点或浮点算术运算。

比较指令通常只更新条件码或状态标志，不保存普通算术结果。

### 5.3 逻辑和位操作类指令

常见操作包括：

- 按位与、或、异或、取反；
- 逻辑移位、算术移位和循环移位；
- 位测试、位置位和位清零；
- 数据拼接、字段提取等。

逻辑和移位指令常用于掩码处理、乘除 $2^k$、地址计算和状态位操作。

### 5.4 程序控制类指令

程序控制指令改变正常的顺序执行过程，例如：

- 无条件转移；
- 条件转移；
- 子程序调用和返回；
- 循环控制；
- 陷阱、系统调用或软件中断。

顺序执行时，PC 通常指向下一条指令；控制转移指令则按照目标地址和条件修改 PC。

### 5.5 输入输出类指令

采用独立 I/O 编址的系统可以设置专门的输入、输出和设备控制指令。采用存储器映射 I/O 的系统，则可以使用普通 Load、Store 指令访问映射到地址空间中的设备寄存器。

因此，一个 ISA 是否具有专门 I/O 指令，与系统采用的 I/O 端口编址方式有关。

### 5.6 系统和特权类指令

系统控制指令用于管理处理器和系统状态，例如：

- 开关中断；
- 修改处理器工作模式；
- 管理地址转换或 Cache；
- 读写系统控制寄存器；
- 停机、等待事件或返回异常。

其中很多指令只能在特权模式下执行，普通用户程序执行时会触发异常。

### 5.7 其他专用指令

不同 ISA 还可能提供字符串处理、十进制运算、向量运算、原子操作、密码运算等专用指令。这些指令是否存在、采用什么格式，都由具体 ISA 决定。

408 基础复习应优先掌握数据传送、算术逻辑、移位、程序控制和输入输出等基本类型；具体 ISA 的大量专用指令不需要逐条记忆。

## 6. 408 常见考法与易错点

| 考点 | 解题入口 |
| --- | --- |
| ISA 概念 | 区分软件可见的体系结构规定与处理器内部实现 |
| 指令字段 | 分清操作码、地址码、立即数、位移量和寻址方式字段 |
| 地址数 | 判断显式给出几个操作数或结果地址 |
| 定长操作码 | 使用 $k$ 位操作码最多表示 $2^k$ 个编码 |
| 扩展操作码 | 从多地址格式开始逐级预留并扩展编码 |
| 指令类型 | 根据指令功能判断其所属类别 |

特别注意：

- 指令集体系结构不等于某一款处理器的具体内部结构。
- 地址码不一定是主存地址，也可能是寄存器编号、立即数或位移量。
- 零地址指令不一定没有操作数，操作数可以隐含在栈顶或专用寄存器中。
- 一地址指令既可能使用隐含累加器，也可能是一元操作。
- 指令字长、机器字长、存储字长和数据总线宽度不能直接等同。
- 定长操作码和定长指令字是两个不同维度。
- 扩展操作码必须保证短操作码不是其他有效操作码的前缀。
- 扩展操作码题必须逐级扣除已分配编码，并为后续格式保留完整前缀。

## 7. 本节小结

指令系统规定机器级程序能够使用的操作、状态和编码方式。分析指令格式时，应依次判断：

$$
\text{指令总长度}
\longrightarrow
\text{操作码长度}
\longrightarrow
\text{地址字段数量和宽度}
\longrightarrow
\text{可表示的操作与操作数范围}
$$

定长操作码使用统一宽度直接编码操作，扩展操作码则通过减少地址字段逐级增加操作码长度。处理扩展操作码题时，使用“分配当前层—保留扩展前缀—乘以地址字段编码数”的方法最不容易出错。
