<h1><center>第三节 程序的机器级代码表示</center></h1>

高级语言中的变量、表达式、选择、循环和函数，最终都要转换成机器指令才能由 CPU 执行。本节用汇编指令描述这种转换，重点是理解数据通路、控制流和过程调用，而不是记忆某一种处理器的全部指令。

为避免混淆，以下示例统一采用**类 RISC 抽象汇编**，约定如下：

- `R0、R1、…` 表示通用寄存器，`PC`、`SP`、`FP`、`RA` 分别表示程序计数器、栈指针、帧指针和返回地址寄存器。
- 指令采用“目的操作数在前”的格式，如 `ADD R3, R1, R2` 表示 $R3\leftarrow R1+R2$。
- `#n` 表示立即数，`offset(Rb)` 表示主存地址 $R_b+offset$，`LABEL:` 表示标号。
- 示例中的 `int` 按 32 位、4 字节处理，主存按字节编址；栈假定向低地址增长。
- 不同指令集的助记符、条件码、参数寄存器和栈帧布局可能不同。做题时应以题目给定的指令系统和调用约定为准。

## 1. 常用汇编指令介绍

### 1.1 汇编指令与机器指令

机器指令是 CPU 能直接识别的二进制编码；汇编指令用助记符表示机器指令，更便于人阅读。例如：

```text
ADD R3, R1, R2
```

汇编后，该指令中的操作码和寄存器编号会被编码进相应字段。标号也会被转换为目标地址或相对当前 `PC` 的位移量。

从高级语言源程序到可执行程序通常经历：

$$
\text{源程序}\longrightarrow\text{编译}\longrightarrow
\text{汇编程序}\longrightarrow\text{汇编}\longrightarrow
\text{目标文件}\longrightarrow\text{链接}\longrightarrow
\text{可执行文件}
$$

三个转换工具的职责不同：

| 工具 | 主要输入 | 主要输出与作用 |
| --- | --- | --- |
| 编译器 | 高级语言源程序 | 进行语法、语义分析和优化，生成汇编程序或其他形式的目标代码 |
| 汇编器 | 汇编程序 | 把助记符翻译成机器指令，生成可重定位目标文件，并记录符号表和重定位信息 |
| 链接器 | 一个或多个目标文件、库文件 | 合并代码和数据，解析外部符号并完成重定位，生成可执行文件 |

汇编器通常可以确定同一目标模块内局部标号的位置；无法立即确定的外部符号及相关地址修正信息会保留给链接器处理。可执行文件随后由操作系统的装入程序映射到内存，装入不属于上述三个翻译环节。

### 1.2 机器级程序中的基本对象

| 对象 | 作用 |
| --- | --- |
| 寄存器 | 暂存操作数、运算结果或地址，访问速度快 |
| 主存单元 | 存放指令、变量、数组和栈等内容 |
| 立即数 | 直接包含在指令中的常量 |
| `PC` | 保存当前指令地址或下一条待执行指令地址，具体含义由题目约定 |
| 条件码（标志位） | 记录比较或运算结果的零、符号、进位、溢出等特征 |
| 标号 | 汇编程序中表示指令或数据位置的符号名称 |

汇编语言一般不保留高级语言中的变量类型。某段二进制数据表示有符号数、无符号数、地址还是浮点数，取决于执行它的指令及程序语义。

### 1.3 数据传送指令

| 抽象指令 | 含义 |
| --- | --- |
| `MOV Rd, Rs` | $R_d\leftarrow R_s$ |
| `LI Rd, #imm` | $R_d\leftarrow imm$ |
| `LOAD Rd, offset(Rb)` | $R_d\leftarrow M[R_b+offset]$ |
| `STORE Rs, offset(Rb)` | $M[R_b+offset]\leftarrow R_s$ |
| `LEA Rd, offset(Rb)` | $R_d\leftarrow R_b+offset$，得到有效地址而不访问该地址中的数据 |

在典型 load-store 型指令系统中，只有访存指令能访问主存，算术逻辑指令只对寄存器或立即数操作。例如：

```c
z = x + y;
```

可以抽象为：

```text
LOAD  R1, x
LOAD  R2, y
ADD   R3, R1, R2
STORE R3, z
```

其中 `x、y、z` 是数据标号，分别代表相应变量的主存地址。编译器也可能把变量长期保存在寄存器中，从而省去部分访存指令。

### 1.4 算术、逻辑和移位指令

| 类型 | 常用抽象指令 | 主要功能 |
| --- | --- | --- |
| 算术运算 | `ADD、SUB、MUL、DIV` | 加、减、乘、除 |
| 逻辑运算 | `AND、OR、XOR、NOT` | 按位与、或、异或、取反 |
| 移位运算 | `SLL、SRL、SRA` | 逻辑左移、逻辑右移、算术右移 |
| 比较运算 | `CMP Rs1, Rs2/#imm` | 按“第一个操作数减第二个操作数”设置条件码，但不保存差值 |

例如，对 32 位整数下标 `i` 计算 `a[i]` 的地址：

```text
SLL  R2, R1, #2       # R2 = i * 4
ADD  R3, Rbase, R2    # R3 = &a[i]
LOAD R4, 0(R3)        # R4 = a[i]
```

逻辑左移一位在结果未溢出的条件下相当于乘 2。算术右移用符号位填充高位，逻辑右移用 0 填充高位，两者不能混用。

### 1.5 转移指令

| 抽象指令 | 含义 |
| --- | --- |
| `JMP LABEL` | 无条件转移到 `LABEL` |
| `BEQ LABEL` | 相等时转移 |
| `BNE LABEL` | 不相等时转移 |
| `BLT LABEL` | 按有符号数比较，小于时转移 |
| `BGE LABEL` | 按有符号数比较，大于或等于时转移 |
| `BGT LABEL、BLE LABEL` | 按有符号数比较，大于或小于等于时转移 |
| `BLTU、BGEU` | 按无符号数比较后转移 |
| `CALL LABEL` | 保存返回地址并转移到被调用过程 |
| `RET` | 根据已保存的返回地址返回调用点 |

条件转移的本质是：根据比较结果选择是否把目标地址送入 `PC`。有些指令集先用 `CMP` 设置条件码再转移，有些指令集则把比较和转移合并为一条指令。

必须区分有符号比较和无符号比较。例如，相同的位模式在两种解释下大小关系可能不同，因此应选用与高级语言数据类型相匹配的转移指令。

### 1.6 栈操作

栈常用于保存返回地址、寄存器、局部变量和不能放入寄存器的参数。若栈向低地址增长，则分配 $n$ 字节栈空间可抽象为：

```text
ADDI SP, SP, #-n
```

释放这段空间可抽象为：

```text
ADDI SP, SP, #n
```

有些指令集提供 `PUSH` 和 `POP`，有些指令集使用修改 `SP` 加 `LOAD/STORE` 的组合来完成相同操作。栈顶位置、增长方向和对齐要求均由具体体系结构或 ABI 规定。

## 2. 选择语句的机器级表示

选择语句在机器级通常由“比较—条件转移—顺序执行”构成。高级语言中的布尔表达式不一定会先生成数值 0 或 1，编译器常直接根据比较结果改变控制流。

### 2.1 单分支 `if` 语句

```c
if (x < y) {
    z = x;
}
```

可以翻译为：

```text
LOAD  R1, x
LOAD  R2, y
CMP   R1, R2
BGE   END_IF          # 条件不成立，跳过 then 部分
STORE R1, z
END_IF:
```

这里使用“条件不成立时跳走”的方式，使条件成立时能顺序执行语句块。

### 2.2 双分支 `if-else` 语句

```c
if (x < y) {
    z = x;
} else {
    z = y;
}
```

可以翻译为：

```text
LOAD  R1, x
LOAD  R2, y
CMP   R1, R2
BGE   ELSE
STORE R1, z
JMP   END_IF
ELSE:
STORE R2, z
END_IF:
```

`BGE ELSE` 负责在条件不成立时进入 `else` 分支；执行完 `then` 分支后必须用 `JMP END_IF` 越过 `else` 分支。

### 2.3 复合条件与短路求值

C 语言的 `&&` 和 `||` 采用短路求值：

- 对 `A && B`，若 `A` 为假，则不再计算 `B`。
- 对 `A || B`，若 `A` 为真，则不再计算 `B`。

例如：

```c
if (p != 0 && *p > 0) {
    x = 1;
}
```

可以翻译为：

```text
LOAD  R1, p
CMP   R1, #0
BEQ   END_IF          # p == 0，不能继续访问 *p
LOAD  R2, 0(R1)
CMP   R2, #0
BLE   END_IF
LI    R3, #1
STORE R3, x
END_IF:
```

第一个条件为假时不会执行间接访存，这既体现短路规则，也避免了对空指针的解引用。

### 2.4 `switch` 语句

`switch` 的机器级实现取决于分支数量和值的分布：

- 分支较少或取值稀疏时，可依次比较并条件转移。
- 分支较多且取值连续时，可使用跳转表：先检查索引范围，再根据索引从表中取出目标地址并间接跳转。

跳转表的核心地址计算为：

$$
\text{表项地址}=\text{跳转表首地址}+(\text{表达式值}-\text{最小分支值})\times\text{表项大小}
$$

使用跳转表前必须进行越界检查，越界时进入 `default` 分支。跳转表通常能用额外空间换取近似固定的分支选择时间。

## 3. 循环语句的机器级表示

循环在机器级没有特殊的整体指令，其基本结构是：测试循环条件、条件转移到出口、执行循环体、返回测试位置。

### 3.1 `while` 循环

```c
while (i < n) {
    sum = sum + i;
    i = i + 1;
}
```

假定 `i、n、sum` 已分别保存在 `R1、R2、R3` 中：

```text
TEST:
CMP  R1, R2
BGE  LOOP_END
ADD  R3, R3, R1
ADDI R1, R1, #1
JMP  TEST
LOOP_END:
```

`while` 是先测试循环，进入循环体前就要判断条件，因此循环体可能一次也不执行。

### 3.2 `do-while` 循环

```c
do {
    sum = sum + i;
    i = i + 1;
} while (i < n);
```

可以翻译为：

```text
LOOP_BODY:
ADD  R3, R3, R1
ADDI R1, R1, #1
CMP  R1, R2
BLT  LOOP_BODY
```

`do-while` 是后测试循环，先执行循环体再判断条件，所以循环体至少执行一次。

### 3.3 `for` 循环

```c
for (i = 0; i < n; i++) {
    sum += a[i];
}
```

其控制流可以看成：

```text
初始化 → 条件测试 → 循环体 → 更新表达式 → 返回条件测试
```

假定 `Rbase=&a[0]`，`R2=n`，`R3=sum`：

```text
LI   R1, #0           # i = 0
FOR_TEST:
CMP  R1, R2
BGE  FOR_END
SLL  R4, R1, #2       # i * 4
ADD  R5, Rbase, R4    # &a[i]
LOAD R6, 0(R5)
ADD  R3, R3, R6
ADDI R1, R1, #1       # i++
JMP  FOR_TEST
FOR_END:
```

数组元素地址的一般公式为：

$$
\operatorname{Addr}(a[i])=\operatorname{Addr}(a[0])+i\times\text{元素字节数}
$$

编译器也可能用指针逐次增加 4 的方式遍历数组，避免每次重新计算 `i × 4`。优化后的指令序列可以与源程序结构不同，但程序语义必须保持一致。

### 3.4 `break` 与 `continue`

- `break` 转移到当前循环的出口标号。
- `continue` 转移到下一轮迭代应执行的位置。

在 `while` 循环中，`continue` 通常转移到条件测试处；在 `for` 循环中，通常转移到更新表达式处，再回到条件测试处。若忽略这一区别，可能漏掉 `for` 循环的更新操作。

此外，若循环变量是无符号类型，循环条件应使用无符号比较。把无符号数误用有符号转移指令解释，是机器级代码分析中的常见错误。

## 4. 过程调用的机器级表示

过程调用也称函数调用。发起调用的过程称为**调用者**，被调用的过程称为**被调用者**。过程调用不仅要改变控制流，还要按约定传递参数、保存现场并取得返回值。

### 4.1 调用与返回的基本过程

一次典型过程调用包括：

1. 调用者把参数放入约定的寄存器或栈中。
2. `CALL` 保存下一条指令的地址，并把被调用过程入口地址送入 `PC`。
3. 被调用者按需建立栈帧、保存寄存器并执行函数体。
4. 被调用者把返回值放入约定位置。
5. 被调用者恢复保存的现场和栈指针。
6. `RET` 根据返回地址恢复控制流，继续执行调用点之后的指令。

不同指令集保存返回地址的方式不同：有的把返回地址压入栈，有的写入链接寄存器。本文用 `RA` 抽象表示返回地址。

### 4.2 调用约定

调用约定（ABI 的一部分）规定调用双方如何配合，通常包括：

| 内容 | 典型约定 |
| --- | --- |
| 参数传递 | 前若干参数使用寄存器，其余参数使用栈 |
| 返回值 | 放在指定的返回值寄存器中 |
| 返回地址 | 放在 `RA` 或栈中的约定位置 |
| 调用者保存寄存器 | 若调用者在调用后仍要使用原值，应在调用前自行保存 |
| 被调用者保存寄存器 | 被调用者若要改写，应先保存并在返回前恢复 |
| 栈对齐 | 调用点和栈帧通常要满足规定的字节对齐要求 |

“调用者保存”和“被调用者保存”描述的是保存责任，不表示某类寄存器每次调用都必须保存；只有其旧值仍需使用或将被改写时才需要采取相应操作。

### 4.3 简单叶过程

设调用约定规定前两个参数放在 `R0、R1` 中，返回值放在 `R0` 中：

```c
int add(int a, int b) {
    return a + b;
}
```

调用者和被调用者可以抽象为：

```text
# 调用者
LI    R0, #3
LI    R1, #4
CALL  add
STORE R0, result

# 被调用者
add:
ADD   R0, R0, R1
RET
```

`add` 内部不再调用其他函数，称为叶过程。若它不需要局部栈空间，也不破坏必须保留的寄存器，就可能无须建立栈帧。

### 4.4 栈帧与过程的入口、出口

一次过程调用在运行栈中占用的区域称为栈帧。栈帧可能包含：

- 返回地址；
- 旧帧指针；
- 需要保存的寄存器；
- 局部变量和临时数据；
- 无法用寄存器传递的参数。

假定栈向低地址增长，某个非叶过程需要 16 字节栈帧，则入口和出口可以抽象为：

```text
foo:
ADDI  SP, SP, #-16     # 分配栈帧
STORE RA, 12(SP)       # 保存返回地址
STORE FP, 8(SP)        # 保存旧帧指针
MOV   FP, SP

# 函数体：可能继续执行 CALL

LOAD  FP, 8(SP)        # 恢复旧帧指针
LOAD  RA, 12(SP)       # 恢复返回地址
ADDI  SP, SP, #16      # 释放栈帧
RET
```

栈帧大小、保存位置和是否使用 `FP` 由具体 ABI 及编译器决定。分析题中若给出了 `SP` 的精确定义，应据此判断入栈和出栈时地址变化的先后顺序。

### 4.5 嵌套调用与递归

非叶过程会继续调用其他过程。新的 `CALL` 可能覆盖 `RA`，也可能改写调用者保存寄存器，因此仍需使用的返回地址和临时数据必须先保存。

递归调用时，每次调用都有独立的返回地址、参数和局部变量，因而通常需要独立栈帧。返回时按后进先出的顺序逐层恢复：

$$
\text{调用}\longrightarrow\text{建立新栈帧}\longrightarrow
\text{递归返回}\longrightarrow\text{释放当前栈帧}
$$

栈使同一段函数代码能够同时对应多次尚未结束的调用，这是递归得以正确执行的重要基础。

## 5. 408 常见考法与易错点

| 考查内容 | 分析要点 |
| --- | --- |
| 指令语义 | 明确源操作数、目的操作数以及是否访问主存 |
| 选择语句 | 找出比较指令、条件转移目标和各分支汇合点 |
| 循环语句 | 找出初始化、测试、循环体、更新和出口 |
| 数组访问 | 用“首地址 + 下标 × 元素字节数”计算有效地址 |
| 过程调用 | 跟踪参数、返回值、返回地址、`SP` 和寄存器保存情况 |
| 机器码转换 | 根据指令格式编码操作码、寄存器号、立即数或位移量 |

常见错误包括：

- 认为一条高级语言语句只对应一条机器指令；
- 混淆 `LOAD` 得到的数据与 `LEA` 得到的地址；
- 忘记 `if-else` 的 `then` 分支结束后要越过 `else` 分支；
- 混淆有符号比较与无符号比较；
- 计算数组地址时忘记乘元素字节数；
- 把 `continue` 一律跳到循环体开头，导致 `for` 循环漏执行更新表达式；
- 认为所有寄存器都由同一方保存，或认为每次调用都必须保存全部寄存器；
- 把某种 ISA 的固定语法、栈方向或调用约定当成所有机器的通用规则。

## 6. 本节小结

程序的机器级表示可以归结为三类基本行为：

1. 用数据传送和算术逻辑指令处理寄存器与主存中的数据；
2. 用比较和转移指令实现选择与循环；
3. 用调用约定、返回地址和栈帧实现过程调用。

分析机器级代码时，应始终跟踪“数据在哪里、`PC` 将转移到哪里、调用前后的现场如何保存”。掌握这三条主线，就能在不同指令系统的具体语法之间迁移。
