<h1><center>第一节 I/O 管理概述</center></h1>

::: info 例 1
字符设备、块设备和网络设备在应用程序接口上有什么典型区别？
:::

::: details 解析
- 字符设备通常按字符或字节流顺序读写，一般不支持任意位置访问。
- 块设备按固定大小的数据块传送，通常支持随机访问，文件系统一般建立在块设备之上。
- 网络设备通常通过套接字接口进行连接、发送和接收，可以提供报文或字节流语义。

这些分类描述的是操作系统提供的访问模型，不能只根据设备外形判断。
:::

::: info 例 2
I/O 控制器中的数据寄存器、状态寄存器和控制寄存器分别有什么作用？
:::

::: details 解析
- 数据寄存器暂存 CPU 与设备之间交换的数据。
- 状态寄存器保存设备的就绪、忙、完成、出错等状态。
- 控制寄存器保存 CPU 发出的读、写、复位等命令及控制信息。

CPU 读写这些寄存器来控制设备，不需要直接处理设备的机械或电子细节。
:::

::: info 例 3
独立编址 I/O 和内存映射 I/O 在访问设备控制器寄存器时有何区别？
:::

::: details 解析
独立编址为 I/O 端口设置独立地址空间，CPU 通常使用专门的 I/O 指令访问；内存映射 I/O 把控制器寄存器映射到内存地址空间，CPU 可以使用普通访存指令访问，但会占用部分内存地址空间。

这里的内存映射 I/O 是设备寄存器的编址方式，不是文件的内存映射。
:::

::: info 例 4
比较程序直接控制、中断驱动和 DMA 三种 I/O 控制方式中 CPU 的干预程度。
:::

::: details 解析
- 程序直接控制：CPU 持续查询设备状态，并参与每次数据传送，干预最多。
- 中断驱动：CPU 不必忙等，但通常仍要在每次传送一个字或较小单位时处理中断并搬运数据。
- DMA：DMA 控制器成块传送，CPU 主要负责初始化和完成中断处理。

总体趋势是 CPU 干预逐渐减少、CPU 与设备的并行程度逐渐提高。
:::

::: info 例 5
DMA 传送期间 CPU 能否继续执行指令？为什么 CPU 有时仍会等待？
:::

::: details 解析
CPU 可以继续执行指令，但 DMA 控制器与 CPU 会竞争内存总线。例如采用周期窃取时，DMA 占用某个存储周期，CPU 若恰好需要取指或访存，就必须等待该周期结束。因此，DMA 减少的是 CPU 搬运数据的工作，并没有消除总线竞争。
:::

::: info 例 6
传送 $4096$ 字节数据。若中断驱动方式每传送 $1$ 字节中断一次，而 DMA 在整个数据块完成后中断一次，两种方式分别产生多少次完成中断？
:::

::: details 解析
按题设，中断驱动方式产生

$$
4096\text{ 次}
$$

中断；DMA 方式只在整个数据块完成后产生 $1$ 次中断。DMA 开始前仍需 CPU 设置地址、方向和长度，因此“一次完成中断”不等于 CPU 完全不参与。
:::

::: info 例 7
DMA 传送 $8\text{ KiB}$，内存总线每个周期传送 $4$ 字节。若采用周期窃取且不计控制开销，DMA 至少占用多少个总线周期？
:::

::: details 解析
$$
\frac{8\times1024}{4}=2048
$$

因此，DMA 至少占用 $2048$ 个总线周期。CPU 可在其他周期运行，但在取指或访存与 DMA 冲突时需要等待。
:::

::: info 例 8
应用程序发出读设备请求后，用户层 I/O 软件、设备独立性软件、设备驱动程序和中断处理程序各完成什么主要工作？
:::

::: details 解析
1. 用户层 I/O 软件提供库函数等调用形式，并通过系统调用进入内核。
2. 设备独立性软件检查通用参数和权限，处理命名、缓冲等公共功能，并把请求交给相应驱动程序。
3. 设备驱动程序把抽象请求转换为控制器命令，设置寄存器并启动设备。
4. 操作完成后，中断处理程序判断中断原因、读取状态、记录结果并唤醒等待进程。

请求自上而下逐步接近硬件，完成信息自下而上返回。
:::

::: info 例 9
设备独立性软件、设备驱动程序和中断处理程序的职责为何不能混淆？
:::

::: details 解析
设备独立性软件处理命名、保护、分配、缓冲等设备共有功能；驱动程序包含特定控制器和设备的控制细节；中断处理程序在设备发出中断后完成现场保护、原因判断、状态处理和进程唤醒。三者所处层次和触发时机不同。
:::

::: info 例 10
阻塞 I/O 与非阻塞 I/O 的返回时机有何不同？
:::

::: details 解析
阻塞 I/O 在操作暂时不能完成时使调用进程进入阻塞态，待条件满足或操作完成后再返回；非阻塞 I/O 立即返回已有结果或“暂不可用”状态，调用者可以继续执行并稍后重试。

二者判断的关键是：调用不能立即满足时，进程是否因该调用而等待。
:::

::: info 例 11
进程执行阻塞式磁盘读，系统使用 DMA，且数据尚未缓存。按时间顺序说明进程状态、CPU 和数据传送的变化。
:::

::: details 解析
1. 进程通过系统调用进入内核，设备驱动程序设置 DMA 的内存地址、方向和长度并启动设备。
2. 请求不能立即完成，调用进程由运行态转为阻塞态，CPU 调度其他就绪进程。
3. DMA 控制器在磁盘控制器与内存之间成块传送数据，传送期间按需占用总线。
4. 整个数据块传送完成后，控制器发出外中断。
5. 中断处理程序确认结果并唤醒原进程，使其进入就绪态。
6. 原进程以后被调度运行，系统调用返回，进程使用已经传入内存的数据。

该过程同时体现了阻塞 I/O、DMA 成块传送、中断通知和进程调度。
:::

## 答题技巧

- 比较 I/O 控制方式时，重点判断 CPU 是否忙等待、数据搬运由谁完成、一次通知对应多大的数据单位以及 CPU 干预程度。
- 区分阻塞与非阻塞 I/O 时，关键判断调用不能立即满足时，进程是否因该调用而等待。
