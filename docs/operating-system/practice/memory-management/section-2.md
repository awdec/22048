<h1><center>第二节 虚拟内存管理</center></h1>

::: info 例 1：虚拟内存特征
虚拟内存的多次性、对换性和虚拟性分别表示什么？虚拟内存是否真正扩大了物理内存？
:::

::: details 解析
多次性表示程序分多次调入内存；对换性表示页面可以在内存和外存之间换入、换出；虚拟性表示进程看到的逻辑地址空间可以大于物理内存。虚拟内存没有真正扩大物理内存，而是利用地址转换和外存后备区形成容量更大的逻辑视图。
:::

::: info 例 2：TLB 未命中与缺页
访问某合法页面时 TLB 未命中，但页表项存在位为 1，是否发生缺页？
:::

::: details 解析
不发生。TLB 未命中只表示快表中没有该映射，访问内存页表后仍可得到页框号；只有合法页面的存在位为 0 时才触发缺页异常。
:::

::: info 例 3：缺页处理
缺页处理结束后，为什么要重新执行引发缺页的指令？缺页和页面调入完成分别属于异常还是中断？
:::

::: details 解析
原指令第一次执行时所需页面不在内存，访存尚未完成；页面调入并更新映射后必须重新执行该指令。缺页由当前指令触发，属于可恢复的内部异常；磁盘完成页面读取后，通过 I/O 外中断通知处理器。
:::

::: info 例 4：按比例分配页框
三个进程的逻辑页数分别为 $10,20,30$，系统有 24 个可分配页框。忽略最小页框限制，平均分配和按比例分配的结果分别是什么？
:::

::: details 解析
平均分配时每个进程获得 $24/3=8$ 个页框。总逻辑页数为 60，按比例分配为：
$$
24\times\frac{10}{60}=4,\qquad
24\times\frac{20}{60}=8,\qquad
24\times\frac{30}{60}=12.
$$
:::

::: info 例 5：固定与可变分配
为什么“固定分配、全局置换”难以作为稳定的组合？
:::

::: details 解析
全局置换允许缺页进程取得其他进程当前占有的页框，这会使两个进程实际页框数发生变化，与“运行期间页框数固定”矛盾。因此固定分配通常配合局部置换，可变分配可配合局部或全局置换。
:::

::: info 例 6：FIFO 与 LRU
访问序列为 $1,2,3,1,4,2$，分配 3 个初始为空的页框。分别求 FIFO 和 LRU 的缺页次数。
:::

::: details 解析
FIFO：访问 $1,2,3$ 各缺页一次；再次访问 1 命中；访问 4 时淘汰最早进入的 1；最后访问 2 命中，共缺页 4 次。

LRU：访问 4 时，页面 2 最久未使用，淘汰 2；最后访问 2 又缺页并淘汰页面 3，共缺页 5 次。

某一条访问序列上，LRU 不一定比 FIFO 缺页少；LRU 的优势是不会出现 Belady 异常，并不保证对每个序列都严格优于 FIFO。
:::

::: info 例 7：Belady 异常
对访问序列 $1,2,3,4,1,2,5,1,2,3,4,5$ 使用 FIFO。3 个页框和 4 个页框时的缺页次数分别是多少？
:::

::: details 解析
逐项模拟可得：

- 3 个页框时缺页 9 次。
- 4 个页框时缺页 10 次。

增加页框后缺页次数反而增加，这就是 Belady 异常。OPT 和 LRU 属于栈算法，不会出现该异常。
:::

::: info 例 8：CLOCK
某进程有 3 个初始为空的页框，CLOCK 指针初始指向第一个页框，装入或命中页面时将访问位置 1。对访问序列 $1,2,3,2,4,1,5$，求缺页次数、淘汰顺序和最终页框内容。
:::

::: details 解析
访问 $1,2,3$ 均缺页，页框为 $[1,2,3]$、访问位为 $[1,1,1]$。再次访问 2 命中。

访问 4 时，指针扫描一周并把三个访问位清 0，再淘汰 1；访问 1 时淘汰访问位为 0 的页面 2；访问 5 时淘汰页面 3。

共缺页 6 次，淘汰顺序为 $1,2,3$，最终页框为 $[4,1,5]$。
:::

::: info 例 9：改进型 CLOCK
改进型 CLOCK 面对 $(R,M)$ 分别为 $(0,0)$、$(0,1)$、$(1,0)$ 的三个页面时，通常优先淘汰哪一个？为什么？
:::

::: details 解析
优先淘汰 $(0,0)$ 页面：它近期未被访问且没有修改，既符合局部性预测，也不需要写回外存。$(0,1)$ 页面可作为下一类候选，但淘汰前要写回；访问位为 1 的页面通常先获得第二次机会。
:::

::: info 例 10：页框回收
回收干净文件映射页和脏匿名页时，处理有何不同？为什么还要失效 TLB 项？
:::

::: details 解析
干净文件映射页在文件中已有相同副本，通常可以直接丢弃；脏匿名页没有可直接恢复的文件副本，通常要先写入交换区。回收后虚拟页已不再映射原页框，必须同步使页表项和 TLB 项失效，否则处理器可能继续使用陈旧映射访问已经分配给其他用途的页框。
:::

::: info 例 11：内存映射文件
共享映射与私有映射在写入文件映射页时有什么主要区别？
:::

::: details 解析
共享映射的修改可以写回原文件，并可被其他共享映射进程观察到；私有映射通常采用写时复制，为写入者建立私有页面，不直接修改原文件。
:::

::: info 例 12：抖动
系统 CPU 利用率很低、磁盘换页频繁，此时继续增加多道程序度是否合适？
:::

::: details 解析
通常不合适。这是抖动的典型迹象，继续增加进程会进一步压缩每个进程的驻留集。应减少多道程序度，或依据工作集、缺页率为活跃进程调整页框数量。
:::

::: info 例 13：缺页对性能的影响
TLB 查询时间为 $10\text{ ns}$，内存访问时间为 $100\text{ ns}$，TLB 命中率为 $95\%$，缺页率为 $10^{-6}$，一次缺页平均处理时间为 $8\text{ ms}$。TLB 与内存串行查询，近似求有效访问时间。
:::

::: details 解析
不发生缺页时：
$$
EAT_0=0.95(10+100)+0.05(10+200)=115\text{ ns}.
$$

$8\text{ ms}=8\times10^6\text{ ns}$，所以：
$$
EAT\approx(1-10^{-6})\times115
+10^{-6}\times8\times10^6
\approx123\text{ ns}.
$$

极低的缺页率仍可能明显增加平均访问时间，因为缺页处理比内存访问慢多个数量级。
:::

::: info 例 14：完整地址翻译
系统采用 32 位虚拟地址和 $4\text{ KB}$ 页面。虚拟地址为 `0x12345ABC`，TLB 未命中，页表项存在位为 1、页框号为 `0x02A`。求虚拟页号、页内偏移和物理地址。若存在位为 0，又会怎样？
:::

::: details 解析
$4\text{ KB}=2^{12}\text{ B}$，低 12 位为页内偏移：

$$
VPN=\texttt{0x12345},\qquad offset=\texttt{0xABC}.
$$

页表给出的页框号为 `0x02A`，因此：

$$
PA=\texttt{0x02AABC}.
$$

TLB 未命中但存在位为 1 时，只需通过内存页表完成正常翻译；若存在位为 0，则产生缺页异常，页面调入并更新页表后重新执行原指令。
:::

::: info 例 15：OPT、FIFO 与 LRU 对比
访问序列为 $1,2,3,4,1,2$，分配 3 个初始为空的页框。分别求 OPT、FIFO 和 LRU 的缺页次数。
:::

::: details 解析
前三次访问 $1,2,3$ 都缺页。

- **OPT**：访问 4 时，未来还会访问 1 和 2，而页面 3 不再访问，因此淘汰 3；之后访问 1、2 均命中，共缺页 4 次。
- **FIFO**：访问 4 时淘汰最早进入的 1；随后访问 1 时淘汰 2，访问 2 时再淘汰 3，共缺页 6 次。
- **LRU**：访问 4 时页面 1 最久未访问；随后访问 1 时页面 2 最久未访问，访问 2 时页面 3 最久未访问，共缺页 6 次。

OPT 给出理论最少缺页次数，但无法在真实运行中预知未来访问序列。
:::

::: info 例 16：工作集计算
页面访问序列为 $1,2,3,2,4,1,2,5$。以“包含当前访问在内的最近 5 次页面访问”为窗口，求访问页面 5 后的工作集及其大小。
:::

::: details 解析
访问页面 5 后，最近 5 次访问为：
$$
2,4,1,2,5.
$$

工作集只保留窗口中出现过的不同页面，因此：
$$
W=\{1,2,4,5\},\qquad |W|=4.
$$

若驻留集长期少于 4 个页框，该访问阶段可能频繁缺页；工作集会随着窗口向前移动而变化。
:::

::: info 例 17：多级页表、缺页与置换综合题
系统采用 32 位虚拟地址、$4\text{ KB}$ 页面和二级页表，地址按“10 位一级索引、10 位二级索引、12 位页内偏移”划分。访问虚拟地址 `0x12345678` 时 TLB 未命中，一级页表项有效，但二级页表项存在位为 0。当前可置换页面如下，采用 LRU：

| 虚拟页 | 页框号 | 最近访问时刻 | 修改位 |
| --- | --- | ---: | ---: |
| `0x11111` | `0x02A` | 20 | 0 |
| `0x22222` | `0x02B` | 35 | 1 |
| `0x33333` | `0x02C` | 10 | 0 |

求一级索引、二级索引和页内偏移，说明应淘汰哪个页面，并求所需页面装入该页框后的物理地址。
:::

::: details 解析
地址拆分结果为：

$$
\text{一级索引}=\texttt{0x48},\qquad
\text{二级索引}=\texttt{0x345},\qquad
\text{页内偏移}=\texttt{0x678}.
$$

TLB 未命中后查询页表，二级页表项存在位为 0，因此发生缺页。LRU 淘汰最近访问时刻最早的页面 `0x33333`，其页框号为 `0x02C`；该页修改位为 0，不需要写回外存。

把所需页面装入页框 `0x02C`，更新页表并刷新相关 TLB 映射后重新执行原指令，最终物理地址为：

$$
PA=\texttt{0x02C678}.
$$

完整顺序是：拆分虚拟地址 → 查询 TLB → 查询两级页表 → 发现缺页 → LRU 选择牺牲页 → 必要时写回 → 调入页面 → 更新页表和 TLB → 重新执行并形成物理地址。
:::

## 答题技巧

- 置换题先固定页框数量，逐次标明命中、缺页和淘汰对象。
- 明确初始页框是否为空、首次装入是否计缺页及算法的破平规则。
- 地址翻译先拆虚拟页号和页内偏移，再依次判断 TLB、页表存在位和权限位。
- 性能题统一时间单位，并区分 TLB 未命中率与缺页率。
- 判断抖动时同时观察缺页率、换页 I/O 和 CPU 利用率。
