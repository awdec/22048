<h1><center>第二节 虚拟内存管理</center></h1>

::: info 例 1
访问某合法页时 TLB 未命中，但页表项存在位为 $1$，是否发生缺页？
:::

::: details 解析
不发生。TLB 未命中只表示快表中没有该映射，访问内存中的页表后仍能得到页框号；存在位为 $0$ 才会触发缺页。
:::

::: info 例 2
换出的页面修改位为 $0$，是否必须写回磁盘？
:::

::: details 解析
通常不必。页面装入后没有被修改，外存中已有相同副本，可以直接覆盖页框；修改位为 $1$ 时才需要先写回。
:::

::: info 例 3
缺页处理结束后，为什么要重新执行引发缺页的指令？
:::

::: details 解析
该指令第一次执行时所需页面不在内存，访存操作尚未完成。页面调入并更新地址映射后，需要从原指令重新开始才能得到正确结果。
:::

::: info 例 4
进程把文件映射到虚拟地址空间后，首次访问尚未装入内存的映射页会发生什么？
:::

::: details 解析
处理器产生缺页异常。内核检查访问合法性和映射关系，把文件中对应的数据块读入页框，更新页表后重新执行引发缺页的指令。
:::

::: info 例 5
访问序列为 $1,2,3,1,4,2$，分配 $3$ 个初始为空的页框。使用 FIFO 时缺页多少次？
:::

::: details 解析
- 访问 $1,2,3$：各缺页一次，页框为 $[1,2,3]$。
- 再访问 $1$：命中，FIFO 顺序不变。
- 访问 $4$：缺页，淘汰最早进入的 $1$，页框变为 $[4,2,3]$。
- 访问 $2$：命中。

因此共缺页 $4$ 次。
:::

::: info 例 6
为什么 OPT 的缺页次数不会多于其他页面置换算法？
:::

::: details 解析
OPT 每次都淘汰未来最长时间不再访问的页面，使当前选择对后续访问最有利，因此能给出理论上的最少缺页次数。但实际运行时无法预知完整的未来访问序列。
:::

::: info 例 7
给进程增加页框一定会降低 FIFO 的缺页次数吗？
:::

::: details 解析
不一定。FIFO 可能出现 Belady 异常，增加页框后缺页次数反而增多。OPT 和 LRU 属于栈算法，不会出现该异常。
:::

::: info 例 8
系统处理器利用率很低、磁盘换页频繁，此时再增加多道程序度是否合适？
:::

::: details 解析
通常不合适。这是抖动的典型迹象，增加进程会进一步压缩每个进程的驻留集。应减少多道程序度，或根据工作集和缺页率为关键进程增加页框。
:::

::: info 例 9
回收页框时，干净页和脏页的处理有何不同？回收后为什么还要更新页表和 TLB？
:::

::: details 解析
干净页在外存中已有相同副本，通常可直接回收；脏页包含尚未写回的修改，必须先写回外存。回收后原虚拟页已不再驻留于该页框，因此应使相应页表项失效，并删除或更新旧的 TLB 映射，防止继续使用失效地址映射。
:::

## 答题技巧

- TLB 未命中不等于缺页。
- 置换题应画固定页框表，逐次标明命中、装入和淘汰对象。
- 判断抖动时，要关注缺页率、换页 I/O 和处理器利用率之间的关系。
