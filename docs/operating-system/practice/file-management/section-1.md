<h1><center>第一节 文件系统基础</center></h1>

::: info 例 1：文件与目录
文件内容、文件属性和文件名分别由什么结构管理？文件名是否一定保存在 inode 中？
:::

::: details 解析
文件内容存放在文件数据块中，权限、大小、时间和数据块定位信息等属性通常保存在 FCB 或 inode 中，文件名由目录项保存。UNIX 类文件系统的 inode 通常不保存文件名；多个目录项可以通过硬链接指向同一个 inode。
:::

::: info 例 2：文件系统层次
一次未命中缓存的文件读取请求，大致经过哪些文件系统层次后到达磁盘？
:::

::: details 解析
请求通常依次经过：用户调用接口、逻辑文件系统、文件组织模块、基本文件系统、I/O 控制层和存储设备。逻辑文件系统处理权限和元数据，文件组织模块完成逻辑块到物理块的映射，驱动程序最终控制设备读取数据。
:::

::: info 例 3：持久化与运行时状态
为什么文件系统既需要外存结构，也需要内存中的运行时结构？
:::

::: details 解析
外存结构用于长期保存文件内容、目录和关键元数据，使系统重启后仍能恢复文件；内存结构用于保存当前打开状态、引用关系和缓存，以减少重复的路径解析及磁盘访问。具体结构分别在第二节和第三节展开。
:::

::: info 例 4：无结构文件与有结构文件
字节流文件和记录式文件的主要区别是什么？
:::

::: details 解析
字节流文件由连续字节组成，操作系统通常不解释其内部业务结构；记录式文件由一个个逻辑记录组成，操作系统或文件管理系统可按记录组织和访问。字节流更通用，记录式结构更便于按记录处理。
:::

::: info 例 5：定长与变长记录
一个文件包含定长 100 字节的记录，文件头大小为 200 字节。若记录从 0 编号，第 35 条记录的起始偏移是多少？变长记录能否直接使用相同公式？
:::

::: details 解析
第 35 条记录前有 35 条记录，因此起始偏移为：
$$
200+35\times100=3700\text{ B}.
$$
变长记录的长度不同，不能仅根据记录号使用固定乘法定位，通常还需要长度信息、分隔符或索引。
:::

::: info 例 6：顺序文件
顺序文件为什么适合批量处理，却不适合频繁地在中间插入记录？
:::

::: details 解析
批量处理可以按照记录排列顺序连续读取，访问模式简单且局部性好。若文件必须保持关键字有序，在中间插入记录可能需要移动大量后续记录，或使用溢出区并在之后重新整理。
:::

::: info 例 7：索引文件
索引文件为什么能提高随机检索速度？它带来了哪些开销？
:::

::: details 解析
索引保存关键字到记录地址的映射，查询时无需顺序扫描全部记录。其代价是索引本身占用空间，插入、删除和修改关键字时需要维护索引，索引过大时还可能需要多级结构。
:::

::: info 例 8：索引顺序文件
某索引顺序文件有 10000 条按关键字有序的记录，每 100 条分为一组，并为每组建立一个索引项。一级索引共有多少项？查找记录的大致过程是什么？
:::

::: details 解析
共有：
$$
\frac{10000}{100}=100
$$
个索引项。查找时先在一级索引中确定目标记录所属的组，再在该组的最多 100 条记录中顺序查找。它以较小索引换取了比全文件顺序扫描更快的检索。
:::

::: info 例 9：散列文件
散列文件适合“按学号精确查找学生记录”还是“查找学号在某一区间内的全部记录”？为什么？
:::

::: details 解析
更适合按学号精确查找，因为散列函数可由给定学号直接计算记录所在区域。不同关键字的散列位置不保持大小顺序，因此范围查询通常需要检查多个散列桶甚至遍历全部记录。
:::

::: info 例 10：三类概念辨析
“索引文件”“索引访问”和“索引分配”分别属于逻辑结构、访问方法还是物理结构？
:::

::: details 解析
- 索引文件是按关键字组织逻辑记录的方式，属于逻辑结构。
- 索引访问表示先查索引再定位数据，属于访问方法。
- 索引分配使用索引块记录磁盘数据块地址，属于物理结构。

三者名称相近，但描述的是不同层次。
:::

## 答题技巧

- 区分文件名、目录项、FCB/inode 和文件数据块。
- 文件逻辑结构回答“记录怎样组织”，物理结构回答“磁盘块怎样分配”。
- 定长记录可以按记录号计算位置，变长记录通常需要额外定位信息。
- 分层题按“接口—逻辑文件系统—文件组织—基本文件系统—I/O 控制—设备”回答。
