<h1><center>第二节 目录与文件</center></h1>

::: info 例 1
为什么 `open` 成功后，`read` 通常只需文件描述符而不再提供完整路径？
:::

::: details 解析
`open` 已完成路径解析和权限检查，并在进程文件描述符表中建立到系统打开文件表项的映射。`read` 可以通过描述符直接定位打开文件状态。
:::

::: info 例 2
两个进程分别打开同一文件，是否一定共享同一个文件偏移量？
:::

::: details 解析
不一定。独立执行 `open` 通常会建立不同的打开文件表项，各自维护偏移量；若通过进程复制或描述符复制共享同一打开文件表项，则可以共享偏移量。
:::

::: info 例 3
删除文件名后，正在读取该文件的进程是否一定立即失败？
:::

::: details 解析
不一定。删除目录项只会减少链接计数；只要文件仍被打开，内核可以继续保留 inode 和数据块，直到链接计数与打开引用都归零。
:::

::: info 例 4
硬链接和符号链接的目标文件被删除后分别会怎样？
:::

::: details 解析
硬链接与原目录项平等地引用同一 inode，删除其中一个名字后其他硬链接仍然有效；符号链接保存目标路径，目标路径被删除后会成为悬空链接。
:::

::: info 例 5
“某文件允许用户 A 读、用户 B 读写”更适合用 ACL 还是能力表表示？
:::

::: details 解析
更适合使用 ACL，因为它以文件对象为中心列出各主体权限。能力表则以用户或进程为中心，列出其可以访问的对象。
:::

::: info 例 6
目录项与 inode 的主要区别是什么？
:::

::: details 解析
目录项负责把文件名映射到 inode 号；inode 保存文件权限、大小、时间和数据块地址等元数据。多个硬链接目录项可以指向同一个 inode。
:::

## 答题技巧

- 路径题要区分目录项、inode、系统打开文件表和进程文件描述符表。
- 删除文件名不等于立即回收文件数据，还要检查链接计数和打开引用。
