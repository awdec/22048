<h1><center>第二节 目录与文件</center></h1>

::: info 例 1：目录项与 inode
目录项与 inode 的主要区别是什么？文件名通常保存在哪里？
:::

::: details 解析
目录项把文件名映射到 inode 号；inode 保存权限、大小、时间、链接计数和数据块地址等元数据。文件名通常属于目录项而不属于 inode，因此多个硬链接目录项可以指向同一个 inode。
:::

::: info 例 2：相对路径
当前工作目录为 `/home/alice/docs`，相对路径 `../img/a.png` 对应哪个绝对路径？路径解析从哪里开始？
:::

::: details 解析
`..` 表示父目录 `/home/alice`，所以目标路径为：

```text
/home/alice/img/a.png
```

相对路径从当前工作目录开始逐级查找；绝对路径从根目录开始。
:::

::: info 例 3：连续分配
某连续分配文件起始物理块号为 120，逻辑块从 0 编号。逻辑块 35 位于哪个物理块？连续分配的主要缺点是什么？
:::

::: details 解析
$$
120+35=155.
$$
逻辑块 35 位于物理块 155。连续分配的主要缺点是产生外部碎片、文件增长困难，并可能需要预先估计文件大小。
:::

::: info 例 4：隐式链接分配
某文件的数据块依次为 $9\rightarrow16\rightarrow1\rightarrow10$。若逻辑块从 0 编号，逻辑块 2 位于哪个物理块？为什么该方式不利于随机访问？
:::

::: details 解析
从首块 9 沿指针经过物理块 16，逻辑块 2 位于物理块 1。定位第 $i$ 个逻辑块必须从首块开始沿链访问前面的块，不能直接计算目标位置。
:::

::: info 例 5：FAT
FAT 为什么通常比隐式链接分配更便于随机定位？它是否具有连续分配那样的直接访问能力？
:::

::: details 解析
FAT 把链接指针集中存放；若 FAT 已驻留内存，沿链查找主要访问内存中的表项，不必为每个指针读取磁盘数据块。但它仍要逐项沿链查找，不具备连续分配按公式直接计算物理块号的能力。
:::

::: info 例 6：一级间接索引
磁盘块大小为 $1\text{ KiB}$，块号占 $4$ 字节，一个一级间接索引块可指向多少数据块及多少文件数据？
:::

::: details 解析
一个索引块保存：
$$
\frac{1024}{4}=256
$$
个块号，因此可指向 256 个数据块，对应 $256\text{ KiB}$ 文件数据。
:::

::: info 例 7：混合索引容量
某 inode 有 10 个直接地址、一个一级间接地址和一个二级间接地址。块大小为 $1\text{ KiB}$，块号占 $4$ 字节，求最大文件数据容量。
:::

::: details 解析
每个索引块可保存 $1024/4=256$ 个块号，可定位的数据块总数为：
$$
10+256+256^2=65802.
$$
最大文件数据容量为：
$$
65802\text{ KiB}=64\text{ MiB}+266\text{ KiB}.
$$
索引块自身不计入文件数据容量。
:::

::: info 例 8：混合索引定位
沿用例 9，逻辑块从 0 编号。逻辑块 300 通过哪一级地址定位？求各级索引；若 inode 已在内存、索引块和数据块均未缓存，需要几次磁盘访问？
:::

::: details 解析
直接地址覆盖逻辑块 $0\sim9$，一级间接覆盖 $10\sim265$，二级间接从 266 开始。逻辑块 300 在二级间接区的相对编号为：
$$
300-266=34.
$$
第一级索引为 $\lfloor34/256\rfloor=0$，第二级索引为 $34\bmod256=34$。需要读取两级索引块和目标数据块，共 3 次磁盘访问。
:::

::: info 例 9：打开文件
为什么 `open` 成功后，`read` 通常只需要文件描述符，而不再提供完整路径？
:::

::: details 解析
`open` 已完成路径解析和权限检查，并在进程文件描述符表中建立到系统打开文件表项的映射。`read` 可通过描述符定位打开文件的状态和当前文件偏移。
:::

::: info 例 10：共享文件偏移
父进程打开文件后偏移量为 0，随后创建子进程，二者共享同一打开文件表项。父进程读 100 字节后，子进程再读 50 字节。子进程从哪里开始读，最终偏移量是多少？
:::

::: details 解析
父子进程共享打开文件表项及其偏移。父进程读取后偏移为 100，子进程从字节 100 开始读取，完成后共享偏移为 150。若子进程重新独立执行 `open`，通常会得到新的打开文件表项和独立偏移。
:::

::: info 例 11：硬链接回收
某 inode 有两个硬链接，且文件已被一个进程打开。依次删除两个目录项后，文件数据何时可以回收？
:::

::: details 解析
删除第一个目录项后链接计数由 2 变为 1；删除第二个后变为 0，但进程仍持有打开引用，所以数据暂不能回收，进程也可继续通过文件描述符访问。最后一个打开引用关闭后，系统才可回收 inode 和数据块。
:::

::: info 例 12：硬链接与符号链接
目标文件的一个名字被删除后，硬链接和符号链接分别可能怎样？
:::

::: details 解析
硬链接与原目录项平等地引用同一 inode，只要仍有硬链接，文件仍可通过其他名字访问。符号链接保存目标路径；若该路径不再存在，符号链接会成为悬空链接。
:::

::: info 例 13：ACL 与能力表
用户 A 可读写文件 $F_1$、只读 $F_2$；用户 B 只读 $F_1$、可执行 $F_2$。写出 $F_1$ 的 ACL 和用户 B 的能力表。
:::

::: details 解析
$F_1$ 的 ACL 以对象为中心：

```text
A：读、写
B：读
```

用户 B 的能力表以主体为中心：

```text
F1：读
F2：执行
```

若要撤销所有主体对 $F_1$ 的写权限，修改 $F_1$ 的 ACL 通常更直接。
:::

::: info 例 14：目录权限
某用户对目录拥有读权限但没有执行权限，能否仅凭已知文件名访问目录中的文件？
:::

::: details 解析
通常不能。目录读权限允许读取或列出目录项名称；执行权限才允许搜索目录并把文件名解析为对应对象。访问路径中的每一级目录通常都需要执行（搜索）权限。
:::

::: info 例 15：路径检索的磁盘访问次数
根目录 inode 已在内存中。解析路径 `/a/b/c` 时，假设根目录、目录 `a`、目录 `b` 都各占一个数据块；相关目录数据块以及 `a`、`b`、`c` 的 inode 均未缓存，读取每个数据块或 inode 各需一次磁盘访问。仅定位到文件 `c` 的 inode 需要多少次磁盘访问？若还要读取 `c` 的第一个数据块呢？
:::

::: details 解析
定位过程为：

1. 读取根目录数据块，找到 `a` 的 inode 号。
2. 读取 `a` 的 inode。
3. 读取目录 `a` 的数据块，找到 `b` 的 inode 号。
4. 读取 `b` 的 inode。
5. 读取目录 `b` 的数据块，找到 `c` 的 inode 号。
6. 读取 `c` 的 inode。

因此仅定位到 `c` 的 inode 需要 6 次磁盘访问；若 `c` 的第一个数据块也未缓存并需要读取，则再增加 1 次，共 7 次。若题目规定某些目录项、inode 或数据块已缓存，应相应扣除访问次数。
:::

::: info 例 16：隐式链接分配的有效容量
磁盘块大小为 $1\text{ KiB}=1024\text{ B}$，隐式链接分配在每个数据块中使用 4 字节保存下一块指针。存放一个大小为 $10\text{ KiB}$ 的文件至少需要多少个磁盘块？
:::

::: details 解析
每个数据块可用于文件内容的有效空间为：
$$
1024-4=1020\text{ B}.
$$

文件大小为 $10\times1024=10240\text{ B}$，因此需要：
$$
\left\lceil\frac{10240}{1020}\right\rceil=11
$$
个磁盘块。计算隐式链接文件容量时，不能把保存下一块指针的空间计入文件数据。
:::

## 答题技巧

- 路径题区分目录项、inode、系统打开文件表和进程文件描述符表。
- 物理结构题先确定逻辑块号落在连续、链接、直接或哪一级间接范围。
- 最大文件大小只统计数据块容量；磁盘访问次数要统计未缓存的索引块。
- 删除文件名不等于立即回收文件数据，还要检查链接计数和打开引用。
- ACL 以文件对象为中心，能力表以用户或进程为中心。
