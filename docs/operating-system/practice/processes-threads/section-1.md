<h1><center>第一节 进程与线程简介</center></h1>

::: info 例 1：程序与进程
同一个程序文件被两个用户同时启动，系统中是一个程序还是两个进程？
:::

::: details 解析
磁盘上仍是一份静态程序，但两次执行形成两个进程。两个进程分别拥有独立的 PCB、执行现场和地址空间，可以处于不同状态。
:::

::: info 例 2：进程特征
多个进程以不可预知的速度交替推进，这体现了进程的哪一特征？为保证结果正确，应配合什么机制？
:::

::: details 解析
体现了进程的**异步性**。并发进程的执行速度和先后次序不确定，需要通过同步与互斥等机制协调执行。
:::

::: info 例 3：进程创建
创建新进程时，PCB、地址空间和就绪队列分别在什么阶段发挥作用？
:::

::: details 解析
系统先申请并初始化 PCB，再分配或建立程序、数据和栈的地址空间映射，初始化处理器现场，最后将 PCB 插入就绪队列。进入就绪队列后，进程才等待调度执行。
:::

::: info 例 4：内存映像
下列内容分别属于进程内存映像的哪个区域：全局变量、递归函数的局部变量、`malloc` 申请的对象、共享库代码？
:::

::: details 解析
全局变量位于数据段；递归函数每层调用的局部变量位于栈；`malloc` 对象位于堆；共享库代码通常位于内存映射区（其指令部分可按需共享）。
:::

::: info 例 5：状态转换
一个运行进程等待键盘输入，输入到达后又被调度执行。写出完整状态转换；若时间片先用完，又会怎样转换？
:::

::: details 解析
等待输入时：运行态 → 阻塞态；输入到达时：阻塞态 → 就绪态；被调度后：就绪态 → 运行态。若时间片先用完，则运行态 → 就绪态，而不是阻塞态。
:::

::: info 例 6：PCB 与进程控制
为什么说 PCB 是进程存在的唯一标志？创建进程时只分配程序段和数据段而不创建 PCB，能否被正常调度？
:::

::: details 解析
PCB 保存进程标识、状态、处理器现场、调度和资源信息。没有 PCB，操作系统无法识别、管理或调度该执行活动；PCB 的建立和撤销分别标志进程的创建和消亡。
:::

::: info 例 7：模式切换与进程切换
一次系统调用从用户态进入内核态，是否一定发生进程切换？发生进程切换时通常需要处理哪些信息？
:::

::: details 解析
不一定。系统调用完成后可能仍返回原进程。进程切换必须保存当前进程的程序计数器、寄存器、栈指针等上下文，更新 PCB 和队列，并恢复下一个进程的相应现场；还可能涉及地址空间和缓存相关状态。
:::

::: info 例 8：IPC 选择
父子进程要高频交换一块大型图像数据，另一个程序只需接收“任务完成”的异步通知，分别优先选择什么 IPC 机制？
:::

::: details 解析
大型图像数据宜使用共享内存，并另配同步机制保护访问；异步事件通知宜使用信号。信号不适合传输大量数据。
:::

::: info 例 9：线程资源
同一进程的两个线程共享哪些资源？哪些内容各自独立？
:::

::: details 解析
共享代码、全局数据、堆、地址空间和打开文件；各自拥有程序计数器、寄存器现场、线程状态和栈。
:::

::: info 例 10：线程模型
双核系统中，一个进程有 4 个用户级线程，其中 $T_1$ 执行阻塞系统调用。分别分析多对一、一对一和映射到 2 个内核级线程的多对多模型。
:::

::: details 解析
- **多对一**：唯一的内核线程阻塞，整个进程无法继续运行，也无法利用双核并行。
- **一对一**：仅 $T_1$ 对应的内核线程阻塞，其余线程仍可运行，最多可在两个核心上并行。
- **多对多（2 个内核线程）**：另一个内核线程仍可运行其余用户线程；在 $T_1$ 所在内核线程解除阻塞前，最多只有一个用户线程实际运行。
:::

::: info 例 11：线程切换
同一进程内从线程 $T_1$ 切换到 $T_2$，相比切换到另一进程，通常省去了哪些工作？哪些工作仍不可省略？
:::

::: details 解析
同进程线程共享地址空间、代码、数据和打开文件，通常不必更换这些进程级资源及其地址空间映射。仍须保存和恢复各线程的程序计数器、寄存器、栈指针和线程状态，因此线程切换并非零开销。
:::

::: info 例 12：挂起状态
一个阻塞进程因内存紧张被换出，随后它所等待的 I/O 完成，但操作系统尚未把它调回内存。该进程依次经历什么状态转换？此时能否直接被处理器调度？
:::

::: details 解析
被换出时由阻塞态转为阻塞挂起态；I/O 完成后由阻塞挂起态转为就绪挂起态。由于进程映像尚未调入内存，它不能直接进入运行态，必须先被激活为就绪态，再等待处理器调度。
:::
