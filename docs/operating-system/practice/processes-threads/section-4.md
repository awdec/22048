<h1><center>第四节 死锁</center></h1>

::: info 例 1：死锁、饥饿与活锁
判断下列现象：①两个进程各占一把锁并永久等待对方的锁；②低优先级进程不断被高优先级进程越过；③两个进程发现冲突后都释放资源并同时重试，始终重复。
:::

::: details 解析
1. **死锁**：两个进程形成循环等待，无外力不能推进。
2. **饥饿**：低优先级进程长期得不到服务，其他进程仍可完成。
3. **活锁**：进程持续活动并改变状态，但没有取得实际进展。
:::

::: info 例 2：必要条件
系统只有一类资源，共 3 个实例。$P_1,P_2,P_3$ 各占有 1 个实例，又各请求 1 个实例后才能完成。系统是否死锁？
:::

::: details 解析
可用资源为 0，三个进程都保持已有资源并等待另一个实例，无人能够先完成，已经发生死锁。此时互斥、不剥夺、请求并保持和循环等待四个必要条件同时成立。

若系统共有 4 个实例，则可先将剩余实例分给任一进程；该进程完成后释放 2 个实例，其他进程可依次完成，不会处于同样的死锁状态。
:::

::: info 例 3：死锁预防
规定所有进程必须按资源编号递增顺序申请资源，破坏了哪个死锁必要条件？
:::

::: details 解析
破坏了**循环等待条件**。统一的资源全序使等待链上的资源编号只能递增，不可能首尾相接形成循环。
:::

::: info 例 4：预防策略判断
要求进程运行前一次性申请全部所需资源，破坏了什么条件？这种方法有什么缺点？
:::

::: details 解析
破坏了**请求并保持条件**：进程不会在持有部分资源时继续申请其他资源。缺点是进程必须预先知道全部需求，资源可能被长期闲置，资源利用率和系统并发度较低，需求较大的进程还可能饥饿。
:::

::: info 例 5：安全状态
系统处于不安全状态，是否说明已经死锁？
:::

::: details 解析
不说明。不安全状态表示找不到能够保证所有进程完成的安全序列，系统之后可能死锁；死锁状态一定不安全，但不安全状态未必已经死锁。
:::

::: info 例 6：银行家算法的输入
使用银行家算法判断系统是否安全，至少需要哪些数据？
:::

::: details 解析
需要当前可用资源向量 `Available`、最大需求矩阵 `Max`、已分配矩阵 `Allocation` 和剩余需求矩阵 `Need`，其中：
$$
Need=Max-Allocation.
$$
安全性检查中进程假定完成后，要把其 `Allocation` 加回 `Work`。
:::

::: info 例 7：安全性算法
某系统当前状态如下，判断是否安全并给出一个安全序列。

| 进程 | `Allocation` | `Need` |
| --- | --- | --- |
| $P_0$ | $(0,1,0)$ | $(1,0,1)$ |
| $P_1$ | $(1,0,1)$ | $(0,1,0)$ |
| $P_2$ | $(1,1,0)$ | $(1,0,0)$ |

`Available=(1,0,0)`。
:::

::: details 解析
初始 `Work=(1,0,0)`：

1. $P_2$ 满足 `Need ≤ Work`，完成后 `Work=(2,1,0)`。
2. $P_1$ 可完成，释放资源后 `Work=(3,1,1)`。
3. $P_0$ 的需求可以满足。

存在安全序列：
$$
\langle P_2,P_1,P_0\rangle,
$$
所以系统处于安全状态。
:::

::: info 例 8：资源请求算法
沿用例 7，$P_0$ 请求资源向量 $(1,0,0)$。银行家算法是否应立即分配？
:::

::: details 解析
该请求未超过 `Need₀` 和 `Available`，先进行试分配。试分配后：

```text
Available     = (0,0,0)
P0 Allocation = (1,1,0)
P0 Need       = (0,0,1)
```

此时 $P_0$、$P_1$、$P_2$ 的剩余需求都不能由 `Work=(0,0,0)` 满足，找不到安全序列。试分配会使系统进入不安全状态，因此应撤销试分配，让 $P_0$ 等待。
:::

::: info 例 9：资源分配图
每类资源只有一个实例时，资源分配图中存在环说明什么？若某类资源有多个实例呢？
:::

::: details 解析
每类资源只有一个实例时，有环是死锁的充分必要条件。存在多实例资源时，有环只能说明可能死锁，还需结合资源的可用数量和各进程的剩余请求判断。
:::

::: info 例 10：死锁检测
两类资源的 `Available=(0,0)`，当前状态如下。判断哪些进程死锁。

| 进程 | `Allocation` | `Request` |
| --- | --- | --- |
| $P_0$ | $(1,0)$ | $(0,1)$ |
| $P_1$ | $(0,1)$ | $(1,0)$ |
| $P_2$ | $(0,0)$ | $(0,0)$ |
:::

::: details 解析
令 `Work=(0,0)`。$P_2$ 可立即完成，但它未占有资源，完成后 `Work` 仍为 $(0,0)$。

$P_0$ 和 $P_1$ 的请求都无法满足，继续扫描也不会发生变化。因此 $P_0$ 与 $P_1$ 构成死锁集合，$P_2$ 不在其中。
:::

::: info 例 11：死锁解除
死锁检测完成后可采用哪些解除方法？选择牺牲进程时应考虑什么？
:::

::: details 解析
可终止一个或多个进程、剥夺资源，或让进程回退到安全检查点后重新执行。选择牺牲者时应考虑进程优先级、已执行时间、剩余工作量、占用资源、回退或重启代价，以及此前被牺牲的次数，防止同一进程反复回退而饥饿。
:::

::: info 例 12：综合银行家算法
系统有 A、B、C 三类资源，当前状态如下：

| 进程 | `Allocation` | `Max` |
| --- | --- | --- |
| $P_0$ | $(0,1,0)$ | $(7,5,3)$ |
| $P_1$ | $(2,0,0)$ | $(3,2,2)$ |
| $P_2$ | $(3,0,2)$ | $(9,0,2)$ |
| $P_3$ | $(2,1,1)$ | $(2,2,2)$ |
| $P_4$ | $(0,0,2)$ | $(4,3,3)$ |

`Available=(3,3,2)`。计算 `Need`，判断当前状态是否安全；若 $P_1$ 请求 $(1,0,2)$，能否立即分配？
:::

::: details 解析
由 `Need=Max-Allocation` 得：

| 进程 | `Need` |
| --- | --- |
| $P_0$ | $(7,4,3)$ |
| $P_1$ | $(1,2,2)$ |
| $P_2$ | $(6,0,0)$ |
| $P_3$ | $(0,1,1)$ |
| $P_4$ | $(4,3,1)$ |

从 `Work=(3,3,2)` 开始，可以依次选择：

$$
\langle P_1,P_3,P_4,P_0,P_2\rangle.
$$

每个进程完成后释放其 `Allocation`，因此当前状态安全。

$P_1$ 的请求 $(1,0,2)$ 同时满足：

$$
Request_1\le Need_1,\qquad Request_1\le Available.
$$

试分配后 `Available=(2,3,0)`，$P_1$ 的 `Need` 变为 $(0,2,0)$，仍可先完成 $P_1$，随后存在安全序列。因此该请求可以立即分配。
:::

## 答题技巧

- 概念题先检查四个必要条件是否同时成立。
- 银行家算法逐行验证 `Need ≤ Work`，进程完成后将其 `Allocation` 加回 `Work`。
- 资源分配图有环是否等价于死锁，取决于每类资源是否只有一个实例。
- 区分银行家安全性检查中的 `Need` 与死锁检测中的当前 `Request`。
