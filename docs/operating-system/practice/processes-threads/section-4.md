<h1><center>第四节 死锁</center></h1>

::: info 例 1
系统处于不安全状态，是否说明已经死锁？
:::

::: details 解析
不说明。不安全状态表示无法找到保证所有进程完成的安全序列，之后可能死锁；死锁状态一定不安全，但不安全状态未必已经死锁。
:::

::: info 例 2
每类资源都只有一个实例时，资源分配图中存在环说明什么？
:::

::: details 解析
存在环是死锁的充要条件。若某类资源有多个实例，存在环只能说明可能发生死锁。
:::

::: info 例 3
规定所有进程必须按资源编号递增顺序申请资源，破坏了哪个死锁必要条件？
:::

::: details 解析
破坏了循环等待条件。统一的全序使资源请求关系不可能形成首尾相接的循环。
:::

::: info 例 4
使用银行家算法判断系统是否安全，至少需要哪些信息？
:::

::: details 解析
需要系统当前的可用资源向量 `Available`、各进程已分配资源矩阵 `Allocation` 和剩余需求矩阵 `Need`。只有可用资源和剩余需求时，无法在进程完成后正确计算它释放的资源，因而不能完整执行安全性检查。
:::

::: info 例 5
死锁预防、死锁避免和死锁检测的主要区别是什么？
:::

::: details 解析
死锁预防通过规则破坏至少一个必要条件；死锁避免在每次分配前检查安全状态；死锁检测则允许死锁发生，之后再识别死锁进程并通过撤销、剥夺资源或回退等方式解除。
:::

## 答题技巧

- 先检查四个必要条件是否同时成立。
- 银行家算法逐行验证 `Need ≤ Work`，进程完成后将其 `Allocation` 加回 `Work`。
- 资源分配图有环是否等于死锁，取决于每类资源是否只有一个实例。
