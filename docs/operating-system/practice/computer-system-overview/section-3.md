<h1><center>第三节 程序运行环境</center></h1>

::: info 例 1
操作系统内核与整个操作系统是否完全等同？
:::

::: details 解析
不完全等同。内核是操作系统中常驻内存、运行在内核态的核心部分，负责中断处理、调度、内存和设备控制等关键功能；命令解释程序、图形界面及部分系统服务可以运行在用户态。判断某功能是否属于内核，应看它是否需要直接控制硬件或访问受保护的内核资源。
:::

::: info 例 2
时钟管理为什么属于内核的基本功能？
:::

::: details 解析
内核利用硬件时钟维护系统时间、提供定时服务，并根据时钟中断统计处理机使用时间、判断时间片是否用完。设置硬件定时器和处理时钟中断涉及受保护资源，必须由内核完成。
:::

::: info 例 3
什么是原语？“原语不可分割”是否表示它只能由一条机器指令组成？
:::

::: details 解析
原语是完成特定系统功能、执行过程中必须保持不可分割性的程序段。它可以由多条机器指令组成；“不可分割”表示其他执行活动不能观察或破坏其不一致的中间状态。系统可借助关中断、硬件原子指令或锁机制保证原子性。
:::

::: info 例 4
应用程序能否直接执行关闭中断、设置页表基址和设备 I/O 指令？
:::

::: details 解析
不能。这些操作会影响整个系统或关键资源，属于特权操作，只能在内核态执行。用户程序需要通过系统调用请求内核完成允许的服务；若在用户态直接执行特权指令，处理器会产生异常。
:::

::: info 例 5
用于发起系统调用的陷入指令为什么不能被规定为用户态禁止执行的特权指令？
:::

::: details 解析
应用程序必须能够主动执行陷入指令，才能通过受控入口请求内核服务。因此陷入指令允许在用户态执行；执行后由处理器保存现场、检查预设入口并切换到内核态。真正的特权操作由系统调用服务例程在内核态完成。
:::

::: info 例 6
处理器由用户态进入内核态的三种主要原因是什么？
:::

::: details 解析
1. 用户程序主动执行系统调用。
2. 当前指令同步产生异常。
3. 处理器响应外部中断。

运行模式由硬件按照规定改变，用户程序不能直接修改处理器状态寄存器来取得内核权限。
:::

::: info 例 7
处理器从用户态切换到内核态，是否意味着当前进程一定由运行态变为阻塞态，或者一定切换到另一个进程？
:::

::: details 解析
都不一定。进入内核态只是处理器权限状态发生变化。若系统调用可以立即完成，内核可以直接返回原进程，进程仍处于运行状态；只有等待资源时才可能阻塞，只有调度器选择另一个进程时才发生进程上下文切换。
:::

::: info 例 8
缺页、时钟到期、非法指令和系统调用分别属于哪类中断或异常？
:::

::: details 解析
- 合法地址的缺页由当前访存指令同步触发，属于可恢复的故障。
- 时钟到期来自处理器外部，属于外中断。
- 非法指令由当前指令同步触发，属于异常。
- 系统调用由程序主动执行陷入指令触发，属于陷阱。
:::

::: info 例 9
故障、陷阱和终止在处理后的继续位置与可恢复性方面有什么区别？
:::

::: details 解析
- 故障通常在指令完成前发现；若原因可以排除，处理后重新执行当前指令，例如缺页。
- 陷阱通常由程序主动触发或在指令执行后报告，处理后执行下一条指令，例如系统调用。
- 终止表示严重且通常不可恢复的错误，当前程序一般无法继续正常执行。
:::

::: info 例 10
响应中断时，保存断点、定位处理入口和执行具体设备服务通常分别由谁完成？
:::

::: details 解析
处理器硬件通常完成模式切换，保存程序计数器、程序状态字等关键断点信息，并根据中断号或中断向量确定入口；内核入口代码再保存必要的通用寄存器，判断事件原因并执行具体服务。返回前由内核恢复软件现场，最终使用中断返回指令恢复运行环境。
:::

::: info 例 11
发生外部中断后，处理器是否一定立即切换到另一个用户进程？
:::

::: details 解析
不一定。处理器首先进入内核态执行中断处理程序。若事件不需要重新调度，内核可以恢复原进程；若时钟中断导致时间片耗尽，或者中断唤醒了更高优先级进程，调度器才可能选择另一个进程。
:::

::: info 例 12
用户程序执行系统调用时，系统调用号和参数起什么作用？
:::

::: details 解析
系统调用号用于让内核分派程序确定应用程序请求的是哪一种服务；参数用于描述服务对象和具体要求，如文件描述符、缓冲区地址和数据长度。参数可以按照约定放在寄存器、用户栈或内存参数块中，内核必须检查地址、权限和取值是否合法。
:::

::: info 例 13
执行普通库函数是否一定会切换到内核态？
:::

::: details 解析
不一定。纯计算、字符串处理等库函数可以完全在用户态执行；只有库函数内部发起系统调用时，才会通过陷入机制进入内核态。库函数是编程接口的一种封装，系统调用才是应用程序请求内核服务的基本程序接口。
:::

::: info 例 14
用户进程发起系统调用后，内核发现参数非法并立即返回错误。这一过程是否一定发生进程阻塞和进程切换？
:::

::: details 解析
不一定。陷入指令会使处理器由用户态进入内核态，但参数检查可以立即完成，进程无须阻塞，也无须切换到另一个进程。内核设置错误码、恢复现场后即可返回原进程。这说明模式切换不等于进程状态转换或上下文切换。
:::

::: info 例 15
用户程序调用 `read` 读取尚未缓存的磁盘数据，简述其中的模式、事件和进程状态变化。
:::

::: details 解析
1. 用户程序准备调用号和参数，执行陷入指令，由用户态进入内核态。
2. 内核检查参数，发现数据尚未缓存，启动磁盘 I/O；当前进程由运行态转为阻塞态。
3. 调度器选择其他就绪进程运行，此处发生进程上下文切换。
4. 磁盘完成后产生 I/O 外中断，处理器进入内核态执行中断处理程序。
5. 内核记录 I/O 结果，把原进程从阻塞态唤醒到就绪态。
6. 原进程以后重新被调度，在内核中完成数据复制和返回值设置，再返回用户态继续执行。

该过程包含系统调用、外中断、模式切换、进程状态转换和上下文切换，但这些概念不能相互替代。
:::

::: info 例 16
源程序从编写完成到被处理器执行，通常要经过哪些主要阶段？
:::

::: details 解析
通常依次经过编译、链接和装入：编译程序把源程序转换为目标模块；链接程序把目标模块及所需库代码组织成可执行文件；装入程序把可执行文件装入进程的地址空间并建立运行环境，随后处理器从程序入口开始执行。
:::

::: info 例 17
静态链接、装入时动态链接和运行时动态链接有何区别？
:::

::: details 解析
- 静态链接在生成可执行文件前完成，所需目标模块被合并到可执行文件中。
- 装入时动态链接在程序装入内存时完成尚未解析的模块链接。
- 运行时动态链接把某些模块的链接推迟到程序执行过程中、真正需要该模块时完成。

三者的主要区别是完成链接的时机，不要与程序是否采用动态重定位混淆。
:::

::: info 例 18
绝对装入、可重定位装入和动态运行时装入的地址处理方式有何不同？
:::

::: details 解析
绝对装入要求装入程序按照目标模块给出的确定地址放置程序；可重定位装入在装入时一次性修改与装入位置有关的地址，程序装入后通常不能再移动；动态运行时装入把地址转换推迟到指令执行时，由硬件地址转换机构把逻辑地址转换为物理地址，程序运行期间可以移动而无须修改程序中的逻辑地址。
:::

::: info 例 19
已初始化的全局变量、未初始化的全局变量、动态申请的对象、函数局部变量和机器指令通常分别位于进程内存映像的什么区域？
:::

::: details 解析
已初始化的全局变量通常位于数据区，未初始化或零初始化的全局变量通常位于 BSS 区，动态申请的对象通常位于堆，函数局部变量通常位于用户栈，机器指令位于代码区。编译器优化和具体系统实现可能改变个别对象的位置，但上述对应关系是基本模型。
:::

::: info 例 20
“堆一定向高地址增长，栈一定向低地址增长”能否作为所有系统的普遍规律？
:::

::: details 解析
不能。堆和栈通常从不同区域动态扩展，许多常见系统采用上述方向，但具体地址布局和增长方向由体系结构、操作系统及运行环境决定。多线程进程还会为各线程分别建立用户栈，因此答题时应把它视为常见布局，而不是概念定义。
:::

::: info 例 21
两个进程中数值相同的虚拟地址是否一定对应同一个物理地址？
:::

::: details 解析
不一定。每个进程通常拥有独立的虚拟地址空间，内存管理机构依据当前进程的地址映射把虚拟地址转换为物理地址，因此相同虚拟地址可以对应不同物理页。只有操作系统显式建立共享映射时，两个进程的某些虚拟页才可能映射到相同物理页。
:::

::: info 例 22
创建进程的内存映像时，是否必须立即把可执行文件的全部代码和数据读入物理内存？
:::

::: details 解析
不一定。操作系统需要建立进程的虚拟地址空间、代码和数据映射、堆栈等运行环境，但在请求分页系统中，许多页面可以等到首次访问并发生缺页时再调入物理内存。因此“已经建立虚拟地址映射”不等于“全部页面已经常驻物理内存”。
:::

## 答题技巧

- 判断指令能否在用户态执行时，看它是否会直接改变系统关键状态或控制硬件。
- 判断中断与异常时，先看事件是否由当前指令同步引起；外部异步事件属于中断，当前指令引起的事件属于异常。
- 系统调用是应用程序请求内核服务的接口，陷入指令是实现用户态进入内核态的机制。
- 模式切换只改变处理器权限；进程状态转换和上下文切换还需要相应的阻塞、唤醒或调度条件。
- 链接解决目标模块之间的符号与地址关系，装入解决可执行文件进入地址空间及地址定位问题。
- 区分可执行文件、进程虚拟地址空间和实际驻留的物理页；三者不能相互等同。
