<h1><center>第二节 目录与文件</center></h1>

## 1. 文件控制块与 inode

文件控制块 FCB 保存文件属性和物理位置等元数据，是操作系统管理文件的数据结构。目录项通常保存 FCB，或保存指向 FCB 的索引。

UNIX 类文件系统把文件名与其他元数据分离：目录项保存“文件名 + inode 号”，inode 保存权限、大小、时间和数据块地址。文件名属于目录，inode 才代表被管理的文件对象。

## 2. 目录的基本操作

目录用于按名组织文件。常见操作包括搜索文件、创建文件、删除文件、列出目录、重命名文件和遍历文件系统。

目录实现可以使用线性表或哈希表。线性表实现简单，但查找较慢；哈希表查找较快，但需要处理哈希冲突。

## 3. 目录结构

- **单级目录**：结构简单，但不同文件容易发生重名冲突。
- **两级目录**：每个用户拥有独立目录，可解决不同用户之间的文件重名问题。
- **树形目录**：支持分层组织，可使用绝对路径和相对路径。
- **无环图目录**：允许共享文件或目录，但不允许形成环。
- **通用图目录**：允许形成环，遍历和空间回收更加复杂。

## 4. 路径与目录检索

- **绝对路径**：从根目录开始定位文件。
- **相对路径**：从当前工作目录开始定位文件。

设置当前工作目录可以减少每次路径解析都从根目录开始的开销。路径中的每一级目录都需要经过目录项查找和权限检查。

## 5. 文件的打开与关闭

执行 `open` 后，操作系统完成路径解析和权限检查，把文件元数据装入内存打开文件表，并向进程返回文件描述符。后续 `read`、`write` 等操作可通过描述符定位文件，不必重复解析完整路径。

系统通常维护：

- **系统级打开文件表**：保存打开计数、文件偏移和 inode 等共享信息。
- **进程级文件描述符表**：保存本进程描述符到系统打开文件表项的映射。

不同进程独立打开同一文件时通常拥有不同文件偏移；通过进程复制或描述符复制共享同一打开文件表项时，可以共享文件偏移。

## 6. 文件共享

- **硬链接**：多个目录项指向同一 inode，地位相同；通常不能跨文件系统。
- **符号链接**：建立一个保存目标路径的特殊文件，可以跨文件系统，但目标被删除后可能成为悬空链接。

删除一个目录项不一定立即删除文件数据。只有链接计数归零且没有进程继续打开该文件时，系统才可以回收 inode 和数据块。

## 7. 文件保护

- 口令保护和文件加密。
- 访问控制矩阵。
- **访问控制表 ACL**：以对象为中心，记录哪些主体拥有何种权限。
- **能力表**：以主体为中心，记录其可以访问哪些对象以及相应权限。

::: tip 识别方法
ACL 回答“这个文件允许谁做什么”，能力表回答“这个用户能对哪些对象做什么”。
:::
