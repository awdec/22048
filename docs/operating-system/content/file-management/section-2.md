<h1><center>第二节 目录与文件</center></h1>

目录负责按名组织和查找文件，文件控制信息负责描述文件，物理结构负责定位外存数据块。文件的打开、共享和保护都建立在这些机制之上。

## 1. 目录的基本概念

目录是一种特殊文件，用于建立“文件名—文件控制信息”之间的映射，并把大量文件组织成层次化的命名空间。

目录管理应满足以下要求：

- 按文件名快速检索文件。
- 允许不同用户或不同目录使用相同文件名。
- 支持文件分类、分层组织和路径访问。
- 支持文件和目录共享。
- 便于执行权限检查、遍历和空间回收。

### 1.1 路径名

- **绝对路径**：从根目录开始，能够唯一确定文件位置。
- **相对路径**：从当前工作目录开始，通常比完整绝对路径简短。
- `.` 表示当前目录，`..` 表示父目录。

路径解析需要逐级查找目录项并检查搜索权限。设置当前工作目录可避免每次相对访问都从根目录开始。

### 1.2 目录的实现

- **线性表**：目录项顺序排列，实现简单；查找可能需要线性扫描。
- **哈希表**：根据文件名计算目录项位置，平均查找速度较快；需要处理哈希冲突和扩容。

实际系统还可能使用树形索引等结构，以支持大型目录。

## 2. 文件控制块和索引节点

### 2.1 文件控制块 FCB

文件控制块（FCB）是操作系统管理文件的数据结构，通常保存：

- 文件标识、类型、所有者和访问权限。
- 文件大小及创建、修改、访问时间。
- 文件数据块的定位信息。
- 链接计数及其他状态信息。

FCB 是文件存在和受系统管理的重要标志。目录项可以直接包含 FCB，也可以只保存指向 FCB 的引用。

### 2.2 inode

UNIX 类文件系统把文件名与其他元数据分离：

```text
目录项：文件名 + inode 号
inode：文件类型、权限、所有者、大小、时间、链接计数、数据块地址等
```

文件名属于目录，不属于 inode。多个硬链接目录项可以指向同一个 inode，因此同一个文件对象可以有多个名字。

磁盘 inode 是持久化结构；文件被访问时，系统可把它读入内存形成活动 inode 或 vnode，并增加打开计数、锁状态等运行时信息。

## 3. 目录结构

### 3.1 树形目录

目录和文件构成以根目录为起点的树，支持多级分类、绝对路径和相对路径。不同目录中可以出现同名文件，目录层次也便于按用户或用途组织文件。

::: warning 易错点
硬链接可使同一个文件对象拥有多个目录项和路径，但目录命名空间的基本组织仍按树形目录理解。
:::

## 4. 目录的操作

目录的常见操作包括：

| 操作 | 主要任务 |
| --- | --- |
| 搜索 | 根据文件名查找目录项 |
| 创建文件 | 增加目录项并关联新建的 FCB/inode |
| 删除文件 | 删除目录项并更新链接计数，满足条件后回收文件 |
| 创建 / 删除目录 | 建立或撤销目录节点，并检查目录是否为空等条件 |
| 列出目录 | 读取目录项并显示文件名及属性 |
| 重命名 / 移动 | 修改目录项名称或改变其所在目录 |
| 遍历 | 递归访问目录树，用于搜索、备份和统计 |
| 建立 / 删除链接 | 增加或减少共享文件的目录引用 |

路径解析从根目录或当前工作目录开始，逐级读取目录项。若某一级不存在或缺少目录搜索权限，即使最终文件存在，也不能成功访问。

删除目录时应按系统规则检查目录是否为空，并正确处理其中的目录项和引用关系。

## 5. 文件的物理结构

文件的物理结构描述文件逻辑块在外存上的组织和定位方式。

### 5.1 连续分配

文件占用一组连续磁盘块，目录项或 FCB 记录起始块号和长度。

- **优点**：顺序访问快，随机访问可直接计算物理块号。
- **缺点**：产生外部碎片，文件增长困难，可能需要预先估计大小或移动文件。

若起始块号为 $b$，逻辑块号为 $i$，则：

$$
\text{物理块号}=b+i.
$$

### 5.2 链接分配

文件数据块可分散存放，并通过指针连接，不产生外部碎片且增长方便。

- **隐式链接**：每个数据块中保存下一块指针。随机访问必须从首块顺链查找，指针损坏会影响后续块。
- **显式链接**：把下一块指针集中存放在文件分配表（FAT）中。若 FAT 驻留内存，沿链定位不必反复读取数据块，但仍需逐项查找。

链接指针会占用空间，隐式链接的数据块有效载荷小于完整磁盘块大小。

### 5.3 索引分配

系统为文件建立索引块，索引块中的每个表项记录一个数据块地址。文件数据块可离散分布，同时支持直接访问。

小文件也需要索引开销；文件很大时，单个索引块不足，可采用链接索引、多级索引或混合索引。

### 5.4 混合索引

inode 可同时设置直接地址和一级、二级、三级间接地址，使小文件通过直接地址快速定位，大文件通过多级索引扩展。

若磁盘块大小为 $B$，块号占 $s$ 字节，则一个索引块包含：

$$
K=\frac{B}{s}
$$

个块号。若 inode 有 $d$ 个直接地址，以及一个一级、一个二级和一个三级间接地址，则最大可定位数据块数为：

$$
d+K+K^2+K^3.
$$

计算最大文件数据容量时，只统计被索引的数据块容量，不把索引块自身计入文件内容；计算访问次数时，则必须统计未缓存的各级索引块。

## 6. 文件的操作

### 6.1 创建与删除

创建文件时，系统检查名称和权限，建立 FCB/inode 与目录项；可以延迟到首次写入时再分配数据块。删除文件时先移除目录项并减少链接计数，只有链接计数和打开引用都满足条件时才回收 inode 和数据块。

### 6.2 打开与关闭

执行 `open` 时，系统完成路径解析、权限检查，将文件控制信息装入内存打开文件表，并向进程返回文件描述符或句柄。

系统通常维护：

- **进程级文件描述符表**：保存描述符到系统打开文件表项的映射及描述符标志。
- **系统级打开文件表**：保存文件偏移、打开方式、引用计数及指向活动 inode/vnode 的引用。
- **活动 inode/vnode 表**：保存文件元数据的内存副本和全系统共享状态。

`close` 减少相应引用计数；最后一个引用关闭时，系统释放运行时表项并按需写回数据。

### 6.3 读与写

- `read` 从当前文件偏移读取数据，并推进偏移。
- `write` 从当前偏移写入数据，可能分配新块并扩展文件。

不同进程独立 `open` 同一文件时通常拥有不同打开文件表项和文件偏移；通过进程创建或描述符复制共享同一打开文件表项时，可以共享文件偏移。

## 7. 文件共享

### 7.1 基于索引节点的硬链接

硬链接通过新增目录项指向已有 inode 实现共享。所有硬链接地位平等，通常不能跨文件系统，也通常不允许普通用户为目录建立硬链接。

删除一个硬链接只减少链接计数。只有链接计数为 0 且没有打开引用时，系统才可回收文件数据。

### 7.2 符号链接

符号链接是保存目标路径的特殊文件。解析时系统根据该路径继续查找目标。

- 可以跨文件系统，也可以指向目录。
- 目标被删除或路径改变后，符号链接可能成为悬空链接。
- 符号链接通常拥有独立的 inode 和元数据，其内容保存目标路径。访问目标时仍需检查路径中各级目录及目标文件的权限；在一些 UNIX 类系统中，符号链接自身的普通权限位并不参与常规访问控制。

### 7.3 运行时共享

多个文件描述符可指向同一个系统打开文件表项，从而共享文件偏移和打开状态；也可以分别打开同一 inode，得到彼此独立的文件偏移。共享数据访问还需考虑并发写入、文件锁和一致性。

## 8. 文件保护

文件保护用于控制主体对文件对象的访问，常见访问类型包括读取、写入、执行、追加、删除和列出目录等。

### 8.1 访问控制矩阵

访问控制矩阵的行表示主体，列表示对象，单元格保存相应访问权限。完整矩阵通常很稀疏，实际系统多采用以下两种形式：

- **访问控制表（ACL）**：以对象为中心，记录哪些主体对该对象拥有哪些权限。
- **能力表**：以主体为中心，记录该主体可以访问哪些对象及其权限。

ACL 回答“谁能对这个文件做什么”，能力表回答“这个主体能对哪些对象做什么”。

### 8.2 UNIX 权限模型

UNIX 类系统常分别为文件所有者、同组用户和其他用户设置 `r`、`w`、`x` 权限。目录权限含义与普通文件不同：目录读权限允许列出名称，写权限允许修改目录项，执行权限允许搜索和穿过目录。

### 8.3 其他保护方法

- 口令保护实现简单，但口令管理和共享不便。
- 文件加密可防止未获密钥者理解内容，但不能替代操作系统的访问控制。
- 备份、审计和文件锁分别用于恢复、追踪和并发访问控制，不应与权限检查混为一谈。

::: warning 易错点
删除目录项不一定立即删除文件；硬链接不保存目标路径，符号链接保存路径；ACL 以对象为中心，能力表以主体为中心。
:::
