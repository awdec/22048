<h1><center>第三节 文件系统</center></h1>

## 1. 文件系统的层次结构

典型文件系统自上而下包括：

1. 用户调用接口。
2. 逻辑文件系统：管理目录、权限和元数据。
3. 文件组织模块：完成逻辑块到物理块的映射。
4. 基本文件系统：发出通用块读写请求。
5. I/O 控制层：包括设备驱动程序和中断处理程序。
6. 存储设备。

分层结构把按名访问、空间分配和具体设备控制分离，使上层操作不依赖特定磁盘硬件。

## 2. 文件系统的磁盘布局

磁盘分区或卷通常包含：

- 引导块。
- 超级块或卷控制块。
- 空闲空间管理信息。
- inode 或 FCB 区。
- 目录与文件数据区。

超级块保存文件系统类型、容量、块大小和关键区域位置等全局信息，挂载文件系统时通常需要读取这些内容。

## 3. 外存空闲空间管理

### 3.1 空闲表法

记录每个连续空闲区的起始块号和长度，适合连续分配，但空闲区较多时表项会增加。

### 3.2 空闲链表法

把空闲块或空闲区链接起来，实现简单，但随机取得大量连续块的效率较低。

### 3.3 位示图

用一个二进制位表示一个磁盘块是否空闲，查找、分配和回收方便。位示图占用空间为：

$$
\frac{\text{磁盘块数}}{8}\text{ 字节}.
$$

### 3.4 成组链接法

把空闲块号分组存放，并通过组之间的链接管理大量空闲块，适合大型文件系统。

## 4. 虚拟文件系统

虚拟文件系统 VFS 位于系统调用与具体文件系统之间，用统一的文件、目录项、索引节点和超级块等抽象屏蔽实现差异。

不同文件系统按照 VFS 约定实现相应操作后，应用程序就可以使用相同的 `open`、`read`、`write` 等接口访问它们。

## 5. 文件系统挂载

挂载把一个文件系统的根目录接入现有目录树中的某个挂载点。挂载后，访问该目录会进入被挂载文件系统，挂载点原有内容暂时被遮蔽，但并未删除。

卸载前应确保相关文件不再被使用，并将需要持久化的数据写回存储设备；否则卸载可能失败或造成数据不一致。

::: tip 主线
文件系统把有名字的逻辑文件映射为外存上的数据块：目录负责命名，文件分配方式负责定位，空闲空间管理负责分配和回收，VFS 负责统一不同文件系统的访问接口。
:::
