<h1><center>第三节 程序运行环境</center></h1>

应用程序通常在受限制的处理机模式下运行，需要操作系统服务时，通过系统调用、中断或异常进入内核。处理器的运行模式、中断机制和系统调用共同构成操作系统控制程序执行、保护系统资源的基本运行环境。

## 1. 操作系统内核

操作系统内核是操作系统中常驻内存、运行在内核态的核心部分。它直接控制硬件，管理关键系统资源，并为上层系统程序和应用程序提供最基本的服务。

内核不等于整个操作系统。命令解释程序、图形界面和部分系统服务可以运行在用户态；只有需要执行特权操作或访问关键内核数据的功能才必须进入内核。

### 1.1 内核的基本功能

不同操作系统对内核功能的划分不完全相同，通常包括：

- 中断与异常处理：响应硬件事件和程序执行中的异常，转入相应处理程序。
- 时钟管理：维护系统时间、提供定时服务，并为时间片和调度提供依据。
- 处理机管理：保存和恢复执行现场，实现进程或线程调度与切换。
- 存储器管理：完成内存分配、地址转换、共享和保护等核心操作。
- 设备与 I/O 管理：控制设备驱动程序、处理中断并协调数据传送。
- 系统调用处理：检查系统调用号和参数，执行应用程序请求的内核服务。

### 1.2 原语

原语是由若干条指令组成、用于完成某种特定系统功能的程序段，在并发执行意义上必须保持不可分割性：执行过程中不允许其他相关活动插入并观察或破坏不一致的中间状态。原语的原子性不等同于系统崩溃后的事务回滚能力。

原语通常用于修改进程状态、维护队列和实现同步等关键操作。其原子性可以借助关中断、硬件原子指令或锁机制实现；具体方法取决于处理器结构和系统设计。

::: tip 内核功能与内核态
“内核功能”描述操作系统的核心职责，“内核态”描述处理器的权限状态。执行内核功能通常需要处于内核态，但进入内核态并不表示一定发生了进程切换。
:::

## 2. 处理机的双重工作模式

为了保护操作系统和关键资源，处理器通常至少设置两种运行模式，并在程序状态字（PSW）或专门状态寄存器中保存当前模式。

### 2.1 用户态与内核态

- 用户态（目态）：普通应用程序所在的受限模式，只能执行非特权指令，不能直接访问内核数据或任意控制硬件。
- 内核态（管态、核心态）：操作系统内核使用的特权模式，可以执行全部指令并访问受保护的系统资源。

处理器还可能提供多级特权级，但 408 通常使用用户态和内核态的双重模式进行分析。

### 2.2 特权指令与非特权指令

特权指令只能在内核态执行，若用户程序直接执行，处理器会产生异常。典型特权操作包括：

- 修改中断屏蔽状态。
- 设置时钟或定时器。
- 直接执行设备 I/O 控制操作。
- 修改页表基址等关键地址转换状态。
- 停机或改变处理器的特权状态。

非特权指令可以在用户态执行，包括一般的算术、逻辑、转移和普通访存指令。用于发起系统调用的陷入指令必须允许用户程序执行，因此它不是普通意义上的特权指令；执行该指令后，处理器按照预设入口转入内核态。

### 2.3 运行模式的转换

用户态进入内核态的主要原因包括：

1. 应用程序主动执行系统调用。
2. 当前指令执行时发生异常。
3. 处理器响应外部中断。

运行模式的改变由处理器按照硬件规定完成，用户程序不能通过直接修改状态寄存器获得内核权限。内核处理结束后，使用专门的返回指令恢复原程序的状态，并重新进入用户态。

模式切换不等于进程切换。处理器进入内核态后，可以处理完事件并返回原进程；只有调度器选择了另一个进程，才会发生进程上下文切换。

## 3. 中断和异常的概念

中断和异常都会使处理器暂停当前执行流程，保存必要现场，并转去执行相应处理程序。二者的关键区别在于事件来源及其与当前指令的关系。

### 3.1 中断

狭义的中断通常指外中断，事件来自当前处理器执行指令之外，与当前指令的执行不同步。

常见外中断包括：

- 时钟或定时器中断。
- I/O 设备完成或设备请求中断。
- 处理器之间的中断等硬件事件。

外中断可以使操作系统获知设备完成、时间片用完等事件，从而实现 CPU 与设备并行工作以及抢占式调度。

### 3.2 异常

异常也称内中断，由当前正在执行的指令同步引起。根据能否恢复以及处理后从哪里继续执行，可分为：

| 类型 | 主要特点 | 典型例子 |
| --- | --- | --- |
| 故障（Fault） | 通常在指令完成前被发现；若原因可以排除，处理后重新执行当前指令 | 缺页 |
| 陷阱（Trap） | 通常由程序主动触发或在指令执行后报告，处理后执行下一条指令 | 系统调用、调试断点 |
| 终止（Abort） | 严重且通常无法恢复当前程序，可能无法准确确定出错指令 | 严重硬件错误或系统状态破坏 |

并非所有异常都会终止进程。例如，合法地址产生的缺页故障可以由操作系统调入页面后重新执行原指令。

### 3.3 中断和异常处理过程

典型处理过程如下：

1. 处理器在适当时机检测或响应中断、异常。
2. 硬件保存程序计数器、程序状态字等关键现场，并切换到内核态。
3. 处理器根据中断号、异常号或中断向量找到对应处理程序入口。
4. 内核入口代码保存仍需保护的通用寄存器和其他现场。
5. 内核判断事件原因，执行中断或异常处理程序；必要时阻塞、唤醒进程或调用调度器。
6. 内核恢复现场，并使用中断返回指令恢复被选中程序的运行模式和执行位置。

保存关键断点、切换模式和定位入口通常由硬件完成；保存完整软件现场和执行具体服务通常由操作系统完成。处理结束后不一定返回原进程，也不一定返回触发事件的原指令，取决于事件类型和调度结果。

## 4. 系统调用

系统调用是操作系统向应用程序提供程序接口的基本方式。应用程序不能直接执行特权操作，只能通过系统调用请求内核代为完成进程控制、文件访问、设备 I/O 等服务。

### 4.1 系统调用的类型

| 类型 | 典型服务 |
| --- | --- |
| 进程控制 | 创建、终止进程，等待子进程，装入并运行程序 |
| 文件管理 | 创建、删除、打开、关闭、读写文件 |
| 设备管理 | 请求或释放设备，读写设备，设置设备参数 |
| 存储管理 | 申请、释放或映射内存 |
| 进程通信 | 建立通信连接，发送和接收消息，共享内存 |
| 信息维护 | 获取时间、系统信息、进程或文件属性 |

### 4.2 系统调用的执行过程

一次典型系统调用经历以下步骤：

1. 用户程序调用相应的接口函数，准备系统调用号和参数。
2. 接口函数把参数放入寄存器、用户栈或约定的内存区域，并执行陷入指令。
3. 处理器保存关键现场，由用户态切换到内核态，进入统一的系统调用入口。
4. 系统调用分派程序根据调用号选择服务例程；内核检查参数、地址和访问权限。
5. 服务例程执行请求。若等待的资源暂不可用，当前进程可能阻塞，调度器可以切换到其他进程。
6. 服务完成后，内核设置返回值或错误码，恢复用户现场并执行返回指令。
7. 处理器回到用户态，用户程序从系统调用之后继续执行。

系统调用会引起用户态到内核态的转换，但不一定引起进程阻塞或上下文切换。例如，查询进程标识通常可以立即完成。

### 4.3 系统调用、库函数与普通函数调用

- 系统调用进入内核，请求受保护的操作系统服务。
- 库函数是程序库提供的函数，可能完全在用户态运行，也可能封装一个或多个系统调用。
- 普通函数调用只改变当前程序的控制流和栈帧，通常不改变处理器特权级。

::: warning 易错点
陷入指令由用户程序执行，用于安全地进入内核，因此不是用户态禁止执行的特权指令；真正的特权操作由系统调用服务例程在内核态完成。模式切换、进程状态转换和进程上下文切换是三个不同概念。
:::

## 5. 程序的链接与装入

源程序需要经过预处理、编译和汇编形成可重定位目标模块，再由链接程序处理模块之间的符号引用，形成装入模块或可执行文件。程序运行前，装入程序还要把可执行文件映射或复制到内存，并建立运行环境。

$$
\text{源程序}\rightarrow\text{目标模块}\rightarrow\text{链接}\rightarrow
\text{可执行文件}\rightarrow\text{装入内存}\rightarrow\text{运行}.
$$

### 5.1 程序的链接

- 静态链接：程序运行前，把所需目标模块和库代码链接成一个完整的可执行文件。运行时不再查找这些模块，但多个可执行文件可能各自保存相同库代码。
- 装入时动态链接：装入某个目标模块时，根据外部符号引用装入并链接所需模块。未被引用的模块可以暂不装入。
- 运行时动态链接：把某些模块的链接推迟到程序执行过程中，只有真正调用相应功能时才装入并链接，便于共享库和按需加载。

动态链接可以减少可执行文件中的重复代码并方便库更新，但运行环境必须能够找到兼容的共享模块。

### 5.2 程序的装入

- 绝对装入：编译或汇编时已经确定程序将驻留的物理地址，装入程序按指定地址直接装入。它不适合多道程序环境中的灵活内存分配。
- 可重定位装入（静态重定位）：目标模块从相对地址开始编址，装入时由装入程序一次性修改与地址有关的内容。装入后程序通常不能在内存中随意移动。
- 动态运行时装入（动态重定位）：装入时不永久修改所有逻辑地址，程序运行期间由硬件地址转换机构把逻辑地址转换为物理地址。程序可以在运行过程中移动，现代虚拟内存系统通常采用这一思想。

链接解决的是不同目标模块之间的符号和地址关系；装入解决的是如何把可执行程序放入内存并建立运行地址。两者不能混为一谈。

## 6. 程序运行时内存映像与地址空间

### 6.1 地址空间

- 逻辑地址或虚拟地址：程序指令中使用的地址，属于进程自己的逻辑/虚拟地址空间。
- 物理地址：主存单元的实际地址，属于物理地址空间。

进程通常只能直接产生和使用虚拟地址，处理器中的地址转换机构在操作系统建立的映射控制下，把虚拟地址转换为物理地址。同一个虚拟地址可以在不同进程中映射到不同物理位置，从而实现进程隔离。

### 6.2 运行时内存映像

一个进程的典型虚拟地址空间包含：

| 区域 | 主要内容 | 典型权限与特点 |
| --- | --- | --- |
| 代码段 | 程序的机器指令 | 通常可读、可执行，不允许普通写入 |
| 只读数据段 | 字符串常量等只读数据 | 通常只读，不可执行 |
| 数据段 | 已初始化的全局变量和静态变量 | 可读写，初始值来自可执行文件 |
| BSS 区 | 未显式初始化或初始化为零的全局、静态变量 | 装入时建立并清零，通常不在文件中保存同等大小的数据 |
| 堆 | 动态申请的内存 | 通常按需扩展，由内存分配器管理 |
| 共享库和内存映射区 | 共享库、映射文件、共享内存等 | 可在进程间共享物理页，权限取决于映射方式 |
| 用户栈 | 函数调用帧、局部变量、参数和返回地址等 | 随函数调用动态变化，每个线程通常有自己的用户栈 |

许多系统中堆大致向高地址扩展、用户栈大致向低地址扩展，但这不是所有体系结构和操作系统必须采用的固定布局。地址空间布局随机化等机制也会改变各区域的实际位置。

### 6.3 可执行文件到进程映像

创建进程或装入新程序时，操作系统通常：

1. 建立新的虚拟地址空间和地址转换数据结构。
2. 根据可执行文件的信息建立代码段、数据段和 BSS 区等映射。
3. 建立用户栈，写入命令行参数和环境信息。
4. 建立共享库、动态链接器和其他必要映射。
5. 设置程序计数器、栈指针等初始处理器现场。
6. 把进程置为可运行状态，从程序入口开始执行。

采用请求分页时，建立内存映像不表示所有代码和数据已经读入物理内存；系统可以先建立映射，在进程实际访问相应页面时再通过缺页机制调入。

::: warning 地址辨析
链接与装入负责形成可执行程序并建立运行映像，地址转换负责程序运行时的虚拟地址到物理地址映射。可执行文件、虚拟地址空间和实际占用的物理页是三个不同概念。
:::
