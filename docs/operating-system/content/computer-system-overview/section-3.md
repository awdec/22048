<h1><center>第三节 操作系统的运行环境</center></h1>

## 1. 处理器运行模式

处理器通常设置两种运行模式：

- **用户态（目态）**：执行普通应用程序，只能使用非特权指令。
- **内核态（管态、核心态）**：执行操作系统内核，可使用全部指令。

涉及资源管理和系统安全的指令属于特权指令，如修改中断屏蔽字、设置时钟、执行 I/O 指令和切换页表基址。访管指令在用户态执行，用于主动请求操作系统服务，不属于特权指令。

## 2. 中断与异常

中断和异常使处理器暂停当前程序，转去执行相应处理程序，完成后再决定是否返回。

| 类型 | 来源 | 同步性 | 示例 |
| --- | --- | --- | --- |
| 外中断 | CPU 外部 | 异步 | 时钟、I/O 完成、硬件故障 |
| 异常（内中断） | 当前指令内部 | 同步 | 除零、缺页、非法指令、系统调用 |

异常通常分为：

- **故障（Fault）**：通常可修复，处理后重新执行当前指令，如缺页故障。
- **陷阱（Trap）**：有意触发，处理后执行下一条指令，如系统调用。
- **终止（Abort）**：严重错误，通常无法恢复当前程序。

## 3. 中断处理过程

1. 处理器响应中断，切换到相应运行模式，并按体系结构和中断优先级暂时屏蔽相关中断。
2. 保存程序计数器、程序状态字等硬件现场。
3. 根据中断向量找到相应处理程序入口。
4. 保存通用寄存器，执行中断服务程序。
5. 恢复现场并执行中断返回。

其中，切换运行模式、保存断点并找到处理程序入口通常由硬件完成；保存通用寄存器和执行具体服务通常由操作系统完成。保存关键现场后，系统也可以按优先级允许更高优先级中断嵌套。

## 4. 系统调用

系统调用是应用程序请求操作系统内核服务的程序接口，常见类型包括设备管理、文件管理、进程控制、进程通信和内存管理。

典型调用过程为：

1. 用户程序准备系统调用号和参数。
2. 执行陷入指令，由用户态切换到内核态。
3. 内核根据调用号执行相应服务例程。
4. 内核写回返回值并恢复用户程序现场。
5. 执行中断返回，回到用户态继续运行。

用户态进入内核态的原因包括执行系统调用、发生异常和响应外部中断。运行模式的切换由处理器完成，不能由用户程序直接修改状态寄存器实现。

## 5. 程序的运行过程

源程序通常依次经过预处理、编译、汇编和链接形成可执行文件，再由装入程序把它装入内存。程序运行时，进程的典型地址空间包括：

- 代码段：保存可执行指令，通常只读。
- 数据段：保存已初始化和未初始化的全局数据。
- 堆：用于动态分配，通常由低地址向高地址增长。
- 共享库和内存映射区域。
- 栈：保存函数调用现场和局部变量，通常由高地址向低地址增长。

进程使用虚拟地址空间，地址转换机构负责把虚拟地址映射为物理地址，并实现进程隔离与保护。

::: warning 易错点
访管指令在用户态执行，随后处理器进入内核态；真正的特权操作由系统调用处理程序在内核态完成。
:::
