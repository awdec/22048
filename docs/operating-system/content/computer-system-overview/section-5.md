<h1><center>第五节 操作系统引导</center></h1>

## 1. 操作系统引导

操作系统引导（boot）是计算机从加电或复位开始，经过固件和引导程序逐步装入操作系统内核，直到内核完成初始化、启动系统服务并进入可用状态的过程。

主存通常是易失性存储器，断电后其中的程序和数据会消失。因此，计算机不能在开机时直接从主存运行内核，必须先执行保存在 ROM 或闪存等非易失性存储器中的固件，再从磁盘、固态硬盘或网络等启动设备装入操作系统。

### 1.1 固件与复位入口

CPU 加电或复位后，各寄存器进入规定状态，并从体系结构规定的复位入口开始取指。该位置指向或能够转入固件代码。

固件主要完成：

- 检查和初始化处理器、内存及必要的 I/O 硬件。
- 建立启动阶段所需的基本运行环境。
- 根据启动顺序或用户配置选择启动设备。
- 找到并启动下一阶段的引导程序。

固件最先获得处理器控制权，但它不是操作系统内核。固件只负责早期硬件初始化和建立启动链，完整的进程、内存、文件与设备管理要在内核运行后才建立。

### 1.2 引导程序

引导程序（boot loader）负责定位操作系统内核，把内核映像和必要的启动数据装入主存，准备启动参数，并最终把处理器控制权移交给内核。

引导程序经常分为多个阶段，原因包括：

- 固件最初能够直接装入的代码大小和功能有限。
- 早期阶段只能使用固件服务或少量自带驱动访问设备。
- 后续阶段需要识别分区和文件系统、读取配置、显示系统选择菜单，并装入较大的内核映像。

引导程序还可能装入初始内存文件系统、硬件描述信息等辅助数据。引导程序能够选择和装入内核，但不负责替代内核长期管理系统资源。

### 1.3 内核装入与初始化

引导程序把内核及启动参数装入合适的内存位置后，设置内核所需的初始执行环境，并跳转到内核入口。此时引导程序的主要任务结束，内核开始接管系统。

内核通常依次完成以下工作：

1. 建立处理器运行环境和异常、中断处理机制。
2. 初始化物理内存管理、地址转换和内核内存分配器。
3. 初始化时钟、调度器和进程管理数据结构。
4. 探测硬件并初始化必要的设备驱动程序。
5. 建立存储与文件系统环境，挂载根文件系统。
6. 创建首个用户态进程或系统管理进程。
7. 启动后台服务、登录程序或图形环境，使系统进入可用状态。

不同系统的具体次序可能交叉或有所调整，但必须先建立底层内核机制，才能安全地运行一般用户程序。

### 1.4 典型引导流程

```mermaid
flowchart LR
    A["CPU 加电或复位"] --> B["执行固件"]
    B --> C["硬件检查与初始化"]
    C --> D["选择启动设备"]
    D --> E["装入并执行引导程序"]
    E --> F["装入内核与启动参数"]
    F --> G["内核初始化"]
    G --> H["挂载根文件系统"]
    H --> I["创建首个用户态进程"]
    I --> J["启动系统服务并进入可用状态"]
```

用文字概括就是：

1. CPU 从复位入口执行非易失性固件。
2. 固件初始化基本硬件并选择启动设备。
3. 固件装入引导程序，或直接启动固件能够识别的引导程序。
4. 引导程序读取配置，装入所选操作系统的内核及辅助数据。
5. 引导程序跳转到内核入口，内核接管处理器。
6. 内核初始化中断、内存、调度、设备和文件系统。
7. 内核创建首个用户态进程并启动系统服务。

::: warning 易错点
计算机启动时最先执行的是固件，不是操作系统内核；把内核映像读入主存也不表示系统已经可用，内核还必须完成初始化、挂载根文件系统并启动必要的用户态进程和系统服务。
:::
