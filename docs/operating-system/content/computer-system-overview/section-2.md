<h1><center>第二节 操作系统的发展历程</center></h1>

计算机系统的发展始终围绕两个基本目标展开：提高处理机和其他资源的利用率，以及为用户提供更方便、更及时的服务。随着硬件和应用需求变化，操作系统经历了手工操作、批处理、分时、实时等阶段，并进一步发展出网络、分布式和微机操作系统。

## 1. 手工操作阶段

早期计算机没有操作系统，用户直接操作机器。程序员需要人工完成程序和数据的装入、启动运行以及结果输出，并在计算机旁等待整个执行过程结束。

该阶段具有以下特点：

- 用户独占整个计算机，资源由用户直接控制。
- 一次只能运行一个程序，程序之间没有自动转换机制。
- 人工操作时间远长于处理机执行时间，处理机经常等待用户操作。
- 程序设计、运行和调试都直接依赖具体硬件，使用困难。

这一阶段的主要矛盾是人工操作速度与计算机处理速度之间的矛盾，即“人机矛盾”。提高系统利用率首先需要减少人工干预，并使作业能够自动连续执行。

## 2. 批处理阶段

批处理是把一批作业集中起来，由系统自动依次处理。用户提交作业后不能直接干预其运行，系统则通过监督程序或早期操作系统自动完成作业之间的转换。

### 2.1 脱机输入/输出

为了减少主机等待慢速输入/输出设备的时间，可以由外围机预先把程序和数据输入磁带等高速介质，主机再从高速介质读取；输出也可以先写入高速介质，再由外围机送往低速输出设备。

脱机输入/输出使低速设备的操作与主机计算分离，缓解了处理机与 I/O 设备之间的速度矛盾，但它本身还不是完整的操作系统。

### 2.2 单道批处理系统

单道批处理系统把作业成批送入计算机，由监督程序自动按顺序装入和运行，减少了作业转换过程中的人工干预。

- 优点：作业能够自动连续执行，提高了相邻作业转换的效率。
- 缺点：内存中始终只有一道作业；该作业等待 I/O 时，没有其他作业可以使用处理机，处理机和内存利用率仍然较低。

### 2.3 多道批处理系统

多道程序设计允许内存中同时存放多道相互独立的作业。当一道作业因 I/O 或其他事件暂停时，操作系统选择另一道就绪作业占用处理机，使处理机与多台设备尽可能并行工作。

多道批处理系统的主要特征是：

- 多道：内存中同时驻留多道程序。
- 宏观并行：多道程序在同一时间段内都在向前推进。
- 微观串行：在单处理器上，同一时刻只能执行其中一道程序。

其主要优点是提高资源利用率和系统吞吐量；主要缺点是用户提交作业后难以交互，作业响应时间通常较长，而且作业执行顺序和完成时间不容易预测。

多道程序设计需要操作系统完成内存管理、处理机调度、I/O 管理和资源保护，是现代操作系统并发管理的重要基础。

## 3. 分时操作系统

分时操作系统建立在多道程序和交互式终端基础上。系统把处理机时间划分为较短的时间片，按照一定策略轮流为多个终端用户或进程服务。由于切换速度很快，每个用户都感觉自己在独占计算机。

分时系统具有四个典型特征：

- 同时性：多个终端用户可以在同一时间段内共同使用系统。
- 交互性：用户能够通过终端输入命令，并及时得到系统反馈。
- 独立性：各用户彼此独立地操作，感觉不到其他用户的存在。
- 及时性：系统能够在用户可接受的时间内响应请求。

分时系统的主要目标是改善人机交互和缩短响应时间，而不是单纯追求作业吞吐量。它通常采用可抢占调度和时间片轮转，防止某个计算密集型进程长期独占处理机。

分时系统只保证一般意义上的及时响应，通常不能保证关键任务必定在严格截止时间之前完成。

## 4. 实时操作系统

实时操作系统能够在规定时间内响应外部事件，并在截止时间要求内完成相应处理。实时系统强调结果的正确性和产生结果的时间，两者缺一不可。

### 4.1 实时系统的应用

- 实时控制系统：控制工业设备、交通工具、航空航天设备等，通常直接影响物理过程。
- 实时信息处理系统：及时查询、处理和更新票务、金融、通信等信息。

### 4.2 硬实时与软实时

- 硬实时系统：关键任务必须在截止时间前完成，错过截止时间可能造成系统失败或严重后果，例如汽车安全气囊控制。
- 软实时系统：允许个别任务偶尔错过截止时间，但服务质量会下降，例如部分音视频处理任务。

实时操作系统通常重视及时性、可预测性和可靠性。它需要采用优先级、中断、定时器和实时调度等机制，保证关键任务具有可分析的最坏响应时间。

::: tip 分时与实时
分时系统强调让多个交互用户得到较快的平均响应；实时系统强调任务在规定时限内完成。响应“较快”不等于能够保证截止时间。
:::

## 5. 网络操作系统和分布式操作系统

### 5.1 网络操作系统

网络操作系统使网络中的各台计算机能够通信并共享文件、打印机、计算能力等资源。各计算机通常拥有自己的操作系统和相对独立的资源管理机制，用户往往需要知道资源位于哪台计算机，并显式进行远程访问。

网络操作系统的主要功能包括网络通信、远程登录、网络文件服务、资源共享和访问控制。其重点是把原本相互独立的计算机连接起来并提供网络服务。

### 5.2 分布式操作系统

分布式操作系统统一管理分布在多台计算机上的资源和任务，力图向用户提供一个整体、透明的系统视图。用户提出任务时通常不必明确指定由哪台计算机执行，也不必关心数据的具体物理位置。

分布式操作系统强调：

- 分布性：资源和计算活动分散在多台计算机上。
- 透明性：尽量隐藏资源位置、迁移和复制等分布细节。
- 协同性：多个结点共同完成任务并进行统一协调。
- 自治性与容错性：部分结点具有独立处理能力，单个结点故障不应必然导致整个系统失效。

### 5.3 二者的区别

| 对比项 | 网络操作系统 | 分布式操作系统 |
| --- | --- | --- |
| 系统视图 | 多台相互连接但相对独立的计算机 | 对外尽量表现为一个统一系统 |
| 资源位置 | 用户通常知道并显式指定远程资源 | 系统尽量隐藏资源的物理位置 |
| 资源管理 | 各结点主要管理本地资源 | 多个结点之间进行统一或协同管理 |
| 主要目标 | 网络通信和资源共享 | 透明地协同使用分布式资源 |

网络操作系统与分布式操作系统都建立在计算机网络之上，但“能够联网”不等于“构成分布式操作系统”。

## 6. 微机操作系统

微机操作系统是运行在个人计算机等微型计算机上的操作系统。随着微处理器性能和存储容量提高，它经历了从单用户单任务到单用户多任务，再到支持多用户、多任务、网络和图形界面的发展过程。

### 6.1 单用户单任务操作系统

一次只允许一个用户运行一个任务，系统结构简单、资源需求少，但不能让多个应用程序并发执行。早期微机操作系统多采用这种形式。

### 6.2 单用户多任务操作系统

允许一个用户同时运行多个应用程序，操作系统通过进程调度、内存保护和图形界面等机制为用户提供并发工作环境，是个人计算机中常见的使用方式。

### 6.3 多用户多任务操作系统

允许多个用户通过不同终端或网络会话同时使用系统，并让多个任务并发运行。系统需要提供用户身份管理、资源隔离、访问控制和公平调度。

现代微机操作系统通常同时支持多任务、网络通信、图形交互、多核处理和设备即插即用。微机操作系统描述的是面向微型计算机的平台类别，不等同于“只能供一个用户运行一个任务”。

| 发展阶段 | 主要目标 | 典型特点 |
| --- | --- | --- |
| 手工操作 | 直接使用硬件 | 人工装入和控制，人机矛盾突出 |
| 单道批处理 | 减少人工干预 | 自动顺序执行，I/O 时处理机空闲 |
| 多道批处理 | 提高利用率和吞吐量 | 多道程序并发，缺少交互 |
| 分时系统 | 改善交互和响应 | 时间片、多个终端用户 |
| 实时系统 | 满足时间约束 | 截止时间、可预测性和可靠性 |
| 网络与分布式系统 | 扩大资源共享和协作范围 | 网络服务或统一透明的分布式视图 |
| 微机操作系统 | 服务个人计算平台 | 从单任务发展为多任务、网络化和图形化 |

::: warning 易错点
多道批处理系统和分时系统都采用多道程序技术：前者主要追求资源利用率和吞吐量，后者主要追求交互性和响应时间。普通分时系统不能替代需要严格截止时间保证的硬实时系统。
:::
