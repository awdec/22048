<h1><center>第四节 操作系统结构</center></h1>

## 1. 分层结构

操作系统被划分为若干层，每层只使用更低层提供的服务，并向更高层隐藏实现细节。

- **优点**：结构清晰，便于调试、验证和扩充。
- **缺点**：层次划分困难，跨层调用可能增加开销。

## 2. 模块化结构

系统按功能划分为具有清晰接口的模块，各模块可以相互调用。

- **优点**：提高设计的正确性、可理解性和可维护性，便于扩展功能。
- **缺点**：模块之间可能形成复杂依赖，接口定义也会影响系统效率。

## 3. 宏内核

宏内核把进程管理、内存管理、文件系统和设备驱动等主要功能都放在内核态，各模块可直接调用。

- **优点**：调用路径短，运行效率高。
- **缺点**：内核庞大，模块之间缺乏隔离，局部故障可能影响整个系统。

## 4. 微内核

微内核只在内核中保留最基本的功能，如进程通信、基本调度和低级内存管理，其他服务以用户态进程形式运行。

- **优点**：内核小，可靠性、安全性和可扩展性较好，便于移植和分布式处理。
- **缺点**：服务之间频繁通信和运行模式切换会产生额外开销。

## 5. 外核

外核只负责安全地分配、回收和保护硬件资源，把较多资源管理策略交给用户态的库操作系统。

- **优点**：减少抽象层次，应用可按需定制资源管理方式。
- **缺点**：系统设计、应用编程和兼容性处理更复杂。

::: tip 对比重点
宏内核的主要服务运行在内核态；微内核把许多服务移到用户态；外核则进一步把更多资源管理策略交给用户态库操作系统。
:::
