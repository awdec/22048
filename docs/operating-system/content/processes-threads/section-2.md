<h1><center>第二节 CPU 调度</center></h1>

CPU 调度决定“哪个就绪进程（或线程）在何时获得处理器”。它直接影响系统的吞吐量、响应速度和公平性。

## 1. 调度的概念

调度是操作系统按一定策略分配处理器、内存和 I/O 等资源的过程。按作用层次可分为：

| 层次 | 又称 | 主要任务 | 特点 |
| --- | --- | --- | --- |
| 高级调度 | 作业调度 | 从外存后备队列选择作业进入内存 | 决定系统并发度，频率较低 |
| 中级调度 | 内存调度 | 挂起或激活进程，调整内存中的进程数量 | 缓解内存紧张，提高内存利用率 |
| 低级调度 | 进程 / CPU 调度 | 从就绪队列选择执行实体占用处理器 | 发生最频繁，直接决定下一个运行者 |

本节的 CPU 调度通常指低级调度。现代系统的实际调度对象往往是内核级线程；若进程只有一个线程，则可将其视为调度对象。

调度可分为两类：

- **非抢占式调度**：一旦进程获得 CPU，除非它主动阻塞或终止，否则继续运行。
- **抢占式调度**：时间片用完或更高优先级进程到达时，系统可收回 CPU 并重新调度。

## 2. 进程调度

进程调度从就绪队列中选择一个进程（或线程）投入运行。调度程序通常在以下时机被触发：

1. 运行进程终止。
2. 运行进程因 I/O 请求、等待资源等原因进入阻塞态。
3. I/O 完成等事件使阻塞进程转入就绪态。
4. 时钟中断使时间片用完，或有更高优先级进程到达。

前两种情形中当前进程主动放弃 CPU；后两种情形是否发生调度和抢占取决于系统策略。抢占式调度响应更快，适合分时和实时场景，但会增加切换开销。

即使产生了调度请求，内核在以下关键阶段通常也不能立即进行进程切换：

- 正在处理中断，且中断现场尚未保存或恢复完毕。
- 正在执行必须保持原子性的操作。
- 正在访问需要互斥保护的内核临界数据结构。

内核会先记录调度请求，待退出关键阶段、到达安全的调度点后再执行切换。处于普通用户态执行、系统调用完成返回前或中断处理结束时，若调度条件满足，则可以进行调度。

调度相关的主要组成如下：

- **调度器**：维护就绪队列，依照调度算法选出下一个运行实体。
- **分派程序**：执行上下文切换，将 CPU 控制权交给被选中的实体。
- **闲逛进程**：没有普通就绪任务时运行；它不参与普通任务竞争，常用于降低功耗或等待中断。

## 3. 调度的目标

不同系统的调度目标不同：批处理系统重视吞吐量和周转时间，交互式系统重视响应时间，实时系统重视在截止时间前完成任务。

| 指标 | 含义 | 一般目标 |
| --- | --- | --- |
| CPU 利用率 | CPU 忙于有效工作的比例 | 高 |
| 吞吐量 | 单位时间完成的作业数 | 高 |
| 周转时间 | 完成时间 − 到达时间 | 低 |
| 带权周转时间 | 周转时间 ÷ 服务时间 | 低 |
| 等待时间 | 在就绪队列中的累计等待时间 | 低 |
| 响应时间 | 首次得到 CPU 的时间 − 到达时间 | 低 |
| 公平性 | 进程获得服务的合理程度 | 避免长期饥饿 |

$$
\text{周转时间}=\text{完成时间}-\text{到达时间}
$$

$$
\text{带权周转时间}=\frac{\text{周转时间}}{\text{服务时间}}
$$

$$
\text{等待时间}=\text{周转时间}-\text{服务时间}
$$

上式只适用于不计 I/O 或其他阻塞时间的简化调度模型。一般情况下，等待时间是进程在就绪队列中的累计时间，不能直接用“周转时间减服务时间”计算。

一个调度策略通常无法同时使所有指标最优，因此需要根据系统类型权衡。例如，过小的时间片可改善响应性，却会使上下文切换过于频繁。

## 4. 进程切换

进程切换（上下文切换）是 CPU 从一个执行实体转而执行另一个执行实体的过程。内核通常需要：

1. 保存当前实体的程序计数器、寄存器、栈指针等处理器现场。
2. 更新其 PCB 或 TCB 中的状态和队列位置。
3. 选择下一个就绪实体，必要时切换页表或地址空间。
4. 恢复下一个实体的上下文，并从保存的位置继续执行。

上下文切换本身不推进任何用户任务，还会影响高速缓存和 TLB 的有效内容，因此属于调度开销。同一进程内的线程切换通常不必更换地址空间，代价一般小于进程切换。

::: tip 区分模式切换与进程切换
用户态进入内核态（如执行系统调用）是模式切换，不一定更换执行实体；进程切换一定需要内核参与，但不一定由一次系统调用直接引起。
:::

## 5. CPU 调度算法

### 5.1 先来先服务（FCFS）

按进程到达就绪队列的先后顺序调度，通常为非抢占式。实现简单，但长作业可能使短作业长时间等待，形成**护航效应**。

### 5.2 短作业优先（SJF）与最短剩余时间优先（SRTF）

SJF 选择估计服务时间最短的作业，属于非抢占式算法，通常可获得较小的平均等待时间；但服务时间难以准确预测，长作业可能饥饿。其抢占式版本 SRTF 在新到达进程的服务时间短于当前剩余时间时发生抢占。

### 5.3 高响应比优先（HRRN）

HRRN 每次选择响应比最高的作业：

$$
R_p=\frac{\text{等待时间}+\text{服务时间}}{\text{服务时间}}
=1+\frac{\text{等待时间}}{\text{服务时间}}.
$$

等待时间越长，响应比越高，因此它在照顾短作业的同时能缓解长作业饥饿；通常采用非抢占方式。

### 5.4 时间片轮转（RR）

每个就绪进程最多运行一个时间片；时间片结束且尚未完成时，进程被放回就绪队列尾部。RR 公平且响应较好，适用于分时系统。时间片过大时接近 FCFS，过小时切换开销过高。

### 5.5 优先级调度与多级反馈队列（MLFQ）

优先级调度总是优先选择高优先级进程，可采用抢占或非抢占方式。低优先级进程可能饥饿，可用**老化**逐渐提升等待过久进程的优先级。

多级反馈队列为不同优先级设置不同时间片：新进程先进入高优先级、短时间片队列；若未完成则降到较低优先级队列。它能较好兼顾交互型短任务和计算型长任务，但参数设计较复杂。

::: warning 计算题
画甘特图前，必须明确到达时间、服务时间、算法是否抢占、时间片大小及同优先级的破平规则。再计算完成、周转、等待和响应时间。
:::

## 6. 多处理机调度

多处理机调度需要在提高并行度、维持负载均衡和利用缓存局部性之间权衡。

- **对称多处理（SMP）**：多个处理器地位相同，都可执行内核代码并参与调度，是现代通用系统的常见形式。
- **非对称多处理（AMP）**：一个主处理器负责调度等系统任务，其他处理器执行分配的工作，管理较简单但主处理器可能成为瓶颈。

就绪队列组织有两种典型方式：

| 方式 | 优点 | 挑战 |
| --- | --- | --- |
| 公共就绪队列 | 所有处理器都可取任务，天然利于均衡负载 | 队列锁竞争较明显 |
| 每处理器私有队列 | 本地访问快，缓存局部性好 | 可能负载不均，需要任务迁移 |

**处理器亲和性**是尽量让任务继续在原处理器上运行，以保留其高速缓存内容；**负载均衡**则通过迁移任务避免部分处理器空闲。实际系统需要在两者之间折中，并在必要时迁移任务。
