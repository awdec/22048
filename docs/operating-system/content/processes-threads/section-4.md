<h1><center>第四节 死锁</center></h1>

## 1. 死锁的概念

多个进程因竞争资源而相互等待，若无外力干预将永远无法推进，称为死锁。

死锁与饥饿不同：死锁常涉及一组进程形成循环等待；饥饿是某进程长期得不到服务，其他进程仍可推进。

## 2. 死锁产生的原因

死锁通常由系统资源竞争和进程推进顺序不当引起。不可剥夺资源数量不足时，多个进程各自占有部分资源并继续请求其他资源，就可能形成相互等待。

## 3. 死锁的四个必要条件

1. **互斥条件**：资源在一段时间内只能由一个进程使用。
2. **不剥夺条件**：进程获得的资源在使用完之前不能被其他进程强行夺走。
3. **请求并保持条件**：进程保持已有资源的同时继续请求新资源。
4. **循环等待条件**：存在进程—资源的循环等待链。

四个条件同时成立才可能发生死锁；破坏任意一个条件即可预防死锁。

## 4. 死锁处理策略

### 4.1 预防死锁

通过制度破坏死锁的必要条件，如一次性申请全部资源、允许剥夺资源，或要求所有进程按统一编号顺序申请资源。预防方法限制较强，资源利用率和系统并发度可能较低。

### 4.2 避免死锁

系统在每次分配资源前检查分配后是否仍处于安全状态。银行家算法需要掌握各进程的最大需求、已分配资源和系统可用资源。

安全状态表示存在一个安全序列，使每个进程都能依次获得所需资源并完成。安全状态一定没有死锁；不安全状态不等于已经死锁，但系统有可能进入死锁。

### 4.3 死锁检测

系统允许死锁发生，并定期使用资源分配图或死锁检测算法判断哪些进程已经陷入死锁。检测需要记录当前可用资源、各进程已分配资源和剩余请求。

### 4.4 死锁解除

检测到死锁后，可以采用以下方法解除：

- 撤销一个或多个死锁进程。
- 从部分进程处剥夺资源并分配给其他进程。
- 让进程回退到先前的安全状态后重新执行。

选择牺牲进程时，应综合考虑进程优先级、已执行时间、占用资源和回退代价。

## 5. 资源分配图

- 进程指向资源的有向边表示请求边。
- 资源实例指向进程的有向边表示分配边。

每类资源只有一个实例时，资源分配图中有环是死锁的充要条件；存在多实例资源时，图中有环只表示可能发生死锁。

::: warning 易错点
银行家算法不是检测已经发生的死锁，而是在分配前进行安全性检查，避免系统进入不安全状态。
:::
