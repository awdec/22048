<h1><center>第一节 I/O管理概述</center></h1>

## 1. I/O 管理的功能

I/O 管理负责控制输入/输出设备、协调设备与处理机的速度差异，并向应用程序提供统一、方便和安全的设备访问方式。其主要任务包括：

- 隐藏设备的物理细节和控制方式。
- 提供统一的 I/O 接口。
- 完成设备分配、回收和调度。
- 使用缓冲、缓存等技术提高设备利用率。
- 处理设备中断、故障和访问保护。

## 2. I/O 设备分类

- 按使用特性：人机交互设备、存储设备、网络通信设备。
- 按信息交换单位：字符设备、块设备。
- 按共享属性：独占设备、共享设备、虚拟设备。
- 按传输速率：低速设备、中速设备、高速设备。

块设备通常以固定大小的数据块传输并支持随机访问；字符设备以字符流方式顺序传输。

## 3. I/O 控制器

设备控制器位于 CPU 与设备之间，负责接收 CPU 命令并控制设备完成具体操作，通常包含：

- 数据寄存器。
- 状态寄存器。
- 控制寄存器。
- 与 CPU 和设备连接的接口逻辑。

CPU 可以通过独立编址或内存映射 I/O 访问控制器寄存器。内存映射 I/O 把设备寄存器映射到统一的地址空间，可以使用普通访存指令访问。

## 4. I/O 控制方式

### 4.1 程序直接控制

CPU 发出 I/O 命令后不断查询设备状态，数据传输也由 CPU 完成。实现简单，但忙等待会浪费大量处理器时间。

### 4.2 中断驱动

CPU 发出命令后可以运行其他程序，设备准备好数据或完成操作后通过中断通知 CPU。它减少了轮询，但每次传输一个字或较小单位时仍需 CPU 参与。

### 4.3 DMA

DMA 控制器在设备与内存之间成块传输数据。CPU 负责设置内存地址、传输方向和数据量，整块传输完成后 DMA 再通过中断通知 CPU。

DMA 降低了 CPU 干预频率，但会与 CPU 竞争内存总线，并非完全不需要 CPU。

## 5. I/O 软件层次

I/O 软件通常自上而下分为：

1. 用户层 I/O 软件。
2. 设备独立性软件。
3. 设备驱动程序。
4. 中断处理程序。
5. 设备控制器和硬件设备。

上层负责提供统一抽象，下层逐步处理与具体设备相关的控制细节。

## 6. I/O 应用程序接口

- 字符设备接口按字节流读写，通常不支持任意位置访问。
- 块设备接口以固定大小的数据块为单位，可以支持随机访问。
- 网络设备通常通过套接字接口收发数据。
- 阻塞 I/O 在操作暂时不能完成时使调用进程等待。
- 非阻塞 I/O 立即返回当前结果或“暂不可用”状态，调用者可以稍后重试。

::: warning 易错点
DMA 负责设备与内存之间的成块传输，但 CPU 仍需初始化 DMA，并在传输完成后处理中断。
:::
