<h1><center>第二节 设备独立性软件</center></h1>

## 1. 设备独立性软件

### 1.1 设备独立性的含义

设备独立性是指应用程序通过逻辑设备名和统一操作使用设备，而不必了解设备的物理特性、物理编号和具体控制方法。更换同类设备、调整设备分配或重定向 I/O 请求时，应用程序通常不需要修改。

设备独立性软件位于用户层 I/O 软件与设备驱动程序之间，负责处理各类设备共有的功能，使硬件相关细节尽量局限在驱动程序中。

其主要功能包括：

- 向应用程序提供统一的设备访问接口。
- 完成逻辑设备名到物理设备名的映射。
- 对设备进行保护、分配、回收和调度。
- 提供缓冲和 SPOOLing 等通用服务。
- 选择相应的设备驱动程序，并向其传递规范化的 I/O 请求。
- 统一报告 I/O 完成状态和错误信息。

### 1.2 逻辑设备名与物理设备名

应用程序使用逻辑设备名提出请求，操作系统通过逻辑设备表（LUT）将其转换为具体的物理设备，并找到相应的驱动程序入口。

逻辑设备表通常可以记录：

- 逻辑设备名。
- 物理设备标识。
- 设备类型和当前状态。
- 对应设备驱动程序的入口地址或引用。

逻辑设备表既可以由整个系统共用，也可以按用户或进程设置。前者便于统一管理，后者能够让不同用户把相同逻辑名映射到不同设备。

::: tip 核心关系
应用程序面向逻辑设备，设备驱动程序面向物理设备；设备独立性软件负责在二者之间进行映射和衔接。
:::

## 2. 缓冲区管理

### 2.1 设置缓冲区的目的

- 缓和 CPU、进程与设备之间的速度不匹配。
- 减少设备对 CPU 的中断频率。
- 提高 CPU、进程与设备之间的并行程度。
- 匹配生产者与消费者不同的数据传输粒度。
- 减少因数据到达时机不同而造成的丢失或停顿。

缓冲只能缓和速度差异，不能从根本上消除生产者与消费者长期平均速度不匹配的问题。

### 2.2 单缓冲与双缓冲

单缓冲在设备与用户进程之间设置一个系统缓冲区。输入时，设备先把数据送入缓冲区，再由系统把数据传送到用户工作区。缓冲区腾空后才能接收下一块数据，因此设备输入与进程处理只能部分重叠。

双缓冲设置两个缓冲区。当设备向一个缓冲区输入时，进程可以处理另一个缓冲区中的数据；两者交替使用，可以获得更充分的并行。双机通信时，如果发送端和接收端都只设置一个缓冲区，双方同时向对方发送数据可能因缓冲区被占用而相互等待，使用双缓冲可以改善这一问题。

### 2.3 循环缓冲与缓冲池

循环缓冲由多个大小相同的缓冲区首尾相接，生产者和消费者分别按照指针依次存入和取出数据。使用时必须正确区分缓冲区的空、满状态，并对共享指针进行同步保护。

缓冲池由系统统一管理多个缓冲区，适合多个进程和设备共享。典型缓冲池包含：

- 空缓冲队列：保存尚未使用的缓冲区。
- 输入队列：保存已经装入输入数据、等待进程提取的缓冲区。
- 输出队列：保存已经装入输出数据、等待设备提取的缓冲区。

根据工作方向，还可设置收容输入、提取输入、收容输出和提取输出四类工作缓冲区。缓冲区在各队列和工作状态之间转换时，需要使用互斥与同步机制保证一致性。

## 3. 设备分配与回收

### 3.1 设备分配应考虑的因素

设备分配策略需要综合考虑：

- 设备的固有属性：独占设备、共享设备或虚拟设备。
- 分配算法：先来先服务、优先级等。
- 分配安全性：是否允许进程在持有部分设备时继续申请其他设备。

独占设备同一时刻只能分配给一个进程；共享设备可以交错处理多个进程的请求；虚拟设备利用 SPOOLing 等技术在逻辑上供多个进程同时使用。

### 3.2 设备分配的数据结构

操作系统通常使用下列数据结构记录设备及其连接关系。

| 数据结构 | 主要记录内容 |
| --- | --- |
| 系统设备表（SDT） | 汇总系统中全部设备，并给出相应设备控制信息的入口 |
| 设备控制表（DCT） | 设备标识、类型、状态、占用者、等待队列以及所连接的控制器 |
| 控制器控制信息 | 记录控制器状态、所连接的设备以及等待使用控制器的请求 |
| I/O 请求控制块和请求队列 | 记录操作类型、数据位置、数据量、请求进程和完成状态，并组织等待请求 |

这些结构记录“进程—I/O 请求—设备—控制器”之间的关系，为分配、阻塞、唤醒和回收提供依据。不同操作系统的数据结构名称和具体组织方式可能不同。

### 3.3 设备分配过程

独占设备的一般分配过程如下：

1. 根据逻辑设备名和设备类型查找 SDT，选择合适的物理设备及驱动程序。
2. 检查设备状态和访问权限；若独占设备正忙，则把请求加入设备等待队列。
3. 设备可用时进行安全性检查，更新 DCT 中的占用者和设备状态。
4. 检查设备控制器及相关 I/O 通路是否可用；暂时不能启动时，将请求排队等待。
5. 建立占用关系，把规范化 I/O 请求交给设备驱动程序启动。

逻辑设备映射使系统可以在多个同类设备中选择可用设备，避免应用程序固定依赖某个物理编号。

### 3.4 分配方式与回收

- 静态分配：进程运行前一次获得所需全部设备，结束后统一释放。它可以防止设备分配死锁，但设备利用率较低。
- 动态分配：进程运行过程中按需申请和释放设备，利用率较高，但申请多个独占设备时可能形成死锁。

I/O 完成或进程主动释放设备后，系统应解除相应控制器和设备的占用关系，更新控制信息，并按照分配策略唤醒等待进程。异常终止进程所占用的设备也必须由操作系统回收。

## 4. SPOOLing 技术（假脱机技术）

SPOOLing 利用可共享的高速外存模拟脱机输入/输出，使独占设备转化为可由多个进程共享的虚拟设备。它以多道程序设计为基础，用进程模拟外围控制机完成数据预输入和缓输出。

### 4.1 SPOOLing 系统的组成

- 输入井和输出井：位于磁盘等外存中，分别暂存输入数据和输出作业。
- 输入缓冲区和输出缓冲区：位于内存中，缓和内存与外存、外存与设备之间的速度差异。
- 输入进程和输出进程：模拟脱机输入、输出过程，负责在设备、内存缓冲区和井之间传送数据。
- 井管理程序：管理井中作业的组织、排队、调度和完成状态。

### 4.2 SPOOLing 的工作过程

以打印为例：用户进程不直接占用打印机，而是向逻辑打印设备提交打印请求。系统把待打印数据经内存输出缓冲写入磁盘输出井，并为该请求建立打印任务。打印进程按照调度策略从输出井选择任务，再经输出缓冲逐步送往物理打印机。

用户进程通常在打印数据进入输出井后即可继续运行，无须等待整份文件真正打印完。

### 4.3 SPOOLing 的特点

- 提高 I/O 速度：把对低速独占设备的直接访问转化为对高速外存的访问。
- 将独占设备改造为虚拟设备：多个进程可以并发提交请求。
- 实现设备的逻辑共享：物理设备仍然按照调度次序逐个处理任务。

::: warning 易错点
输入井和输出井位于外存，输入缓冲区和输出缓冲区位于内存。SPOOLing 使独占设备在逻辑上可共享，但不会把一台物理设备变成多台能够并行工作的物理设备。
:::

## 5. 设备驱动程序接口

设备驱动程序是设备独立性软件与设备控制器之间的软件层。它与具体设备和控制器密切相关，通常运行在内核态，把上层提交的抽象 I/O 请求转换为硬件能够执行的命令。

### 5.1 统一驱动接口

操作系统规定统一的驱动程序接口，使设备独立性软件可以用一致方式调用不同设备。常见操作包括：

- 初始化设备。
- 打开与关闭设备。
- 读、写和定位。
- 查询设备状态。
- 执行设备专用控制操作。
- 处理完成状态和错误。

统一接口只规定上层如何调用驱动，并不意味着所有设备都支持完全相同的操作。例如，字符设备通常不支持任意定位，设备专用参数可以通过控制操作设置。

一个规范化 I/O 请求通常包含操作类型、逻辑或物理设备标识、内存地址、数据长度、起始位置、完成状态等信息。

### 5.2 驱动程序的主要工作

1. 检查请求参数，并把逻辑操作转换为设备能够识别的命令。
2. 检查设备状态；设备忙时将请求排队。
3. 设置控制器寄存器和 DMA 参数，启动 I/O 操作。
4. 与中断处理程序协作，取得完成状态并处理设备错误。
5. 更新请求结果，释放相关资源，并通知设备独立性软件或唤醒等待进程。

中断处理程序负责快速响应设备中断、保存必要现场和确认中断原因；驱动程序负责较完整的设备控制逻辑。两者关系密切，但职责不能混淆。

## 6. I/O 操作举例

### 6.1 阻塞式磁盘读

假设应用程序需要从磁盘读取一个必须访问设备的数据块，系统使用 DMA，典型过程如下：

1. 应用程序调用读接口，用户层库函数通过系统调用进入内核。
2. 设备独立性软件检查文件描述符、访问权限、用户缓冲区和请求参数。
3. 系统分配内核缓冲区，建立 I/O 请求，并根据逻辑设备映射选择磁盘驱动程序。
4. 驱动程序把逻辑块请求转换为控制器命令，设置 DMA 的内存地址、传送方向和长度，然后启动设备。
5. 请求不能立即完成，调用进程进入阻塞态，CPU 调度其他就绪进程运行。
6. 磁盘控制器准备数据，DMA 控制器在设备控制器与内存之间成块传送。
7. 传送完成后，控制器发出中断；中断处理程序读取状态并通知驱动程序完成后续处理。
8. 系统更新请求状态并唤醒原进程；原进程重新获得 CPU 后，内核把所需数据从内核缓冲区复制到用户缓冲区，随后读调用返回。

### 6.2 SPOOLing 打印

1. 应用程序向逻辑打印设备提交输出请求。
2. 设备独立性软件接受请求，经输出缓冲把打印数据写入磁盘输出井。
3. 用户进程在任务成功进入输出井后继续运行，不直接占用打印机。
4. 打印进程按调度策略选择任务，调用打印机驱动程序逐步输出。
5. 驱动程序控制打印机；每次设备完成或需要继续传送时，由中断处理程序和驱动程序共同推进任务。
6. 整个任务完成后，系统更新任务状态并回收输出井空间。

这两个例子说明：设备独立性软件负责通用策略和统一接口，设备驱动程序负责具体硬件控制，缓冲、DMA、中断和进程调度共同完成一次 I/O 操作。
