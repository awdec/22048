<h1><center>第二节 虚拟内存管理</center></h1>

虚拟内存只把程序当前需要的部分调入主存，使进程获得大于实际物理内存的逻辑地址空间。其核心问题是何时调页、分配多少页框、淘汰哪个页面以及如何控制缺页开销。

## 1. 虚拟内存的基本概念

### 1.1 局部性原理

虚拟内存建立在程序访问的局部性基础上：

- **时间局部性**：刚被访问的指令或数据，在不久后可能再次被访问，如循环变量和循环体。
- **空间局部性**：访问某地址后，其相邻地址可能很快被访问，如顺序执行的指令和数组元素。

因此，程序运行时只需让当前活跃的页面驻留内存，其余页面可以暂存在外存中。

### 1.2 虚拟内存的定义与特征

虚拟内存通过请求调入和页面置换，在逻辑上扩充主存容量，使进程看到的地址空间可以大于物理内存。

- **多次性**：程序分多次装入内存，不必一次全部装入。
- **对换性**：运行期间页面可在内存与外存之间换入、换出。
- **虚拟性**：用户看到的逻辑内存容量大于实际物理内存容量。

虚拟地址空间的上限主要受地址位数限制，可支持的实际虚拟存储容量还受外存容量和系统实现限制。虚拟内存并没有真正增加主存，频繁换页反而会显著降低性能。

### 1.3 虚拟内存的实现方式

请求分页是现代通用系统实现虚拟内存的主要方式：页面只有在被实际访问时才调入内存，内存不足时再置换其他页面。

## 2. 请求分页管理方式

### 2.1 请求分页页表

请求分页在基本分页页表项的基础上增加状态信息：

| 字段 | 作用 |
| --- | --- |
| 页框号 | 页面驻留时所在的物理页框 |
| 存在位 / 有效位 | 页面当前是否在内存中 |
| 访问位 | 页面近期是否被访问，为置换算法提供依据 |
| 修改位 / 脏位 | 页面调入后是否被修改，决定换出时是否写回 |
| 保护位 | 控制读、写、执行等访问权限 |
| 外存地址 | 页面不在内存时，其副本在外存中的位置 |

### 2.2 缺页异常

处理器访问合法虚拟页而页表项存在位为 0 时，产生**缺页异常**。其处理过程为：

1. 处理器保存当前指令状态并陷入内核。
2. 内核检查虚拟地址和访问权限是否合法；非法访问直接终止或向进程发送异常。
3. 查找空闲页框；若没有空闲页框，则选择一个牺牲页。
4. 若牺牲页为脏页，先把它写回外存。
5. 从外存读取所需页面；等待 I/O 时，当前进程通常阻塞，处理器可调度其他进程。
6. I/O 完成后更新页表、页框表及相关 TLB 项。
7. 恢复进程并重新执行引发缺页的指令。

缺页属于由当前指令触发、可恢复的内部异常；页面调入完成则由设备通过 I/O 中断通知处理器。

::: warning TLB 未命中与缺页
TLB 未命中只说明快表中没有对应页表项，内存页表中仍可能存在有效映射；只有合法页面当前不在内存时才发生缺页。
:::

### 2.3 请求分页与基本分页

基本分页要求进程全部页面装入内存后才能运行；请求分页只调入当前需要的页面，能够运行大于物理内存的程序，但需要缺页处理、页面置换和外存后备区支持。

## 3. 页框分配

### 3.1 驻留集与最小页框数

分配给一个进程的物理页框集合称为**驻留集**。进程获得的页框不能少于执行一条最复杂指令所需同时访问的页面数，否则该指令可能永远无法完成；具体最小值由指令格式、寻址方式和体系结构决定。

### 3.2 页框分配策略

- **平均分配**：将可用页框大致平均分给各进程，实现简单，但不考虑进程大小。
- **按比例分配**：根据进程逻辑页数或大小按比例分配页框。
- **优先级分配**：高优先级进程获得更多页框，也可从低优先级进程处取得页框。

若进程 $P_i$ 有 $s_i$ 个逻辑页，系统可分配页框总数为 $m$，按比例分配可写为：

$$
a_i=\left\lfloor\frac{s_i}{\sum_j s_j}\times m\right\rfloor,
$$

舍入后剩余页框需按规定继续分配，并保证每个进程不少于其最小页框数。

### 3.3 分配数量与置换范围

| 页框数量 | 置换范围 | 含义 |
| --- | --- | --- |
| 固定分配 | 局部置换 | 页框数不变，只从本进程页框中选择牺牲页 |
| 可变分配 | 局部置换 | 根据缺页情况增减页框，置换时先在本进程内选择 |
| 可变分配 | 全局置换 | 缺页进程可从系统可替换页框中取得页框 |

固定分配与全局置换在语义上难以长期共存：若进程可直接置换其他进程的页框，各进程实际占有的页框数就会发生变化。

## 4. 页面置换算法

页面置换算法在没有空闲页框时选择牺牲页，目标是降低缺页次数和写回开销。

### 4.1 最佳置换算法（OPT）

淘汰以后最长时间不再访问的页面。OPT 能获得给定访问序列下的最少缺页次数，但实际运行时无法预知未来，只能作为理论最优基准。

### 4.2 先进先出算法（FIFO）

淘汰最早进入内存的页面。实现简单，但没有利用页面访问局部性，可能出现 **Belady 异常**：增加页框后，缺页次数反而增加。

### 4.3 最近最少使用算法（LRU）

淘汰最长时间没有被访问的页面，使用过去的访问情况预测未来。LRU 属于栈算法，不会出现 Belady 异常，但精确记录访问次序需要时间戳、栈或较强的硬件支持。

### 4.4 时钟算法（CLOCK）

CLOCK 将页框组织成循环队列并设置访问位：

1. 指针遇到访问位为 0 的页面时将其淘汰。
2. 遇到访问位为 1 的页面时，将访问位清 0，指针后移并继续扫描。
3. 新装入或被访问的页面将访问位置 1。

CLOCK 是对 LRU 的近似，也是第二次机会算法的循环队列实现。部分教材将它称为最近未使用（NRU）算法；答题时应以题目给出的访问位扫描规则为准。

### 4.5 改进型 CLOCK

改进型 CLOCK 同时考虑访问位 $R$ 和修改位 $M$，把页面分为四类：

| 类别 | 含义 | 淘汰优先级 |
| --- | --- | --- |
| $(R=0,M=0)$ | 近期未访问、未修改 | 第一优先，不需要写回 |
| $(R=0,M=1)$ | 近期未访问、已修改 | 第二优先，淘汰前需要写回 |
| $(R=1,M=0)$ | 近期访问、未修改 | 暂不淘汰，先清除访问位 |
| $(R=1,M=1)$ | 近期访问、已修改 | 暂不淘汰，先清除访问位且淘汰时需写回 |

典型扫描过程为：

1. 第一轮从指针位置查找 $(0,0)$ 页面，本轮不修改访问位。
2. 若未找到，第二轮查找 $(0,1)$ 页面，同时把遇到页面的访问位清 0。
3. 若仍未找到，重复第一轮；原来的 $(1,0)$ 页面此时已变为 $(0,0)$。
4. 必要时再重复第二轮；原来的 $(1,1)$ 页面此时已变为 $(0,1)$。

若同一类别中有多个候选页，按循环指针最先遇到的页面淘汰。题目另有扫描或清位规则时，应以题目为准。

| 算法 | 主要依据 | 是否可能出现 Belady 异常 |
| --- | --- | --- |
| OPT | 未来访问距离 | 否 |
| FIFO | 进入内存时间 | 是 |
| LRU | 过去最近访问时间 | 否 |
| CLOCK | 访问位和循环指针 | 通常作为 LRU 的近似实现 |

## 5. 页框回收

当空闲页框低于系统设定的阈值时，操作系统可主动扫描可替换页面，建立或补充空闲页框链表，而不必等到某次缺页时才开始回收。

回收页框时需要：

1. 按置换策略选择牺牲页，并锁定相关页表或页框数据结构。
2. 若为脏页，将内容写回交换区或映射文件；干净页通常可直接丢弃。
3. 使原页表项失效，并删除或失效对应的 TLB 项。
4. 更新页框表、驻留集和空闲页框链表。

若被回收的是文件映射干净页，后续可从文件重新读取；匿名页的修改内容通常需要写入交换区，才能在以后重新调入。

## 6. 内存映射文件

内存映射文件把文件的一段内容关联到进程虚拟地址区间，使进程可以像读写内存一样访问文件。

- 首次访问尚未驻留的映射页时产生缺页，内核从文件相应位置读入数据。
- 对共享映射的修改可写回原文件，并可被映射同一区域的其他进程观察到。
- 对私有映射的写入通常采用写时复制，不直接修改原文件。
- 多个进程映射同一文件区域时，可让页表项指向相同页框，实现共享。
- 解除映射时，系统撤销虚拟地址与文件的关联，并按映射类型处理脏页。

内存映射减少了显式 `read`、`write` 调用和用户缓冲区管理，但实际文件 I/O 仍会通过缺页和回写过程发生。

## 7. 虚拟存储器性能影响因素

### 7.1 页面大小

页面较小可减少内部碎片并提高局部性匹配精度，但会增加页表项数量和地址转换开销；页面较大可缩小页表并提高一次 I/O 的传输效率，却可能调入较多暂时不用的数据。

### 7.2 页框数量与置换策略

页框过少会提高缺页率；分配过多又会减少系统可并发运行的进程数。置换算法、局部或全局置换范围以及脏页比例都会影响缺页和写回开销。

### 7.3 TLB 与页表结构

TLB 命中率越高，地址转换开销越小。多级页表节省页表空间，但 TLB 未命中时需要更多次访存。大页面可以扩大单个 TLB 项覆盖的地址范围，但可能增加内部碎片。

### 7.4 页面调入与写回策略

- **请求调页**只在实际访问时调入页面，避免无效调入，但首次访问会产生缺页延迟。
- **预调页**预测即将访问的页面并提前调入，预测准确时可减少缺页，预测错误则浪费 I/O 和页框。
- 脏页可按需写回，也可由后台程序提前成批写回，以缩短真正回收时的等待时间。

### 7.5 工作集、缺页率与抖动

某时间窗口内进程实际访问的页面集合称为**工作集**，分配给进程的页框集合称为驻留集。若驻留集长期小于工作集，进程会频繁缺页。

系统大部分时间都用于换入、换出页面，CPU 利用率反而下降的现象称为**抖动**。可通过以下方法缓解：

- 减少多道程序度，暂停部分进程。
- 根据工作集调整驻留集。
- 使用缺页率控制：缺页率过高时增加页框，过低时回收部分页框。
- 改善程序访问局部性和数据布局。

若访问序列长度为 $N$、缺页次数为 $F$，则：

$$
\text{缺页率}=\frac{F}{N}.
$$

缺页处理时间通常比一次内存访问高若干数量级，即使缺页率很低，也可能显著影响有效访问时间。

## 8. 地址翻译的示例

以下用 32 位虚拟地址、$4\text{ KB}=2^{12}\text{ B}$ 页面说明包含 TLB 和请求分页的完整地址翻译过程。

虚拟地址 `0x12345ABC` 可拆分为：

$$
\text{虚拟页号}=\texttt{0x12345},
\qquad
\text{页内偏移}=\texttt{0xABC}.
$$

### 情形一：TLB 命中

若 TLB 中虚拟页 `0x12345` 对应页框 `0x02A`，且权限检查通过，则物理地址为：

$$
\text{PA}=\texttt{0x02A}\,\Vert\,\texttt{0xABC}
=\texttt{0x02AABC}.
$$

其中 $\Vert$ 表示把页框号与页内偏移拼接。

### 情形二：TLB 未命中、页面在内存

硬件访问内存中的页表。如果页表项存在位为 1、页框号为 `0x02A`，则把该映射装入 TLB，再形成同样的物理地址并访问数据。这是 TLB 未命中，不是缺页。

### 情形三：TLB 未命中、页面不在内存

若页表项存在位为 0，则产生缺页异常。内核调入页面，必要时置换并回写牺牲页，更新页表和 TLB 后重新执行原指令。若新页框为 `0x031`，重新翻译得到：

$$
\text{PA}=\texttt{0x031ABC}.
$$

### 情形四：非法访问

如果虚拟地址不属于进程合法地址空间，或写入只读页，即使相关页面在内存中，也会产生地址或保护异常，而不是正常缺页调入。

::: tip 地址翻译顺序
先拆分虚拟页号和页内偏移，再查 TLB；TLB 未命中后查页表，最后根据存在位和权限位区分“正常翻译、缺页、越界或保护异常”。
:::
